# 原桌面消息投影的性能边界

2026-11-23 实机回访：r4 投影修复未改善目标持续 CPU，不能据合成基准标为已解决。后续使用[有界 Main CPU 与分层计时](host-cpu-profile.md)定位剩余开销；旧证据及已发布包保持可追溯。

## 实现

调用链为原 owner 快照 → `desktopSnapshot`（同步控制/回执）→ 最多两个 `runDesktopProjections` → `projectDesktopMessages` → `upsert` → 附件呈现。新快照仍覆盖等待槽，不排历史快照队列。投影有效性同时核对关闭、job 身份与版本；每32项让出事件循环后、每个附件和内嵌图片摘要分块后再次核对。过时结果不发布，但已经发生的合法附件注册不回滚，也不执行任何模型输入。

短小且无媒体字段/链接的普通回复直接呈现，避免指纹与副本开销。较长或复杂消息使用 Adapter 的进程内 LRU 最多2048项、16MiB序列化呈现数据，单项最多256KiB；仅存摘要、呈现副本和原引用正文，不保存整个上游对象。指纹前的原输入扫描限定64Ki UTF-16单位和512个扫描节点；超限直接沿原投影/分块媒体路径，不创建大JSON副本，不改变消息或媒体限额。有效输入包含完整项目/线程上下文、原 item、实际状态/轮次及当前用户回执的正文与附件；子代理仍先经过当前适配器映射。命中也补回原消息链接来源，条目失效或淘汰即正常重投影。调用者不能修改缓存副本。无文件字段的结果最多保留60秒，使用单调时钟且不滑动延长；显式刷新当前线程直接失效，删除/关闭也释放。原生 `content/changes/path/savedPath` 文件字段不缓存，每次快照继续检查。

缓存不是许可。原生文件每次投影仍核对原文件/路径变更与服务繁忙错误；不能为了性能吞掉当前版本的503失败。原链接 resolve、下载和固定版本准备继续沿原来源、完整目标、路径与版本边界实时检查；不能凭呈现命中取得字节。撤权、符号链接替换、删除或版本改变不得借缓存绕过，已提交操作及原附件不修改。文件检查失败不升级为授权，503等真实投影失败仍显式失败。

## 兼容与验证

协议、能力、媒体格式、原文、状态、队列、回执及命令截止时间不变；旧 App 继续使用原接口。iOS/Android 共用此 Host；不声称另一 Agent、Windows 或原生移动端已通过。每次投影及显式刷新仍能核对同路径新媒体；没有新增持久缓存、迁移、历史删除或未知输入重放。

执行 `pnpm build`、`node --test scripts/desktop-projection-cache.test.mjs` 和 `pnpm check`。受控基准 `node scripts/desktop-projection-benchmark.mjs` 使用合成 owner 快照；可通过 `BASELINE_RUNTIME_MODULE` 指定已冻结的修前 ESM，其他依赖保持相同。保存输入规模、CPU/墙钟和实际投影/文件检查次数，不能将它等同于目标运行 Host 的 CPU 占比或内存泄漏根因。真实复测由部署负责人核对实际 ESM 闭包、新 PID、同类负载与原回执，再取同时间窗 CPU/内存及 owner 行为；不得为测试中断正式模型任务。

升级使用规范源码构建的统一冻结包与组件指纹，保留本机私有状态、身份、配置和旧运行包。先旁路解压、校验与准备回滚，不覆盖运行中的源目录。只有原 owner、在途输入和队列的责任已经对账，且 Host 能安全退出并保存状态时，由部署负责人切换本产品 Host；不重启原桌面、不停止模型轮次、不重放 uncertain/submitted 输入。不能确认安全切换时继续使用旧 Host，明确记录尚未部署，不能用磁盘新字节冒称进程已更新。新主线包可能同时包含既有功能更新，部署前比较实际旧包，不承诺把新 Adapter 单文件移入任意旧包即可兼容。回滚同样先对账新版本落盘状态，保留原操作与未知回执，通过原正式入口恢复旧程序和兼容配置；不能整目录覆盖状态。

CI 同期核对的附件恢复边界：固定版本捕获失败先完成原快照与预算释放，再向同一读取标识公布原错误；清理期间仍是 preparing，不重建、不发布字节、不重放操作。此排序修复已有 Linux 轮询与异步删除的竞态，不改变来源校验或原失败原因。
