# Stage 14: voice permission receipt lifetime

Base `865e0102db3f48f1f4abf74ce953e7e36fba48c0`. This is a separate voice/settings lifecycle stage after the long-notice commit. Only the narrow VoiceInputView permission fragment and its new native fixture change. The existing recorder, both providers, question/composer drafts, original recording recovery, transcript routing and five shared files are unchanged.

The prior permission launcher key is restored by AndroidX, while its `launched` capture ID was only remembered in the live composition. After saved-state restoration, a new capture could launch against that restored key and a delayed older OS result could be labeled with the new capture's ID. The controller's existing generation check cannot reject a result that its caller has mislabeled with the current generation.

VoicePermission now keeps the immutable submitted capture ID, last completed capture ID and launcher epoch in saveable view state. The known physical request remains associated with its original ID across restoration. Its receipt retires that launcher epoch before another capture launches; the next epoch creates a distinct registry registration, and callbacks/effects from retired epochs are ignored. The completion marker also prevents another composition from relaunching the just-consumed ID while the controller's deferred continuation clears its request. A replacement controller still checks the original submitted ID through its existing generation/permission guard, rather than accepting an old receipt as permission for its own draft. No raw draft, audio, target identity, Host operation or credential enters saveable state. This adds no durable storage/migration schema or second permission/recording implementation.

The new fixture uses the actual Compose saveable-state restoration helper and AndroidX ActivityResultRegistry routing with an injected registry. It covers both DESKTOP and SYSTEM for: same-request restoration without another launch; cancelled old controller/replacement draft plus old and duplicate receipts; a current receipt after draft authority changes; and synchronous denial followed by another composition/restoration. All ordinary results are denials; every injected grant first revokes draft authority. Consequently the counterexample also stops before microphone/audio-focus/file capture when run against a broken old association. Readiness for the desktop branch is a typed synthetic response, and the system factory fails if invoked. No OS permission dialog, recognizer, microphone, Host or model is started by the fixture. These are compiled/prepared native scenes, not actual OS-dialog or process-death acceptance.

The remaining two-provider boundaries were reviewed in the current source. Capability inspection queries services and exact locale support without starting listening, asking permission or downloading a model. Installed language data does not make the general system service offline-guaranteed; `mayUseNetwork` remains true for SYSTEM_SERVICE/unconfirmed routes, and the existing phone warning stays visible. Actual capture rechecks service availability. The explicit system route bypasses the Host readiness/AI-sharing/upload path and only fills the original current draft. Generation, foreground, draft/connection and explicit recovered-partial-text guards remain in the existing controller. No code here treats `PREFER_OFFLINE` as a guarantee or feeds saved audio through an optional injected-audio path. `canTranscribeSavedRecording` remains false: Android's original-file phone fallback is still unimplemented, and the supported failure action is an explicit new phone recording, not a claim of iOS file-transcription parity.

No product copy, design token, generated catalog, iOS source, Manifest or global feature table is changed. Parent's current catalog and P8/notice/voice/discard hooks remain intact in the separately compiled integration candidate. Final fingerprints, auxiliary checks, source reconstruction and APKs are in the private handoff. Native saved-state/registry scenes, actual OS permission interruption, real recognizer/locale/model availability, acoustic input, file-local transcription and full real DEV remain separate gates. This workline executes none of those physical/Host/model operations. A6, task/project operations and the sealed unknown original remain paused/untouched.
