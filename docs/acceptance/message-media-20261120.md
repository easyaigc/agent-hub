# 消息媒体渲染修复验收（2026-11-21）

范围：F17/F19/F32，UI05/UI12，S04/S11/S18。实现和传输边界见[消息媒体设计](../design/message-media.md)。

## 问题与实现

指定 MacBook 原消息用 `![标题](/path/to/sample.mp4)` 引用本地视频。Host 保留原文和具名读取授权，iOS 原文本 Markdown 投影只保留标题，丢失可点击入口。独立 Foundation 检查复现 MP4 和 PNG 图片语法没有 link 属性，普通 Markdown 链接保留地址。

iOS 公共段落现在先分离完整媒体节点，呈现图片、视频和音频卡片；点击复用原消息／完整目标鉴权、当前版本解析、长度和 SHA-256 校验及系统预览。图片打开后只从已下载本地版本后台生成至多 640 像素缩略图，每条消息最多保留八个缓存文件指针，目标或消息变化时清除。

Codex Adapter 为新登记的 MP4/MOV/M4V、GIF/HEIC、MP3/M4A/WAV 补充 MIME；已存在的旧附件元数据保持。历史读取、刷新和分页不会因这些 Markdown 卡片扫描、哈希或下载媒体，视频仍由用户显式打开后完整下载。

## 性能与兼容范围

模拟器实际核对打开聊天前媒体解析和下载均为零。通用场景中图片解析／下载各一次，视频解析两次而下载一次，缺失文件解析一次；原样片点击后解析和完整下载各一次。当前交付保证 Markdown 媒体卡片的初始呈现不主动拉取媒体正文，不宣称已经具备流式播放。指定旧 Host 对 `Range: bytes=0-1023` 仍返回 200 和完整视频；完整下载回退及已有 Buffer/Data 路径保持，分段读取、起播延迟、拖动和峰值内存属于独立后续能力，不用小文件测试代替大视频性能证明。

Android 原 Markdown 图片目的地址入口保持，媒体卡片与内联缩略图尚未对齐，A6 暂停保持。EasyWork 复用公共 iOS 组件，其实际来源映射和播放未据此补签，不变更唯一对齐台账。原生模拟器结果不代替其他平台、真机网络、桌面 GUI 或正式发布结果。
