# 消息中的图片、视频与音频

2026-11-21 MV2 iOS 播放器源码候选：公共媒体会话由聊天窗口持有，inline 卡片、附件播放、原消息视频链接和 Markdown 文档视频链接共用 AVPlayer。原生资源加载代理通过原 `AgentClient`/配对 URLSession 取得带版本约束的字节，不将 Host Key 放入播放器 URL；未协商能力的适配器沿原完整下载。每块256KiB、内存块缓存4MiB、磁盘部分缓存64MiB，部分缓存独立校验且每次新播放先重新授权/准备准确版本。播放器内保留显式完整下载及分享，继续使用原 API 和 `VerifiedResourceExport`，不将部分缓存交给外部 App；外部媒体直链保留 Safari 与链接分享入口。

真机补验后的背压候选：常态按前方5秒缓冲停止供数；目标帧尚未定位，或希望播放但实际时钟超过0.75秒未推进时，同一停滞位置最多额外补4MiB，避免解码仍需数据时自锁。实际位置相对上次额度基点变化超过0.25秒才重置这项额度，包含后跳；同位置或阈值内的seek不保证重置；这不是整个会话总下载额度。原1MiB/100ms供数速率、分块/缓存上限、鉴权和版本检查保持，异步窗口更新按序号丢弃旧值；已暂停且目标帧已定位时不触发补数。播放状态按实际时钟推进，恢复与定位等待显示缓冲。源码、冷暖缓存及关闭诊断写盘的实际验收分别见[专项记录](../acceptance/mobile-video-streaming-20261121.md)，Android实现仍待原计划。

播放器请求整个尾部时保留未完成请求，以当前/待seek位置的实际已缓冲时间限制前向供给，不能按全片平均码率推算，也不能提前 finishLoading 伪造EOF；聚合供给另设每100毫秒1MiB额度，避免状态刷新前无界预取。自定义数据源关闭AVPlayer的自动防卡顿预测，按用户播放意图和实际缓冲恢复。inline↔全屏共用同一AVPlayer，真实窗口持有全屏呈现，消息行回收不撤销已经移交的全屏；只有已注册inline容器接收内联播放，普通文字链接进入全屏。重试绑定新会话的画面观察器。取消、目标切换和窗口释放关闭自有读取；首帧等待有20秒预算，分块8秒且最多两次瞬态重试，独立时钟监测起播后的30秒无进度，认证/版本错误不降级。此处描述源码，不代表全部入口和新旧组合已经验收；当前模拟器结果、失败、源码/运行包和遗留项见[专项记录](../acceptance/mobile-video-streaming-20261121.md)。

2026-11-21：视频渐进播放按 [执行与验收计划](../plans/mobile-video-streaming-20261121.md) 推进，覆盖 inline、附件、各种文件/媒体链接及网页原播放器；先做经过验证的私有固定快照和受保护 Range，原完整下载接口保持。首阶段 Host 源码、辅助 HTTP 与实际原生播放分别记录在 [专项验收](../acceptance/mobile-video-streaming-20261121.md)。手机尚未接入前继续原完整下载预览，下面的旧通过不升级为流式通过。

长视频在读取期限前通过同版重新授权换读会话；不会放宽Host期限、身份或源版本校验。先等待旧块读取退出并确认旧快照清理，再准备新读ID，避免两个大快照同时占满预算。缓存读取也检查期限；续期认证/版本/清理失败有界结束，保留显式恢复入口。最终短期注入和原生结果独立记录。

## 已核实的缺口

2026-11-20，指定 MacBook 的原消息使用 `![标题](/path/to/sample.mp4)`，属于 `output_text` 中的 Markdown 图片节点，扩展名实际为 MP4。Host 保留原文，`attachments=[]` 是普通本地引用按需解析的既有设计，不能通过全量扫描聊天目录补附件。iOS 原 `AttributedString(markdown: .inlineOnlyPreservingWhitespace)` 仅投影标题且没有 link 属性，因此图片和视频引用在手机正文中没有入口。

样本为 MP4、H.264 High/yuv420p、AAC-LC、1920×1080/30fps，121.6 秒、37,415,132 字节，moov 在 mdat 之前。指定 Host 的具名解析和完整下载成功，但 MIME 为 application/octet-stream；请求 `Range: bytes=0-1023` 仍得到 200 和全部字节。原消息、机器路径、指纹及回执仅保存在本机私有验收记录，不提交业务媒体。

## 2026-11-20 入口修复的调用链与历史范围

- 公共 iOS Markdown 段落在文本样式投影前分离完整 `![标题](引用)`；保留文本顺序、中文、转义字符、尖括号目的地址和有界平衡括号。代码示例和不完整语法保持文字。解析在后台进行，普通无媒体段落沿原路径，不因客户端名称分叉。
- 图片、视频和音频显示可点击卡片。卡片只根据引用给出展示提示；扩展名不授予读取权限，也不保证系统支持实际编码。
- 点击复用 `MessageLinkOpening → resolveMessageFile → AgentClient.download → filePreview/QuickLook`。Codex Host 沿原消息、完整机器目标和具名引用授权；下载继续做当前版本解析、长度和 SHA-256 校验。原来源不存在、被替换、没有能力或断线时沿原错误和恢复入口，保留原链接、草稿及已提交操作，不创建模型任务。
- 已打开图片从已认证下载的本地文件后台生成至多 640 像素缩略图。消息内仅保存至多八个本地缓存 URL，不保存媒体正文；目标或消息变化时清除，取消或消失后的旧结果不回写。
- Adapter 按解析出的文件名补充 MP4/M4V/MOV、GIF/HEIC 和常见音频 MIME；其他扩展名继续为通用文件。已存在的旧附件登记保留原不可变元数据，不为补 MIME 重写历史或已提交附件。旧端仍可使用既有文件入口，不新增强制能力或协议版本。

上述历史候选解决媒体入口丢失并沿用系统原生预览，当时视频为用户点击后完整下载再预览。2026-11-21 的流式源码另见本页开头及专项验收，不以旧结果代替新结果。视频封面、自动图片缩略图下载、HTML video／source 与引用式 Markdown 图片仍未新增；普通第三方网页保持原网站播放方式，不将扩展名当作可播放证明。

## 性能边界与后续流式方案

聊天首屏、刷新和分页不因这些 Markdown 媒体卡片 stat/hash 文件、下载媒体、抽视频帧或创建播放器。现有结构化原生附件的独立处理保持；其自动图片下载策略不在此次候选中变更。此保证必须通过实际请求计数验证，不能只凭 UI 存在卡片判定。

大视频完整下载在 Host 和当前 Codex iOS 下载器中仍会使用整份 Buffer/Data。仅添加 Range 响应头或给 AVPlayer 一个 Host 地址不能消除此限制；生产凭据也不能写进消息 URL、网页或外部播放器地址。

独立协商的资源读取设计如下；固定快照/Range 和 iOS 数据源已进入候选，缩略图及其他来源仍属后续：

1. 具名解析获得准确目标、来源消息、资源版本、长度和媒体类型。只按用户已授权的来源读取，不能接受任意电脑路径；引用解析与字节搬运保持窄接口。
2. Host 从已授权、已核对真实路径及文件身份的来源准备私有独立快照，同时计算摘要并核对来源前后身份；单个句柄本身不等于固定版本。快照读取使用有界缓冲与背压，正确返回单 Range 的 206/Content-Range、无效范围 416、HEAD、长度和版本标识。来源变化终止该版本，不将两个版本拼接为同一视频，不在每个分段重复哈希全片。
3. 原生播放器通过带原认证/证书约束的资源加载或本机回环网关访问；网关仅映射具名资源，隔离完整目标和版本，不泄漏 Host Key。点播放才创建 AVPlayerItem，离开或切换目标取消请求、释放播放器。
4. 图片和视频封面走独立有界缩略图能力，按显示像素降采样、可见项低并发、离屏取消。缓存键含完整目标/资源版本/尺寸，设磁盘与解码内存预算；未知内容或过大解码开销用占位卡片和显式打开入口。
5. 旧 Host 或无流式能力的其他 Adapter 保持完整文件下载回退；共同界面按能力选择，不能按 Agent 名称新增另一套业务流程。新能力未实现前不宣告已支持。

## 验收与双端影响

当前实现的辅助检查、原生交互和正式部署分别登记在[专项验收](../acceptance/message-media-20261120.md)。普通 iOS 场景使用独立原生模拟器即可；指定 MacBook 原样片已读取并在模拟器验证播放，App 与原 Host 的直连另记，不为只读媒体额外发送模型输入。

共同断言对应 F17/F19/F32、UI05/UI12、S04/S11/S18：原引用不丢失，图片可查看、视频可播放，失败可恢复，无额外模型输入，加载聊天不拉取视频正文，切目标无迟到覆盖。覆盖中文/空格/括号/代码/混排、旧 Host 回退、损坏或不支持编码、大文件、取消/重进及缓存隔离。后续流式能力另测首帧时间、播放和拖动请求范围、峰值内存、正文加载时间及下载字节，记录设备、网络、冷暖缓存与实现指纹；不承诺固定网络时延指标。

Android 当前 Markdown Image 节点已有可点击目的地址，尚无本候选的媒体卡片/内联缩略图；Host MIME 修复可共用，Android 原生媒体呈现需独立实施与验收，A6 暂停保持。EasyWork 复用公共 iOS 段落与现有下载接口；其实际来源映射、能力和原生结果独立验证，不据 Codex 结果提升唯一对齐台账。
