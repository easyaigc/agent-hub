# Host 原生建议、Windows 存活性与 Trace 回收

本轮目标是修复手机建议缺失、Windows 只读连接 502，并按同一接入包逐机部署后完成原桌面与实体手机核对。每个会话保留最新一条建议；建议持久保存并读回后，原始 Trace 仍须满足封口、安静及未占用条件才能回收。已知失败、空结果和取消诊断短期保留；未知结果不按时间直接删除。

## 已确认的问题

- 原生样本的原始 Trace 可能取消或不含正文，实际建议稍后由原桌面的 JSON-RPC 结果及对应安全决策给出；采集必须按准确来源轮和当前 producer 绑定。
- 大历史正文中的 `thread/sample` 字样曾误选采集边界并使另一条 pending 建议失效。R10 改为有界顶层 envelope 路由，相关辅助反例已验证。
- Windows 更新后的旧 CLI 路径造成只读连接失败。R10 当前环境两次独立新建的只读 reader 均完成 initialize、thread/list 并正常退出；这是只读运行时证据。
- Windows R10 真实时钟诊断复现租约失效：构造 11.906 秒；第一次空闲 tick 10.945 秒，返回时租约年龄 5448ms；第二次 11.277 秒，转为 unavailable 并报 `native_bridge_lease_expired`。三个前置原生 range 阶段均成功，107 次底层执行无原生错误。该诊断使用明确的合成 producer 身份，不能替代真实原桌面进程链证明。

## R11 源码候选

Windows 原始双向字节先建立管道，建议采集由固定 Worker 承担。Worker 在统一的三十秒启动预算内核对真实原桌面 IPC 与 producer 链，再建立持久原生读取 scope。私有 Trace 根、配置目录和 vendor-log 根固定，沿用原 DACL、句柄、PID/启动时间、启动器摘要、包身份及 range 守卫；没有任意 shell、IPC 方法或根目录透传。

每次原生调用及整个阶段均受原预算约束，六秒有效期不放宽。采集队列与帧有界；采集失败、超限或未知退出不影响原字节转发，不重放未就绪前的帧，也不自动重复模型输入。

旧基线 R11 的完整 `pnpm check` 已通过，635.987 秒、1310 份输入前后未变。当前组合候选加入规范库的 Windows 更新恢复、严格私有文件创建及首次目录修复，保留各自权限守卫；最终租期校验在原生权限检查完成后、实际原子发布前执行。组合构建和建议定向辅助回归已通过，组合完整检查仍待完成。Windows 隔离预检已编译两份新的 Trace C#，S/P 只读正例和错误 producer 链拒绝已观察到；这些 primitive 不证明真实 producer、六秒稳定运行或手机建议通过。最终统一包与逐机结果仍须补齐。

## 连续建议的回收边界

同一会话两次 Native 建议先后完成时，唯一正文槽位会保存后一条。旧 Trace 首次扫描若已无法从原始载荷提取正文，旧逻辑只确认同来源轮的结果，可能把它长期保留为未知。新逻辑在同一目标和会话中，确认现存真实提取正文的请求时间严格晚于旧 Trace 结束时间，再完成写锁、flush 和读回，才认可它已被替代。pending 请求时间本身不构成确认；无效时间、来源冲突、未封口、未静默、占用或未决删除仍保留原数据。

该边界已动态复现：旧策略的一轮回归退出 1，78 项中 31 项失败（含失败父测试）；修复后同一组 78 项中 72 项通过、0 失败、6 项平台跳过。原先仅按 25/72 小时仍不能删除未知记录的用例保持。当前修订 Adapter 指纹为 `bb036b1d924b3ce1a49ccfd825b0d012b55cbf9af01167cbb8a7d5147c0138d1`，其完整检查及实际 Windows、原桌面和手机结果仍须单列。此前组合版本的完整检查为 735.68 秒通过，不能替代本修订。

最终完整检查曾在合成 Worker 夹具轮询代次文件时读到截断后的空 JSON。夹具已改为同目录原子替换，原截止时间和隔离断言保持，原失败用例单次复核通过；此修订没有改变生产 Adapter 指纹。完整检查仍按当前源码重新执行。
