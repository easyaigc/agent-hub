## Existing data and ordering

Document/photo/camera result children each store `document-requests-v1`. Exact v1/v2 JSON contains revision and up to32 records: immutable request/destination key, generation, presentation selection, requestId, errorGeneration, original phase, ordered content URI strings and releaseReadGrants subset. V1 maximum is10; V2 explicitly carries5 or10. Preserve the signed original errorGeneration rather than assuming a nonnegative counter. There are11 phases (listed in the JSON contract), one awaiting permission/prepared/launched row at most, and distinct selected/held/terminal states. Inert migration must not call the producer decoder to normalize historical limits or run recovery.

Each result child has its own `payloads` child containing the inbox index and exact draft metadata/payload/thumb graph. Process order can leave selected journal plus receiving/failed/pending payload, ready journal plus pending/bound/consumed payload, or a terminal journal plus partially cleaned consumed bytes. Consumed payload receipts can outlive the journal's32-row terminal expiry, so a naive one-to-one journal/batch requirement would reject legitimate history. A final graph validator needs an explicit table of supported crash/interruption states and explained terminal residue; unknown nonterminal ownership must still reject, never disappear.

Camera additionally has an `outputs` encrypted child with exact `output-v1-<UUID>` claims containing only version/id. Raw files are `files/camera-output-v1/<sourceScope>/photo-<UUID>.jpg`; scope is derived from the source outputs storage identity. That source scope is audit provenance, not a destination path or FileProvider authority. Prepare creates raw file then writes claim, so failed/unsettled publication can leave an unclaimed file. Cleanup deletes raw file before removing claim, so a claim without raw file is a distinct possible interruption. Neither state may be silently omitted or reconstructed.

## Actual producer and external writer boundary

NativeSelectionRecovery has a coroutine scope, journal, nested payload store and ActivityResultRegistry launchers independent of Session tasks. Several finally blocks remove a job before their suspending refresh completes. Current `busy`/pending checks therefore are not a writer fence. Register/recoverReady can restore callbacks, persist/release grants, read a provider, bind/import into the old destination, or cleanup raw data. The completed external-inbox gate covers nested inbox store calls but does not own selection journal/output mutations or external camera writes.

Camera endWait records detached and clears UI pending while retaining the possibility of a late camera result. It does not prove that the external camera closed its writable FileProvider descriptor. Version/id claims contain no completion or content manifest. Sampling an unchanged hash, cancelling an app coroutine, or taking a lock the external app does not use cannot establish closure. Migration must refuse a live or unproved external writer without revoking grants, relaunching the camera or deleting an original to make the fixture pass. Current encrypted-child rejection is also not proof that every independent raw/orphan directory was inventoried.

## Planned implementation and destination

Finalize a versioned closed inert schema before enabling export: distinct exact journal, payload-index/text/binary, output-claim and raw-original entries; full hashes/bounds; explicit absent/empty/incomplete status; every alias owned once. Introduce a named existing-only reader for fixed document/photo/camera and fixed payloads/outputs nodes, with key-only/no-create/no-Atomic-recovery access and private owned no-follow descriptors. Keep Source51 default reader child refusal and limits. Do not accept arbitrary path/child/key aliases from a portable candidate.

A typed actual Session/recovery owner must seal new selection/permission/result callbacks, retry/retire/endWait/recoverReady, join admitted work to actual completion and hold journal/payload/output identity through publication. If external writer closure cannot be proved, leave that scope explicitly unsupported. Inventory exact raw scope siblings, claims, files, links, sidecars and unexplained residue. Preserve originals and their partial states on refusal.

Imported archives stay outside active recovery children. Enumeration/copy must not construct NativeSelectionRecovery, register an old request, call a provider, revive a URI grant, import into an old destination, upload, retry or clean old originals. New installation authority is independent. Exact same candidate/receipt recovery and re-export must preserve later drafts and never turn a detached late result into an active command.
