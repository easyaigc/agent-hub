# 图片预览与多选

对应 F71、UI07、UI12。用户确认方案一：图片主体打开预览，右上角圆圈用于快速多选；最近图片和相册共用选择状态，点“添加（N）”统一加入草稿。Android 对应界面待 A6，暂停保持。

## 交互与实现

- 加号面板展示可访问的最近图片。点图看大图，点圈选择或取消；选中显示顺序号。相册使用三列网格并分批加载，返回保留选择，关闭附件面板放弃尚未添加的选择。
- 全屏预览显示页码、文件名和缩略导航。支持左右切换、双击／双指缩放及放大后的拖动；底部可选择当前图片或统一添加已选图片。加载失败可重试，离开当前页取消加载，晚到结果不替换新图片。
- 草稿图片卡片点开同一预览器，可翻看当前准确草稿中的图片、缩放及移除当前图片；文字草稿保持。最后一张移除后返回输入区。
- 选择、预览均不上传。添加仍经原本地附件准备、持久化与草稿代次围栏；点击发送后才上传和执行。五个附件与每项 20 MiB 上限保持，剩余名额计算包含已有文件。
- 本地 `LocalAttachment.photoAssetId` 是可选的照片来源元数据，随草稿和准备日志恢复以显示“已添加”；旧草稿缺失该字段时继续正常读取。它不进入 Host 上传清单，不改变协议或远端命令。
- 明确拒绝照片读取时保留系统选图器；部分授权只展示可访问照片，并保留管理授权入口。完整权限、主题、字体、方向和大图库矩阵须分别验收。

## 验收入口

`testQuickAttachmentImagePreviewSelection` 使用独立验收 App 在物理 iPhone 创建并操作测试自有照片，检查预览／多选、跨相册选择保留、缩放／翻页、移除、草稿重启恢复、剩余名额及取消选择；同时验证旧附件解码和照片来源准备日志恢复。测试只清理其自有照片。

`testQuickAttachmentImagePreviewSendDEV` 从预览中添加测试图片与独立文本附件，原生手机显式发送一次真实 xhigh 模型输入，再由准确原桌面 owner 独立检查附件内容、原操作和完成轮次。未知结果先核对，不能重放。独立 Bundle、代码和签名包指纹、CoreDevice、xcresult、失败与本次通过范围分别保存；编译和合成检查不代替物理执行。

验收脚本为 `scripts/mobile/quick-attachments-ios-acceptance.mjs`，显式指定独立 Bundle、设备、冻结构建模板和测试名。真实模型还需本机私有 HTTPS DEV 夹具。执行结果记录在本机忽略的专项验收目录，不能由其他设备或旧版本通过推定本版本已验收。

本次实现对应的物理 iPhone、真实模型、辅助检查、失败记录与未验收范围见[专项验收](../acceptance/image-preview-selection-20261027.md)。
