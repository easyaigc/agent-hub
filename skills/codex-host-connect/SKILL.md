# 接入一台 Codex 电脑

Codex 按机器运行目标、证书和设备密钥连接，不将 Codex 登录账号变化当作另一台电脑。保留稳定 Host、workspace、runtime 与原设备绑定；旧账号字段仅作为历史元数据，不能据此清除草稿或更换未知提交。App 人类登录、设备会话、项目权限和其他 Agent 的账号协议继续按原规则执行。版本交付必须注明此策略是否已在目标机实际部署并验证，不能把源码修改或旧验收记录写成当前通过。

在目标电脑上执行。配置结束必须向请求接入的用户交付可直接填写的电脑名称、实际 HTTPS 地址、稳定 Host ID、私有密钥文件位置和分层验收结果。升级优先复用手机原有连接与设备凭据，不轮换密钥；完整密钥只留在受保护的本机私有配置、环境变量或设备密钥库，不写入聊天、日志、源码、可分享报告或接入包。多台电脑各自保留状态，不复制身份、令牌或通过记录。

本 Skill 的完整接入包附带 `assets/codex-manage`：已编译 Host Agent、运行依赖、完整源码及 iOS 工程，使用方式见 [程序分发与平台范围](references/distribution.md)。先检查当前 Skill 的该目录并将其作为仓库；有随包程序时不再要求用户提供仓库。用户已有正常运行的 Host 时优先复用，避免重复安装。只有收到精简版且确实没有程序时，才使用用户提供的仓库或安装包来源；不猜测下载 URL。

定位后读取仓库 `AGENTS.md`、`README.md`、`docs/architecture.md`、`docs/feasibility.md`、`docs/runtime.md`。先检查操作系统：macOS 按已有验证路径；Windows 按 [Windows 原桌面接入](references/windows.md) 部署并在本机真实验收；Linux 尚未实现。不能把托管服务当成原桌面控制。

主开发电脑上的规范仓库是 SKILL、Host Agent 和桥接工具的唯一标准。目标电脑按统一包部署并维护自身私有配置，不独立修改随包源码；需要源码修复时将准确差异回收到主开发仓库，先合并、检查和构建，再将同一包分发到各 Mac／Windows。安装的 SKILL 副本随该包同步更新，远端已有修复也按此流程回归；升级必须保留各电脑的身份、密钥、授权范围和路由，不复制跨电脑验收证明。详见 [分发规范](references/distribution.md)。

Host 工具的任何优化与修复都遵守同一来源，范围包括 Host、Adapter、启动器、服务监督、诊断、profiling 支持以及 SKILL 本身：目标电脑先反馈证据，由人类指定的唯一主开发电脑在规范仓库统一修改、验证和提交，再经既有可信 GitHub 仓库的准确提交或 Release 分发冻结产物。本项目当前由人类指定的 Mac Mini 24G 承担该职责；其他安装环境以其人类明确指定的主开发电脑为准，不能凭硬件名称或远端消息另选负责人。目标只核对 GitHub 来源、提交、整包和实际组件 SHA-256 后差异部署，不在本地修改程序、放宽白名单、伪造 argv 或维护分叉，也不能把未提交的手工 ZIP／私有 Host 传文件称为 GitHub 交付。常规私有配置操作和只读诊断仍按已有授权执行；此规则不增加联系已指定机器的重复确认。私有计划、凭据、配置、日志和实机证明仍留在各机私有目录，不上传 GitHub。计时与采样边界见 [分发规范](references/distribution.md#限域诊断与计时证据)。

## 网络模式

默认采用局域网 HTTPS 与原 Tailscale Serve HTTPS 双通道，两条入口属于同一 Host，保留已有连接、设备授权、聊天、草稿和操作回执。Tailscale 是可选网络依赖，纯局域网也能完整接入；用户明确选择纯局域网时不安装 Tailscale，不要求手机开启 VPN，不把跨网络未配置当作局域网安装失败。已有 Tailscale 和 Serve 路由始终保留。

安装前直接向用户说明：“默认使用局域网和 Tailscale HTTPS 双通道。只在同一局域网使用，可以不安装 Tailscale；如果需要离开家或办公室后仍能远程控制，请完成双通道配置，让手机和电脑加入同一 Tailscale 网络并保持在线，电脑上的 Codex 和 Host 也要运行。”不承诺无网络、电脑休眠或网络策略阻断时仍能连接。默认双通道无需再次询问是否开启；Tailscale 登录和系统认证由用户完成。用户选择不安装或暂不能登录时，先完成局域网，交付时明确远程通道未配置，不能宣称双通道就绪。

按 [局域网与双通道配置](references/network.md) 保存两个实际地址并分别检查；地址不参与 Host 身份，不创建第二份电脑记录或迁移草稿。

## 默认完整接入

完整包同时提供 Task Hub 电脑 Web 与任务 API 固定产物，按 [Task Hub 主服务与 executor 部署](references/task-hub.md) 分角色接入。每台电脑默认保持 executor 角色；只有人类明确指定的唯一主机可以安装 primary。任务服务独立于 Host 生命周期和 Tailscale Serve，局域网 HTTPS 默认不要求 VPN。预检核对可信主机登记、Bonjour/HTTPS 与旧非 Bonjour 任务 API，沉默或旧主离线不能授权第二库；Windows primary 尚未实现。明确隔离 DEV 使用新身份/状态/端口，旧数据库迁移另行处理，不能把新空库或健康检查当作全流程验收。

首次接入、增加电脑、修复和升级都默认配置本产品当前已实现的全部适用原桌面与手机能力。新建、零聊天项目首聊、无项目新建和主动打开属于必需范围，配置和真实协议就绪后默认启用正式入口；不再询问用户是否需要这些功能。只有用户明确要求缩小范围时，才按指定子集接入。

**macOS 默认完整接入必须配置原桌面单实例共享通道**，与 Host 自启、独立创建桥接和持久 Trace 一起完成，不再等待用户单独选择。按 [共享通道配置](references/host.md#默认配置原桌面单实例共享通道macos) 安装 v2 持久环境，并将同一个回环地址持久保存为 Host 的 `CODEX_SHARED_SERVER_URL`；单独启动 Host、开启 Trace 或能回复聊天均不能替代这一步。它让原桌面和 Host 通过同一官方执行服务管理聊天，避免已完成但仍加载的聊天因 `already has an active writer` 无法归档／删除。用户明确缩小范围或保留其他 CLI 配置时尊重选择并报告缺项；Windows 尚无此安装路径，按当前实现单列限制，不能照搬 macOS 或报告跨平台全功能已接通。

共享环境与 Trace 应在同一个首次安装流程准备好，再由用户保存工作后正常退出并从原图标重开一次；不强退、不自动重开、不打断其他任务。重开后独立核对共享服务进程与 owner、准确聊天实时状态和手机操作。等待重开时交付“配置就绪，待正常重开”，不能宣称安装已全部生效或全功能可用。归档、恢复、删除及批量归档列入必验清单，其中已完成但仍加载聊天的归档／删除必须实际覆盖；配置与实测结果分别记录。

自动发现属于默认完整接入，发现本身不授予访问权。局域网 Bonjour、VPN 目录和私网 HTTPS 按 [Host 部署](references/host.md#身份与本机检查) 配置。新版 Host 声明 `connectionMode: host-key`，首次点选后输入该电脑的 Host Key，Host 校验后颁发加密设备凭据，之后自动重连。App 同时保留旧版 `automatic` 的发现与连接兼容，按实际描述选择流程；不得把新版拒绝降级为免密 claim。公开描述、完整目标和真实工作区分别核对。授权表单只由明确点选触发，取消或切换后保持可操作，后台重试不得反复弹窗。旧免密绑定升级后需显式补做一次授权，保留原设备凭据、草稿和操作，不轮换 Host 身份或密钥。

按 [完整功能清单](references/full-functions.md) 确定必验项目，并按 [原桌面与手机验收](references/acceptance.md) 执行。读取仓库实现、手机界面和实际能力，不能只按 Host 当前声明的能力缩减清单；已实现但没有开放的能力应定位并修复。当前未实现的能力单独列出，不承诺通过修改声明即可接入。

普通安装不需要目标电脑具备 Xcode、模拟器、iPhone 在场或验收报告。独立桥接按本机身份、私有权限和真实运行时就绪开放能力；不检查 Codex 应用版本，不比较已验证构建清单，也不要求校正桥接配置的版本字段。`desktopVersion` 可省略，已有值仅作历史元数据并保留。`verification` 仅引用验收证据，报告缺失、过期或不可读取不关闭正式功能。正式配置默认省略 `validationOnly`，但用户明确选择的验证专用配置必须保留；升级先核对遗留限制的用途，不能无条件解除。

安装、能力启用和真实 DEV 验收分别记录。功能交付仍按仓库最新 `AGENTS.md` 完成真实桌面、原生手机 App、真实模型和桌面独立核对，不删除或跳过场景，不把能力声明或 fixture 写成通过。验收使用独立状态与端口，测试后用普通 App 验证正式入口；缺设备或证据时保留实际可用功能，交付安装参数并标明验收未完成，不能报告全功能实测通过。

Host 默认安装当前用户登录自启，无需再询问是否开启。macOS 使用用户 LaunchAgent，Windows 使用当前用户交互登录计划任务及等待 worker 退出的无控制台启动器；升级原 Node action 后核对新进程与窗口，步骤见 [Windows 后台迁移](references/windows.md#后台启动与旧任务迁移)。首次安装、修复及升级都核对持久注册与启用状态，不能只临时运行进程。按对应平台执行 `start`／`restart` 后检查 `running`、`loginAutostart` 和身份探测，分别记录已配置、当前在线及真实注销／重启后的恢复结果。显式 `stop` 停止本产品 Host 并关闭自启，保留私有状态；之后 `start` 重新启用。用户明确要求不自启时尊重其选择并记录。自启发生在该用户登录后，原 Codex 仍须正常打开并登录，跨网络通道使用时 Tailscale 须在线；不把 Host 自启表述为原桌面自动冷启动或未登录即可远控。

## Trace 与桌面下一轮建议

完整接入默认配置已实现平台的持久 Trace 和 Host 观察器，一次完成安装。先简要说明用途、推荐方案和本机保存范围，直接进行常规配置，不为日志、私有目录、登录环境或 Host 观察器逐项追加授权确认。用户明确关闭、仅本次诊断或缩小范围时保留其选择；只同步文档不改变运行配置。系统实际要求的登录、权限与原 Codex 正常重开时机另行说明，不强退或打断现有任务。Trace 暂不可用时继续完成 Host 与其他已实现功能，交付具体缺项和后续动作，不将日志条件变成整个接入的门禁。

先向用户解释：当前手机原生建议链路依赖原 Codex 的 Trace，开启后可读取桌面已经生成的下一步建议及其准确聊天、来源轮次，在手机输入框显示灰字和全文；用户点“采用”才填入本机草稿，可撤销，不自动发送，也不额外调用模型生成建议。原生路径近实时刷新，尚不证明桌面输入框此刻的显示／隐藏；普通消息、任务进度、完成和错误由既有运行时通道提供，并非必须开启 Trace 才能使用。Trace 还保留请求／返回、时间与关联 ID 供本机排查，进一步的耗时或错误分析须按实际字段扩展，不能当作已上线手机功能。详细说明与推荐话术见 [Trace 用途与安装流程](references/desktop-suggestions.md)。

macOS 默认使用随包持久环境工具及 `status`，将其实际目录配置给 Host；已有有效持久配置复用。记录保存在本机私有目录，登录域设置可能由同用户后续 Codex CLI 继承，交付时简要告知。持久环境就绪后由用户择机正常退出并从原图标重开，不需要一次性启动器；当前进程环境、新 Trace、Host 读取及手机显示分别核对。仅用户选择本次诊断时，才使用参考文档的一次性准备和独立等待器，先验证存活再提示退出。配置已完成但等待正常重开时准确交付下一步，不因等待窗口省略其他已完成安装项。Windows 原生 x64 适配已加入统一源码，使用 `scripts/windows-suggestion-trace-environment.mjs install|status|disable` 管理当前用户环境，按 [Windows 接入](references/windows.md#trace-与下一轮建议) 配置 Host 并核对原进程；ARM64／32 位未验证。源码、正式部署、正常重开、新记录与手机验收分别交付，不照搬 macOS 命令或虚构通过。

原建议读取保持只读。手机灰字不是草稿；明确采用才填本机草稿。已有正文默认追加，替换须确认，预览按目标、来源轮次和草稿编辑版本隔离。真实验收使用手机原有连接，分别核对展示、采用、撤销、原文保护及原 owner 无新增手机输入；临时 DEV 的通过不替代正式连接验证。

## 跨 Agent 协作（按需）

本接入同时提供基于 Host 协议的协作入口：同类场景可让一台电脑的 Codex 分派给另一台 Codex；异类场景由来源侧协议调用端和目标 Host 适配器连接，例如 Claude Code ↔ Codex 或 Codex ↔ EasyWork。客户端使用各自的模型与登录，任务固定目标机器、项目与会话，通过具名操作提交、排队、查询进度和回执。

用户明确要求协作、询问协作方式或需要扩展其他客户端时，读取 [跨 Agent 协作说明](references/agent-collaboration.md)，按其中的实现状态和 [协调流程](references/coordination-guide.md) 选择调用端。已有 `contact-host.mjs` 面向 Codex `desktop-runtime`；不能把它当成所有客户端的通用执行器，也不能将 Claude Code 等尚未内置的目标适配宣称为已完成。只修改文档或安装接入不触发协作，不发送验收消息。

## 执行顺序

1. 确认目标电脑、仓库、电脑名称和默认工作目录。优先复用已安装软件与本机 Host 状态；缺少的必需信息一次问清，继续不依赖答案的检查。
2. macOS 按 [Host 部署](references/host.md)，Windows 按 [Windows 接入](references/windows.md) 检查 Node/pnpm，优先使用随包已编译程序；源码安装则先构建。保持原应用图标与正常启动方式，启用 `desktop-runtime`，默认安装并核对 Host 登录自启。macOS 同时执行 [共享通道配置](references/host.md#默认配置原桌面单实例共享通道macos)：v2 登录环境、共享 launcher、Host 持久 `CODEX_SHARED_SERVER_URL` 缺一不可；已有匹配配置复用，不因旧 Host 当前未声明能力就跳过。不做 Codex 应用版本预检或兼容性提示，不要求更换版本。Windows 与 macOS 一样按每条聊天的实际 owner 开放回复、停止和审批，不以验收聊天白名单或验收报告作为启用条件。更新旧安装后按原环境重启本产品 Host，保留 Host ID、密钥与原配置；核对遗留验证配置的用途，用户明确选择的验证专用配置不自动改成正式配置。
3. 按 [网络模式](references/network.md) 配置局域网 HTTPS，并默认保留／配置 Tailscale Serve HTTPS 备用入口。Tailscale 可选；明确纯局域网或暂不能登录时先完成局域网，不阻塞 Host。双通道的 macOS 步骤见 [Tailscale 接入](references/tailscale.md)，Windows 见 [Windows 网络步骤](references/windows.md#tailscale-与手机)。只将已探测的原 HTTPS 根地址写入 `HOST_AGENT_HTTPS_ENDPOINTS` 并持久保存；不能猜测域名或用直连证书覆盖 Serve 信任。用户完成登录、VPN/系统扩展与管理员认证；不收集密码、验证码或 Tailscale auth key。
4. 按网络参考分别检查回环、局域网 HTTPS 及已配置的 Tailscale HTTPS，核对相同完整机器目标、Host ID、鉴权和 `desktop-runtime`。用 `scripts/probe-host.mjs` 检查回环和系统信任 HTTPS；局域网使用持久证书固定，不能关闭验证。脚本仅 GET，输出摘要，不输出令牌、项目名称、目录或聊天正文；它不检查自动授权，另按 Host 部署参考核对真实私网发现、`host-key`、Host Key 授权的公钥 claim 及新凭据工作区身份，不能用回环／Serve 健康检查替代。
5. 默认按 [独立空会话桥接](references/prepared-bridge.md) 配置原桌面创建；配置匹配本机 Host、私有权限且真实协议就绪时，启用正式 `desktop:creations`、`desktop:creations:projectless`、`desktop:open`，不要求先提供证明。按 [原桌面与手机验收](references/acceptance.md) 另行实际执行创建六项、未加载主动打开和桥接生命周期专项，证据绑定当前 Host、验收环境与运行 Adapter；可取得的应用版本仅作为报告元数据。现有兼容 driver 未通过生命周期门槛时报告设计失败，不把功能场景通过当成完整接入。已有聊天仍按实际 owner 独立开放控制；独立验收聊天只用于测试，不限制日常使用范围。`validationOnly` 和旧兼容 driver 的 `openOnly` 用于验证或用户明确缩小范围，不是默认正式安装配置。
6. 完成 Trace 与共享通道收尾：简要说明建议同步的用途和本机保存范围，macOS 和原生 x64 Windows 默认使用各自工具配置持久环境及 Host 观察器，保留用户明确选择。macOS 在共享 v2、Host URL 和 Trace 都准备好后，交付一次正常重开的具体动作；不反复请求安装授权，不自动退出／打开桌面。仅用户选择本次 Trace 诊断时才使用已验证的独立等待器。重开后分别核对共享官方服务／owner 与 Trace 新记录；Windows 分别核对注册表、原进程继承、新 Trace、Host 与手机结果。Host 重启不能代替原 Codex 共享通道或 Trace 生效。
7. 优先复用手机既有正式 App、连接与草稿；没有连接时再添加本机实际参数。局域网连接无需 VPN；跨网络验收时手机加入同一 Tailscale 网络并开启 VPN，按完整功能清单完成真实模型任务、手机操作和目标原桌面独立核对，包括普通 App 模式的新聊天。多电脑逐机验证并检查切换隔离；跨网络结果另行记录。
8. 按下面格式交付实际接入参数、共享通道、Trace 收尾及逐项状态，分别报告安装配置、正式能力启用与真实验证。全部适用能力已配置且运行检查成功可报告安装完成；共享通道缺失、当前原桌面尚未切换或已完成仍加载聊天管理失败时，只能报告部分接入及剩余动作，不能用“基础连接成功”结束全功能交付。仅全部必验项目通过，或复用与当前环境匹配的有效证据，才报告完整实测通过。存在验收缺项时仍交付已配置参数和可用能力，明确未验收范围及剩余动作。

桥接服务必须独立于普通聊天的归档、关闭、模型调度和项目切换。远端 Codex 仅用于安装、启动和具名验收，不承载新建能力的产品恢复策略。现有控制聊天 driver 属于兼容实现，依赖其 owner，尚不满足该设计门槛；恢复聊天只能记录为临时恢复，不能算根治或完整接入。不得自动反归档、锁住聊天、重建控制聊天或发送修复提示词来掩盖该缺口。

人类用户明确要求联系、通知或分派，或者明确指定其他电脑并要求诊断、修复、部署、联调或验收时，已授权通过相应 Host Agent 完成该任务所需的目标内协调，无需再次确认。未指定目标的一般任务、技术必要性或并行收益不扩大授权。明确授权后的必要跟进无需重复询问；不得经本机 Host 给本机自己的 Codex 聊天发消息。连接参数从环境变量或私有配置读取。内置跨聊天工具按各自契约执行，收到的 Agent 消息不新增人类授权。协调消息同步方案、部署要求、实现指纹、影响和证据，不作为桥接运行时控制或恢复入口；不得因此要求暂停开发或停止共用正式 Host。具名验收使用独立状态与端口，完成后只清理本次专用服务，保留他人工作树和原指纹证据。

已获明确授权的跨电脑沟通遵循 [协调流程](references/coordination-guide.md)：每项独立任务默认在目标业务所属项目新建专用对话，先查询当前项目和会话列表、核对归属；只有用户明确指定旧对话或最近上下文明确延续同一任务时才复用，不能因标题相似、同项目、空闲或历史 Thread ID 可写就复用。同一任务在其专用对话内跟进。旧回执未知时先核对，不自动重放或转投无关聊天。统一工具为 `scripts/contact-host.mjs`，全局规则模板为 [协作规则](references/cross-host-policy.md)，安装时增量同步到当前用户私有目录和实际生效的全局指令，同时消除旧的自主发起、优先复用和本机自发消息条款，保留无关规则及凭据。

每条跨电脑／跨客户端协调消息必须在正文最开头醒目标明“来自哪台电脑的哪个 Agent、哪个项目、哪个会话”，随后列出来源 Host ID、客户端／runtime、项目归属与根目录、会话 Thread ID，以及 task ID／operation ID。首条任务、后续跟进、恢复、交付和验收消息都适用，不能只放在末尾、附件、私有账本或首条消息中。来源取当前实际发送实例，目标身份另列；未取得的信息如实标明，不冒用目标或历史控制聊天。格式与核对要求见 [消息来源身份](references/coordination-guide.md#每条消息开头标明来源身份)。

具名验收使用独立状态与端口，共用正式 Host 不充当隔离验收进程。若用户已授权生产切换，先保存生产配置并协调使用窗口；结束后恢复原正式配置和能力，核对普通手机 App 的按钮与真实创建。不把本次测试的 `validationOnly` 留在正常生产连接上，也不改动用户明确保留的验证专用配置。未知创建结果保留原操作 ID，先核对实际提交、回执与原工具调用；只有明确的提交前拒绝才能判为未执行，超时或查不到历史不足以允许重发。

跨电脑文件交付同步安装同包 `scripts/transfer-host.mjs` 到私有 `.config/agent-hub/transfer-host.mjs`，与 contact-host.mjs 分工。它提供 send/status/resume，先核对完整机器目标并保存不可变清单与字节，再调用既有 files:upload；重复 send 只查询，显式 resume 复用原 ID，完成后保留回执。用法及 20 MiB 限制见 [协调流程](references/coordination-guide.md#私有与接口边界)。程序、SKILL 和工具摘要逐机核对，真实验收不跨机复用。

## 配置后的必交付参数

最终回复必须包含以下表格；示例占位符仅定义格式，执行时替换为该电脑实际值：

| 参数         | 实际值                                                                            | 手机如何填写                         |
| ------------ | --------------------------------------------------------------------------------- | ------------------------------------ |
| 电脑名称     | `<本次配置的电脑名称>`                                                            | App“名称”                            |
| 局域网地址   | `https://<实际局域网 IP 或 .local 名称>:<端口>`                                   | 自动发现保存，填写地址时用完整根地址 |
| 远程备用地址 | `https://<实际 Serve 域名>[:实际 HTTPS 端口]`，或未配置及原因                     | 与局域网共用同一电脑记录             |
| Host ID      | `<已核对的本机 hostId>`                                                           | App 自动读取，用于核对目标电脑       |
| 连接模式     | `desktop-runtime`                                                                 | 说明原桌面接入模式                   |
| 网络要求     | 局域网：同一可互通网络，无需 VPN；在外远控：双通道、同一 Tailscale 网络且两端在线 | 分别标明已配置和已验证状态           |
| 密钥文件     | `<本机实际 access-token 绝对路径>`                                                | 本机找回密钥的位置                   |

已有授权连接不需要重新填写密钥。新连接优先自动发现，点选后让用户从表中本机私有密钥文件安全读取 Host Key 并在 App 输入一次；验证成功后手机只保存独立设备凭据，原 Host Key 不随发现公开、不进入聊天或日志。手动连接同样必须提供有效密钥。Host 访问令牌不是 OpenAI API key、Codex 登录凭据、Tailscale auth key 或 TLS 私钥。

每台电脑另列 **原桌面共享管理通道**：该平台实现范围、v2 持久配置、Host 实际 URL、当前原桌面是否已使用同一官方服务、owner 核对结果，以及已完成仍加载聊天的手机归档／删除结果。配置就绪但等待正常重开时给出准确动作；未配置、配置冲突、未生效、失败和未验收分别标明，不用 Host 在线或能力声明代替。

每台电脑的最终回复另列 **Codex Trace／下一轮建议**：给用户带来的用途、默认持久方案或已有明确选择、当前配置与进程环境、新记录及 Host／手机结果、剩余具体动作。正常安装直接配置，不再次要求选择模式；用户明确关闭时说明建议同步暂不可用，其他已配置功能照常使用。配置就绪才提示择机正常重开，不能只写“未验收”而遗漏下一步，也不能把未来环境写成当前已采集。Windows 报告当前实际适配结果。模板见 [Trace 交付收尾](references/desktop-suggestions.md#每次安装与升级的收尾)。

交付值必须来自当前运行的本机配置和成功的身份探测：

- 局域网地址取实际私网描述和证书核对结果，远程备用地址取实际 Serve 配置和探测结果的 HTTPS 根地址，保留非默认端口，不加 `/healthz`、`/v1/workspace` 或其他路径。iPhone 不使用 `127.0.0.1`、`localhost` 等电脑回环地址。
- Host ID 以本机 `runtime.json` 与接口返回一致为准；密钥以当前 Host 实际接受的令牌为准，默认读取同一状态目录的 `access-token`，去掉文件末尾换行。若环境令牌与文件不一致，先修复并重新验证，不能交付未生效的文件内容。
- 完整客户端密钥不进入聊天、普通探测、日志或可分享验收摘要；仅在受保护的私有配置或设备密钥库中保留。不为交付重新生成、轮换或复制另一电脑的令牌。
- 另列软件安装、Host 自启注册与注销／重启恢复、回环 Host、HTTPS、原桌面 owner 控制、新建/打开、iPhone 跨网络、双实体电脑隔离的实际结果。尚未取得或未验证的地址/身份标明“未配置”或“未验证”及原因，不拼造可用参数，不把未通过说成成功。

## 必须保持的边界

- 每次控制固定 Host/Thread，审批和停止还固定请求/Turn。本产品 HTTP 契约与 Codex 内部协议分开；需要协议检查时复用仓库 Adapter 和验收脚本。
- Host 可通过独立窄接口调用官方 API 准备并持久化空会话元数据；准备阶段禁止模型 Turn，并须确认准备进程实际退出。原桌面接管准确 ID，核对真实 owner 后独占执行首条消息及后续操作。不能切成 `managed-runtime` 来宣称原桌面接入成功，不能修改官方历史、安装包或内部启动配置，不能启动重复执行实例；共享通道仅使用本产品 v2 工具管理当前用户登录环境，保留原图标、云端及远程连接。见 [独立空会话桥接](references/prepared-bridge.md)。
- Codex 应用版本不作为接入、升级或能力启用条件；不对照构建清单、不发版本兼容性提示、不因版本变化修改桥接配置。身份、证明引用及其他配置保持原值，旧验收结论按原环境保留，不能改写成当前通过。Windows 已有聊天的回复不受专用验收 Thread、旧 Windows 安装配置的 `validationOnly` 或报告缺失/过期限制；独立桥接明确的 `validationOnly` 仍保留测试能力。真实 IPC 协议不匹配、owner/身份检查失败才关闭受影响能力并报告具体原因。独立创建/主动打开按本机私有配置与真实运行时就绪开放，报告仅作证据；旧兼容 driver 保持原证明规则。不关闭证书验证或手填通过门槛。
- Tailscale Serve 是私有网络入口。保留现有 Serve 配置，避免占用他人已用端口；不擅自启用 Funnel、公网端口、exit node、子网路由或修改整个 tailnet 权限。
- 重启 Host 前保存其原名称、根目录、端口、Node 路径及控制配置；只操作本产品 Host。启用原建议所需的 Codex 重启按专门流程执行；保留其他活跃任务，不强退原桌面，不用 Host 重启冒充客户端已开启 trace。
- 私有配置、接入报告、令牌、附件和测试历史存入本机忽略目录；可分享报告只含非敏感摘要。完整客户端密钥不放在聊天、命令行参数、Skill、Git 或分发包；不展示其他登录凭据或私钥。

## 完成标准

必须交付电脑名称、局域网地址、远程备用 HTTPS 地址或缺项、Host ID、连接模式、网络要求、密钥文件位置及原连接保留结果，并交付完整功能清单的逐项结果。每项标明本次通过、匹配证据复用通过、失败、未验收或未实现，附范围与原因；能力启用和验收通过分别记录。健康检查、能力声明、导航成功和模拟器结果不能互相替代。

执行用户已经授权的安装配置，不重复索要许可。遇到登录或系统认证时说明需要用户完成的具体动作，继续独立工作。自动化工具拒绝访问时遵守拒绝，不改用另一个通道绕过。

没有真机、第二台电脑或完整验收记录时，完成全部可执行配置并保留实际可用的新建、主动打开和已有聊天控制，准确说明安装状态、缺少的验收条件、未验证项目和下一步。只有单台电脑时双电脑隔离待第二台接入验证；不能因此跳过本机完整配置。验收状态不能伪造，也不作为独立桥接或 Windows 回复的总开关；实际配置、身份或协议失败只关闭受影响能力并继续定位。旧兼容 driver 的证明规则保留。不要将安装完成宣称为全功能实测通过，也不要宣称“无需 VPN 的公网中继已实现”。

升级区分历史免密设备凭据与已通过 Host Key 授权的凭据：旧免密绑定缺少 `hostKeyAuthorized` 时不再通过鉴权，用户可在原连接失败后点“使用 Host Key 重新授权”，输入一次后沿用原设备密钥与凭据，保存连接和草稿不清空。原 Host Key 手动／二维码连接及新版已授权设备照常重连。
