## 审查与实施约束

审查请求为 `gpt-6-astra / ultra`，审查已完成。审查者无法自行读取档位回执，主会话另从该审查本轮官方 `turn_context` 核对同名模型及 `effort=ultra`；不以审查者自述代替运行记录。分派接口未提供速度参数，实际速度不可核验。

- 保留已有 WIP、旧完整文件下载 API、原资源及操作 ID、SHA-256 校验、缓存隔离、分享和系统打开。
- 只读媒体不创建模型输入。只在当前电脑实现和隔离测试；后续用户已明确授权检查全绿后提交 PR 并合并 Gitea main；未授权联系其他电脑或生产部署。

- 新资源能力使用具名资源、完整目标和严格字段；不开放任意路径、URL 代理或 IPC。生产凭据不进入播放器 URL、网页、日志或外部 App。
- 不把 stat、mtime 或文件句柄本身等同于密码学不可变快照；冷文件扫描、稳定版本准备和网络首片等待分别计时。

## 覆盖入口与共同链路

| 入口                           | 新路径                                       | 保留路径与边界                                                |
| ------------------------------ | -------------------------------------------- | ------------------------------------------------------------- |
| 消息 inline、Markdown 媒体节点 | 点击后消息内播放，可切全屏                   | 首屏/分页不取视频正文；不完整流式 Markdown 和代码示例仍为文字 |
| HTML video/source              | 在受支持的本地文档或受控渲染器中解析具名来源 | 普通第三方网页沿网站播放器，不抓取任意网页脚本                |
| 聊天附件、电脑文件链接         | 原消息授权解析后进入共同播放器               | 不凭文件名或路径授予读取权                                    |
| 文档内视频链接                 | 原文档版本及授权绑定后进入共同播放器         | 文档阅读、锚点、原系统预览保持                                |
| 独立文件、业务附件             | 各来源适配器提供同一可读取资源语义           | 服务身份、账号、项目与资源授权各自保持                        |
| 外部视频直链、公开 HLS         | 有界识别后交原生媒体栈                       | 不向外域转发 Host 凭据；签名过期、重定向及子资源分别处理      |
| 网页、登录或 DRM 内容          | 保持网页/站点支持的播放路径                  | 不承诺抽取为通用直链；不绕过原认证                            |
| 已完整下载的文件               | 播放已验证本地版本                           | 分享、保存及系统打开继续使用完整文件                          |

共同链路：入口 → 来源授权/版本描述 → 能力选择 → 媒体会话 → 分段数据源/缓存 → 原生播放器。inline 与全屏共享媒体会话；会话归属于阅读窗口而非会被回收的消息行。列表回收、页面退出和切换完整目标分别定义取消边界。

## MV1 已冻结的窄契约

- 能力为 `attachments:range-read:v1`。`HOST_AGENT_ATTACHMENT_RANGE_READ=0` 关闭新能力及新模式；原接口仍可用。
- `GET /v1/attachments/resolve` 的新模式参数为 `read=range-v1`、完整 `target`、`hostId`、`threadId`、原附件 `id`、播放器生成的稳定 UUID `readId`。首次快速返回 `preparing`；同 ID 查询返回准备字节或 `ready`，后者含固定附件描述、强 ETag 和到期时间。`readId` 只作读取会话标识，不能替代鉴权。
- 新模式捕获当前授权来源，一次有界复制同时计算全片摘要，验证来源前后身份后发布私有快照；出现新内容时登记新附件版本，不改旧附件或已提交意图。原消息/文档链接的首次具名解析仍可能计算全片摘要，该部分异步准备接线属于 MV2 的前置，不冒称所有入口已经零额外扫描。
- `GET /v1/attachments` 带同一参数、`Range` 与精确 `If-Match`，仅返回请求区间；`HEAD` 返回完整元数据且无正文。新模式缺版本返回 428，版本不符 412，非法 Range 400，范围不可满足 416。拒绝 `If-Range`，不因其不匹配隐式下载全片。
- `DELETE /v1/attachments/resolve` 带同一目标/资源/readId，取消该播放器独占的准备和读取。独立播放器使用不同 readId；同 ID 轮询合并，不共享可被另一播放器取消的生命周期。取消 ID 在到期前保留终态，迟到轮询不重新开始工作。
- 每个读取都检查实际认证主体、完整目标和 Thread/资源归属，并重新检查来源新鲜度。来源改写/删除后不复活旧缓存。快照不使用硬链接，不向 App 暴露本机路径；流中错误关闭响应，不追加 JSON。
- 初始硬预算：单块 256 KiB、最多两项准备、八个活跃响应、16 个活跃读取会话，总快照预留 2 GiB，保留 256 MiB 卷空间；准备最长 120 秒、读取会话有效期十分钟。超过预算提供明确错误和原完整下载入口，不声称任意大小均已流式支持。所有快照归当前 Host 进程的独占私有目录，关闭和到期按租约回收。
- 长视频不依靠延长Host的十分钟期限。新可选 `remainingSeconds` 提供相对预算；iOS近到期前合并换读会话，先排空/确认清理旧快照，再重新授权准备，并严格核对同一内容版本后续播。旧Host无该可选字段时按v1十分钟期限从请求开始保守计时。验收通过短期限注入验证实际新UUID、旧DELETE、同版本续播及失败不降级，另记录真实长时/大文件压力范围。

## 版本、缓存与恢复门槛

1. 旧资源/下载契约保持。新能力独立协商；新 App + 旧 Host 保持完整下载后预览，旧 App + 新 Host 保持原 HTTP 与校验语义。
2. 新分段请求绑定原完整目标、Thread、资源 ID 和明确版本。元数据解析与字节搬运分离，Range 只读取授权资源。请求范围/长度使用安全整数并有界解析，覆盖闭区间、开放尾段和后缀区间。
3. `206` 的偏移、总长和实际字节必须一致；`416` 不无限重试。上游忽略 Range 返回 `200` 或版本不匹配时不能拼入旧片段。认证/证书/错目标拒绝不触发绕过性回退。
4. 已验证不可变版本可以复用摘要；原始可变文件必须有能证明稳定版本的读取策略。首阶段尚需全片扫描的冷路径如实记录，不用“有 Range”宣告冷启动完成。读取中被改写、换目标或截断须终止；已发响应不能追加 JSON 错误正文。
5. 缓存键包含完整领域目标、授权来源、资源版本与表示；账号隔离遵循各 Provider 原规则。部分区间和完整已校验文件分别存储。磁盘上限、活跃资源租约、去重和回收必须明确。
6. 解析、首片、缓冲、完整下载使用独立且有界预算。只读分段可在原目标/版本下重取；签发、完成确认等有副作用步骤查询原回执，不盲目重放。
7. 关闭或切换目标取消自有请求和播放器；迟到结果不得回写新目标、草稿或播放会话。退出 inline 不终止已经移交全屏的同一会话。

| VA11 | 传输内存不随全片大小线性增长，慢消费不无限预取                   | 进程峰值、最大单块、在途字节、背压和取消后计数            |
| VA12 | Codex/EasyWork/业务服务与 LAN/VPN/中继按实际能力分列             | 对应源/环境/授权边界；未具备条件的组合保持未验收          |

冻结的原生参考门槛：H.264/AAC、1080p，约 100 MiB 与 1 GiB 的头/尾 moov 样本；固定版本已准备、手机媒体缓存冷、20 Mbps/50 ms RTT，20 次首帧 P95 ≤5秒且首帧前网络下载 ≤8 MiB 且小于全片；seek 至未缓存 80% 位置 P95 ≤5秒且不下载整个前缀。传输层缓冲 ≤8 MiB/会话，取消后两秒内释放自有读取；断网十秒后恢复五秒内继续或显示明确错误，最多两次只读重试、总恢复预算30秒。解码器内存单列，100 MiB→1 GiB 不得呈现全片缓冲引起的线性增长。

这些是后续原生退出门槛，尚非通过结果。执行前补准确素材码率、设备/系统及源版本；首次解析/快照准备和用户点击到首帧总时长必须同时报告，不从等待中扣掉准备阶段，也不在未知网络上承诺固定秒数。

普通播放/文件/恢复断言使用独立原生模拟器；蜂窝、实体 VPN、设备硬解差异等只按实际物理环境验证。HTTP/fixture/编译属于辅助证据，不能替代 VA03/VA04 的原生播放。媒体只读场景不为验收额外发送模型任务。
