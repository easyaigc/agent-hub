# Provisional voice streaming migration

This implements one previously rejected scope from `system-scope-inventory.json`, based on committed `926f9cc226fea67297a3ddd4897b6fa7944fa057` (Root d878). The first implementation (`e0fb3a8`) was not adopted: Root review found that the real UI owner still sealed FAILED raw originals and the exporter had no producer ownership freeze. The owner/writer closure below supersedes those two source claims. All results remain source and auxiliary evidence. Native export/stage/activation, raw filesystem negatives and the three-PID protocol are not executed here. Full P7 remains open; all other nonempty system children remain explicit blockers.

## Original semantics

An indexed manifest-null recording is not a sealed WAV and must not gain a manifest, a discard receipt, an old recorder, recognition eligibility or permission to query/replay its operation. The streaming exporter preserves the exact original JSON string and exact original index string, plus absent/empty/nonempty raw evidence. The source index/row/raw file is never edited, sealed, truncated, repaired, renamed or deleted. Arbitrary partial bytes are copied as opaque originals, not advertised as valid PCM.

The portable active voice index excludes these IDs and their normal `voice-recording:<id>` entries. Their full originals instead live in a closed inert catalog. Existing sealed audio, local-result and discard graph validation stays in place. Activation uses the existing authenticated streaming candidate and atomic root generation publication. It does not create raw files or callback registrations. A new PID can enumerate and copy the inert original through `NativeMigrationProvisionalVoice.read/copy`, while the normal VoiceRecordingStore has no indexed recording to offer. Re-export retains the archive. Later independent metadata drafts and the exact original candidate receipt survive repeated activation without a second publication.

## Closed schema and full raw inventory

`migration-provisional-voice-v1` has exactly `version=1` and `originals` (1–128 entries). Every entry has exactly:

- `id`: canonical original UUID, unique and absent from the portable active index/normal row names.
- `index`: the complete original index string, at most 32 unique canonical IDs and containing this ID.
- `row`: the complete original row string. The shared original identity validator checks its closed schema, target/certificate/draft binding and numeric/text bounds. It must have no manifest, attempt flags, phase or prior migration flag.
- `kind`: `absent`, `empty` or `raw`; absence and empty are distinct evidence.
- `size`, `sha256`: zero/empty SHA for absent/empty; otherwise 1–9,600,044 bytes and full SHA.

Each `raw` entry owns exactly one `migration-provisional-raw-v1:<id>` binary frame with matching size/hash. Missing, duplicate, extra, colliding active rows, unknown fields/versions, wrong target or mismatched descriptors reject the whole candidate. The normal stream envelope/chunk/EOF authentication verifies every byte; no second crypto or send path is introduced. Catalog text remains within the existing 8 MiB record cap and the whole stream within the existing 192 MiB quota.

The source raw directory is inventoried completely, with at most 128 canonical `<uuid>.wav` files and aggregate raw size bounded before hashing. Every file must be owned by the current indexed/terminal/local-result graph. Unknown names, orphan IDs, links, hardlinks, unreadable or over-limit content reject without omission. Existing sealed raw leftovers must equal the sealed manifest, and discard leftovers must match their retained evidence. Reads use O_RDONLY/O_NOFOLLOW, owner/private-mode/regular/single-link checks, exact EOF and stable descriptor/path identity. The entire directory identity, filename set, empty files and every raw hash are checked again after envelope generation and before AtomicFile finish. The helper never creates the raw directory or opens a writer.

The legacy bounded `capture/seal` path continues to reject live provisional originals. It now also applies the same before/after nonempty-system-child gate as streaming; this closes the previous legacy omission. Already inert archives may use the bounded format only if its normal quota permits. The supported product file exporter is the streaming path. Both NativeVoiceLocalResults discovery sites in Root's export source are retained.

## Real owner and writer closure

The actual `MainActivity → MobileSession → VoiceInputController` migration route now admits only stationary IDLE/FAILED controllers with completed capture/registration/work and no discard, cancel or saved-file transition. Active or unfinished capture is explicitly unsupported for export. Rejection precedes monitor shutdown, Session pause, microphone stop, header repair and original-store mutation. Normal navigation/background pause behavior is unchanged. During accepted migration, `leaveForeground` skips its ordinary voice suspension, and migration-specific quiescence joins only stationary housekeeping; it never calls stop, suspendRecording or seal.

All production capture and original mutation entries share `NativeVoiceRawOwnership`. NativeAudioCapture acquires a writer permit before microphone setup or rw open, holds it through raw writes, final header/sync and recorder release, and releases it on coroutine completion/failure. VoiceRecordingStore begin/seal/mark/remove/discardLocal acquire the same authority before storage transactions. Retired/strict owner admission is checked in memory before opening the coordination file. Multiple local recording IDs may hold writer permits; the same local ID cannot acquire twice.

One zero-byte private, single-link `voice-recordings-writer-v1.lock` lives beside the raw directory. Writers hold a shared kernel FileLock; migration holds an exclusive nonblocking lock plus the singleton's local owner token. This is cooperative producer ownership, not an arbitrary same-UID write monitor. The control file remains installed and is never exported or unlinked for lock reuse. Native lstat device/inode identity and private-owner checks detect a replaced control path. Export requires the actual frozen object bound to this storage, canonical lock path, operation and quiescent owner epoch; a callback or a constructed token does not provide authority.

MainActivity acquires this exclusive ownership before stopping producers. The controller passes that actual owner lease through streaming projection, raw inventory/copies and the final unchanged check, holding it until AtomicFile publication ends. Publication/failure then releases ownership while the old Session is still paused, before fresh-owner restoration enables producers. An unresolved owner retains the existing operation receipt and does not replay inputs. Imported originals remain inert as described above.

The new storage admission method is a narrow addition. The Root intake patch is based on Storage `91107ee6` and MobileSession `101c186b`, retaining their strict existing-reader/P9/F73 code; the child checkout uses its own earlier base. Patch readback proves composition only. Root must compile and accept the actual combined source separately. The cumulative patch also includes the unadopted e0 provisional prerequisites, with exact old/new SHA-256 per shared path; no whole-file replacement is authorized.
