# P7 相机原请求与私有结果恢复

## P7-4f 共同断言与实现

逐项对照 iOS `QuickAttachmentViews` 的原菜单关闭、准确原草稿、取消不加附件、单张图片本地准备及发送时才上传。Android 使用外部系统相机和 FileProvider，iOS 使用 UIImagePickerController；系统窗口与进程保存方式分别登记，不能互相替代通过。此次未修改 iOS 程序，不执行暂停的 iOS A6。

Android 相机权限和拍摄各有按原请求 ID 注册的稳定回调键，注册独立于附件面板。原完整草稿键、导入代次、呈现代次和错误代次先进入独立加密账本；父草稿持久化确认后才请求权限或打开相机。恢复只注册原回调、呈现原等待，不重复请求权限、不重新启动相机。权限拒绝不覆盖之后产生的新错误。

输出使用 App 私有持久目录，按加密仓库范围及 UUID 隔离，每个文件另有加密认领。外部相机只获得该 URI 的临时读写权；回调只读取原输出，不信任返回 Intent 的其他 URI。字节先归一化、进入加密暂存，再清理准确原输出和本次授权。原附件 ID、草稿事务及消费回执复用文件/照片协调器，确认原草稿持久化后才关闭回执；未知文件和未认领碰撞保留，不扫描删除整个目录。

准备期间取消会完成准确本地清理；外部操作结果未知时，“结束等待”保留原记录及输出。迟到成功先加密并呈现“加入原草稿”，不自动加入当前或原草稿。明确加入仍检查原目标/代次，不能改投新草稿；丢弃只处理原认领结果。结束等待与回调同时发生时保存第一份结果，重复成功或晚到取消不覆盖它。旧失败与新等待分别保留，旧回调不清理新输出、不结束新请求。

文件、照片与相机入口互斥；原本地结果提交期间保护附件移除。损坏或未知版本账本保留原字节，独立文件选择仍可继续。未解决记录不因32项回执上限被静默淘汰；完整配额、迁移与自然异常矩阵仍未关闭。

## P7-4g 原系统相机进程死亡与冷开

新增专用SDK接收身份、独立观察UID及seed/只读方法；既有验收/DEV/正式版保持。API37准确核对原相机调用方、STOPPED且已保存状态的原Activity/PID后，由ActivityManager终止接收进程；原系统相机留在前台，只执行一次快门和一次原确认。两个SDK相机均为后置emulated、前置none，不是物理相机或自然崩溃证明。生产Kotlin/res/KMP与4f一致。

API37最初30秒内AX索引未读到新附件，失败快照中的实际图片已可见。随后只读探针核原记录/暂存均已消费、原草稿两附件及原输出已删除；探针前后八份原加密文件逐字节一致，没有借探针恢复导入。结合原ActivityRecord、变化后的PID及一次快门/确认意图对账后，完整只读核对原目标/代次、原文/设置、另一草稿、原先附件、原图片ID/摘要/JPEG解码及临时读写授权释放。原失败不改记为及时通过，不再拍摄或重开相机。

原冷开也出现AX视口截止失败；新观察器清理自身索引缓存并只滚动同一附件栏后接续成功，没有第二次MAIN启动意图。冷开图片已查看，同一请求/附件ID/摘要和原草稿保持。共1个对账后的系统冷结果、1次冷开、3项只读原生方法（含1项诊断）及2项合成准备；准备与GET-only夹具不冒充真实Electron/模型验收，新增模型0、累计220/P4 205。原AX及时性、完整IME/AX/主题/横屏仍待验。

API26首次打开因旧Google权限组件漏识别而未点击；补准确组件并核原调用方包名/UID后，接续原应用权限。系统相机进入自身首次位置引导Activity，调用来源为相机自己的UID，未通过原调用链门槛。没有点击快门、推进位置引导、清理数据或重新发起拍摄；该原请求与输出对账单列待验，不阻断当前文件/照片及其他本机开发。

首次新包安装被具名安装器白名单在实际安装/seed之前拒绝，确认新包尚不存在、保留原回执后补入准确独立身份。观察器/runner分版本登记，接收APK全程相同，不把最终观察器套用于早期动作。API37已消费用例的专用反向映射已清理，API26原待验记录保持。完整仓库命令及晚变更输入边界见[复核摘要](../P7-camera-process-cold-review.json)。

完整`pnpm check`命令退出0，用时约615秒；1013项输入中1012项准确保持，期间一份独立观察器补索引缓存与旧权限组件识别。该晚变更另经编译、原API37窗口及API26原权限流程核对，最终一致性/审批边界/文档格式另验，不声称1013项源完全冻结的整套检查通过。平台跳过不计实际Windows/iOS手机通过。
