# 目录授权机制梳理（2026-10-24）

历史审计记录：下文描述修复前状态；后续已实施的资源授权与原生验证见[ADR](../adr/0003-desktop-resource-authorization.md)及[验收记录](../acceptance/desktop-directory-policy-20261024.md)。

本轮为源码审计和本地辅助复现。没有修改生产权限策略、重启服务或联系其他电脑；下面的调整方案尚未实现、部署或完成真机验收。

## 结论

默认的原桌面接入模式不应再让用户维护一份覆盖整台电脑的固定项目目录白名单。当前 `HOST_AGENT_ROOT` 同时承担默认工作目录、部分文件授权、建议观察器作用域及功能就绪条件，既不能完整表达现有桌面权限，又会让无关目录的变化破坏正常功能。建议取消它作为桌面接入总授权边界的作用，将其旧值仅按兼容规则处理为默认工作目录。

这不意味着取消文件访问边界。需要分别保留电脑及设备鉴权、原 Agent 的执行权限／审批、系统实际文件权限，以及 Host 对会话附件和消息资源的准确归属与字节检查。默认工作目录、执行权限、具体文件授权应由不同接口表达。

原桌面模式的项目和聊天目录、项目内／无项目新建及分支，本来已经有按准确原项目／会话执行的路径。`RuntimeSession.workspace` 返回原桌面目录，`prepareDesktopCreation` 和 `forkSource` 从原项目／会话取得目录，而非要求所有项目位于 `HOST_AGENT_ROOT` 下。因此这个环境变量已经不是覆盖全部功能的一致授权边界。

## 已确认的问题

### 1. 跨项目建议曾被误过滤，修复后仍有全局目录依赖

上一任务已修复“固定根目录拒绝另一个项目的预测 cwd”：准确原 owner 的来源目录会传入 Trace 读取。但 `DesktopSuggestionObserver` 的构造、`boundReadAvailable`、`assertBoundReadAvailable` 和 prepared 读取仍会检查固定根目录是否存在且身份不变。

本轮在真实当前源码上移动一个无关的合成配置目录，观察器的 `rootStable()` 从 `true` 变为 `false`；准确来源目录未变。源码中的能力与请求入口又把该结果作为拒绝条件。该辅助实验验证目录耦合，不冒充完整原生 Trace／原桌面验收。

代码入口：`packages/codex-adapter/src/desktop-suggestion-observer.ts:89`、`:140`、`:156`、`:200`。

### 2. 无关目录失效会使仍存在且已授权的文件报“文件不存在”

`AttachmentFiles.authorized` 在判断准确资源授权之前，先并发执行目标文件和**所有候选根目录**的 `realpath`。候选范围又包含固定根目录、整个 Host 状态目录及原 owner cwd。任一无关根目录失效，整个检查先失败，根本走不到准确文件授权判断。

本轮复现两种情况：

- 文件仍位于有效会话目录，但另一候选根目录被移动，读取返回 `410 / ENOENT`。
- 文件已有准确资源授权，但一个未被使用的候选根目录被移动，仍返回 `410 / ENOENT`。

相同文件只使用有效会话目录、或只使用准确资源授权，均检查成功；未被引用的相邻文件仍被拒绝为 `403 / RESOURCE_NOT_AUTHORIZED`。因此既可消除这类误拒绝，也有条件保留准确文件边界，无需放开整个主目录。

代码入口：`packages/codex-adapter/src/attachment-files.ts:141`、`packages/codex-adapter/src/runtime-session.ts:3073`。

### 3. 纯建议读取还依赖项目目录的物理存在性

`desktopSuggestionSource` 要求原 cwd 的 `realpath/stat` 成功，Trace 的 `configuredCwd` 还检查该目录及其身份。该读取实际消费的是私有 Trace 中的预测数据，并不读取项目目录中的文件。

因此建议来源证明应围绕准确原 owner、最新完成轮、预测来源 ID、当前原桌面实例与私有 Trace 完整性建立。cwd 可以保留为上下文和必要的元数据一致性条件；单纯复制一段已生成文本，不宜额外要求项目文件夹一直存在或 inode 永不变化。这是本轮设计判断，删除这些条件前仍须逐项证明剩余来源校验足够，不能据此删减私有 Trace 的真实安全检查。

代码入口：`packages/codex-adapter/src/runtime-session.ts:1139`、`packages/codex-adapter/src/desktop-prediction-trace.ts:317`、`:1422`。

### 4. 启动配置把项目路径变成了服务运行依赖

macOS 默认将服务启动时的仓库／安装目录持久保存为 `HOST_AGENT_ROOT`；Windows 启动／重启明确要求它是现存目录。安装位置或某个项目移动后，可能导致与该项目无关的服务启动或建议功能受影响。

服务自身工作目录、私有状态目录、无项目操作的默认 cwd，以及托管模式的显式访问策略应分开配置。

代码入口：`scripts/desktop-service.mjs:77`、`scripts/windows-desktop-service.mjs:84`、`apps/host-agent/src/runtime-server.ts:130`、`:155`。

## 建议的收敛方案

1. **原桌面内容读取不经过全局项目白名单。** 历史、状态、建议按完整机器目标和准确原会话／来源返回；来源校验失效只影响当前目标。纯内容读取与项目文件夹物理存在性解耦。
2. **执行沿用准确原 Agent 的权限。** 原 owner 的有效执行策略、审批和手机明确选择继续生效，不以 Host 的默认 cwd 再套一层不一致的权限。托管／共享模式需要的显式目录隔离单独建模，不默默删除。
3. **下载按具体资源授权。** 已上传附件限于其登记的会话和文件；原桌面产物从准确消息引用登记只读资源。保留规范目标、符号链接变化、归属、文件身份、大小和摘要检查。任意路径不能构成下载权；不要因为一个备用授权候选失效而否决另一个有效授权，也不要吞掉实际目标失效和系统拒绝。
4. **默认目录只决定落点。** 新字段与旧环境变量的兼容关系显式定义，原值只在合适的模式中作为默认 cwd；不自动改为 `/` 或整个 home，不改写设备凭据、原操作或用户已明确选择的托管边界。
5. **上游目录能力留在适配器。** EasyWork 项目创建仍遵守其 `directoryRef`／桌面授权；其他客户端按各自接口实现。手机正常查看和继续已有任务，不再额外请求目录授权。

无需为正常桌面接入增加一份让用户长期维护的路径列表。如未来确有“某台设备只能访问部分项目”的产品需求，应按设备／项目／资源建立一致的权限策略，并贯穿目录、历史、命令和文件；当前零散的固定根目录不能宣称提供了该能力。

## 实施与验收约束

建议先修复附件的无关根目录故障和错误归因，再拆除桌面建议中的无关 cwd／全局根目录就绪依赖，最后迁移启动配置和旧变量语义。已确定失效的来源不能改走另一来源；未知写操作继续只查询原回执。

影响 F16（项目登记）、F17（历史）、F26／F27（创建）、F31／F32（附件）、F35（执行权限）、F59（文件互传）、F62（分支）、F69（建议）。当前实现和验收状态保持原记录；后续更改 F69 的目录身份断言时，须同步协议说明、两端产品／设计／验收合同，不能先把拟议行为写成已实现。

必要回归包括：多项目与项目外产物、无项目聊天、删除无关旧项目后仍可读取准确资源、项目路径移动／替换、符号链接改指、未知资源和跨会话拒绝、目标文件确实消失与系统拒绝的准确提示、已提交附件和未知回执不重放。macOS、Windows 的真实原桌面及 iOS／Android 原生结果分别记录；本轮辅助复现不提供这些通过证明。

本地辅助证据位于忽略的 `.local/directory-authorization-audit-20261024/`。实验从当前 TypeScript 源码转译被测类，使用本任务合成文件，不连接真实运行时、不启动观察器 worker、不读取业务文件，结束后删除合成目录。被测源码 SHA-256 及逐例结果保存在 `result.json`。
