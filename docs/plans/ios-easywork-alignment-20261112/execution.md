## 并行职责

使用本机现有 Host，分别创建专用对话，配置 `model=gpt-6.1-sol`、`effort=xhigh`，速度不另指定。创建与首条提交使用稳定原操作 ID，超时先查询同一操作，不再次创建或重发。核返回的准确项目、thread、turn和实际设置；不能把“已请求模型”写成“已确认运行模型”。

三个首批职责是大文件补缺、文档导航与桌面契约补齐、既有功能验收收尾。每个任务只写分配的隔离候选/证据目录。主协调会话审查并集成差异、更新权威台账；两个开发任务触及同一文件时，以语义审查合并，不能互相覆盖。辅助子代理的审查与 Host 专用对话分别登记，不能冒充同一执行通道。

桌面归档 pin 缺本地源码时，最新目标的集成、交付和精确匹配复用保持阻塞。明确基线加冻结补丁的隔离候选可以继续开发、辅助检查及限定范围的真实 DEV 验证；必须分别记录候选源、包和环境，不能冒充最新目标。真实 Electron 尚未运行时先准备独占环境，不把缺少最新 pin 当作所有候选验证的前置。不得凭接口名猜测支持或关闭安全机制解决环境限制。已有暂停/范围外项保持原口径。

## 证据与清理

证据至少包含完整输入源摘要、契约版本、候选差异摘要、实际包/runner、模型与强度的请求和观察值、场景及子断言、命令/退出码、原始日志、独立核对、原操作引用、状态及下一步。原始证据保存在忽略的私有目录；计划只存脱敏索引和 SHA-256。清理前对索引逐个核验文件仍存在且摘要一致。

- 自有临时服务：核 PID、启动时间、目录和端口后停止；再核端口释放。不停止共享 Host、Electron 或他人进程。
- 自有缓存/中间产物：只删除可重建且不再支撑未完成验收的内容。保留失败日志和原始回执。
- 开发分支/工作树：仅在变更已集成、没有独有提交、未提交内容已保存且验收证据已归档后清理。未合候选保持“待集成”，不能为了清理丢弃。
- 未知操作：不清除回执、原意图和附件，不把删除现场当作远端取消。
- 只创建源码副本而未创建 Git 分支时，分支清理记为“不适用”；将候选打包留证后再清理可重建依赖。

每次工作结束必须回填本次实际停止位置和继续条件。没有创建、运行、通过或删除的动作，不得在总结中用完成时态代替。
