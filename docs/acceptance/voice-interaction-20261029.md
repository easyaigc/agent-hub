# 输入区长按录音与失败恢复（2026-10-29）

首次开发现场与 PR 主线集成结果分别记录，使用各自的实现指纹。

F64，S04／S11／S17／S18，UI06／UI21。iOS 主输入区长按 0.5 秒开始录音，松手后继续录音，由结束按钮进入转写；短按继续文字编辑。无建议且草稿为空时占位提示“输入消息，长按语音输入”，有建议时继续显示原建议。麦克风按钮沿用同一入口，原草稿保持。

失败保留在录音条内，显示失败图标、标题和具体错误，不依赖弹窗。存在原录音时显示圆形重试图标（读屏名称“重试转写”）及本地转写／重新录音；准备失败或采集为空时显示“录音未完成”和重新录音。电脑重试只查询／补齐原操作，不新建或重放已提交操作；本地转写成功只填回原草稿。失败期间不能发送空草稿，丢弃、导航隔离和迟到结果边界保持。主输入及问题回复共用失败呈现。

Android 本次未改，输入区长按、占位提示与新的明确失败呈现待对齐；既有电脑录音转写与重试保留，主线已有原录音本地转写与恢复能力按其独立证据保存。A6 其他暂停范围保持。

修改前的独立原生模拟器复现两项均按预期失败：输入区长按未开始录音，电脑失败后没有常驻失败标题。修改后的同一独立模拟器，主输入六项通过：空／已有草稿长按录音、普通录音取消／完成／发送、准备失败／深色外观、空草稿电脑失败与再次重试／后台返回、原草稿失败后本地回填、丢弃与跨进程恢复。问题回复单项补测另轮通过，服务核对零答案提交。结果是六项加一项分别通过；早轮七项整组为六通过、一失败，失败来自旧合成服务将新增只读 `/v1/usage` 当作错误断言并退出。私有补测服务对未实现路由返回 404 后，仅补跑该问题场景通过，生产源码未变化。失败标题、文字按钮及问题回复截图已逐张核对。

辅助检查：`pnpm build:ios`、独立签名设备版 build-for-testing、双语 1649 条与五项权限提示、74 项功能表／来源／场景结构、本次五个源码／资源的准确摘要覆盖、六项清单测试、相关文档格式和差异检查通过。默认 Node 22 的首次资源检查有引擎警告，最终使用本机 Node 24.19.0。根 `pnpm check:mobile-parity` 仍因既有未提交 Android `UsageViews.kt` 的变更指纹过期而失败；未改写该任务的证据，只单列本次 F64 覆盖通过。初次模拟器安装与根 iOS 构建遇到 ENOSPC，清理本次可重建编译缓存后分别重跑；原失败与后续通过日志均保留。
