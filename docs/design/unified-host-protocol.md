# 统一 Host 协议与客户端适配规范

生效：2026-11-20。依据用户确认的 iOS × EasyWork 对接方向：复用现有 App 能力，由 EasyWork Host 与 Codex Host 接入同一套领域协议。本文规定后续实现与审查边界；规范写入不代表现有代码已经全部符合或通过验收。

本项目完整的当前功能及双端实现、模拟器和真机验收状态，只维护在 [唯一完整功能清单](../plans/android-ios-alignment-20261107/progress.md)。[旧 EasyWork 计划](../plans/ios-easywork-alignment-20261112/README.md) 及其 `status.json` 仅保留历史来源与验收证据，不作为当前状态入口。本文不另建功能进度表。版本演进同时遵守 [兼容规范](compatibility.md)。

## 共同契约的基准

1. 已有能力以 [实际运行时契约](../protocol-runtime.md)、`packages/protocol` 内对应已实现的 Schema／解析器及其真实语义为基准。先核实际调用链，区分早期草案、已实现接口和已验收范围。发现文档与实现冲突时明确差异，不能选用草案覆盖已部署行为。
2. 同一业务能力只维护一份操作含义、输入／输出约束、完整目标、能力条件、错误分类、操作回执和恢复规则。新增共同语义先补共同契约，再由各 Host／Adapter 映射其上游实现。
3. `AgentClient` 接口、相同类型名、复制的 Schema 或契约摘要一致只能分别证明对应边界；不能单独证明生产请求和恢复路径遵循共同契约。审查必须追到实际 dispatcher、持久账本和客户端消费路径。
4. 不为接入尚未使用的 `AgentCommand` 等类型新增第三套通用 RPC、重复端点或并行命令账本。采用新的封装须证明已有契约无法表达实际需求，并给出兼容迁移与旧流程保护；默认继续复用现有具名能力。
5. HTTP 路径、WSS 封装、上游方法名及认证格式可以由适配层转换。相同领域操作在手机公共层具有相同的业务含义；两种 wire 格式不同本身不构成不兼容，业务语义漂移也不能用“只是传输不同”解释。

## 各层职责

| 层                    | 必须负责                                                             | 允许的差异与约束                                                                              |
| --------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 公共契约              | 领域目标、具名操作、能力条件、消息／资源、错误、回执与恢复语义       | 维护版本和可选扩展；不同语言使用受控生成或经过共同向量核对的投影                              |
| Host 与 Agent Adapter | 上游服务装配、身份／权限校验、命令分派、持久回执、实际执行及领域投影 | Codex wire 留在 Codex Adapter；EasyWork wire 留在其 Host／Adapter；上游能力缺口优先在这里补齐 |
| 认证与传输            | 建连、证书／设备授权、加密帧、序号、连接恢复与字节搬运               | 保留 HTTPS、LAN WSS、Relay、EWDAP／grant／DPoP；重连不产生新的业务提交许可                    |
| App 适配层            | 旧端 wire／DTO 与共同模型之间的必要映射、特定凭据生命周期            | 兼容实现允许暂留，明确其边界和退出条件；不能复制公共业务状态机                                |
| App 公共状态与界面    | 共同草稿、发送／等待／恢复、历史、文件、审批与页面组件               | 依据共同能力和领域状态决定行为；Agent 名称用于展示，专属认证页面依据真实认证能力装配          |

Host 拥有本机执行权限和原桌面服务；Relay 保持身份、绑定、路由与密文边界。历史可读、进程健康、运行时连接和当前会话可控分别表达，不能相互替代。

## 操作分类、回执与恢复

- 操作定义须包括：准确目标范围、输入／输出版本、所需能力、是否产生业务副作用、幂等键／指纹、可查询回执、超时与恢复方式。只读、安全可重取、订阅和写入分别说明，不能按方法名称前缀猜测。
- 同一操作的分类有共同来源。Swift、TypeScript 与其他语言需要静态集合时，从共同定义受控生成或以共同向量检查其映射；不得长期独立维护互不核对的读写白名单。
- 只读重取使用原目标及明确的读取契约。写入必须在提交前保存稳定操作 ID、不可变原目标／参数／指纹；同 ID 同意图查询原结果，不同意图拒绝。
- 超时、断连、缺失记录和结果不确定不得自动解释为未写入。先核原回执和权威状态；只有契约明确允许的证据及原授权条件满足时，才进入对应恢复动作。传输层不能自行决定重发输入。
- 自动重连只有一条已授权路径时，保留该路径供正常握手及原回执查询；仅存在不同端点的替代路径时才排除失败候选。重连不改变原操作 ID、目标、设备授权、证书或参数指纹，不授予再次发送原写操作的许可。
- 排队接受、指令处理完成、模型执行结束和失败／停止分别投影。结束手机等待不声称取消远端；迟到结果不能覆盖新草稿、新操作或另一个目标。
- 控制操作继续绑定原 Thread、Turn／Run、队列消息或审批请求。原 owner 丢失、过期和错目标按相同领域原因拒绝，不以历史缓存恢复控制权限。

## App 改动的范围

每项对齐工作先沿实际操作分类：已有共同能力直接复用；缺少上游装配或投影则补 Host／Adapter；共同界面缺陷则修共用组件；确需新增产品能力时才扩展共同契约和 App。

- 不把 F01–F75 视为需要为 EasyWork 重新开发的页面或功能列表。原功能、已合入交付和范围匹配的原验收按唯一台账复用。
- 每个新增 App 业务改动说明复用入口、实际缺口、为什么 Host 映射不足、公共组件与双端影响。普通字段转换和专属认证无需扩大为 App 重构。
- 公共 Markdown、输入按钮、草稿清理、首次发送、未知结果、文件限制等不得仅按 `agentId == "easywork"` 选择业务规则。平台／上游差异由窄能力、明确状态或适配策略描述，并复用同一消费路径。
- 对现有客户端名称分支逐项核语义和既有保护，按受影响流程渐进收敛。不得通过删除检查、隐藏功能、丢弃旧数据或未经核对的一次性替换消除分支。
- 大小限制区分 Host 宣告的业务上限、旧实现的流式／内存限制和渲染预算。旧实现限制须如实记录并保留安全门禁；不能仅删常量冒充流式能力完成。

## F59／F64 的有限生产映射

本节说明现有复用入口与审查边界；不替代唯一清单中的实现和验收结论。独立文件传输和录音转写都不提交聊天 Turn。

| 共同操作           | Codex Host 已有入口                                                                               | EasyWork Host／Adapter 映射                                                                                                        | App 公共消费                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 上传能力与原传输   | `/v1/uploads/capabilities`、`/v1/uploads` 及其 `chunk`／`complete`／`cancel` → `ResumableUploads` | 认证的 `runtime/context` 能力与限制；`resource/upload`／`upload-status`／`upload-chunk`／`upload-complete`／`transfer-cancel`      | Android `AgentRegistry`／`AgentCommands.uploadCapability`／`uploadRequest` → `NativeUploadCenter`；iOS `AgentClient.uploadRequest` → 共用上传流程 |
| 独立文件结果       | `/v1/file-transfers` → `FileTransfers`                                                            | `resource/transfer-list`／`resource/upload-status`；上游 `purpose=transfer` 映射领域 `file-transfer`，不套用聊天附件的 Thread 条件 | 双端公共文件互传流程；Adapter 投影原名、大小、摘要、路径与完成状态                                                                                |
| 转写就绪           | `/v1/voice/readiness` → `VoiceTranscriptions`                                                     | `voice/readiness` → `RemoteVoiceTranscriptions`／`RemoteVoiceInputPort`；从认证上下文投影 Host 身份                                | `AgentCommands.voiceReadiness`／`AgentClient.voiceReadiness`                                                                                      |
| 原录音、音频与结果 | POST／GET `/v1/voice/transcriptions`、POST `/v1/voice/transcriptions/audio`                       | `voice/prepare`／`voice/status`／`voice/upload`；不回退到一次性 `voice/transcribe`                                                 | Android `VoiceTranscriptionFlow`／`VoiceCodec`／`VoiceRecordingStore`；iOS 公共录音及原结果恢复入口                                               |

- 上传清单与稳定 ID 在首次远端写入前保存。EasyWork 的传输、分块和完成 ID 沿用原映射，不能因改用公共接口重算旧意图。未知结果先核原传输及原命令回执；完成与取消竞态使用权威原结果，不重新发布文件。
- Android 独立文件清单中的 `hostId` 沿用本地客户端标识；转写 Manifest 使用认证后的物理 Host 标识。Adapter 显式映射两者，完整领域目标仍由认证信封及公共目标规则校验，不交换这些标识或改写既有清单。
- EasyWork 的 `resources:transfer-limits:v1` 与 `resourceTransferLimits.version=1` 从认证上下文协商。文件上限的显式 `null` 表示未配置业务上限，缺失、布尔、小数、非正数及超出安全整数范围均不等价于 `null`；未声明能力的旧端继续使用原 20 MiB 保护。分块采用 Host 上限与 Adapter 有界实现保护中的较小值。独立文件上限、聊天附件上限及渲染预算分别处理。
- 转写就绪的共同 DTO 只含 `hostId`、`available`、`reason`、`maxBytes`、`maxDurationMs`。EasyWork wire 的 `diagnostics` 留在 Adapter 边界；适配器须明确投影共同字段并核对认证目标，再交严格 Schema 校验，不能透传整份 wire JSON 或放宽共同 Schema 来接纳上游诊断字段。旧端缺少有效录音限制时保留不可用错误，不补造上限或触发录音／上传。
- 转写 Manifest 仍按 `voice-transcription.ts` 与 KMP `VoiceTranscriptionRules` 核对原 Host／Thread／草稿／操作 ID、WAV、字节数、时长和 SHA-256。原结果恢复入口不能重新准备或上传；缺失、过期、鉴权失败、未知结果和解码失败须分别处理，不把所有错误当作“从未提交”。完成回执不能跨目标或覆盖新草稿。
- `ai-sharing-voice-v1.json` 是现有 Node／Schema、KMP 及 Swift 边界检查共同使用的合成向量来源，覆盖严格 Manifest、原目标／原内容、状态与文本类型。向量通过不证明真实上传、ASR、原生界面或桌面集成通过。
- 兼容差异必须明示：当前 Codex 语音 HTTP 使用历史 `hostId/id` 入口，服务持久作用域与 EasyWork 的完整 runtime／设备作用域不同。App 保存并核对完整本地目标不能单独证明两个 Host 持久作用域相同；扩展该边界前应单独评审旧端、旧回执与迁移，不在客户端静默补造目标字段。

## 兼容与安全不变量

完整领域身份绑定 Agent、Host、workspace、runtime，操作再按能力绑定 Thread／Turn／资源等目标。Codex 账号仅为历史元数据；EasyWork 原账号、设备绑定、grant 和 DPoP 继续按其真实授权校验。统一领域契约不等于复用另一客户端的凭据或放宽完整目标校验。

迁移保留原身份、配置、绑定、草稿、附件、操作 ID、不可变提交与回执。旧端通过可识别版本与独立能力继续使用已有功能；不能要求所有端同时升级。新增可选字段、未知扩展和不支持能力按已定义兼容行为处理，只限制真正受影响的能力。

读写分类、错误和 DTO 的变化要审查旧操作指纹与账本读取，不重算已提交意图，不重放未知操作。不得直接编辑原 Codex 历史或另启执行实例模拟原桌面接入。

## 开发交付与审计门槛

实现方在相关修改前提供有限的架构映射：共同操作／原契约 → Host dispatcher 与上游服务 → Adapter 投影 → App 消费入口，以及需保留的兼容例外。修复具体问题时只扩展必要范围，不把架构收敛变成所有能力重写。

| 核对项           | 需要的证据                                                                     |
| ---------------- | ------------------------------------------------------------------------------ |
| 契约进入生产路径 | 真实调用方、严格解析、dispatcher、权限／能力装配和消费路径，含准确源码版本     |
| 共同操作无漂移   | 两个 Host 的语义映射；读写、错误、回执、超时及恢复的适用共同向量与差异说明     |
| App 保持复用     | 受影响公共组件、剩余专属分支及原因；没有重复业务状态机或第二次发送路径         |
| 旧端与恢复安全   | 受影响旧／新组合、可选字段、原操作查询、重启／断连、无重复执行和数据保留       |
| 实际功能可用     | 按场景要求的原生模拟器与真实 Electron 独立核对；只读／文件场景不额外发模型输入 |
| 交付状态准确     | 源码、辅助检查、真实验收、提交合并与部署分别记录；未覆盖项明确保留             |

静态审查、编译、Schema 哈希与 fixture 分别作为辅助证据。功能缺陷修复按受影响范围回归，不因本规范重复全量已有验收，也不能用辅助通过补签真实场景。

当前主协调会话维护唯一台账；审计会话保留不可变发现、来源摘要和操作回执，复核实际差异与验收证据后给出结论。审计发现的当前处理状态回填原台账，不另建平行进度源。未处理的重要偏差须明确列出负责人、影响和下一步，不能用“已收到建议”结项。

本规范不改变既有提交、合并、部署、跨电脑沟通的授权范围；F75／A6 的原暂停要求保持。每个结束阶段及时回收本任务无依赖资源，保护其他现场与持久服务。

## INC01：已认证的网络范围学习

实现边界：候选已实现，验收与合并状态只在 [唯一台账](../plans/ios-easywork-alignment-20261112/README.md) 的 `F06-easywork-authenticated-discovery-networks` 维护。

Codex 的已认证 `GET /v1/discovery/networks` 与 EasyWork 的加密 `runtime/context.discoveryNetworks` 映射到共同 `DiscoveryNetworksSnapshot`（version、完整 target、networks），共用 `interfaceDiscoveryNetworks`。精确范围来自实际 IPv4 网卡掩码；隧道、虚拟桥、非 RFC1918 与异常掩码不成为范围来源。原地址广告、VPN 路由和授权不因该观察变化。

EasyWork 原绑定、设备密钥、grant/DPoP 与 `runtime:read` 在入口先行核对；dispatcher 仅在已装配生产者时追加可选字段，无新增命令或写入回执。公共 `/host` 和 Bonjour 仍只提供候选，不能学习可信范围。

iOS 两端共用解析与扫描；EasyWork 通过现有连接元数据传递观察，经原 captured/current 以及缓存观察快照比较回填 Client 的独立本地观察；该观察按完整目标、credentialRef 与证书指纹集合隔离。严格 Connection 领域 DTO 的四字段及 Schema 不变，新 Client 字段被旧端忽略，旧缓存缺字段继续可读。未知字段兼容读取，已认证空列表表示新观察为空；缺失、损坏或错误目标的可选数据不替换旧缓存。原完整 context 目标错误仍拒绝。删除或重新配对记录同时删除旧观察。

普通 EasyWork 页面合并本轮真实扫描结果与原已保存行，用既有“本轮已发现”提示已收到匹配目标的当前扫描结果；停止保留本轮结果，重新查找在实际再次命中前不冒充已发现。相同目标的证书/公钥校验保留。

验收仅覆盖新增范围：模拟器正常连接学习、持久与冷恢复、真实扫描命中/停止/草稿；真实 Electron 独立核网卡范围和零模型输入。原 Codex 扫描、旧发送与已合交付按其原范围复用。Android 当前不消费此可选观察，既有连接和原验收保持。

INC01 的只读观察兼容未知扩展字段，但只投影已验证的 `address/cidr` 与原目标；响应中额外的 token 等字段不进入连接、授权或持久缓存。公开描述和命令输入的严格校验保持。可选生产者读取失败时省略观察字段，保留原 context 与既有缓存，不冒充真实空范围。

## INC02：同一固定版本视频读取

候选映射与兼容例外见 [设计](easywork-progressive-video.md)，当前状态只在唯一台账 F77 扩展行。Codex HTTP 与 EasyWork 的既有 resource/read、resource/download 严格 range-v1 分支映射到 AttachmentReadState 和同一 Range 解析规则；WSS 的192 KiB信封上限由 Adapter 拆分公共窗口，不增加播放器或第三套领域模型。公开描述不授予文件权限。

完整目标、绑定、原设备/线程资源和 files:read 保持前置；源来自已有授权记录，固定快照核真实源身份、大小及摘要。未知取消仍返回410，同时记录有界完整 scope 墓碑；两个 Host 均防止取消先完成时迟到 prepare 重新打开，原写操作不可重放规则不变。

App 将真实 Host ID 映射到 EasyWork 完整目标派生的本地 Client ID 之前先核完整 readTarget、原资源/线程及 ETag。新读取错误有界结束，不因 HTTP/WSS 或版本失败静默换内容。视频完整下载继续原传输完成协议、稳定操作 ID 和原正文；接收/验证全部字节及原终态后才分享。新私有快照服务缺失的平台不声明能力；Windows 保留完整下载，Android 尚未提供此播放器/适配，不从 Mac 模拟器证据扩签。
