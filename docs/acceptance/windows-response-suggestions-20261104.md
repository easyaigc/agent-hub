这次恢复继续使用原正式运行包。局域网 HTTPS 按原证书指纹验证，未认证健康请求返回 401，认证工作区返回同一 Host。独立 CLI 的一次临时模型请求收到预期回复，模型列表刷新仍有超时。新版源码构建、配置清理和 Windows 升级门禁分别通过。桌面冷启动和双端实体手机未复验。下文保留旧转发的历史证据，当前操作见[退役流程](../runtime.md#windows-原生建议-responses-转发退役)。

完整 `pnpm check` 在 Windows 附件元数据测试停止，三项失败，后续阶段未执行。附件源码和该测试在本轮未修改，失败根因未单独确认。Windows 升级门禁另行执行，9 项全部通过。

2026-11-04。人类授权将已验证的转发采集接入 Host，并明确前台画面确认只用于技术验收，不作为常驻产品依赖；保护现有 macOS 功能。本记录区分实现、隔离回归、真实 Host 与手机结果。

## 实现契约

- 仅 Windows `desktop-runtime` 显式配置 `CODEX_DESKTOP_RESPONSES_CONFIG` 时选用新通道。Mac 原有 Trace／native-sample、安全判定、共享通道和环境工具保持。旧 Windows `CODEX_CLI_PATH` 安装仍停用。
- 原 App 正常启动；一次性官方 `openai_base_url` 配置指向同机 IPv4 回环。固定官方 HTTPS 上游保持证书验证，沿用原请求认证，不读取登录文件；不生成、重试或重放模型请求，不跟随重定向。
- 从实际 Responses 请求的预测来源元数据取得 source Thread／Turn，匹配同次 `response.created`／`response.completed` 的 response ID，解析原 `suggestion` 正文。普通回答、错误、取消、空结果、丢帧和不确定关联不发布。
- 保留原 IPC 管道核对桌面进程，再核 TCP 客户端为同用户／会话的直属 codex.exe，绑定 PID、启动时间及执行文件摘要。沿用 Host 的当前 owner 与邻接协议安装检查；这是同用户进程／来源绑定，不是独立的发布者签名认证。真实验收另核原 GUI 和直属 CLI 的准确路径与摘要。身份检查在独立 worker 中，不阻塞模型字节转发。
- 读取继续执行 Host 原 owner 与最新完成轮的前／中／后校验；同目标、同轮和同一次结果才可提交。新请求立即使旧结果失效，迟到结果不覆盖更新请求。读取不生成建议。
- 每聊天持久保存最新完成状态和关联信息；新 Host epoch 不把磁盘历史当成新鲜结果。正文在私有目录，认证、提示词、完整原始响应和原始异常不进入审计。
- 返回兼容 `source=native-trace`、`validity=native-version`，新增可选 `provenance={kind:responses-forwarder,responseId,desktopDisplay:unobserved}`。这里的 native-trace 表示原生生成的网络记录，绝不声称它就是 renderer 当下可见状态。Mac 安全后 native-sample 契约未放宽。

## 配置与运行边界

先启动正确端口的 Host 通道并通过带 bindingId 的健康检查，再运行 `windows-response-suggestions-config.mjs install`。配置器用 TOML 解析检测 provider／URL 冲突，实际编辑只增删自己的一条前缀，保留原字节和并发其他设置。替换采用乐观校验、原子替换及实际备份检查，不冒称对非协作写入者提供严格 CAS；未决事务保留恢复资料，不自动重放。`disable` 只删除有所有权回执的准确配置。

本次使用标准 ChatGPT upstream。包含 `/backend-api` 的本地前缀保持 realtime 路径判断，转发器还透传已核实的图像、记忆、搜索与实时 HTTP／WS 路由；只有 Responses 进入建议解析。官方自定义 base URL 会省略部分内部工具结果／MCP 归因元数据，且本通道不提供企业专用 workspace origin 路由等价证明，不能宣称与直连的所有内部请求字段相同。既有已加载聊天不保证热切换；新聊天或正常冷恢复后分别验收，不强退原 App。

观察 worker 故障或预算超限只关闭观察，已建立的字节转发继续。Host 自身仍是回环网络依赖，当前没有转发服务离线后的自动直连；正常升级应保持既有 Host 自启／恢复入口，不能将单次请求成功写成此项已通过。

新预测在异步进程核验前同步建立来源屏障。连接／正文超出观察预算时，未知内容可能属于任意来源，因此暂时撤销建议读取并清除旧值；盲区连接结束再清除重叠区结果，随后新验证请求可以恢复，不影响原字节转发。配置器采用同卷私有 staging，明确恢复仅写独立无变更回执，不自动放行历史失败。
