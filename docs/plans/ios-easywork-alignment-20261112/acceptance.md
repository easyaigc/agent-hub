## 单包检查与真实 DEV 顺序

1. 确认准确源/运行包和原操作；旧结果UNKNOWN先核对，不通过再次发送“复现”。保护手机、桌面、共享服务和既有未提交工作。
2. 契约/持久边界测试覆盖真正可能出错的目标隔离、指纹、乱序、恢复和能力，不写仅重复静态类型的测试。
3. TypeScript、workspace或工具变更执行 `pnpm check`；原生变更在完整Xcode可用时执行 `pnpm build:ios`。共享KMP、Android变化运行仓库当前实际提供的相关检查，不将计划命令当可用命令。
4. 真实Electron + 原生iOS（适用模拟器或真机）+ 实际模型/原资源/真实通知，按对应子断言执行；只读场景要求0业务模型。模拟器通过且范围不含实体断言即可关闭；混合组保留逐子项结果。消息操作以唯一nonce/operation ID核对，不能制造重复输入求截图。
5. 从桌面canonical、操作账本和真实Provider记录独立核对原始输入/轮次/设置/文件。模型口头称成功、UI显示成功、命令外层completed均不独立构成通过。
6. 归档本次成功与失败，再回填F/UI/S及四格；变更指纹后仅复用依赖完全相同的具体断言。清理自有进程/端口/runner，保留必要证据和原未知现场。

Agent Hub只用pnpm；EasyWork桌面的构建执行其自身准确源码指南。不能在本仓新增npm/Yarn/Bun锁文件。只因文档变更不运行无关全量编译；实际开发变更按受影响检查与验收门槛执行。

## 回执格式与关闭规则

每个结果至少记录：`EW包 / AC子项 / F与UI / OS与设备 / Agent / Host模式与目标私有引用 / 通道 / 完整源SHA与WIP摘要 / 契约和包SHA256 / 实际Adapter指纹 / 原operation-thread-run引用 / 预期与实测 / 新输入与模型轮计数 / 原始证据摘要 / 状态 / 失败原因 / 下一步`。

公开文档只放脱敏ID引用/摘要；密钥、账号、真实对话、附件、设备完整标识和机器绝对路径只进忽略的私有证据目录。协调正文含来源头最多8KiB UTF-8、建议2KiB内；工具输出最多16KiB。补丁、长日志或附件经独立文件通道，以传输ID、实际路径、大小和SHA256引用，不编码/切片绕过正文限制。

状态严格区分：拟实现、已实现、辅助通过、本次真实通过、匹配复用、失败、未验收、环境阻塞、暂停。只有该功能在声明范围内的所有适用断言都有本次或匹配证据，且失败已关闭，才可汇总完成。供应商不支持Fast等真实能力边界必须保留原因和后续，不把按钮隐藏或删行计成对齐成功。完成率要在EW01冻结完整断言分母后计算，本报告不提供误导性百分比。
