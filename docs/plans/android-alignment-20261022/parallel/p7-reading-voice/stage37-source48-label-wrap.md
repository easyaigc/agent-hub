## Matching dependency review and implementation

Resolved compile dependencies are Compose foundation/ui/ui-text **1.12.1** and Material3 **1.4.0**. Official Google Maven source jars were downloaded, SHA-recorded, and read; compact licensed excerpts are kept in private evidence. In 1.12.1, `getInfoText` exports the owner's unmerged Text property. Clickable already merges descendants regardless of enabled state, so adding an otherwise empty merge modifier alone does not put the child's Text into that native owner. This conclusion comes from matching implementation, not only generic documentation.

The new small compound controls keep actual Material TextButton and FilterChip. Their single label parameter supplies both visible text and the owner's Text name. The visual Text uses `hideFromAccessibility`, which retains Compose Text/layout inspection; the parent is not hidden by that child's property. Thus the native name comes from the product label, with no duplicate contentDescription or separate second spoken Text target. Button role, FilterChip's real Checkbox role, selection, enabled/disabled state, ripple, styles and actions remain Material-owned. No Role.Tab, invented click action or manual enabled-state override is added. This explicit name is required by the matching native exporter; it is not a replacement expected value in the test.

The label uses `width(IntrinsicSize.Max)`: its preferred width is natural intrinsic width clamped by the parent's incoming maximum, then supplied to Text as tight constraints. Short labels retain shrink-wrap controls; long labels naturally wrap within available width. TextLayoutResult compares box width against paragraph width, so consistent tight width addresses the measured geometry while retaining the overflow assertion. Font, line height, soft-wrap/default unlimited lines, padding, button colors and parent FlowRow remain. There is no fillMaxWidth on these small labels/chips, no ellipsis, maxLines cap, font reduction or density override. Fresh native measurement must confirm the fix; this child does not assert that the four failures are closed.

Official background: [merging and hiding semantics](https://developer.android.com/develop/ui/compose/accessibility/merging-clearing).
