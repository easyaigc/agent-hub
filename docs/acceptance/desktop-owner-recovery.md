# 已跟随 owner 恢复：实现与验收范围

2026-10-21：已修复共用 Host 的一处可复现缺口。不同窗口或客户端接手原聊天、旧 peer 仍连接时，owner 广播只进入可选通知发现；关闭通知会跳过重新核对，可能继续展示旧状态。既有目标的基本恢复现与未知聊天的通知发现分离。

## 已实现

- 只有已明确加载或已通过 IPC registry 核实且取得可用 state 的目标，才在通知关闭时继续必要发现。单纯目录／持久历史存在不构成资格。
- 不同 source 仍只是提示；重新 discovery、合法新快照及 ID／host／streamVersion 校验全部保留，不从 hint 或旧缓存授予控制。
- 同一目标合并在途发现，失败保持原不可用／无控制结果，不增加轮询、自动重试或模型输入。discovery 1000 ms、snapshot 5000 ms 及帧／命令预算未变。
- 未知聊天在通知关闭时不探测或引入；等待中关闭通知后，后续 open 的实际创建记录点也核对资格。已加载目标保留在途恢复标记，新的快照不会丢掉富消息更新。仅跟随摘要的目标不自动加载全文。

## 辅助证据

同一合成 IPC fixture 的 10 场景：原版 4 通过／6 失败，补丁 10 通过／0 失败。覆盖通知关闭的已加载迁移、仅跟随摘要、未知目录拒绝、两处异步 opt-out、通知启用的新发现、失败后恢复、伪造 source、错误 ID／host／version、首次富消息投影期间新快照。真实经过帧解码、DesktopIpc 和 RuntimeSession；所有 CLI／helper／模型进程创建均拒绝并计数为零。

该 sidecar 实跑为 macOS／Node 22，严格 TypeScript、格式及补丁适用性通过。主仓库 Node 24 完整检查与 Windows 边界回归须按本候选补齐；上述结果不是原桌面或手机真实通过。iOS 与 Android 共用本 Host 行为，未修改界面；Android 原生结果不从 iOS 或合成数据推定，A6继续暂停。

## 实际故障的区别

Windows 独立只读连接对既有源 A 取得 initialize，唯一 discovery 在约6.98 ms返回 no-client-found、follow约7.56 ms结束，4帧994字节，最大解析约0.74 ms，写队列峰值0，Node及父控制器正常退出。它仅证明该次新连接没有 owner，不能倒填先前1.586秒503或历史21.67秒的唯一原因。原生目录另确认两个测试源未加载；正常导航回执也不能代替实际 owner。

本修复不降低原生建议所需的来源与 owner 校验，不将本缺口宣称为上述 Windows 原请求的唯一根因。旧失败与未知回执保留；Windows普通13项、两项拒绝、无接口空闲及 iPhone真机业务仍须独立完成。全部实际结果通过后再正式合并、统一打包并逐机更新。
