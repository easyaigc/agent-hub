## Implemented candidate

`MobileSession.phoneReading` owns one `NativePhoneReadingStore` and the existing `NativeReadingLedger`. Workspace and accepted latest history metadata feed the same authority. Reconciliation scopes include every saved real target, including offline computers, with Codex account metadata excluded from canonical identity. This stage includes already loaded/persisted workspace summaries and ledger/push rows; a separate complete unread-directory pagination scan for previously unseen server pages remains open and is not claimed as implemented. Source unread stays source metadata: sidebar dots and client unread counts use the cached phone snapshot. Running/pending status precedence is unchanged. Unknown initial ledger state displays an em dash, and storage failure retains the last successful projection and actual error; it does not publish an empty reset.

`readState` is strictly decoded from workspace thread summaries and the current history thread envelope, carried by `MobileThread`/`MobileHistory`, and retained by workspace encoding and existing encrypted history fragments. History summary host/thread identity must match its outer envelope. Earlier pages and cached rows do not renew reading proof. The accepted latest network page, complete runtime target, selection and connection revision, fresh workspace/history and original reader ID must all match. Terminal assistant text/status must match the exact current content digest; newest equal-revision conflicts do not fall back to older matching text. Legacy complete replies get stable local positions on actual accepted latest history; repeated unchanged legacy inputs reuse their prior position.

`AgentHubApp` mounts a one-dp marker directly after the actual assistant body and before attachment cards. Both the current viewport and the marker must have real nonempty clipped geometry. It waits a frame, rechecks the captured content, then requests a lifecycle lease for that version. Being at the list's last index alone does not acknowledge anything. Background, selection/connection changes, changed content, uncovered-state changes, active/closing drawer, sheet/dialog, loss of main-window focus, voice input and attachment/system surfaces invalidate the lease. Search projections do not mount the body marker. The final ledger check runs on the background writer; geometry/foreground changes never wait on encryption I/O.

The existing Host implementation in `runtime-server.ts` / `runtime-session.ts` and iOS `AgentClient.acknowledgeRead` were inspected. The only added transport operation is typed `acknowledgeRead(client, NativePendingRead)` through AgentRegistry and the existing authenticated NativeCodexCommands transport. It posts the actual closed `/v1/threads/read` body (`hostId`, `threadId`, `readerId`, `position`, `target`), bounds the response at 32 KiB, and validates exact response target/thread/reader/position. The central generic HTTP schema has no definition for this operation; `NativeThreadReadingWire` is its closed native decoder, not an arbitrary method/route escape hatch. No Host code or central schema was changed.

The native stored reader ID is preserved and normalized by the already used `nativeReaderId` for workspace/history/events and this acknowledgement alike. Only a still saved, freshly authenticated, online matching target with `threads:read-state` can acknowledge. Local reading is durable first. Duplicate acknowledgement jobs coalesce per full target/thread. A 409 settles only the captured old pending metadata, following iOS; it preserves the local read watermark and newer unread content. Other failures keep the exact pending record for a later authenticated refresh. A late old acknowledgement cannot remove or indefinitely block a newer pending position. These are reading metadata operations and never send, approve, resume or replay input.
