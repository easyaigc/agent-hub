# Preserve the form lifecycle predicates while driving its test clock

The source31 native action auxiliary class passed three methods, but both lifecycle methods stopped at the five-second `entered` wait before grant install/HTTP read. That failure does not pass the lifecycle gate. Original logs, source/App/runner and the prior driver remain preserved.

The installed Compose1.12.1 implementation explains a scheduling hazard: `runOnIdle` waits for idle before running the supplied callback, while v2 composition uses the test dispatcher. Launching from that callback can leave the new caller queued. The old subsequent blocking `CountDownLatch.await` could not run that queue. The rule's `waitUntil` runs its current dispatcher tasks and, with auto-advance, advances its own frames. An actual JVM StandardTestDispatcher plus the unchanged production form bridge reproduces five seconds with no caller start, then entry of the same body once after `runCurrent`. This is auxiliary evidence of the hazard; it does not confirm the cause of either Android failure.

Only `NativeMigrationEasyWorkFormLifecycleTest.kt` changes. The original five-second entry budget and actual latch condition remain. The waiter uses the same rule's `waitUntil(5_000)`; it fails if the actual caller completes before entry, records the cause, and never forces a lease or latch. All original save/close, cancelled-quiesce, second-migration, preserved draft/claim and no-activation assertions remain verbatim. No production owner, Session, Page, P8 target/NSD logic or authorization path is changed.

Bounded diagnostic events record before/after launch, caller/body start, completion/cause classes and frames, original lease/form validity, Session/admission state, dispatcher/frame-clock class, test-clock identity/time and real Android Choreographer callback counts. Diagnostics do not log input bodies, codes, credentials or targets. The unique owned fixture writes `form-action-clock-observations.json` (maximum160 events/256KiB) on wait exit and teardown, including failures. Choreographer observers are removed in finally; they never declare work complete. Test-clock advancement can start a queued caller without a positive physical/virtual frame delta, so inspect the event ordering and actual dispatcher alongside frame counts.

If no caller/body start precedes the rule wait and entry follows scheduler progress, that supports a driver explanation.
