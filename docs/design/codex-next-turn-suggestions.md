## 来源与产品语义

截图中的灰色文字是 Codex 桌面的输入预测（composer prediction），尚未成为用户草稿，也不是上一轮助手正文。手机可以提供更明确的快速采用交互，但要同步**桌面同一条预测**，必须先取得该预测的具名只读来源。

当前安装代码使用 `cumberbatch` 服务：以 Host、Thread、上一轮 Turn 为缓存键，读取远端配置后，由桌面执行器创建 `ephemeral` 预测分支并返回 `text`、`sourceTurnId`、预测 Thread / Turn ID 等信息。结果存在 Electron 查询缓存和输入框插件中；普通会话 owner 快照没有该字段。不能把手机重新生成的文本标成“桌面同步”。

第二阶段产品行为为空输入框内两行灰字，独立“采用”和“全文”按钮；已有正文时提供“下一步建议”入口。采用只写草稿并聚焦；追加保留原文，替换需要再次确认，之后可以撤销。现有发送按钮仍由用户明确触发。

后续调查补充：安装 CLI 的实验 schema 含 `thread/prediction/request` 及 `thread/prediction/updated`，但请求返回空确认，没有只读缓存模式；当前桌面没有调用该请求，初始化还明确 opt out 该通知。原执行器没有具名 Unix / TCP listener，现有默认 proxy 连接失败；原 owner 两次有界被动观察得到 19 次真实快照，未观察到预测或嵌套转发。它们不是已验证的原桌面缓存读取出口。观察中的原会话仍在运行，不把零事件扩大为完整预测周期的否定证明。电脑操作工具先前拒绝原 Codex App 的 UI 访问，本轮未重试或换通道绕过。

## 数据来源的落地选择

### 原桌面同一条预测：当前已实现的只读来源

当前通过既有完成通知与原生 rollout trace 读取原执行器**已经生成**的结果；同一请求内的四个身份字段提供权威绑定，响应正文与通知逐字一致后才返回手机。原 owner IPC 用于前后核对最新已完成来源，不用于获取建议缓存。手机轮询只读取现有结果，不能隐式生成模型任务；未绑定观察记录不进入聊天建议。

Host 必须显式配置 `CODEX_DESKTOP_SUGGESTION_OBSERVER=1` 和 `CODEX_DESKTOP_SUGGESTION_TRACE_ROOT`，并确认观察器及私有目录实际就绪，才开放读取能力。启用原生 trace 会生成完整诊断记录并附加请求标识，本次已获准临时启用；一次性启动器不等于正式服务默认支持，后续部署和持续可用性须另行验收。

不能通过调用 Electron 内部任意服务、调试器注入、修改官方程序或历史、复用受保护工具入口完成。也不把“请求一次内部预测方法”视为普通读取：缓存未命中时该方法会执行预测，具有模型消耗及临时执行副作用。

### 助手明确给出的下一步：可以独立实现，语义不同

若最终回复带明确、结构化的后续动作，例如既有 `codex-followup` 指令，可由 Adapter 解析为 `assistant-followup` 来源。无需额外预测模型，但只在回复确有该动作时出现；正文里的任意祈使句或“需要的话……”不能自动变成待发指令。该能力不能宣称已同步截图中的灰色预测。

### App 独立生成：另一个产品选择

若未来要求手机无论桌面是否打开都能生成建议，应明确标为 `app-generated`，单列开关、模型消耗、上下文授权和生命周期。不能作为原桌面同源读取的静默兜底。本次不实现或调用此路线。

## 已实现接口与后续领域草案

已实现协议为 `DesktopNextTurnSuggestionResponse`，通过独立 GET 返回 `schemaVersion`、完整 `target`、`threadId`、`sourceTurnId`、`readOnly:true` 和可空 `suggestion`；建议包含 `id/text/contentSha256/expiresAt` 和可选 `validity:source-turn`。来源绑定值按真实原 owner 的最新完成轮次及原生证据判断有效性，不因一小时限制消失；旧 Host 与旧客户端仍使用兼容时间字段。准确契约及拒绝条件见[运行时协议](../protocol-runtime.md#桌面下一轮建议只读准确来源绑定)。原始 trace、预测执行 ID 和内部 prompt 不暴露给 iOS。

下面多来源的 `NextTurnSuggestion` / `SuggestionProvider` 保留为未来设计草案，不是当前 GET 的 DTO 或能力范围。DOM Bridge PoC 继续使用独立的 `desktop-dom / rendered-text` 响应，尚无原 Codex DOM 实读证据，不能与本次原生 trace 来源混用。

建议归属完整机器目标：`agentId / hostId / workspaceId / runtimeId / threadId / sourceTurnId`。Codex 登录账号只保留为历史元数据，不作为读取、缓存、草稿或发送的拒绝条件。连接仍核对证书、设备密钥和实际机器目标。

```ts
interface NextTurnSuggestion {
  id: string;
  target: RuntimeTarget;
  threadId: string;
  sourceTurnId: string;
  text: string;
  source: 'desktop-prediction' | 'assistant-followup' | 'app-generated';
  createdAt: string;
  contentSha256: string;
}

interface SuggestionProvider {
  // 只返回已存在结果；不能因读取而启动预测。
  readExisting(
    target: RuntimeTarget,
    threadId: string,
    sourceTurnId: string,
  ): Promise<NextTurnSuggestion | null>;
}
```

Adapter 隔离桌面版本字段，Host 返回稳定领域模型；iOS 不接触 `cumberbatch`、临时预测 Thread 或上游方法名。响应只包含必要的建议正文和归属，不泄露内部预测 prompt、凭据或调试日志。

建议 ID 以来源自身稳定 ID 为优先；无可用 ID 时由完整目标、来源 Turn、来源类型和正文 SHA-256 确定。建议列表、有建议、无建议和来源暂不可用应可区分；长度与数量有界，未知来源拒绝投影。

建议可作为 `ThreadRuntime` 可选字段随既有历史/事件快照同步；另声明经过真实实现验证的版本化能力。新手机兼容旧 Host 无字段，旧手机忽略可选字段。不能只加 Swift DTO 和 fixture 就宣称桌面已接入。

读取缓存不能改变原 owner 或执行状态。只向真实可用 provider 开放读取能力，桌面未连接时的缓存明确降级为缓存，不能充当运行时连通证明。可见当前会话有界刷新，完成、轮次切换、重连时核对；不逐会话扫描隐藏预测分支，也不另起预测执行实例。

采用是纯本地操作：核对捕获的草稿 key、完整目标、建议 ID 和正文版本后写 Draft。发送仍使用既有不可变 `clientMessageId`、附件清单、正文及模式；若提供快速发送，需扩展领域前置条件到 Host，并在真实原 owner 提交前核对 `sourceTurnId`，拒绝过期建议而保留本机草稿。不能仅依靠手机几秒前的运行状态。
