This is a test-only follow-up to the unchanged `c6b97a50` commit. It supersedes that proposal's diagnostic ownership/scope/deadline policy; it does not change product rendering, fonts, input, labels, chip widths, authorities or the seven native test bodies. Root has not adopted c6, so delivery includes both an incremental c6→new patch and a combined exact Source46/a969→new patch. ## Failure-open-window evidence, never a pass

A separate capture runs only when an actual button/chip TextLayoutResult hasVisualOverflow is true, or the actual exact-owner full-label expression is false, immediately before its unchanged hard assertion. It receives only the typed NativeSavedVoicePanelActivity and its exact Window. Package/class, lifecycle, native window token and focus are checked; no display/global screenshot API is used. The existing control measurement supplies viewport root/window coordinates. Metadata includes actual window size/orientation/density/resource fontScale, composed fontScale, language/theme/profile, expected/actual label, controller phase/busy/status and the corresponding layout/AX diagnostic filenames.

The normal `point()` body and its 24-point budget are unchanged. Failure capture has at most two attempts per method, edge≤4096px, pixels≤6×1024², bitmap allocation≤24MiB, PNG≤2MiB per attempt and a 5-second observation deadline. Frame preparation waits≤1s and PixelCopy callback waits≤2s within that deadline; PNG stream writes check byte/time limits before writing. Screenshots are unscaled, own-window PixelCopy PNGs. Partial PNGs retain a `.png.part` name and are never a captured proof. Each attempt has an independent metadata/error sidecar and never counts as a product pass.

Screenshot errors are caught separately and never replace the original AssertionError. Bitmap release is in finally, with an atomic ownership state: a request still in flight may only be recycled by its callback finally. A late callback only releases its bitmap; it cannot write a PNG or claim an image taken after cleanup as pre-assert evidence. Pending release is explicitly reported. All ordinary successful methods take zero additional failure screenshots. The new path runs before the original assertion and cleanup, so a blank closed-terminal capture is not substituted for the failed open state.

## AX ownership and content scope

The diagnostic collector borrows its root and never recycles it. Every newly acquired getChild/labelFor/labeledBy node and owner.window is identity-tracked and released in finally, including objects returned by an over-budget call. The original nativeAx caller separately owns and finally recycles its root and new children after the existing assertions. Recycle failures are recorded; caller release failures enter cleanupErrors. API26 cleanup is retained even though newer APIs deprecate recycling.

Content traversal requires both the exact target package and the same known owned root window ID. Foreign package, unreported package or unknown/different window is metadata-only, incomplete, and is not recursively entered. Package-null same-window association may be noted but does not authorize content. Label relations and window titles are read only after this same package/window verification. No foreign text, descendants, label content or title is read. Exact-owner versus descendant matches remain evidence only; no descendant text substitutes for the original owner-label guard.

UIAutomation original flags are captured before modification, restored in finally and read back. A restore mismatch or exception is added to cleanupErrors and makes the actual JUnit result fail; recording `false` alone is insufficient. The primary failure and cleanup failures remain separate.

## Generation, deadline and publication bounds

Read-only diagnostic groups use explicit budgets: root fetch 1s, AX collector/owner search 2s, TextLayout groups 2s, failure frame 5s. Checks occur before/after framework reads and between generated elements. A result returned after its read budget is discarded and cannot supply new traversal, content serialization or input. Existing hard assertions remain; they are not reinterpreted as successful observations when diagnostics are unavailable.

Before allocation/copy, strings are clipped by character access rather than full toString, to a shared 8192-character budget and per-field limits. Layout generation has a shared 128-line budget and at most 64 lines per layout, plus the prior 16-node/four-layout limits. Native search/subtree/owner/action limits remain 512/48/4/8. A streaming JsonWriter and fixed-capacity byte sink reject before output grows beyond its byte cap; no full JSONObject.toString is generated before checking size. JSON snapshots are at most96KiB and a diagnostic group at most8MiB. Incomplete/truncated observations explicitly carry complete=false.

Deadline-exceeded read payloads are not serialized. Only non-content elapsed/limit/exceeded/late-read-discard counters are published. Snapshots use a private pending file, deadline checks around publication, and discard their newly owned pending output if a write missed the budget. Framework calls and filesystem operations cannot be forcibly interrupted by these checks; actual elapsed time and exceeded status are recorded, not described as a guaranteed hard OS-call timeout. Failure-frame PixelCopy callbacks are similarly bounded waits with explicit unknown/pending cleanup. No late callback triggers UI input or publishes a frame.

## Auxiliary and native boundary

Pure-host contracts check rejection of a late result/no later read, prefix copying of a huge CharSequence without toString/full allocation, and byte rejection before growth past the limit. Existing lease/late-return vectors, exact source/guard retention, unchanged point body, and SDK compilation are separate auxiliary evidence. This child performs no device, Host, microphone, ASR download or native screenshot action and does not rerun full pnpm check. Parent supplies a new candidate/new leases for actual failure-window PNG, node-release, scope, deadlines and flags restoration acceptance. Old claims and label/wrap failures remain sealed. iPhone/A6 and task/project work remain paused.
