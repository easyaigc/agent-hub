# Coordinator binding replacement and restoration native preparation

Four new `NativeChatNotificationCoordinatorTest` methods bring the class to twenty-five cases. The existing twenty-one method names and assertions remain; the separately committed navigation callback case uses its terminal journal outcome instead of demanding a stale report. The private fixture now captures storage immutably in each Session port and constructs each system sound library with that exact port storage. Fresh coordinator construction is explicit so a replacement cannot accidentally keep a prior port/scope/transport. The five shared Session/Activity hooks and production code are unchanged in this stage.

| Native method                                                    | Falsifiable boundary                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `credentialReplacementDuringLookupKeepsOriginalTicketAndDraft`   | While a real locator read is suspended, stop old authority before changing the owned saved token. The old route stays unavailable, its original ticket stays unconsumed, no feed/submit occurs while reading readiness is false, and the original draft/selection remain.                                                                                                                                                                               |
| `restoredSessionCanOpenOriginalBeforeReadingLedgerAllowsPolling` | Separate Session-ready and P7-reading-ready projections. A queued original route can open once the Session is ready, without making a notification identity or starting polling before the required reading port is ready. A later explicit readiness publication starts one registration; the original other-thread draft survives.                                                                                                                    |
| `disposedBindingCannotPublishLateLookupIntoReplacementStorage`   | Hold an old lookup through disposal with a deliberately late synthetic reader. Create a new owned child storage, real MobileSession, immutable port and coordinator. Await the exact old lookup Job completion, then require zero old/new navigation or presentation pollution, no private original/identity records in the new storage, and an unconsumed old ticket in the original storage. A finally block always releases the owned held callback. |
| `actualSessionRestoreRetainsOriginalUnknownWithoutAnotherSubmit` | Flush owned storage, dispose the old binding, construct a new real MobileSession and call its actual `restore()`. Original draft/selection, installation identity and encoded unknown operation survive. With reading polling gated, only the retained original-ID query runs; no replacement submit/feed or notification is allowed.                                                                                                                   |

These are native auxiliary scenarios using real MainActivity, independent owned MobileSession, Android Keystore/AtomicFile and the shipping coordinator/locator/journals. Required reading, Host, model and OS presentation ports stay synthetic. The readiness case tests the port's two readiness projections; it does not claim a real P7 ledger initialization result. The child-storage replacement is a binding-isolation scenario, not a migration activation entry or proof of archive activation. Actual migration remains unimplemented at the Session boundary and must follow the disposal/preservation rules before its future activation path is added.

Build the parent's integrated candidate and run these four methods explicitly, together with the corrected navigation method, before assigning runtime success. This workline compiles them locally but has no device lease. Parent-owned Activity restoration/dispatch and the P7 rendered-notice consumer retain their own evidence. iOS behavior and evidence are unchanged. No real device, Host, model, OS notification or deployment is exercised here. The adjacent F52/UI11/S15,S16 delta is for the parent-owned central parity/design/acceptance tables.
