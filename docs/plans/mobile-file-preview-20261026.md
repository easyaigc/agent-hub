# 手机内置文件预览

## 范围与状态

用户确认采用点击文件直接进入 App 内阅读页的方案。首期实现 Markdown 文件预览，文件类型选择、加载、阅读界面和解析器保持窄接口。当前为源码候选，辅助检查与真实设备结果见[验收记录](../acceptance/file-preview-20261026.md)。A6 保持暂停，任务看板不在本次改造范围。

## 已实现的源码边界

- 消息文件链接、聊天附件继续复用已有目标绑定和资源下载；Markdown 按扩展名或明确媒体类型进入内置阅读页。iOS 其他文件继续使用 Quick Look，Android 提供受限 URI 的系统打开和分享。
- `FilePreviewRules` 在 KMP 中维护 Markdown 类型、2 MiB 排版预算和文档链接类型策略。UI 不根据 Codex／EasyWork 展示名称分支。
- 两端各有静态预览器注册表，声明源码、目录、搜索能力，注册对应解析器。阅读页管理加载、错误、导航、分享和阅读位置；渲染器不持有 Host 凭据或任意文件读取入口。
- iOS 使用独立 `FilePreviewKit` Swift 包，以固定版本 Swift Markdown 解析 CommonMark／GFM；Android 沿用 commonmark-java。结构和内联样式在后台解析，原生视图呈现；解析结果在当前文件版本内复用。
- 标题、列表、引用、代码块、表格和原始 HTML 文本分别显示。表格单独横向滚动，不扩大正文宽度；正文和源码均可选择，代码与源码提供独立复制操作，分享保持原文件字节。
- 标题目录、按内容块查找、预览／源码切换与进程内阅读位置保留。阅读位置缓存有界，按完整目标及文件内容版本隔离；新版本不套用旧版本阅读位置。

Android 当前从已登记附件行进入预览；聊天正文中的电脑路径链接直接解析尚未接入，不能把附件行可用记为与 iOS 全部入口一致。Android 的同名跨目标、错误回退与视觉原生矩阵仍待验收。

## 文件、链接与安全

原下载管线先解析当前资源版本，再校验长度、摘要和目标，缓存不能绕过版本检查。打开后的阅读页持有下载快照，后台消息更新不重新解析同一快照；切换来源目标会撤销旧等待和预览。

文档内部章节锚点在本页定位；普通网页和明确外部操作交给平台处理。图片引用首期显示说明及显式打开入口，不自动抓取外部内容。相对路径、本机路径或未注册引用不取得新的电脑文件权限，显示可理解的原因；不以文件名猜测授权资源，也不新增任意路径读取接口。后续本地图片和相对文档导航须通过独立的受控资源解析设计。

不执行 Markdown 内原始 HTML、脚本或其他活动内容。解析设置字节、节点、嵌套及表格规模预算；无法排版时保留原文件并提供系统打开／分享，不静默截断。

## 后续扩展

代码预览器通过注册表接入，增加语法高亮、行号、跳转与换行选项；Markdown 代码块再复用对应原生显示组件。JSON、CSV 等各自解析并声明能力，系统预览继续作为其他格式的兜底。Mermaid、公式、任意 HTML 渲染和文件编辑不属于本期已实现能力。

## 验收要求

两端共同核对中文、重复标题、转义竖线、长表格、长代码行、源码复制、锚点、搜索及失败回退。另核对目标切换、相同文件名、文件更新和迟到下载的隔离。真实 DEV 使用独立 Host 与验收 App，从真实原桌面任务中的文件链接打开，并独立核对原文件摘要、原 owner 和任务输入数。构建、解析测试、合成 UI 与真实手机结果分别记录。
