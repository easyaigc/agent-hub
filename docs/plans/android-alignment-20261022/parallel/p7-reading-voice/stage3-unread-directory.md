`NativeReadingDirectory` follows every thread page for one full actual target, deduplicates IDs, keeps the highest known read version and rejects conflicting equal revisions. It discards titles/projects/raw wire from the returned projection; only target/thread, readState, source unread and local reader metadata reach the existing background ledger. Projects are not paginated: the unread domain is the thread directory. It yields every 32 rows and between pages. Repeated/empty/oversized cursors, missing/foreign runtime targets or children, over 1,024 pages or over 16,384 threads fail without publishing a partial completion. The existing ledger's own global bounds still apply. A host without a complete read target cannot be promoted to a verified full-directory scan; existing known counts remain.

The Session owns one serial sweep across saved real clients, including unselected/offline ones. Concurrent triggers coalesce to the existing Job, ordinary attempts have a 30-second minimum interval, and the existing 15-second foreground maintenance loop supplies retries; there is no second polling loop or per-thread read. A successful workspace read/connection can seed its first page, avoiding another request for that page. Each traversal has local cursors and captures the full target, connection revision, endpoint/certificate, reader, provider connection, management revision and foreground generation. It checks ownership before and after every page and before publication. Background/restore/reset cancels and advances the generation; removing/replacing a client invalidates its captured owner. Selecting another chat does not redirect the sweep or consume its cursor.

Only a fully validated traversal submits small metadata to the existing ledger. The sweep neither replaces ordinary sidebar/workspace pages nor grants fresh history/runtime/command authority. Offline failures retain known rows, local read watermarks, pending metadata ACK and notification tombstones. Completion/failure diagnostics are small, target-scoped, in-memory and explicitly describe this traversal; counts remain the phone's last known ledger projection. No storage Schema or migration path changed. The existing connection-removal counting rule is unchanged.
