# P7 照片原请求与本地结果恢复档案

## P7-4c 实现与共同断言

iOS保持图片选择最多五张、原destination/importId、PNG/JPEG本地准备和显式发送才上传的来源约束。Android把照片请求接入独立加密子命名空间与稳定photo回调键；文件原document键、v1记录及命名空间保持兼容，旧类名仅为编译期别名。文件与照片现在只有一个本地结果协调器，平台种类只选择系统契约、上限与本机loader，不能调用Host命令。普通文件字节精确保留，照片继续图片方向/PNG/JPEG准备；原URI/顺序、原完整草稿/代次、固定槽位/清单与加密暂存按原请求核对后消费。

恢复prepared/launched只保留本机等待，绝不重开选择器。照片超过五个结果在读取提供者/申请持久化前拒绝；恢复记录也校验种类上限。照片与文件及相机互斥，恢复读取/工作中入口明确禁用；账本未知格式保留原字节，关闭该来源选择并保护附件移除，独立文件来源仍可用。已选照片原草稿过期时保留加密原结果，显式重试/丢弃不影响新文件等待；源文件删除后仍能核对原暂存，重复/迟到回调不能加入新草稿。

修复共同恢复时序：本地结果ready早于父元数据完成时，恢复效果观察父草稿就绪。新增文件/照片两组真实Keystore/仓库准备，在父恢复前已有加密ready、注册后零选择器启动，父恢复完成后不切焦点也能消费原结果。测试提供受控registry与原生提供者，不是实际进程死亡证明。
