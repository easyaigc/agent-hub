# 文件互传与预览取消 20 MiB 上限（2026-11-03）

范围：F59 独立文件互传；F19／F32 聊天资源下载、预览与分享；UI05／UI12 文件入口及提示。用户截图为 `HTTP 413 · FILE_TOO_LARGE`，由 Host 附件读取器的固定大小校验触发。

## 实现

- 协议接受安全整数表示的正长度；新 Host 目录的 `maxFileBytes: null` 明确表示未配置大小上限。iOS 同时接受旧 Host 的有限正整数，旧版本超限时提示更新。
- 独立文件上传的 iOS 选择与电脑发送 CLI 不再限制 20 MiB；Host 仍流式写入、按不可变长度及 SHA-256 校验，使用原传输 ID、防覆盖发布及持久回执。
- Host 资源读取、iOS 消息链接解析／版本刷新及 Android 下载移除 20 MiB 拦截。Android 下载按清单长度流式写临时文件与摘要校验，完成后发布；失败清理部分文件。
- 来源授权、符号链接／非普通文件限制、目标隔离、文件变化检测及未知结果不重放保持。iOS 中英双语移除文件互传页面的 20 MB 提示。
- 聊天输入附件、任务证据上传属于其他操作，本次未改变其上游大小契约。Markdown／HTML 的解析预算保留，超过解析预算仍可使用系统打开或分享原文件；文件传输受存储、内存、网络与系统能力的实际约束。

## 共同断言与证据

S04／S11／S17／S18：大于 20 MiB 的原文件完成选择、登记、上传、下载及摘要核对；重复操作不重复发布；错误目标、损坏摘要、越过清单的正文与变更文件仍拒绝。旧有限目录与新无限目录分别校验。Android 尚无独立文件互传入口，不据此宣称 F59 双端实现。
