## 状态解释

- **未开发/部分实现**：有明确缺实现依据，并写到具体子能力，不能把整个“开放”列表叫未开发。
- **代码已存在、完整性待核对**：有源码，但尚不能证明覆盖当前全部对齐目标；先审再决定补开发或补验收。
- **已实现、未验收/历史部分通过**：代码状态与真实验收分开；有源码或编译通过不等于功能通过。
- **历史限定通过、待匹配复用**：保留原范围，确认当前源/包/设备/断言依赖后才能复用。
- **历史限定通过、本次匹配未成立**：审查已经完成，当前证据不足或实现已变化；明确等待补证/重验，不再标成审查仍未开展。
- **待集成/部署未核实**：提交合入与实际运行包是两个事实，不把本机候选算成已部署主线。
- **待执行/阻塞/暂停**：不再使用旧in-progress推定正在开发；实际Fast阻塞与F75/A6暂停分别记录。

原“44个开放父项”只是首次盘点的范围统计，包含不同开发与验收状态，不是44个未开发功能。以后所有数量从status.json生成，本入口不手写易过期的当前数字。

## 继续工作的固定顺序

读取本台账与维护规则 → 核对应F/EW/AC及准确基线 → 先收尾已实现/待验收项，有开发缺口则补齐后验收 → 按依赖继续后续开发与验收 → 保存证据并更新四维状态 → 生成并检查两份视图 → 满足证据/集成门槛后清理自有分支和过程资源。

按用户最新要求，**不涉及手机真实环境的断言，原生模拟器通过即可验收收尾**；混合场景拆分，实体设备特有断言单列。模拟器不替代真实 EasyWork Electron、实际模型结果或原始资源；辅助测试不升级为端到端通过。Host 并行任务使用用户指定的 `gpt-6.1-sol / xhigh`，具体运行事实仍只登记到台账。

```sh
python3 docs/plans/ios-easywork-alignment-20261112/render_status.py --write
python3 docs/plans/ios-easywork-alignment-20261112/render_status.py --check
```

全局F/UI/协议定义仍由原规范维护；Android独立进度及其他业务域保持各自责任。旧EasyWork计划和矩阵仅保留历史证据，新增iOS × EasyWork进度统一回填本计划。证据显示事实发生变化时及时校正台账，不把旧记录或此权威约定当作事实不会变化的保证。

首次盘点和状态规范化没有新增产品验收。本轮已按后续授权进入开发与验收执行，原始来源限制和每项实际结果均保存在台账；没有通过证据的项不会因启动任务而自动完成。
