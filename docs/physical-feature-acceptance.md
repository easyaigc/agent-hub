# 实体 iPhone 新增功能验收

当前用例覆盖统一新建入口、聊天置顶与搜索、归档恢复与删除确认、工作区批量管理，以及任务通知。实体设备结果与编译、fixture、模拟器结果分别保存，不能互相替代。源代码与设备安装包使用同一冻结候选；并行工作区的后续变化不进入通过指纹。

使用 `scripts/physical-features-dev.mjs` 启动专用 Host、真实 APNs 服务及固定验收控制入口。所有状态、凭据、设备备份、XCTest 结果和实现指纹留在工作树外的私有目录。必须先核对本机原 Host 身份、配对设备、签名团队及现有 App 数据，并备份 App 和通知共享容器。使用正常安装、正常启动，不传入 `-ui-testing`，不删除或重置用户 App。

驱动所需环境变量：

| 变量                                                         | 用途                                              |
| ------------------------------------------------------------ | ------------------------------------------------- |
| `PHYSICAL_ACCEPTANCE_DIRECTORY`                              | 私有状态与证据目录                                |
| `PHYSICAL_ORIGINAL_HOST_ID`                                  | 已核对的本机原 Host，只用于临时通知排除及恢复选择 |
| `PHYSICAL_DEV_BASE_URL`                                      | 专用 Host 的私有 HTTPS 入口，转发至本机 18988     |
| `PHYSICAL_DEV_RELAY_URL`                                     | 专用推送服务的私有 HTTPS 入口，转发至本机 18989   |
| `PHYSICAL_APNS_SANDBOX_KEY` / `PHYSICAL_APNS_PRODUCTION_KEY` | 本机 APNs 签名文件路径，内容不进入源码或日志      |
| `APPLE_TEAM_ID`                                              | 当前 App 签名团队                                 |
| `PHYSICAL_DEVICE_UDID`                                       | 本次明确选中的实体设备，供原生用例使用            |

先为该设备完成 `xcodebuild build-for-testing`，独立输出到 `.build/ios-physical`。运行 `pnpm test:physical:features <阶段>`；驱动通过 USB 下发私有 fixture 配置，在 Mac 独立读取原 Electron 和官方目录验证结果。手机 App 仍走正常 HTTPS 连接及真实 APNs 链路。每次必须实际执行一个 XCTest；零测试执行不是通过。

| 阶段                              | 必须核对的结果                                                                                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `model`                           | 手机选择专用项目、设置当前模型与 xhigh、仅提交一次输入；原 Electron 确认同一聊天、唯一输入和一次成功命令                                                                 |
| `pin`                             | 手机显示置顶；官方目录进入内置置顶 section                                                                                                                               |
| `search`                          | 取消置顶、无结果、真实工具输出匹配、点击定位及突出显示；记录已加载聊天生命周期限制                                                                                       |
| `archive` / `restored`            | 专用未加载聊天从活动目录移至归档，历史保留，原 ID 恢复                                                                                                                   |
| `delete-cancelled` / `deleted`    | 红色删除二次确认；取消不改变原记录，确认只删除专用副本                                                                                                                   |
| `bulk-archive`                    | 精确选择专用聊天，手机结果与官方归档目录一致                                                                                                                             |
| `projects-deleted`                | 搜索和全选仅选中两个专用项目；取消后仍存在，确认后项目记录移除而文件及模型聊天保留                                                                                       |
| `notification-settings`           | 保存原设置，临时隔离本机正式 Host 的通知，启用专用 Host；真实设备注册绑定成功                                                                                            |
| `notification`                    | App 在后台接收真实审批 APNs，展开卡片可见标题、概要、电脑及类型，点击回到原目标并保留草稿；按原 owner 实际提供的拒绝或停止选项处置专用审批，核对命令未执行且没有重复输入 |
| `notification-resolve`            | 首次通知已完成展示和点击但处置用例中断时，只重开原聊天处理同一待审批；不再次提交模型输入                                                                                 |
| `completion-notification`         | App 在后台接收专用真实模型任务的完成 APNs，展开和点击定位正确；输入唯一、无工具调用、草稿保留                                                                            |
| `completion-notification-recheck` | 已确认原完成任务后，具名提交新的复验短任务；复用回执不重放，等待通知点击后的连接就绪                                                                                     |
| `restore-preferences` / `cleanup` | 恢复原设置、移除专用连接、撤销专用推送绑定、切回原本机连接                                                                                                               |

归档与删除受上游 active writer 限制。已加载的原桌面聊天目前明确禁用相关菜单；未加载聊天的通过不能作为已加载聊天通过。零 Turn 元数据可能不进入官方列表，不能通过 reader 修复或改写官方状态。模型场景通过后，可显式设置 `PHYSICAL_PREPARE_UNLOADED=1` 重启专用驱动：经 Adapter 的官方元数据 fork 白名单复制本次已完成的前缀，准备三个含历史但未执行新轮次的专用副本，确认准备器退出及官方目录可见后再验收生命周期。

创建和模型输入的提交意图保持不变。已有创建、未知结果或未完成的准备记录必须先只读核对，禁止重放。手机存在未确认管理回执时，只查询原操作，不重新发起管理命令。只有打开归档列表等只读界面允许在原生菜单过渡吞掉点击时重试；保留首次失败证据，不能据此宣称连续首次点击场景通过。

验收网关只允许固定控制动作；模型与管理写入限定到专用聊天或项目。通知观察仅过滤至专用 IDs，不伪造运行事件，推送使用真实 APNs sender。停止本任务服务后，只移除本任务添加的私有转发端口，并核对原转发、正式 Host 身份、密钥和服务配置保留。保存必要产物与证据，再清理本任务临时工作树。

通知处置核对原始可用选项。若上游只提供允许和停止，使用停止并要求官方原轮次为 interrupted，不能把它记成正常完成；完成通知另用一次独立、无工具调用的专用模型输入验收。

移除当前连接会自动选择下一连接并收起列表。清理用例重新打开列表后按准确原 Host ID 选择；恢复阶段可用 `cleanup-restore-original`，仅核对专用连接已移除并选择原连接。正式 Host 配置的保留由独立文件摘要核对，不由订阅撤销回执代替。
