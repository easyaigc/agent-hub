## 目标与边界

短暂离开活跃状态不应制造离线、重连提示或失去原聊天。真正进入后台后允许系统挂起网络和 App 暂停读取；返回时保留页面、已确认的连接信息、草稿和原操作，按真实连接状态恢复。实际失联、授权撤销、证书或目标错误必须准确显示，控制权限不能由旧缓存恢复。

修复覆盖 iOS 与 Android 的共用连接状态、聊天订阅及原操作回执恢复，并处理 iOS 开发服务预览的后台退出。通知、发现、额度、仓库、子 Agent、录音和上传分别核对其生命周期，保留必要的省电与内容保护。Task Hub 只保留盘点结果，不实施 A6 暂停范围内的业务改动。

不要求手机永久后台在线，不新增常驻后台权限，不以静音音频、后台计时器或延长系统租约维持连接。默认复用现有 Host 领域契约和具名接口；不要求桌面同步升级，不新增任意 RPC 或第二套操作账本。

## 连接事实与控制就绪分开表达

前台恢复只表示需要检查新鲜度，不能直接写入离线，也不能仅保留旧 `online=true` 后继续授予控制。公共规则区分三个事实，平台适配器提供证据，页面消费同一语义：

| 事实               | 来源与有效范围                                                             | 界面与控制                                                                                      |
| ------------------ | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 最近已确认的连通性 | 原完整目标上实际成功的认证响应；保留最近确认信息，不等于此刻仍在线         | 前台核对期间保留电脑、聊天和原路径，不闪成断开重连                                              |
| 当前恢复阶段       | 未检查、核对中、已核对、可恢复故障、需人工处理；生命周期事件只能改变此维度 | 核对中使用轻量“正在同步…”；明确失败显示原因与重试入口                                           |
| 当前可控性         | 当前目标、凭据修订、连接/网络代次及实际 runtime/thread 控制证据均有效      | 发送、停止、审批、队列执行和新建沿原能力与 owner 条件开放；历史可读与 socket 存在均不能授予控制 |

实施优先在现有共同规则和原生 store 增加最小的内存恢复状态，不新增持久配置或 wire 必填字段。冷启动继续视为未核对。旧缓存没有新状态时使用保守默认，不凭保存的 online、缓存能力、时间未过期或 App 仅短暂离开，就推断仍可控。

真正后台、目标/凭据变更或实际网络代次变化后，使控制证明待重新确认；页面保留最近信息并可读写本地草稿，控制操作等待所需证据。单纯 inactive 不使现有证据失效；期间收到的真实断线、授权或目标错误仍立即生效。恢复成功可以来自当前目标上已校验的实时响应，无需为了刷新徽标再请求完整目录。

原 failed、需重新授权或迁移待验证状态不被生命周期覆盖。新的有效凭据与显式重试按原恢复入口进行；旧代次的成功/失败都不能改写新目标或新授权状态。保留现有“晚到暂态失败不能推翻更新成功”的规则，认证、证书及身份错误仍按同代次证据拒绝。

控制证明按范围消费：workspace 级证明只支持当前目标与能力允许的新建；Thread 级证明只支持该聊天已核实的读取/发送；停止、审批和队列执行还须匹配当前 Turn/Run、请求或队列项。它们不能互相替代。恢复期间所有具副作用入口都检查对应就绪门禁，不能只改输入条；特别核对目前只查能力的 `createThread/createProjectless`、iOS 缓存 `accessPolicy` 和 Android `freshWorkspaces/freshHistories`。准确事件/历史证据到达后，Thread 控制不得继续被无关的慢目录锁住；workspace 级新建仍等待它自己的有效证明。本地编辑草稿与网络控制分别判断。

## 生命周期处理矩阵

| 事件                               | 连接与读取                                                                             | 页面与内容                             | 保护条件                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------- |
| 首次启动或冷恢复                   | 当前目标进入未核对，启动必要检查及原操作查询                                           | 恢复原聊天、附件、草稿和阅读位置       | 原数据加载成功后发布；不把未知提交当空输入     |
| active → inactive                  | 不设置离线，不取消健康主会话及其读循环，不重启发现；暂停不可交互 UI 工作               | 保留页面和本地状态                     | 录音、手势、隐私覆盖等仍遵守各自中断保护       |
| inactive → active，未曾 background | 不做整组重连；只处理期间实际失败及明确待恢复工作                                       | 不出现人为连接闪烁                     | 生命周期处理幂等，不因重复通知累计观察者       |
| 进入 background                    | 持久化已有原状态，取消本任务拥有的事件/补读/轮询等待；不关闭可复用健康传输，不中断写入 | 保留当前页面；预览另按下节暂停         | 停止前台专属扫描；不制造后台保活               |
| background → active                | 合并为一次恢复周期；当前目标优先，实时、回执与目录独立启动                             | 沿原目标继续阅读；核对中不显示虚假断开 | 控制证明按上节重新确认；未选中目标不批量置离线 |
| 实际网络改变或读取失败             | 按完整目标合并恢复，只取消可重取的原读取；失效传输才重建                               | 显示真实恢复状态，保留缓存与草稿       | 不取消/重发在途写入，原 ID 先查回执            |
| 切换目标、偏好或凭据               | 使用原有身份隔离和关闭/更新语义                                                        | 新目标不继承旧页面操作结果             | 原操作和附件继续绑定原目标；不能为当前目标改写 |
| 注销、撤销授权或证书/身份拒绝      | 立即停止相关控制与读取，结束本次等待并给出准确原因                                     | 可按现有权限读本地历史，提供原恢复入口 | 不降级到另一认证方式，不后台盲重试             |

iOS 用 scene 生命周期驱动一个幂等入口，不在多个 `onChange` 中各自作不同的连接状态决定。BG1 必须同时修改 `RootView` 中与发现、连接读取相关的 `.task(id: scenePhase == .active)`、其 guard 及显式 stop，使网络任务使用稳定的“已进入前台且未 background”代次；仅改 `onChange` 不能阻止 SwiftUI 在 inactive 自动取消任务。未读读取、侧栏轮询等前台专属任务逐项明确归属，不机械替换全部 task key。

阅读可见性/已读确认、通知前台呈现、手势、录音和交互仍要求真正 `.active`，不统一替换为“非 background”。inactive 不应发送新的可见阅读确认、继续采音或接受手势提交。网络任务可继续与用户正在实际阅读是不同条件。

Android 区分 Activity 重建与真正离开前台，复用原 Session 的归属；旋转/配置变化不能因旧 Activity 的 `onStop` 把保留 Session 当成一次真实退后台，也不能让新 Activity 重复启动观察者。保留原账号、Activity result、迁移和受控测试会话生命周期。公共规则由 KMP 提供或由共同向量校验，不按 Agent 名称复制业务状态机。

## 恢复工作不等待完整工作区

一个恢复周期绑定完整目标、客户端/授权修订、选中 Thread 和连接代次。恢复管理只拥有可取消的读任务，不拥有模型输入和业务写入。以下工作可并行，但各自只允许一个当前任务：

1. **连通性与控制核对**：适配器复用已实现的认证读取和目标校验。已选聊天优先采用原 history/events 中明确的运行时与 owner 证据；无聊天时采用原 workspace/已实现上下文读取。空事件、receipt 成功、health、metadata 标题或 socket 存在不能单独证明可控。现有接口不能提供所需证据时，等待原核对路径，不发未知命令或另造无目标探测。
2. **聊天状态**：从已保存 epoch/cursor 继续事件读取，同时保留原有有界 history catch-up；不能因 workspace 慢而推迟整个循环。事件缺能力时继续原只读补读。早期分页与最新页仍保留各自快照围栏。
3. **原操作回执**：按原命名空间、ID、目标和指纹恢复查询，独立于长轮询和目录。已接受、未知结果、队列、创建/打开及已封存上传/转写分别沿原契约查询，不把查询结果解释为自动重发许可。
4. **工作区与发现**：刷新目录、可信候选和其他客户端状态；已有请求合并，保留已加载目录与未选中目标的最后确认信息。发现仅提供可信候选，不决定授权或可控性。

前台等待设置独立的八秒界面预算：预算届满时结束“核对中”阻塞，显示“暂未核实连接，当前显示缓存”及重试，不继续无限转圈，不宣称取消了远端。预算不覆盖原控制操作期限，也不重置整个 URLSession/共享握手。可取消的独占读取按其任务截止，不能取消别的读取所依赖的共享建连；同一通道仍只保留一个恢复任务，未结束前不叠加重试。

暂态恢复沿用有界退避，初始 1 秒、上限 15 秒，网络变化或明确用户重试只合并唤醒一次。真实认证/目标/协议不兼容错误立即结束本次等待，不走无限暂态退避。前后台与网络变化同批到来时共用一次恢复周期，不能累计重启。记录八秒为拟定界面预算，需以验收计时证明，不能把请求配置上限当实测延迟。

### 适配层建连与取消归属

BG2 同时修正真实适配层，不能只改 store 调度。当前 EasyWork 的首个请求直接执行 `connect`，其取消会触发 `disconnect`；`requestData` 的单读超时也会断开共享传输。这两条路径必须与新编排一起收敛，Android 对应实现按同一向量核对。

- 共享建连由 `EasyWorkRemoteSession`/对应原生 session 持有一个有代次的 producer task。调用者只登记自己的等待者；取消 workspace、事件或界面等待，只注销该等待者，不取消其他读/写依赖的建连、接收泵或传输。全部等待者离开且无在途操作时，session 才可回收其独占 producer。
- 单次读取超时只结束该 request ID 的等待并记录通道故障，不直接 `disconnect`。接收错误、关闭、握手确认超时或独立会话活性核对失败才可使传输失效；优先使用同代次更新的认证成功证据，缺证据时使用既有具名只读上下文核对，不能发写操作探测活性。该核对仍只有一个 owner 且有截止，不能因 Relay 尚在线而永久保留已经失效的 Host 加密会话。
- 真正的传输失效需要重建时，受影响的在途写入保留原 ID/意图，进入原未知结果查询；不承诺物理失联后写请求仍能继续，也不因重建自动重发。正常的页面/单读超时不得主动中断它们。

| 时钟         | 预算与归属                                                             | 届满后的释放                                                                                                           |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 前台界面核对 | 从本次恢复开始用单调时钟计八秒，不因重试重置                           | 仅结束界面等待并显示缓存/重试；无新证据时控制仍不可用，不能由超时解锁                                                  |
| 单次恢复只读 | 单调时钟三十秒；长轮询使用原有已实现窗口，不更改显式业务操作期限       | 完成对应 waiter/request ID，清理其 singleflight 占位；迟到响应按代次丢弃或沿原结果归档，不关闭健康共享传输             |
| 共享建连     | 每候选沿用现有八秒握手上限；本次 producer 总计最多三十秒，包含候选准备 | 只清理同代次 producer 的候选、接收泵与等待者；所有等待者得到明确结束，下一轮可按退避新建，旧 producer 不能清掉新 owner |

代码以 `defer/finally` 和精确 owner/epoch 校验释放占位；界面已结束而底层读尚未到截止时不额外复制任务。T04/T08 必须验证首个读取消及超过原三十秒等待两种情况，不能仅用八秒以内的正常返回代替。

### 开发服务预览保留页面并显式继续

预览真正进入后台时继续停止本地网关并沿原接口撤销本次租约，但不 dismiss 页面、不清空可安全保留的页面描述。回到前台显示“预览已暂停”。已确认原租约关闭后显示“继续预览”；点击后先核对当前完整目标、Thread、授权与 LAN/VPN 能力，再沿既有具名创建流程建立新网关并加载原服务页面。此方案不维持后台代理，不影响电脑上 DEV 服务。

当前 Codex Host 的预览控制只有 POST/DELETE，没有状态 GET；EasyWork 仅使用它实际开放的对应能力，不推定存在 status。已有引擎的 `revoke` 在 create 尚未进入 receipts 时返回 404，而 create 随后可能完成；404 不能证明原创建已结束。客户端必须保留并校验关闭结果，不能继续吞掉该结果后直接开放新建。

| 本次原预览状态         | BG3 必须实施的行为                                                                                        | 当前及旧 Host 的退出条件                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 创建请求尚未结束       | 原有创建由页面 session 持有，保留原 UUID/意图；后台停止页面发布，等待原请求的有界结果，成功后按同 ID 关闭 | 原关闭 confirmed 后才可继续；晚到 create 不重新显示页面                                                       |
| 创建与租约已经确认     | 停网关并按原完整目标/Thread/ID 关闭；保留页面                                                             | 原关闭成功可显示继续；明确错误显示原因                                                                        |
| 关闭响应未知           | 保留原 ID 和暂停页；仅按现有已证实幂等的同 ID DELETE 契约重试关闭，不能以 POST 冒充查询                   | 成功确认后才继续；404/断网仍属未确认                                                                          |
| 创建已经超时或无法核实 | 不重发 POST、不换 ID 创建、不调用不存在的 status                                                          | 八秒结束界面等待，显示“上次预览状态未确认”、结束等待/退出和按能力重试核对；原上下文保留，不把该分支记为已恢复 |

上述限制也适用于当前 Host，不仅是旧端。BG3 的必交付是正常已确认租约的暂停/继续，以及未知分支有界、安全退出；不承诺当前无查询能力时所有未知状态都能继续。界面退出不表示电脑上的原创建已取消，不能仅按客户端经过的三十分钟推定晚到创建已到期。切换目标、授权变化、服务消失或能力不足时保留明确错误和退出入口，不复用旧票据。

若后续要消除无查询能力的兼容限制，另在原预览引擎与既有 POST/DELETE 上设计独立协商的具名状态和 pending-close/tombstone 语义：关闭成功必须阻止 creating 及晚到同 ID 创建再生效，各 await 返回后重检同一完整目标与关闭标记；不新增通用 RPC 或第二套账本。该增强不属于本次 BG1–BG3 的完成条件，不要求已部署 Host 升级；未经契约与兼容审核不得宣告具备此能力。

首期只保留内存中的来源、服务、页面相对导航与用户主动继续入口；不增加跨启动网页会话迁移，不承诺恢复表单和脚本内存。敏感 URL、票据与凭据不写日志或公开报告；保留原系统浏览器/外部打开行为。Android 预览尚未具备的部分保持原独立计划，不为本次修复复制新页面。

## 2026-11-24 最终补修：旧 writer 之后的阅读恢复

真实双端新→旧→新循环已证明：旧端保存普通 metadata/history 会删除新可选分页和视口字段，并用 latest 页覆盖早页。上面的可选字段方案只能覆盖新端冷启动，不能满足回退后再升级的阅读保全。本节取代该有限方案的跨版本部分；普通 wire、草稿、附件、不可变输入和回执格式保持原契约。

此补修已由 `gpt-6-astra / ultra` 独立审核，主会话核对官方 turn_context 的实际模型与档位。审查原文 SHA-256 为 `36df8ab13b4babc4ab9a634d567e5dff71b592c17160f6a3bf5b07c0acd81c6b`。最终采用以下有界方案；审查通过不等于新实现或验收通过，当前结果仍只回填原 LIFE01 台账及双端功能清单。

1. **保留实际 reader，验证连接连续性。** iOS 正常 state 保存现有 `readingClient` 实际产生的 `readingScopeId`，不另存基础 Client 的 `readingTarget`；Android 保留已有 readerId，普通 EasyWork 的旧 nil-reader 在成功验证连接后或正常恢复期间初始化并持久化真实 readerId。必须先检查磁盘原 carrier，再给旧 nil 字段补值。连接不存在、target/reader 不同或 carrier 丢失时，先串行失效原恢复入口并读回成功；失败则不盖章、不自动恢复。旧 remove/re-add 或重建 Client 丢字段按失效处理，不能仅凭相同 target 复活。reader 本身不构成实时阅读或控制证明。
2. **独立加密阅读家族。** Android 使用当前 NativeSessionStorage 的 namespace 与持久 migration generation；iOS 使用当前 History-v1 下 ReadingRecovery-v1 的 namespace 子目录，避免旧普通页清理器删除。index 和独立 UUID body 同时绑定完整 target、cache key、reader、namespace、schema、消息数、字节与 SHA-256；index 另存 paging/viewport，body 仅存完整自洽消息。禁止保存 runtime、fresh、控制许可、输入、凭据或回执。Codex 账号字段继续按既有非绑定规则比较。
3. **同队列发布及失效。** body、index、viewport、删除和 GC 共用串行 lane；捕获不可变候选和 owner/content epoch，排队前、执行时、发布前核对。先登记单份 staging，写 body 并读回验证，再原子替换小 index 并读回，最后删除精确旧 body。启动只处理 index 明确引用的 staging/garbage，不扫描“最大快照”复活。未知 schema、损坏或超预算保留原文件并停止自动替换，向用户报告。每个 key 只有一个 current，替换中最多一个 staging 和待清旧 body；不积累所有代次。
4. **限定写入量。** 成功加载早页、首次非 follow 阅读落稳、受保护内容在稳定退出前需要保全时建立完整 body。普通流式 batch 继续原正常 cache，仅标记内容变化。已有 body 覆盖当前真实 timeline compound anchor 时，滚动落稳只发布去重的小 index，不重新编码 body；旧回调不能携带旧 index 覆盖新快照。先完成快照再认为位置 durable。单 body 上限 32 MiB、50,000 条消息，index 上限 256 KiB、128 个 target，已发布 body 总预算 128 MiB；超限不截掉早期前缀。暂存/待清旧代的额外容量在测试中单列核对。
5. **iOS 不向旧普通页借 revision。** 普通 SessionHistoryPage 无 window/revision，只能先按原路径读取。companion 经完整校验后作为一整份 cached reading 候选显示，不能与普通页直接拼接，也不能在未核验时覆盖普通源。发 earlier GET 前，必须有真实远端页通过共同 HistoryCacheRecovery 的同目标、同模式、有效相同窗口 revision 与正重叠证明；否则不使用旧 cursor。mismatch/no-overlap 取消自动恢复与旧视口，保留原文件直到精确失效/清理，不开放控制。
6. **owner 能力先于 I/O。** Android readOnly/inspection/existingOwned/严格 migration 等未授权家族直接跳过；iOS R2 或明确禁用新增 family 的受限 writer 同样跳过。检查在 enqueue、AtomicFile 修复、目录创建、开 key、读取和 GC 之前，不扩 owner 允许列表、不从旁路写入。普通产品已有 namespace/key 不因此被误判为只读。state carrier 成功后才进入 iOS historyQueue，禁止反向等待 stateQueue；remove/replace/migration 在排队前使旧 token 失效。

T07/T12 增加以下退出断言，两端分别留真实原生证据：

- 全新 profile 新→旧→新→旧→新，核早页顺序、耗尽 cursor、revision、anchor/offset/messageLimit/follow、授权、草稿与附件字节，以及原未知操作的完整不可变意图；模型写入为零。旧 source 变体与正式已发布二进制分开登记。
- 旧 remove→add 同 target、旧编辑丢 carrier、新端删除及迁移后的晚到 viewport/body 均不得复活旧入口；Android 覆盖已有 Codex reader 与 EasyWork 原 nil-reader，证明未从缓存获得阅读/控制授权。
- body 前后、index 发布前后的故障只能恢复旧或新完整快照，不能混代或删除唯一 good。注入异常、磁盘构造和真实进程中断分列，不冒称掉电耐久。
- 错 target/namespace/reader、revision 不同、无重叠、未知 schema、截断/hash 错误均失败封闭。iOS 无 revision 普通源不得被套用 companion revision。
- 受限模式新增 family、目录、key 与 GC 零变化；普通模式确实建立恢复保护。长流与高频滚动的 body 次数对应稳定 checkpoint，index 去重，代次及字节有界。辅助 native/fixture 检查不代替真实升级循环。

### Android 既有资料导出兼容补充

F55 是已开放的正常设置入口，不属于暂停的 A6。它与旧端导入器都严格校验 metadata 和 root 记录图；直接在 root 增加 family 或给 portable metadata 添加 paging/viewport，会使原导出失败。最终采用以下布局与纯导出适配，取代本轮早期 root-family 试验布局：

- Android 使用 `noBackupFilesDir/ReadingRecovery-v1/<namespace-generation-hash>/` 独立物理目录；仍由当前 NativeSessionStorage 的实际 key、逻辑 namespace、持久 generation、snapshot 队列与 owner/epoch 管理，认证记录名含 namespace/generation。目录不冒充 history part 或 migration generation，不进入旧 root inventory。受限能力检查先于路径、key、AtomicFile、目录或清理。普通 metadata 不再写两个新字段，保留兼容读取；分页和视口由独立 index 保存。
- 新版 F55 在同一 snapshot/ioLock 与 generation 捕获区读取普通记录及独立 family，校验完整 target、reader、namespace、hash、计数、消息内容和预算，只生成旧版已认识的 history v1。普通页必须是 body 中同 ID、同完整内容、同顺序的子集，窗口模式和有效 revision 一致；无法证明时整体导出失败，保留两份源，不拼接猜测，不丢弃普通页独有新消息。paging 只取本 body 绑定的 index；runtime、fresh/control 及 viewport 不进入旧 portable 格式。两个新 metadata 字段校验后从投影移除，不扩大旧闭合允许列表。
- 保持原导出单记录 8 MiB 等预算；32 MiB 阅读 body 不代表同大小导出已支持。超限明确失败并保留原件，不扩大 A6 或新增通用迁移格式。投影不修改源文件、原意图、附件、凭据和回执。
