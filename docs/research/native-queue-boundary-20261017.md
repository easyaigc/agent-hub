# 原生队列边界与验收范围（2026-10-17）

需求为 Host 排队输入进入桌面可见队列，手机与电脑同步，手机可立即执行，且同一输入只执行一次。EasyWork 可修改其原生 Host 与界面；官方 Codex 需要依赖实际提供的集成边界。

## 早期严格并发门槛下的本机实测

环境为 macOS，官方桌面版本 `26.1013.40934`、build `20770`。仅使用专用零 Turn 会话和无文件副作用的模型等待任务。官方安装与历史均未修改，原桌面独占模型执行。

| 边界                                 | 本次观察                                                | 结论                                           |
| ------------------------------------ | ------------------------------------------------------- | ---------------------------------------------- |
| 持久服务器队列 add/list              | 元数据连接可添加并读取输入；原桌面任务结束后能执行它    | 不证明桌面原生界面已显示，也不证明可以安全提升 |
| 原 owner remove-queued-message       | 以服务器项 ID 和原消息 ID 分别摘取，均返回 removed=null | 不能安全把该后台项转为原生立即执行             |
| 相同 clientUserMessageId 两次 steer  | 原 owner 接受为两个不同 steeringUserMessage             | 消息 ID 不是上游去重保障                       |
| follower-set-queued-follow-ups-state | 接收整条线程的队列数组，无条件追加或版本比较            | 陈旧快照可能丢失新项或复活已消费项，生产不使用 |
| 桌面视觉核对                         | Computer Use 明确拒绝操作 Codex 应用                    | 未验收，不改用其他界面通道绕过拒绝             |

私有原始证据位于忽略目录 `.local/native-queue-research`：`afaa1be3-85bb-435e-9a6d-d0433c240ba8` 记录服务器排队后自动执行；`2170bc04-d263-476d-8c0d-0120f3fee937`、`9d039d88-51a1-48ad-a1e6-93593c4a4086` 记录两种摘取 ID；`c3c2f5f5-9e5e-4781-bc5e-766148fa27ff` 记录同 ID 双重追加。公开文档不包含真实正文、凭据或机器本地绝对路径。

早期原生模拟器场景通过过服务器删除后再追加的顺序路径，但后续并发研究发现上述去重边界不成立。该早期通过保留为研究证据，不能作为当前生产实现或完整原生队列的通过证明。该阶段探索代码曾暂时移出生产源码；下方记录用户确认延迟同步后的实现。

## 用户确认后的实现

用户接受双端状态在一定时间内同步，不再要求手机与电脑同时操作时的严格原子保证。当前实现使用独立的 queue 元数据白名单，只允许 initialize、add、list、delete，不允许恢复或启动模型 Turn；执行仍交给原桌面 owner。Host 提交原生队列项后不再用自身 FIFO 自动执行。手机取消或提升先落盘动作，再按原生项 ID 删除；删除成功后才调用原 owner 的 steer／next-turn。删除失败、结果未知、任务变化及同项重复动作均保留核对路径，不自动复制或重发输入。

事件轮询期间每秒刷新原生队列，连续读取间隔至少 750 ms；Host 写操作的前后代次使旧列表不能覆盖新状态。桌面移除原项后手机隐藏该项，并结合原 owner 输入证据更新回执。入队时与桌面不同的生成设置明确拒绝，避免通过只接受 input 的原生队列静默丢弃选择。原生方法不支持时保留 Host FIFO。该同步方式仍存在双端同时操作的竞态，不宣称跨端严格只执行一次；Host 内部同项去重、持久边界与未知结果不重放保持有效。

本机还以只读方式核对当前安装包：原生队列管理器监听 `thread/queue/changed`，通过 `thread/queue/list` 重读，并将外部输入转换为 QueuedMessageList 的消息模型；安装文件未修改。这是界面绑定代码证据，不等同于屏幕视觉验收。Computer Use 对官方 Codex 的拒绝保持有效，未改用其他界面通道绕过。

原生接口、原 owner、真实模型与原生 iOS 的新一轮验证单独留证；上方旧的严格并发结论和失败观察保留为历史边界。

## 验收入口

- Codex：`pnpm build` 后使用 `node scripts/codex-queue-desktop-ios-acceptance.mjs`，指定专用 `IOS_SIMULATOR_ID`。报告分别记录原生队列 API、电脑侧删除向手机同步、手机提升、自然消费、原 owner 唯一输入和视觉未验收范围。
- EasyWork：使用其仓库要求的 Bun 执行 `scripts/easywork-receive-desktop-ios-acceptance.mjs --easywork-root <checkout> --device <dedicated-simulator> --native-queue`。真实隔离 Electron、原生 iOS、模型任务及桌面独立 DOM/截图分别核对，局域网与本地中继分别留证。
- 编译、类型检查、协议摘要检查和 fixture 是辅助证据。Windows、实体手机、公网中继及跨来源全局 FIFO 不在本次本机 DEV 通过范围内。
