# Positive pairing commit boundary: synthetic native preparation

The earlier pairing fixture deliberately returned503 for every runtime call. This stage
adds a separate bounded synthetic issuer/desktop fixture; the earlier fixture and40
prepared methods stay frozen. No original Desktop, actual issuer, Host, real model, other
computer or independent EasyWork checkout is contacted or represented as verified.

The new loopback HTTP service reuses the existing independent EWDAP claim/delivery and
DPoP verifier. Every relay operation authenticates the original access token, P-256 proof,
HTTP URI/verb/body and unique jti. Its independent RFC7748/AES-GCM codec checks full binding,
sender/recipient/session/sequence and authenticated protocol target. It supports only
runtime/context({}, connected target with workspace:read), project/list({}) and
thread/list({limit:100}). Lists are empty; no history, model, command/status, submit, proxy,
filesystem, arbitrary method or external forwarding is available. The first thread/list
response is withheld until one explicit named release-read(ok/error). Invalid protocol
or crypto fails; nothing is forwarded. No refresh/revoke route is exposed in this stage.

Start the separate fixture using node fixture.mjs --start <new-private-directory> only
under the parent's lease. Two fresh127.0.0.1 ports are emitted in config.json; reverse the
exact authOrigin/controlOrigin ports for a leased emulator/phone. Native arguments are
p8CommitConfig and p8CommitBuild(sourceSha256/appSha256/runnerSha256). They are separate
from the existing pairing UI sidecar arguments and namespaces. Config binds the fixture
source graph, public crypto vector, instance, process and start time. The original eight Node checks
invoke the pure dispatcher/codec only. A separately labelled CLI startup check now
starts its own bounded synthetic loopback process, verifies health/config/source graph,
then closes it and checks both ports; it creates no case or Android/native proof.

NativeEasyWorkPositiveCommitTest has four independent cases. Two tap the actual Provider
form button and observe its actual saved callback: success activates the candidate after
the final read and completes once; disposing the original form at that final read leaves
its callback absent and rolls back only its candidate. Two explicitly labelled bounded
NonCancellable Session probes exercise final-read failure alone and combined with a newer
original draft. These are actual mounted owners/Session/disk/relay, not copied submit UI.
Grant/claim bytes, immutable unknown operation bytes and default mobile-v1 namespaces must
remain unchanged. The success case records that the exact hashed candidate file existed
while metadata clients were empty, then validates the actual final client credential ref
and complete target, switches back to the original draft, and checks fresh same-process
storage/Session restore separately. No raw credentials, original secrets or screenshots
are output. Filename-only enumeration is bounded to this freshly owned test namespace;
it is not a production restore scanner or a migration/ref inventory API.

NativeEasyWorkCommitColdTest is a separately leased writer/reader pair. Select one exact
method at a time with p8CommitColdPhase(writer/reader) and the same UUID p8CommitColdCaseId.
The writer publishes files/acceptance/p8-positive-commit/<UUID>/writer-ready.json after a
real candidate write while the last read remains held and metadata has no client ref.
The parent must preserve that proof, force-stop the exact acceptance target within18s,
verify termination, and start the reader in a new target PID. An elapsed hold/completed
writer is a failed attempt; writer JUnit completion is not expected or counted as pass.
The reader also requires p8CommitWriterProof with the exact writer JSON, same packages,
source/config/sidecar instance and original storage + DPoP keys. It never begins a case,
creates an identity/key/grant or retries a claim. Fresh production restore must leave the
unreferenced candidate/grant/claim/journal/metadata bytes unchanged, restore no candidate
client and emit no extra claim or named protocol request. Only the reader ends this case.
A dead writer thread is never reconstructed. This pair is prepared, not executed here.

There are no production/shared source changes in this stage. Parent adopted phase5

## Node-only startup correction

The first source-graph entry is now a URL object, matching the other three entries.
Passing import.meta.url as a string to readFile treated file:/// as a filesystem path
and failed before listening or creating any case. The parent failure is preserved.

fixture-startup.test.mjs starts the actual --start CLI from an isolated copy of the
four exact sources plus public vector, under a path containing spaces, percent and
Unicode characters. Five-second startup, 1.5-second health/auth and three-second close
bounds keep failure handling finite. It checks emitted config against disk, exact four
source hashes/canonical graph, public vector, child PID and two distinct loopback ports;
health must match and an unauthenticated auth read must be refused. SIGTERM must exit0
and both ports must refuse connections. Only config.json may exist: zero cases/claims,
zero reverse rules, zero submit/model input. The owned temporary copy is removed.

The original URL-string implementation is a negative control: the new real startup
check fails with ENOENT before health. With the URL-object fix, all15 Node checks pass:
eight unchanged positive pure checks, six unchanged original pairing checks and this
one actual CLI lifecycle check. This is Node-only auxiliary evidence. Android source,
app/runner hashes, actual native leases and parent tree remain untouched. Parent binds
the new sourceGraph independently; changing this helper does not require an APK build.
