# P9 notification settings recovery checkpoint

This checkpoint follows F53 and only changes the ordinary Codex notification root settings, its async system test path, and owned UI fixtures. It leaves notification storage v1, sound storage v1, event claims, registration, migration and shared navigation unchanged.

The root page no longer reads encrypted preferences during composition or a lifecycle callback. Initial/retry/resume reads and encrypted channel-title lookups run on IO. System permission/channel queries and UI updates run on Main. A page generation is invalidated on pause, replacement and disposal; late reads and tests cannot update the replacement page or post its test notice. Updates compare the loaded revision inside the existing storage transaction. Already completed atomic writes remain persisted even if the page is later disposed.

Unreadable, malformed and future-version preferences produce an unavailable state with retry. The original bytes remain intact. There is no writable default-off form on error. A failed refresh removes the previously successful controls; a pending refresh retains successful values with editing disabled. Retry only reads; the user can repair the existing record through the separately owned recovery workflow and retry without resetting it here.

`NativeChatNotificationSettingsUiTest` adds four compiled scenarios: malformed record, future version, failed resume after a successful load, and a replaced page rejecting an old blocked encrypted read. The first three assert preserved bytes and a repaired retry. `NativeChatNotificationSoundUiTest` retains its four F53 assertions while adopting `NativeTestForeground`, `createAndroidComposeRule<MainActivity>`, `OwnedControlAcceptance`, the default eleven-field preservation check, an isolated namespace and a 90-second outer timeout. The fixture follows the owned Activity pattern introduced for the voice tests; a prior empty-Activity timeout is not evidence that these sound assertions failed.

Both UI suites mount the production page in the real Activity window. They never select a real host, invoke a model, show a permission prompt, choose an external file, play audio or post a test notification. The recovery suite uses a page-local lifecycle to exercise resume without restarting the default session's foreground behavior. The native scenarios are compiled auxiliary coverage until the coordinator executes them under its device lease.

App and instrumentation APK compilation passed. The central parity/localization owner must merge the accompanying deltas and run its checks. No physical-device or real DEV pass is claimed. The F53 child sound page still has the synchronous storage paths documented in its earlier checkpoint; this root recovery change does not claim those are converted.
