| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |

| 执行 | 待执行；正在执行；有明确阻塞；暂停/暂缓；共用维护；范围外；关闭                                                                                                                                                        | 负责人、具体动作/开始时点、真实阻塞与下一步。历史in-progress不能解释成现在有任务运行       |

状态码的精确集合在 status.json 的 `stateDefinitions`；中文显示由同一集合生成。父功能可以“已实现+历史部分通过+部署未核实+待执行”，这是正常组合。**不能再用单个“开放”“进行中”代替四个维度。**

对开发与验收特别区分：

- F13/F24/F45/F75 的部分实现判断保留其历史范围；未取得最新全量审查时不得冒称发现了新的具体代码缺陷。
- 历史限定闭合父项在审查前标“待匹配”；审查完成但当前证据链不成立时标“历史限定通过；本次匹配未成立”，下一步明确补证或重验。两者均不计当前通过。没有重新执行不等于此前从未测试。
- F75和A6暂停保持；免重复手机UI验收不等于自动通过。

## 更新流程

每次任务开始前读取本目录入口和 status.json，核当前 `revision`、对应F/EW/AC、范围、原操作、暂停项及证据依赖。计划文档本身不触发业务提交、自动重放或部署。

1. **先记事实。** 将本次源提交/WIP摘要、契约、构建/部署包、准确目标私有引用和原始结果留证。失败、跳过、环境错误及未知结果分开，原始证据不可改写。
2. **先更新唯一台账。** 修改对应 `features[].development/acceptance/delivery/execution`、具体 `openItems`、`workPackages`、`acceptanceScenarios`；每条更新 `updatedAt`、负责人/角色、下一步与证据引用。只改变被证据支持的范围，不整组补签。
3. **登记证据。** `evidenceRegistry`记录种类、准确源、路径、范围。当前真实通过使用 `kind=real-dev`；匹配复用使用 `kind=exact-match-review`，必须记录原证据、当前依赖/指纹比较及复用理由。`sourceCommit`、`packageSha256`、`environment`、`scope`、`path`、`sha256`均必填；引用ID放在对应 `currentEvidence`。辅助检查只记录辅助，不能用来关闭真实功能。
4. **登记状态变化。** `revision`递增，`changeLog`追加实际日期、变化功能/子项、旧→新状态、依据、失败/阻塞和下一步；新增输入/模型与操作ID保持原口径，不将资料迁移计作运行。
5. **生成与检查。** 运行下面命令，生成总表和75项清单，再执行校验。不要手改两份投影；initial/historical字段只保留首轮快照，不作为新汇总来源。
6. **同步规范与交付。** 如果功能/协议/UI发生变化，按AGENTS维护原产品manifest、设计和验收规范；这些文档的当前进度只链接本计划。PR/交付说明引用本计划及本次证据，不能另起一份当前完成清单。

在仓库根目录运行：

```sh
python3 docs/plans/ios-easywork-alignment-20261112/render_status.py --write
python3 docs/plans/ios-easywork-alignment-20261112/render_status.py --check
```

校验覆盖75个唯一F ID、工作包/场景/事项引用、合法状态、通过所需证据、父项关闭条件、场景定义一致性和生成文档未漂移。它只校验台账一致性，**不执行或证明产品验收**。

`sourceCommit` 只填写实际基准提交；未提交候选另记 `sourceTree` 及补丁/输入摘要。Git tree 只标识文件内容，不能写作合入提交。`currentSourcePins` 生成当前源码与运行边界表，按实际源、构建包和执行记录更新；不同候选的编译或检查结果不能自动互换。

同时有多个开发现场时，每个现场先保存追加证据和变更条目；合并依据具体F/AC及原操作，不以最后写入覆盖另一条事实。不另指定平行“权威计划”。同一字段结论冲突时保留双方证据，将该项标为待核/阻塞后解决；解决前不宣布完成。

## 数量与完成定义

- F01–F75 是父功能分母；EW是工作包，AC是场景组，DEV/REV/ENV等是子事项，不能相加成总功能数。
- 当前统计从 `features` 的四维状态计算。`initialAuditCounts`、`initialScopeStatus`、`historicalEvidence`只作历史快照，禁止拿它们当实时数量。
- “当前按范围关闭”要求开发范围完整且有真实本次或匹配验收证据；交付完成另须准确目标部署证据。上游不支持、暂停、未验、失败不能靠删行或隐藏入口从分母消失。
- scope变更必须有明确依据及历史保留。例如首次把F72拆出对接、F31大文件重新开放，不能以新口径推翻原小文件通过。
- 远端访问未恢复、桌面源码pin仅来自归档等事实边界保留。采用缓存源可以继续本地工作，但不对外写“已核对远端最新”。

## 2026-11-12 后续执行与模拟器规则

用户已授权使用 Host 分多个专用对话，以 `gpt-6.1-sol / xhigh` 并行补齐缺口、验收收尾并继续后续计划。每个任务登记实际操作回执、对话与配置核对引用；协调模型轮和产品验收业务轮分别计数，不能用请求参数代替实际模型配置核对。共享主台账仅由协调会话写入，其他会话输出带来源/摘要的证据和状态增量。

不涉及手机真实环境的适用断言，原生 iOS 模拟器可作为正式验收环境。模拟器完成的原生页面、协议、文件、持久化、进程重启及恢复断言可以关闭，不附加等待真机。混合场景按 `acceptanceScenarios[].environmentPolicy` 拆分：手机相机、真实声学采集、手机蜂窝/设备 VPN、实体通知到达等断言另验；其缺失只阻塞对应子项。真实 Electron、模型/原始资源和独立核对要求按场景保留。

当前通过证据须明确 `mobileEnvironment`（`simulator`、`physical` 或 `not-required`）和实际断言。`kind=auxiliary-check` 不能关闭功能或场景。含实体子项的场景不能仅凭模拟器证据整组关闭，可在 `assertionResults` 保留已通过子项。设备权限/构建/连接错误属于环境阻塞，不能写成产品通过或产品功能失败。

每轮结束先保存来源摘要、补丁/提交、运行包、原始结果及 SHA-256，回填台账并验证，再清理自有资源。未合并或未验收候选、未知操作及其附件/回执、原始失败证据均保留。分支删除须证明变更已经集成且没有独有提交；本轮未创建分支就记录不适用，不删除其他任务分支。具体顺序见 [执行规则](execution.md)。
