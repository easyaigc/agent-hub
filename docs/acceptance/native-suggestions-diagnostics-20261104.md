## 现场与结论

本轮只排查本机 Codex／Host，不联系其他电脑，不重放模型输入。旧 producer 的首次停止事件未被持久化，当前进程已经由正常桌面启动替换，不能事后补签首次错误码或精确故障时刻。

现场发现一个独立、确定的停止触发条件：旧 producer 只接受最多 16 个准确桌面 PID 的日志，却将零字节 worker 日志也计入。原桌面实例共有 54 个匹配文件；故障前一天／当天的实际扫描范围有 45 个，其中 42 个为空，仅 3 个有正文。第 17 个匹配文件是一个空 worker 日志。旧 scan 会抛出 `native_bridge_log_file_limit`，随后 close 停止 timer；原桌面字节转发仍继续，但同一 wrapper 不会重新建立采集器，因此新建议持续漏采。桌面重新启动后 PID 改变，文件集合缩小，暂时恢复并非修复。

至少七条晚间来源具有准确 Thread／Turn 的原桌面 `suppressed=false` 决定，但精简存储只有原始 Trace 的 cancelled 状态，证明不能将这段缺失归因为 Codex 一直没生成建议。原始 Trace 内部取消与原桌面稍后收到的完整 sample 结果是不同证据。重开后的原生 sample 结果已保存并读回；该旧程序的恢复不算本次修复正式验收。

文件形状、出生时间与摘要、七条关联证据及原 HTTP 结果保存在本机私有任务记录，不提交机器路径、实际源会话、建议正文或凭据。文件出生时间只能证明可复现的容量条件，不能排除首次停止更早由其他守卫触发。

## 源码修复与日志

- 空且未跟踪的普通日志不占 16 个内容候选名额，每次扫描重新确认，后来增长的文件从零读取。仍检查准确 PID、普通文件及单链接；已有 cursor 的文件即使变空也保留在验证集合，截断仍失败。
- 原目录项、非空文件、单 tick 文件数／字节预算、原 owner／来源以及六秒租期保持；不回退旧建议，不触发预测或自动发送。
- macOS producer 保存 starting/listening、停止／关闭与精简建议状态，保留底层固定 capture 错误码、阶段、PID／启动时间／epoch、实现摘要、心跳年龄、tick 间隔、阶段耗时、候选／空文件／目录项计数及来源 Thread／Turn／request ID。窗口不按每次 heartbeat 写日志。
- 日志位于私有 Trace 的目标摘要目录下 `native-diagnostics/producer.jsonl`，最多当前及两份轮转，各约 128 KiB。目录 0700、文件 0600，拒绝符号链接／硬链接；字段白名单不保存正文、凭据、路径、任意异常正文或堆栈。诊断失败不改变结果或原始字节转发。
- Windows 正式 producer 本轮不启用额外同步日志，保留原 status 通道，避免 ACL helper 消耗既定采集预算。共享采集选择规则有同一源码修复，不据此声明 Windows 已部署或通过。
