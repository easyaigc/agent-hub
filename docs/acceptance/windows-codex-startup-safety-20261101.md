# Windows Codex 启动安全修复

后续目标（2026-11-01）：人类要求保留建议采集，先完成独立于原桌面启动的可行性研究，再开发并在 Windows 验证。下文是前一阶段防复发修复的辅助结果，不能作为完整采集交付。当前研究、数据缺口及实施门槛见[独立采集研究](../research/windows-suggestion-independent.md)。

## 现场与因果边界

用户提供的现场报告：用户级 `CODEX_CLI_PATH` 指向 Agent Hub 的 `launcher.exe`，进程链已到固定 Node 入口，但没有实际 Codex CLI，桌面初始化一直等待；移除变量后桌面恢复。这是用户提供的 Windows 证据，本轮未直接取得原机日志或进程快照。

仓库可核对的原因是建议采集安装器把附加功能放进了原桌面的必经启动路径：`windows-native-suggestions-environment.mjs` 写入 HKCU Environment，随后 C# launcher 启动 Node；Node 在启动真实 CLI 前还要加载 Adapter 模块、检查私有权限并解析当前桌面安装。任一步失败或阻塞都可能让原桌面无法初始化。重装应用不会自动清除这个用户变量。

`desktop-stdio-bridge.ts` 中的 `env: { ...process.env, CODEX_CLI_PATH: ... }` 只设置该次子进程环境，不是持久化注册表入口。`environment.json` 的源码／配置摘要主要用于安装器核对；已有 Node 进程意味着 C# 启动 Node 前的检查已经通过，不能据此认定是 shim 自校验或应用升级唯一造成。本轮尚未唯一确定原机 Node 启动前置阶段的具体失败点，也没有端口或网络导致失败的证据。

## 本次实现

Windows 全局建议采集垫片安装暂停，防止它再次阻断原桌面启动。恢复完整被动采集需另行设计：原 Codex 启动不能依赖 Node、采集配置、Trace 目录、Host、观察 Worker 或上游协议识别；采集失败不得重放输入或另启执行器。当前保留的旧 launcher 源码不代表已满足此条件。

- `install` 兼容入口只执行旧覆盖恢复；新安装不编译垫片、不创建状态、不注册变量，报告 `WINDOWS_NATIVE_INSTALLATION_SUSPENDED` 并非零退出，不能作为安装成功。
- `disable` 只读取受保护的旧安装清单，核对产品、目录、版本和原空覆盖记录；当前 HKCU 仍是该安装记录的 `launcher.exe` 时才删除。执行边界再次检查路径、清单和当前值；低层注册表操作也拒绝写入非空覆盖。
- 注册表使用普通 Windows API；删除前重复核对只能拒绝检查时已经出现的值变化，读取与删除不是原子 compare-and-delete，不能保证消除两者之间极窄的并发写入窗口。本轮未以 fixture 声称原子 CAS，也未引入未验证的注册表事务机制。
- 不读取损坏的 `config.json`，不要求当前源码摘要一致，不需要旧 Node／CLI／Trace 路径存在。缺少或不可信清单时保留现场并明确拒绝，不猜测归属。
- 已经手动删除的值不会再写回。其他用户覆盖、机器级覆盖、当前进程环境、Host 身份、密钥、服务配置及旧二进制／配置保留。注册表删除与私有标记保存中断后可重复恢复，不重复设置覆盖。
- 状态始终区分未来安装、遗留 HKCU 覆盖与当前继承环境；不自动退出、重启桌面，不宣称当前原进程已恢复。保留旧文件用于已继承旧环境的进程及审计，不能改名令这些进程失去启动入口。

恢复命令在目标原生 Windows、使用统一包原有 Node 执行：

```powershell
node scripts/windows-native-suggestions-environment.mjs disable
node scripts/windows-native-suggestions-environment.mjs status
```

自定义安装目录时两条命令都加 `--state <原私有安装目录>`，该目录包含原 `environment.json`，不是 Trace 子目录。命令输出不含密钥。若当前进程仍继承旧覆盖，保存工作后经已刷新环境的正常图标启动另行核对；不强退或为验证重放业务输入。
