# P7 进程冷恢复档案

## P7-1c 系统接收与原草稿跨进程

对照iOS本地收件箱/准确草稿固定ID与持久确认语义，产品程序保持P7-1b不变。新增只在acceptance Gradle配置出现的SDK观察APK，无界面/依赖/Host权限，instrumentation目标仅合成来源测试APK；来源UID与接收App独立，不在接收App中启动测试进程冒充系统冷唤起。安装仍核准确APK包名、SHA及授权设备，不卸载/清数据。

API26/API37四段SDK观察通过：先核接收App无PID，再由独立来源发送2个合成文件，真实系统冷唤起；稍后关闭后停止App，再仅MAIN冷重开，同批原名保留，来源未重启，接收PID不同。随后另起原生进程解密核名字/顺序/字节和未绑定状态，只清理当前nonce批次，原批次不变。没有点添加/发送；默认App后台读取/阅读确认未代理，不宣称该段所有网络写入为零。早期截图捕获展开动画首帧，保留为过渡观察；最终两台自有模拟器临时关闭动画补验并逐项恢复原设置，不计完整动画矩阵。

三环境原草稿跨两次真实进程死亡通过：隔离命名空间绑定原目标/草稿代次，先仅导入2文件中的第1项并确认落盘，删除临时Provider原文件；新进程恢复原文/设置/第1文件，原生确认只补第2固定ID并消费；再换新PID恢复完整2文件原字节/ID/原草稿，收件箱无复活或重复。Host是稳定严格GET合成服务，不是原Electron冷恢复证明。手机新观察APK被系统拒装INSTALL_FAILED_USER_RESTRICTED，手机2段系统冷接收待验，不绕过权限；既有runner可执行的手机草稿4方法通过，两模拟器各5方法，共14，PID逐段不同。

当前另有三环境各16项存储/UI/独立接收回归，API26双倍字号与API37深色各7项，共62；合计76辅助JUnit方法、4独立SDK观察，分开计数。3实际原Electron目标/工具资源整例再次通过，仍是暖原目标具名GET及本地独立来源文件确认，无上传/新模型输入，原owner/Turns不变，不代替实际Host冷恢复或模型消费。累计219/P4 205不变，79份默认存储证明。
