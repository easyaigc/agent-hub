# External inbox inert archive v1

The Android source now implements the stream-only external-inbox extension below, on owner/writer IO closure `a795ee6` plus the strict Source51 reader prerequisite and Root Source53 private Activity factory. SDK/JVM results and exact source fingerprints are recorded separately. Root has adopted the exact increment while preserving F73 and the scoped runtimeContext hook; Root combined SDK, native execution, real Provider routing and real DEV remain pending. Other child scopes still refuse nonempty data; this is not full P7 completion.

## Closed portable schema

`external-inbox-archive-v1.schema.json` fixes the catalog shape. The root record is `migration-external-inbox-v1` with version 1 and 1–128 sorted unique archives. Each archive has a content ID and 0–512 sorted unique entries. Each entry records original logical name, text/binary kind, exact plaintext byte size and lowercase SHA-256. There are at most 1,022 entries across archives, a 1 MiB catalog, 8 MiB per text and 20 MiB per binary. Existing stream limits of 1,024 total records and 192 MiB total plaintext also apply. Limits reject complete sources without dropping records.

The archive ID is SHA-256 over UTF-8 `agent-hub/inert-external-inbox/v1` followed by NUL, then each sorted entry: four-byte big-endian length plus UTF-8 name, length plus UTF-8 kind, four-byte big-endian size, length plus ASCII content SHA-256. Aliases are `migration-external-inbox-text-v1:<archiveId>:<entryIndex>` or `migration-external-inbox-binary-v1:<archiveId>:<entryIndex>`, with canonical zero-based decimal index. The catalog owns the exact alias set. Unknown versions/fields, missing/extra aliases, duplicate IDs/names, wrong kind/size/hash and invalid original graphs reject. Same original content deduplicates across re-export; different index spelling is different content. An absent child adds no archive and stays absent; a present empty child has a zero-entry original.

## Exact source graph

The source index remains the original `external-inbox-index-v1` string, including whitespace, revision, batch IDs, sourceHash, receiving/failed/pending/consumed phase, ordered slots, exact optional CreationFile, old binding key/generation and historical maximum. V1 has a ten-file maximum; V2 explicitly carries five or ten. The new five-file intake policy does not reinterpret old ten-file evidence. Binding/sourceHash are encrypted audit data only.

Every source text and binary record is enumerated. Known indexed draft metadata, full modern payload, legacy inline bytes and optional validated thumbnail retain their original bytes. A receiving/failed/consumed manifest with missing metadata or a known full payload left by interrupted prepare/cleanup remains incomplete audit evidence; nothing is reconstructed into a ready file. Pending rows require complete valid metadata/payload. Null manifest cannot own payload/metadata/thumbnail. Unknown IDs/names, duplicate payload owners, mismatched manifests/bytes, malformed thumbnails, missing declared payload and unexplained orphan/sidecar state refuse export with originals retained.

## Ownership and strict reading

Main seals actual Session ingress before the first suspension and records its epoch. NativeExternalAttachments tracks all admitted receive, retry, add, discard, init-cleanup and refresh jobs until actual completion. A busy producer is refused without cancellation or ordinary pause/seal. Every public inbox store operation, including snapshot/payload paths that can recover or write a thumbnail, holds an independent kernel/local writer permit. The migration lease binds the actual root object, child namespace/generation, operation and sealed NativeExternalAttachments owner; caller callbacks do not supply this authority.

The source reader derives the exact existing child/key from the root generation. It never calls ordinary child creation, generates a key, performs AtomicFile recovery or weakens the default reader's child refusal. Absent/empty/nonempty/missing-key states differ. Owned private no-follow file descriptors, directory inventory, repeated fixed namespace sibling/sidecar checks, authenticated ciphertext hashes and generation checks stay valid through final stream publication. Unknown records, links, nested directories, unsettled backup/new sidecars and generation siblings refuse. Legacy provider buffering and all plaintext/ciphertext size bounds remain explicit.

A new Intent during acquisition invalidates the epoch and is queued once. After quiescence it invalidates the lease. Failure/export restores a fresh Session while transferring the exact idle source inbox object, avoiding a new startup cleanup on the original. Import to a fresh generation starts an empty active inbox; archived originals never become active rows. Raw voice exclusion and F73 admission remain intact.

## Destination behavior and checks

Candidate validation authenticates the full closed graph before atomic generation publication. `NativeMigrationInbox.read/text/copy` enumerate and retrieve authenticated inert originals. They return no InboxBatch, receivedSources, URI token, callback, current binding, retry/upload/cleanup authority or automatic active conversion. Same receipt recovery preserves later destination drafts and does not revive consumed input. New-PID enumeration/copy and re-export use the original candidate receipt without restaging.

`external-inbox-native-cases.json` records three JVM core cases and thirteen pending native selectors: eight storage/process roles and five actual Activity/controller cases. Owner cases use Root's debug-only, non-exported prelaunch subclass pattern; they do not warm normal Main or use NativeTestForeground. Existing Main/P9 owner/router material is refused. Run each owner selector in its own fresh acceptance process with an explicit UUID; the three cold roles deliberately reuse their one run/receipt across distinct PIDs. Private source and destination installation identities are checked before launch. These selectors are not real SAF or system routing evidence.

F71/F56 are the primary attachment and persistence features; preserved F33/F42/F58/F64 constraints remain exact bytes/identity, source preservation, complete inventory, no inherited authority and exact idempotence. UI and copy are unchanged, with no archive browser or local-copy action in this increment. iOS intake/migration does not implement this Android catalog or establish interoperability. Root owns central product/design/acceptance reconciliation; the adjacent parity delta records this source-only increment. A6 and task/project business remain paused.
