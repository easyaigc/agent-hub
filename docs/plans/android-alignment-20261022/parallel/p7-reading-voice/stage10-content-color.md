This is a fixture theme-environment defect. Production NativeSheetHost embeds NativeVoiceSettingsPage in ModalBottomSheet with containerColor=colors.surface. The installed Material3 implementation resolves the default contentColor with contentColorFor(containerColor); the default Text path reads LocalContentColor and merges it into its style. GroupCard draws colors.background without replacing that content color. The actual sheet therefore supplies the primary onSurface color to provider labels and the service title. The bounded fixture used only MaterialTheme plus background Boxes. Changing the Box background does not install the sheet's content color. Explicit onSurfaceVariant captions/buttons remained visible, while the inherited primary labels could remain black on a black card. The actual app sheet was not rendered in these failing viewport images; they do not prove a production sheet color failure.

The fixture now uses a Material3 Surface with the same surface container and onSurface content color before composing the unchanged production page. No production component, shared theme, string, storage or iOS file changes. The same environment is used by the existing question and retained-Activity scenes. This matches the sheet's content-color boundary; it still does not simulate the sheet dialog, system bars or insets.

New checks cover both provider labels and the primary service title in every language/theme case. Each uses the actual unmerged TextLayoutResult color, requires the production palette's onSurface value and at least 4.5 contrast against GroupCard's background, and checks complete Text bounds are inside the viewport/window. The same owned-window PixelCopy bitmap is then sampled only inside each Text rectangle, requiring a minimum count of expected foreground pixels. The RGB channel tolerance is 40/255 for native antialiasing/pressed ripple; the minimum is max(12, 0.2% of that text rectangle). Adjacent selected checkmarks and buttons cannot satisfy a different text rectangle. PNG and color/pixel diagnostics are saved before the color assertion aborts. This adds a rendering gate beyond semantics/layout existence; it is not a claim that automated pixel sampling replaces native image review.
