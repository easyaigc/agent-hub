## Narrow source delta

The observer now uses the pure `NaturalProcessVisibility.java` parser from its own examiner module. Every numeric `ps -A -n -o UID,PID,NAME` snapshot must contain the current observer's exact PID/UID and a distinct UID1000 process named `system_server`. UID/PID columns and complete rows are mandatory; numbers must be canonical/in range, PIDs unique, and the target set includes every row of the exact installed target UID regardless of process suffix. Header-only, missing/mismatched self, missing cross-UID witness, malformed/unterminated output or budget overflow refuses before a click. Names of the App/observer need not be untruncated in `ps`; their actual PID/UID establishes that join.

The earlier `dumpsys activity instrumentation` subcommand/header is not implemented by the checked AOSP dispatcher. The fixed supported AM command is **unfiltered global** `dumpsys activity processes`. Its active-instrumentation section is parsed separately; other process-state text cannot establish instrumentation absence. Each active record must have matching summary/component, sequential complete running-process rows, target ApplicationInfo UID and a complete arguments tail. The observer's exact component, own target package/UID and current running PID/UID label must be present and unfinished. The installed App target/UID is checked explicitly across the complete section; the examiner package prefix does not falsely count as the target. Unknown/missing/partial sections refuse. This does not use the restricted `ActivityManager.runningAppProcesses` API as a replacement for the full target UID `ps` set.

The known layout is grounded in AOSP's [ProcessList global dump](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/services/core/java/com/android/server/am/ProcessList.java) and [ActiveInstrumentation record](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/services/core/java/com/android/server/am/ActiveInstrumentation.java). An unsupported OS/OEM layout is a refusal, not an empty table. Source inspection does not prove that a particular device exposes these diagnostics.

## Live writer handoff without a second broadcast

The same fixed signature-protected custody Intent still has only `publication` and the original system-returned PendingIntent. It is now sent **once as an ordered broadcast**. Producer remains in its already-authorized execution while awaiting that original broadcast's result, under its existing overall selector timeout. The examiner's async receiver validates the original installed/lease/plan/token bindings, observes the original writer PID at the exact App UID in `ps`, and observes that writer in the active original target runner instrumentation record. It saves this positive custody witness before returning a fixed SHA-256 acknowledgement bound to lease, attempt, plan hash, UID and writer PID. Producer proof adds `writerVisibilityAcknowledged`; missing/negative/unknown acknowledgement fails, never resends or reposts.

The receiver releases the original custody latch and finishes that ordered result at handoff. The observer then uses its **same single fixed 30-second** post-custody emptiness loop, with the existing requirement for two complete empty target UID observations and absent target instrumentation. Producer exits normally after its existing final default-family scan/proof. No process is prestarted to manufacture visibility, killed or force-stopped to manufacture absence. No new post-exit acknowledgement, configurable grace, independent diagnostic deadline, deadline reset or wait extension is introduced. Positive writer visibility is evidence before exit, not authority to replay after an unknown outcome.
