# Shared owner hooks (contract, not applied code)

The exact ThreadReading full-file proposal and SHA pair are recorded in stage11-visible-notice-contract.md and the private delivery index. It adds NativeNoticeReadGuard to notice leases and calls its ifCurrent inside the existing lifecycle ifCurrent. No encryption or disk operation moves into the guard. The new public guard interface is in NativeNoticeVisibility.kt. Neither ThreadReading nor NativeReadingLedger is changed by this commit.

The remaining hooks are named interfaces and ordering requirements for the shared owners, not a fabricated whole-file patch. Their observed source hashes and these exact hook text hashes are supplied in the tree-outside shared-hook-proposals.json. A null full-target-file hash explicitly means no owner implementation was generated. Re-read active P9 changes before editing them.

**MobileSession / current frame producer.** Publish a stable `NativePanelNoticeVisibility?` from one selected frame bound to its validated original target/certificate. An eligible exact cached frame may be read offline; this never proves a live desktop connection. Its target/thread and renderEpoch capture the original full client/connection/certificate/selection/history owner; foreground/uncovered must include sidebar interaction settlement, not only selected-chat state. Its notices come from the current `phoneReading.ledger` projection after existing reconciliation. Use the existing P9 update path to refresh this metadata when an event arrives late. Do not add a second notification subscription or ledger. Loading encrypted notices must stay off the UI thread and late snapshots must pass the captured identity/epoch check before publication. Forget the binding on restore failure, background, target/connection change or departure.

**NativePhoneReadingStore / writer.** A named `visibleNotices(report, readerId, currentFrame)` entry should validate `report.visible`, original model, complete target/thread, render epoch and `report.proof.isCurrent()` for scheduling. It must then obtain `lifecycle.visibleNotices(report.target, report.threadId, setOf(report.notice.id), noticeGuard=report.proof)` using the proposed shared guard, and call the existing same-instance ledger.readVisible on the existing coroutine/background writer. Publish through the existing snapshot/failure/changed path. Recheck the current Session frame before taking a lease; the view guard is not a substitute for connection ownership. P9's existing event-level mayPresent reads the same ledger after this mutation.

**One lifecycle presentation.** At fresh selected-frame presentation, call `lifecycle.present(target, thread, currentLatestPosition, knownNoticeIds)`, preserving both the current body position and the known notice inventory. NativePhoneReadingStore.visible currently resets notices with its no-notice-argument present call. Replace that call with the current exact frame's notice inventory, clearing inventory on target/frame departure. This inventory is view metadata, not a new unread store. Keep geometry proof for notice IDs separate from the body-end proof. Notice leases have null position; body leases must not inherit arbitrary visible notice IDs. In particular, the old `visible()` path constructs a body Lease with all presented notices: the owner must ensure its body lease carries an empty notice-ID set after adding a notice inventory, or otherwise it would acknowledge offscreen notices. This is a required shared correction, not optional cleanup.

**AgentHubApp / actual surface caller.** Pass the stable nullable binding explicitly into ExecutionPanels. For inline tool cards, pass it into InlineToolApproval through the real message renderer; that separate call site is not wired by this commit. Default null remains inert. Closed async count rows and closed plan disclosures are not witnesses. Expanded async content acquires its native dialog's focus/lifecycle geometry; covered underlying content retracts. A message-rendered plan needs an explicit same-original plan/body witness in its expanded message path; the generic review prompt cannot stand in for it.

**NativeSheets / overlays.** Existing shared surface-visibility ownership must make uncovered false synchronously when drawer/sheet/cover interaction starts, and restore it only when the owning surface is current and settled. The helper detects native window focus loss/pause/detach and clipping, including visible-window/IME bounds, but cannot detect arbitrary same-window paint/alpha overlays. Do not declare every selected Activity uncovered. A parent owner may provide a separately scoped binding for an uncovered question dialog. No generic overlay API or remote UI command is introduced.

**Atomicity and locks.** The proposed lifecycle guard wraps only the existing ledger transaction's in-memory mutation. The ledger already loads and saves outside the lifecycle mutation closure; retain that ordering. View fence state changes release its monitor before invoking the report callback, so callbacks do not wait on the lifecycle lock while retaining the view lock. Close revokes even if a callback throws. A one-time `isCurrent()` check followed by async I/O is insufficient; use the guard. The native fixture bridge intentionally does not claim to implement this unapplied shared integration.
