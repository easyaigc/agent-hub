# Stage 4: voice defaults, service capability and recovery actions

Base `a0ec7825cab7193c55b340f66199b72516841cf3`. This independent stage touches ordinary voice/settings fragments only; question-answer voice is the next isolated stage. No MainActivity, Manifest, P9, migration implementation or central catalog/manifest change.

Actual iOS references are VoiceTranscriptionPreference, Sheets' default picker, SessionStore.voiceProvider and VoiceInputController/QuestionAnswerField. iOS defaults to desktop, offers phone recognition, and can transcribe the original saved file through its own local adapter. Android now exposes the same two default titles in a voice-only settings page and captures the chosen provider at start. Changing the default cannot retarget an active capture. Desktop voice retains its explicit AI-sharing grant; explicitly selected system speech does not upload to the Host or borrow that Host grant. Both keep exact target, connection/reader/provider, draft version and foreground fences. Failures and capability checks never send a reply.

Persistence is intentionally incomplete at this owner boundary: NativeVoicePreferenceStore is a narrow load/save port for the storage/migration owner. No backend, new record, metadata field or migration was implemented here. Until bound, the selector is a session default and the UI explicitly says it lasts for this app opening. The port prevents a late load overwriting a user choice and serially coalesces writes. The parent must bind an approved existing storage path and validate reopen behavior before claiming persistent defaults. The proposed integration contract is in stage4-owner-handoffs.json.

The inspector only queries services. API31+ selects the on-device engine when advertised; API33+ uses checkRecognitionSupport for the requested system locale, distinguishing installed, download-required and remote languages. Exact region tags are not guessed from a base language. Missing/unsupported/timed-out queries remain unconfirmed. There is no model download, permission prompt, microphone start or recognition operation in a capability query. Leaving/backgrounding cancels its owner and rejects late callbacks. Existing system speech still rechecks service availability at actual start.

Android's service may use network processing even when a model is installed on the phone. PREFER_OFFLINE is advisory and can be ignored. EXTRA_AUDIO_SOURCE may be unsupported and open a new microphone instead; it is not used to impersonate original-file transcription. Consequently same-recording phone transcription remains unavailable, and the failure action is explicitly “switch to phone and record again.” A synthetic unknown original's exact ID, manifest, attempted flags and encrypted bytes are checked unchanged while a new injected system capture fills text. Ending/cancelling never reports cancellation of the remote transcription.

System interruption/error preserves recognized partial text. The user can explicitly fill it only into the still-current original draft; background, changed draft/connection or old callbacks cannot auto-apply it. Native UI actions use the same listening/finishing component and keep existing literal service/Host errors outside product localization. Desktop-to-system fallback is an explicit new recording instead of iOS' automatic fallback: opaque Android service/network capability is not silently selected. This difference remains registered, rather than claiming complete F64 parity.

The current Manifest lacks the Android 11+ RecognitionService queries declaration. MainActivity/Manifest are parent-owned; the exact proposal is handed off, not silently patched. On these devices an unavailable default service is reported as unconfirmed, since visibility may be the limitation. No real service/microphone, acoustic or physical UI capability pass is claimed by compiling mocked tests.

Official primary references checked this stage: [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer), [RecognizerIntent](https://developer.android.com/reference/android/speech/RecognizerIntent), [RecognitionSupport](https://developer.android.com/reference/android/speech/RecognitionSupport). These support the API thresholds, service visibility declaration, advisory offline flag, optional injected-audio behavior and language capability distinction above.

Auxiliary verification and exact APK/source fingerprints are external. Prepared native cases cover the real default-picker navigation/session routing without Host voice calls, active-provider fencing, original unknown audio preservation, partial-text recovery through the actual native button, serial preference writes/late load and late capability callbacks. They compile but have not executed here. New copy is a proposed catalog delta; parent integration/regeneration and bilingual native verification remain required. Real microphone, original-file local transcription, persistent preference integration, question input alignment and real Host/DEV remain separate open items.
