# P7 原文件请求与本地结果恢复档案

## P7-4a 实现及共同断言

Android 文件选择现在使用按不可变原请求 ID 注册的 Android ActivityResultRegistry 键，注册独立于附件面板和 Compose 自动生成的启动键。原完整草稿键、附件导入代次、呈现代次及请求 ID 先保存到独立加密账本，并确认父草稿代次已持久化，再写入启动阶段并调用系统选择器。恢复 prepared / launched 记录只恢复本机等待，不自动重新打开选择器。已关闭记录最多保留32项，未解决记录不为腾出空间静默删除；全量配额和清理矩阵仍待验。

返回的准确 content URI 顺序先写入原记录；仅尝试持久化本次新增的读取授权，不申请写入授权、不撤销已有读取授权。选中字节先进入独立加密暂存，复用既有固定附件 ID、原清单及缺失字节核对。进入父草稿前核对准确原目标/代次；文件字节与父元数据持久化确认后才消费暂存并关闭原回执。重建、重复和迟到结果不选择当前新草稿、不重复追加、不上传或发送。

原目标已变化或加入失败时保留原本地记录，显式重试仍使用准确原结果；用户丢弃只清理该本机暂存，来源文件保持。记录读取/未知版本失败保留原加密字节，不能写入空记录覆盖。当前草稿同一导入代次的文档事务在确认回执前禁止移除附件，避免部分提交与移除竞争；保护同时覆盖持久selected/ready恢复、内存任务尚未创建、账本载入及读取失败，不能只因内存job为空就认定原结果已关闭。旧代次的准备不把新草稿标为忙碌，也不阻止新草稿明确移除。旧失败的重试/丢弃、旧回调不能隐藏或结束另一个新请求的等待。

超过10个系统结果在访问提供者或申请持久化前，以共同的附件数量限制文案拒绝。照片与相机的原请求仍走各自既有 Session 路径，本批没有把文档账本结果扩大宣称为它们的进程冷恢复。共享核心、Host/Adapter、iOS程序及领域/线上协议本批未变；原目标与不重放的双端共同断言继续保留，iOS当前真机行为未重新验收。

## 交互与界面

异常恢复提示区分读取失败、系统结果未确认和原文件尚未加入。结束等待不重开选择器；迟到文件不加入草稿。旧失败结果和当前未确认请求同时展示各自控件，按钮忙碌绑定准确请求 ID。使用现有重试/结束等待与明确的丢弃文件结果，增加五条平台文案，当前1687双语键（1603共享+84平台）。

提示区占屏幕高度最多30%、上限160dp，内容可滚动，动作横向不足时换行，保留至少48dp触达。三环境基础界面及API26暗色字号2、API37暗色字号1.3有界通过。截图是准确原生语义子树和当时滚动位置，部分上文可以滚回查看，不把滚动后的上缘截图当作固定标题裁切。手机实际宽视口/系统字体另记，完整IME、AX、语言/旋转及API37横屏仍开。

## 验收范围与指纹

真机/API26/API37各68项：文档恢复10项，最近图、附件归属、图片/相机准备、收件箱、粘贴、双语目录与照片授权其余58项。每组包含真实系统选图取消、系统文件选择取消各1项；其余为原生/受控来源辅助。文档原字节经真实本机FileProvider和Keystore/草稿仓库核对，但 Android 系统结果回调与 registry 保存/恢复由受控 registry 提供；同一进程重建的 journal/registry 不计实际进程死亡返回。

文档检查覆盖原目标导航、稳定ID及重复结果、重建不重新启动、结束旧等待/迟到回调不消费新请求、损坏账本、失败暂存重试与丢弃、旧失败与新等待并存、11项结果不读取提供者、事务内移除保护、旧导入代次不阻塞新草稿。暂存结果的来源文件删除后，重试仍核对原加密字节；原代次无效时不加入新草稿。两个事务检查使用该自有子仓库的有界IO锁和闩锁，验证业务状态，不暂停正式服务。

另六项暗色大字号恢复布局，以及三环境同一已完成真实模型图片回复的冷Host GET-only核对，原owner、原输入/最终回复及原轮摘要不变，没有写请求或重发输入。有效检查点为204辅助、6系统取消、3原回复只读，共213份默认草稿/附件/代次、最近图偏好、授权与文档账本保护证明。前期检查不重复累计到此最终候选；准确源/APK/runner关联见[复核摘要](../P7-document-recovery-review.json)。新增模型0，累计220 / P4 205。

## P7-4b 原系统文件进程死亡返回

使用独立接收包、测试来源包及构建输出，保护既有验收/DEV/正式版。两个SDK原生系统选择器由独立来源UID驱动，启动后核对准确调用UID、STOPPED/已保存状态、原ActivityRecord和PID，再终止接收进程；选择器留在前台，未force-stop待返回App，未再次启动选择器。独立GET-only Host和两份聊天草稿、先前照片尝试标记属于合成准备；真实系统选择器/提供者/URI、进程、Keystore和草稿导入边界独立登记。

API37 am kill成功；API26 am kill对previous级别进程未生效，原PID仍在，准确核对后只以该独立调试包自身UID SIGKILL。两端原结果均返回同一原接收Activity，进程PID变化；原有附件在前、新文件在后，精确原字节/MIME/名称/顺序/SHA核对，原草稿键与代次、两份草稿文本和设置保持，原请求/暂存消费、只释放本次新增读取授权。随后各一次冷开并横向滚动核对新文件可见，另四项只读原生方法核对无重复。两项seed为辅助准备，不计系统通过。

早期驱动失败分别为全局STOPPED误读、API26旧haveState字段、连接未就绪、旧DocumentsUI网格无AX点击和API37新附件位于横向条右侧。均保留原失败与现场，不重建原选择器/不再次选择已返回文件。API26仅对唯一受控文件记录原生边界后注入触摸；API37原结果只读核对通过后冷开滚动补UI证明。观察器迭代APK逐项绑定原场景，接收/来源APK从seed至核对完全一致，未把所有记录笼统归为最终观察器通过。

本批产品Kotlin/res/共享核心保持4a；只新增隔离构建身份、来源配置和冷验收器。4a既有213份结果保留原指纹；本批不以新包复用其默认证明。当前模型新增0、累计220/P4205。完整Provider/权限、自然系统回收、真机观察器、照片/相机冷结果与存储/语音/阅读继续；iOS A6保持暂停，任务/项目业务暂缓。根检查结论及准确包/源/观察器指纹见[复核摘要](../P7-document-process-cold-review.json)。

## P7-4e 当前共同协调器系统冷回归

4c调整父草稿就绪及共同文件/照片事务后，本次在API26/37使用新请求分别完成真实系统文件选择器下的接收进程死亡、原结果返回及冷开。同一请求/附件ID/摘要、原文/设置/原草稿代次、既有附件与另一聊天草稿保持，归一化文件字节准确且只消费一次，读权限回到基线。共2个系统冷结果、2次冷开、4个只读方法及2次准备；新增模型0，累计220/P4 205。
