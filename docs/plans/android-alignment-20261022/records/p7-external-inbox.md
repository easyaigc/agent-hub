# P7 外部文件收件箱档案

## P7-1b 本地接收与准确草稿确认

逐项对照iOS ExternalAttachmentIntake/AttachmentInbox：Android注册系统单项/多项分享和content URI打开，使用原生singleTask Activity；文件快照后台读入独立加密收件箱，不选择聊天、不上传/发送。确认页固定展示当次批次，原名/大小保留，添加当前草稿、稍后、丢弃与重开使用相同双语文案；旧面板/后台动作先拒绝，迟到来源不改旧面板。系统入口外观不同，语义一致。

原子索引先保存固定槽位ID与清单，再写payload；重试核同一来源摘要/原文件，目标一经绑定不能挪到新草稿。每批和固定文件ID串行租约覆盖准备、提交及清理；已有ID只接受相同字节，满10项仍可修复原缺失字节，不增加附件。等原草稿元数据队列和真实加密字节/摘要持久确认后才消费，消费回执先落盘，清理失败保留原清单待重试，不复活旧操作。未知旧模型输入不重放。

最终119辅助：三平台各35项，加API26双倍字号/API37深色各7项。覆盖存储重建、部分失败/重试、固定ID碰撞与取消、准确目标/早晚批次、写队列闸门、旧surface/后台拒绝、满容量修复及既有附件/触达/catalog。独立来源测试APK在另一UID/PID生成合成文件，经真实Android单项/多项分享/打开路由进入实际Activity；核原顺序、名字、摘要、只读授权与默认存储，辅助Host为合成读取服务，分开计证。

另三平台各1个实际原桌面目标/资源整例通过：独立来源真实系统多项分享，显式添加准确原草稿，原文/目标和元数据保持，原字节逐一匹配，落盘后才消费。只GET，无上传/提交/新模型输入；新增文件尚未由模型读取。原资源模型只引用验收器107字节文件，不能当作模型消费证明。累计219/P4 205不变。共122份默认存储证明。控制使用原生语义，非坐标；系统剪贴板真机/API37回归匹配，API26原为空未写入。验收器只清理本次新增本地文件及独立来源nonce数据，恢复原Activity Session/附件列表/原剪贴板。

保留失败：Java setClipData返回void的早期编译错误；API26上下文UID为0的错误oracle，改PackageManager实际UID；三次旧runner指纹预检拒绝未启动原生；早期API37正向动作超时孤立复验通过但唯一原因未追认。后来手机/API37同一场景记录为批次pending、附件0、无错误，定位接收结束先发布receiving=false、后刷新最终snapshot的窗口，早期快照可误呈失败；生产改为最终snapshot先发布再释放接收标记，当前批次明确断言pending并通过。旧失败不改成通过，旧包辅助/实际结果不提升为当前候选。

I2根检查616个共享/JS/iOS/工具/catalog输入严格匹配，Android改动本轮构建/原生/审批边界/parity/格式另验；跳过1/24/22不计Windows通过。无iOS A6执行。完整进程死亡/冷启动、Provider阻塞/未知长度/撤权/格式、真实微信来源、模型混合发送、照片/语音/存储/阅读及完整UI矩阵仍待验，继续P7-1c，不阻塞后续。
