# P9 ordinary Codex notification interfaces

Task `android-parallel-p9-notifications-20261028`; base `1e908bea1ac75341e17e56a518d7bebd46620c4d`. This directory is the P9 workline handoff, not central integration or device proof.

## Implemented local boundary

`NativeChatNotificationRuntime.receive(wire, lease, computer, foreground)` accepts only a bounded protocol notification v1 from the already authenticated exact-target local event reader. The captured `NativeChatNoticeLease` includes the complete Codex machine target, opaque credential reference epoch, a UUID registration generation, and preference revision. Endpoints and legacy Codex account metadata are outside machine identity. Never pass a secret/token as credentialEpoch. Reconnect may reuse the lease only while the verified target and credential reference epoch remain unchanged; credential replacement/re-pair, removal and preference edits invalidate it. These are local generations; vendor token registration is not implemented or advertised.

The runtime rejects stale leases, wrong targets, future (>60 seconds) and expired (24 hours) events before invoking reading. It then consumes `NativeChatNotificationReading.receive(event)` and, after suspension, rechecks the lease, preferences and the required synchronous `mayPresent(event)` before claiming a delivery. Each receipt captures the complete target, registration generation/preference revision and original event ID, independent of LAN/VPN path. Live original-event dedupe also spans credential/preference rotations for the same target; a new registration cannot re-alert an already claimed event. The encrypted store is bounded to 256 leases, 2048 live receipts and 4 MiB UTF-8. Capacity failure preserves all original bytes; only expired receipts are pruned during a successful new claim. Claim precedes OS notify. A crash/unknown notify result never automatically replays that event in the same or newer generation. A successful notify return is labelled `submitted-to-system`, not displayed/delivered.

All runtime methods execute on the main thread; its event/route ports can suspend. Persistence uses the existing NativeSessionStorage atomic/encrypted record. The current local boundary is single process. A future vendor service in another process requires explicit cross-process serialization before claiming support.

## P7 reading consumption and one missing query

Read-only reviewed P7 candidate `parallel/p7-reading-voice/interfaces.md`, `NativeReadingLedger.kt`, `ThreadReading.kt` from its own worktree. No P7 uncommitted files were imported here. P7 alone owns the ledger and lifecycle/readVisible policies.

The integration adapter maps `event.readTarget ?: event.target` to `TargetScope("codex", null, null, hostId, workspaceId, runtimeId)`, and a versioned `NativeChatNoticeReadPosition` to `ThreadReadPosition(revision,messageId,contentVersion)`. For a notice with a thread and kind other than `connection`, call the shared `NativeReadingLedger.receive(NativeReadingEvent(id,target,threadId,kind,position))` once; consume its `NativeUnreadSnapshot.count` as the aggregate conversation count. `connection` and threadless creation/operation notices do not invent a conversation row; use `ledger.snapshot().count` and the P9 receipt for their alert admission. Never call `readVisible` on receipt or tap; only actual exposed content may produce the P7 view lease/read acknowledgement. Badge disabled and notification disabled never clear P7 data. The parent retains the last successful snapshot on storage errors.

**Required additional P7 query:** the current `snapshot().isUnread(target,threadId)` is conversation-wide. It cannot tell whether an old completed position conflicts with/is older than latest, or whether this specific unversioned notice tombstone is read while another notice keeps the conversation unread. Therefore it must not be used alone as the P9 `shouldAlert` or `mayPresent` decision. P7 should expose a transactionally checked per-event query, e.g. `mayPresent(NativeReadingEvent): Boolean`, true only for this exact unread notice or current unread reply version. `NativeChatNotificationReading.receive` must return that decision plus snapshot.count; its `mayPresent` must requery that same authority immediately before the claim. There is no production noop/fallback adapter. Main coordinator owns adapter registration after P7 adds/validates the query. This dependency is open, not replaced by another unread ledger.

## Click route and draft preservation

`NativeChatNotificationRuntime.open(intent, route)` reads only an opaque UUID ticket. Event content stays encrypted locally; PendingIntent is explicit and immutable with a unique data URI. Unknown, consumed, expired, removed/re-paired or old-preference tickets fail closed. `NativeChatNotificationRoute.refreshExactTarget(target,credentialEpoch)` must read/refresh the exact original saved connection and workspace/runtime before returning true. The runtime rechecks the original lease after the await, then atomically consumes once and calls only `openPreservingDraft(event)`. That integration method must use normal navigation preserving the current composer/draft, opening the exact thread or computer if threadless. It must not approve, resume, retry, prepare or send. It exposes no such commands. Failed/unknown routing is not an instruction to replay input.

## Platform distinctions and remaining work

There is an actual API26+ NotificationManager implementation, not an empty provider. Category + default/silent + badge variants are stable, bounded channel names, created only for explicit usable actions. Existing channel sound/importance/badge settings are read, never overwritten/deleted. Any blocked variant suppresses the category, so selecting a new variant cannot bypass a block. App preferences and system settings are distinct. Denied/missing POST_NOTIFICATIONS, app-wide disable and channel block are unavailable states. Preview off removes private title/summary from collapsed, expanded and public presentation; privacy changes cancel only this module's owned notifications. Public lockscreen presentation is always generic.

Only system-default/silent sounds are implemented. Custom sound references are preserved by schema but unsupported for posting; builtin generation, import/preview/convert/delete (10 MiB/29 seconds per iOS), custom URI access and system sound/launcher behavior remain open. Android time-sensitive has no equivalent; its persisted field is not advertised as supported. Vendor selection, GMS/non-GMS transports, crypto envelope/AAD, token rotation/revocation synchronization, background delivery, actual sound, locked-screen delivery, launcher badge, system restriction recovery and true device arrival are not implemented/verified by this stage. Remote push stays unready; no provider or accepted-as-delivered claim.

Official platform references: [channels](https://developer.android.com/develop/ui/compose/notifications/channels), [permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [click navigation](https://developer.android.com/develop/ui/views/notifications/navigation).
