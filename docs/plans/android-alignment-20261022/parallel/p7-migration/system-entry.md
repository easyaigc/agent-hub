# Native system migration entry candidate

The Android candidate adds Settings → Secure migration, an in-memory masked password, encrypted export through CreateDocument, import through OpenDocument, a fully validated candidate preview and explicit confirmation. The existing exporter, encrypted candidate store and atomic activation remain the only migration engine. This delivery contains the owned components and eight exact shared-file integration overlays for the parent; the isolated branch alone does not route the new setting.

Import never starts when a file is merely selected. A staged candidate is recovered by its original ID/digest, and the preview shows computers, drafts, operations/receipts, attachments and retained notification archives. Replacement requires a separate confirmation. Cancellation and wrong-password/unsupported-input failures retain active data and the original source file. Content streams are bounded; only owned encrypted cache files can be removed. Export truncates only the destination chosen by the system contract, and never deletes a source URI. Unknown candidate/publication outcomes are queried, not automatically restaged or activated.

The proposed actual Activity/Session hook gates new mutations, disposes the old notification coordinator, stops foreground readers/discovery, joins actual Session jobs and local voice stop/discard work, snapshots the latest in-memory metadata, and waits for the serial storage writer. An unresolved save or quiescence failure keeps the old Session/draft model. A successful boundary restores a fresh handle and Session, waits for its reading reconciliation, retires the old writer/scope, and supplies that fresh Session's existing reading ledger to its notification port. Rotation retains the controller and exact picker correlation; an Activity changing configuration cannot publish a stale owner replacement. Late incoming intents invalidate an in-flight publication lease and retain their original local ingress IDs for later handling.

The production notification coordinator begins closed. Its migration check starts only after the Session is ready, avoiding a race with initial restore. On IO it reads the existing migration archive/setup rule and actual durable notification preference. A migrated installation with notifications disabled remains closed across foregrounding, opening settings and reading archives. Only a saved enabled preference releases that gate. Settings writes wait for the check; an explicit local retry can recover a failed read. Imported original notification journals/authority remain archive aliases and never become live authority.

The Chinese/English page follows the existing iOS password/system-file flow and Android grouped settings/sheet controls. Android uses SAF contracts. The existing Android archive format remains in use; iOS format interoperability is not implemented or verified by this entry.
