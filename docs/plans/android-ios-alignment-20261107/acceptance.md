# Android / iOS 对齐验收方案

更新：2026-11-07；冻结基线与实施顺序见[计划](plan.md)。本文规定未来验收，不新增本轮运行通过声明。每个功能对应 [AC-F01–AC-F75 验收矩阵](acceptance-matrix.md)，历史证据继续保留原范围。

## 功能、交互、界面分别过门

| 门槛 | 每条功能必须回答的问题                                                                                               | 通过证据                                                                       |
| ---- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 功能 | 实际输入、完整目标、原 owner、原操作 ID、输出/文件/回执与 iOS 共同断言是否一致？成功、拒绝、失败、未知是否分别正确？ | 原生动作和实际结果；有远端执行时增加真实桌面、模型和原回执独立核对             |
| 交互 | 所有入口、主/次动作、长按/菜单/手势、选择编辑、取消/返回、禁用、等待/重试、切换和冷恢复是否完整？                    | 动作前置、原动作回执、屏幕/AX 与数据结果；结果未知先查原操作，不能重放取新证据 |
| 界面 | 页面结构、字段/按钮、完整长文、颜色/字号/间距/图标/状态/错误文案、键盘避让和读屏是否对齐？                           | 同状态双端原图、组件几何/token 对照、AX 名称和焦点/触达实际验证；明确系统差异  |

“构建通过”“fixture 通过”“HTTP 200”“工具外层完成”“供应商接受”“子 Agent 声称通过”都不能单独关闭以上三门。代码存在、源码清单复核与运行通过使用独立字段。

## 每条 AC 的最小覆盖

1. 正常入口至终态；有内容/无内容，首次/重访；按能力禁用及明确说明。
2. 取消、返回、再次打开、失败重试；异步结果绑定准确目标、请求、草稿版本和 owner。
3. 切换电脑/Provider/聊天、编辑连接、新请求替换、迟到成功/失败/事件及原回执不污染新输入。
4. 断网/重连、后台/回前台、Activity/进程重建、Host 冷重启；实际适用项逐条列出，不能只做模拟异常。
5. 长字段/多行/长列表、短视口、键盘、横竖屏，中英、深浅色、常规与大字、读屏及减少动画。
6. 原始输入、文件/摘要、失败/UNKNOWN 与当前状态均保留；新测试使用新专用资料，不重放历史未知操作。

不适用项必须说明理由。例如纯展示不启动模型，F74 没有手机入口；任务/项目暂停项登记“暂缓”，不能写成通过。

## 迁移的 24 组系统资料

这些是 Android 本地系统范围，不等同于 24 个跨端公共 wire 域。旧[系统范围档案](../android-alignment-20261022/parallel/p7-migration/system-scope-inventory.md)含早期“尚不支持”及后续增量，不能拿某一旧行作为当前结论；下面给新验收去向。**24 组整体验收均未关闭**，局部生产/组件证据按范围复用。

| 系统范围                        | 新计划的保留/重建规则与验收                                                           |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| root-session                    | 连接、目录/最近项目、小状态与凭据完整；机器目标校验，安装/授权字段按目的端策略处理    |

## 环境矩阵与证据

Android API26、当前API37及当前物理手机分别记录；API33 的组件证据保留为局部结果，不能替代这三个门槛。API37 横屏单列待验。iOS 使用当前匹配源码/包的原生模拟器与已配对真机结果；iOS A6 保持暂停。Codex/EasyWork、macOS/Windows、LAN/蜂窝/VPN/Relay按功能实际依赖分别验收。其他电脑/Provider 的历史成功不替代本环境。

先做确定性的高风险边界和主路径，再做相邻状态/系统矩阵。单元/向量、构建、组件原生、产品原生、真实 DEV 分层报告；性能记录环境、数据量、时间/内存/磁盘，不凭主观“流畅”关闭。系统视觉采用组件和token测量结合原图，不用全屏像素阈值掩盖产品差异。

每条结果保存：功能/子场景/三门状态、源提交/dirty指纹、iOS参考提交、产品/runner安装后包摘要、设备OS/build/进程、Host/runtime/原owner、实际步骤/预期/结果、原操作ID/回执、文件摘要、截图/AX引用、失败/UNKNOWN、复用依据、负责人和日期。私有身份/凭据/实际对话留私有证据，不进Git。留档后清理可重建产物，保护唯一失败/恢复证据。

新结果回填[进度](progress.md)并链接[档案](../android-alignment-20261022/records/README.md)；只有所有适用子场景的三门均通过且证据有效才关闭 AC。发现新 iOS 提交影响某行时只重开受影响范围，历史结果不改写。
