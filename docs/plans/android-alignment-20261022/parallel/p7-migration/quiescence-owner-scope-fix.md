This exposed a production binding error. The coordinator constructor parameter and its private child-scope property were both named `scope`. Kotlin resolves the constructor parameter inside a property initializer. Consequently `NativeMigrationNotificationEnrollment(session.storage, scope)` captured the original Session scope, while coordinator methods used the owned property. Enrollment IO could remain alive outside the coordinator owner Job and its IO context. Disposing the coordinator could therefore complete that owner early. A parent Session join later in the path does not establish the required coordinator ownership or retiring-owner gate.

The minimal production patch renames the constructor parameter to `parentScope` and uses that name only when creating the owner Job and child scope. The existing Enrollment initializer then unambiguously captures the owned `scope`, including its Job and IO tracker. Stop/join, cancellation budgets, storage, notification protocols, original operations and UI behavior remain unchanged.
