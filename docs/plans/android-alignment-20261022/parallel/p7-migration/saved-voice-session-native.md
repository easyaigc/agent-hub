# Actual Session saved-file voice acceptance proposal

This proposal adds nine native methods and no production code. It requires frozen voice commit `6e3a1313524508d9f2dbdc0f3e1d1463f20a903e`, its 17 owned files and six common patches. The reviewed parent base is `3a26db86c11a1f37a5f11dcc4d98840cd7ebf94d`. Preserve the parent's raw EasyWork name: the narrow `MobileSession.kt` result is `f4b2a1352321b7700268418a634ba04b0f9e269b6f131994ebfa781f34f6840d`. Do not replace whole parent files or include later P8/P9 changes in this fingerprint.

The parent owns adoption, central case registration, new app/runner build, device leases and actual results. These methods use actual `MobileSession`, its actual composer/question draft owner, the serial encrypted storage writer and full Session quiescence. The file recognizer and Host transports are synthetic. They do not load JNI, download a model, use a microphone, call a Host or replay an original operation. Kotlin compilation is auxiliary evidence. No native result is claimed by this source proposal.

## Native selectors

Use only `com.easyai.agenthub.android.acceptance` and its `.test/androidx.test.runner.AndroidJUnitRunner`. Run each selector separately with an exact app/runner/source fingerprint, the parent's device lease and a unique `ownerCallbacksRun` argument. The structured registration increment is [saved-voice-session-native-cases.json](saved-voice-session-native-cases.json); it declares one expected JUnit method for each selector.

Class `com.agenthub.android.NativeSavedVoiceSessionTest` has seven methods:

1. `actualComposerAndQuestionPublishOnlyAfterExactSerialWriterReadback`: pauses the actual writer before its write; checks staged catalog/no memory fill, then exact destination, owner, source/accepted revision and authenticated metadata/text digests after release. Original row, audio, attempted flags and independent composer text remain protected.
2. `actualSessionIdenticalOldMetadataEnqueueRevokesVoicePublication`: the actual Session `changeAppearance` producer enqueues an identical old snapshot while the destination is held. The live owner's enqueue revision must reject publication and keep the original recoverable/staged.
3. `actualSessionFailedAndUnknownDestinationWritesKeepTheResultStaged`: injects an exception before the actual write and after the write but before acknowledgement, for composer and non-secret question. Memory stays original, the catalog stays staged and the serial queue reports its failure. Reopened metadata distinguishes absent write from committed/unknown write.
4. `actualSessionLaterDraftEditsRejectLateDestinationAcceptance`: edits the real draft/revision while the writer is held. The newer memory and queued durable text survive; the old result stays staged and cannot fill the changed draft.
5. `actualQuestionOwnerDisposeWaitsForWriterThenAllowsExplicitRecovery`: background stop followed by actual `endQuestionVoice` clears the Session key but stays busy through the executor exit. A later explicit saved-file action can reuse the same staged result without another decode.
6. `actualSessionReopenReadsQuestionOwnerAndNeverAutoRecognizesOffIndexResults`: fails the actual destination before its write or after its write/before acknowledgement, closes the original Session/writer and creates a fresh Session handle from encrypted metadata. It checks actual question/composer owner restoration and zero implicit probe/decode. A committed/unknown write is already visible from disk while the catalog stays staged; only a deliberate edit back to the original text re-enables that original's exact recovery destination. An explicit action uses the same off-index staged result. This method is a same-process reopen, not process-death proof.
7. `cancelledFullSessionMigrationWaitsAgainForSavedWorkerAndKeepsOffIndexQuestionGraph`: keeps a linked Chinese staged result outside the index and holds a synthetic English worker. It cancels the first full Session quiesce, starts a second full Session quiesce after retry admission, and requires no second lease/publication until that same worker actually exits. It then validates the typed and encrypted framed graph, closed question key, catalog, original row and exact audio. The temporary admission flag is not treated as a lease or as a completed native close.

The destination fault injector reads the already configured port's actual `NativeVoiceDraftOwner`, checks that the replacement port retains that same object, and changes only the existing executor-checkpoint parameter. It does not implement a substitute owner, metadata map, publication Boolean, receipt or applied terminal. This reflection is pinned to the reviewed field names and source hashes; a changed source requires review/recompile. No additional shared production hook is proposed.

## Different-process cold pair

Class `com.agenthub.android.NativeSavedVoiceSessionColdTest` has two opt-in methods:

1. `stageFreshActualSessionResultsForDifferentPidWithoutReplayingAnyOriginal`
2. `reopenSameActualSessionResultsUnderDifferentPidAndFillOnlyAfterExplicitAction`

Supply the same fresh canonical UUID as `savedVoiceSessionColdRun`. The writer refuses an existing proof or either existing namespace. It creates two entirely synthetic actual Sessions (composer/question), fails their destination before the actual write, keeps the result staged, removes its active-index entry, closes their writers, and records exact source ciphertext/original/audio/action fingerprints. It does not reuse any business fixture or historical operation.

After the writer method completes, the parent ends that exact acceptance app process and confirms it exited. Preserve the installation, app data, Keystore keys and fixture UUID. The reader requires a different PID and the same original ciphertext before constructing its new Session. It verifies no automatic probe, decode, fill, Host voice request or answer. Only a subsequent explicit saved-file action may accept the existing staged text; the action ID and original row/audio remain unchanged. The reader creates a one-use intent claim before mutation. An existing claim or unknown result must be reconciled through the proof, actual catalog and completion record, without blindly rerunning either method.

Cold proof: `files/acceptance/saved-voice-session-cold-<UUID>.json`. Reader intent/completion files use the same stem with `-reader-started.json` and `-reader-complete.json`. The two `P7-saved-session-cold-{c,q}-<UUID>` native namespaces, keys and derived child scopes remain until the parent reads and saves their evidence. They contain only these fresh synthetic inputs. Their cleanup belongs to the parent's completed cold-pair phase; preserve unknown/in-progress outcomes.

## Evidence and limits

Per-method observations and protected-default proof are written below `files/acceptance/P4-owner-callbacks/<ownerCallbacksRun>/saved-voice-session-<UUID>/`. Ordinary cases close/join their real owners and remove only their fresh UUID namespace and its derived native child scopes. Protected default drafts, attachments and microphone permission are observed and compared, never reset or restored over.

Every method captures three independent original baselines before its restore, transcription, owner change or migration action: the complete canonical `original.json()`, the exact persistent row string, and all WAV bytes. The shared preservation check compares the reloaded complete canonical JSON, the exact row and the complete byte array. This avoids KMP `TargetScope` reference equality without dropping historical account metadata, attempt flags or any other field; raw-row equality also covers receipt/storage fields outside `PendingVoiceRecording.json()`. Cases 2, 4 and 5 use the same three checks. The different-PID reader captures its baseline before constructing/restoring its actual Session; the same-process reopen carries forward the baseline from before its first destination attempt.

Record implementation/source, auxiliary compilation, native method results and actual acoustic results separately. The cold pair covers a pre-write failed destination across a real process change. Actual process death after the destination write, before memory publication, and before/after applied catalog publication remain separate gates. Actual model installation/download interruption, JNI loading/decoder/recognizer close, English/Mandarin acoustic quality, native visual/secret-field behavior and full DEV remain with the voice line and parent. An injected engine exit does not establish any of those results.

The Android question-owner behavior is inherited from RV29. Central product/design/acceptance manifests should associate these cases with F33/F42/F56/F58/F64 without declaring new product/native completion. iOS source and acceptance are unchanged. A6 and task/project business management remain paused; unknown operation 863 and all original operations remain untouched.
