# Leased first-Activity original-ticket boundary preparation

This is a closed debug acceptance harness for the first real MainActivity in a fresh reader process. It does not launch a default App/Session and then adopt an owned Session. It does not claim an OS tap, actual Host/runtime/model connection or complete DEV. The fourteen OS notification scenarios remain independent. All five cases start not-run in [cold-ticket-plan.json](cold-ticket-plan.json).

## Selection before default construction

The parent-only [exact five-file overlay](cold-ticket-hooks.patch) changes two files and records all five base/proposed fingerprints in [cold-ticket-hooks.json](cold-ticket-hooks.json). It is rebased to the parent's P8 phase5 nonblocking IO/phase3 entry bytes (Main e9b56429, Session 2c8f7b2e). Read-only apply check passed. The three other shared files are unchanged. This workline did not edit either parent file or apply the overlay to its older component baseline.

MainActivity calls the fixed selector before NativeSessionStorage(default)/MobileSession(default). The router is a separate fixed encrypted acceptance record. A canonical UUID derives a fresh existing acceptance-scope namespace; no namespace, path, transport, method, credential or business text can be injected. The product Intent stays exact action/component/canonical URI plus one original ticket extra, without lease/config extras. Both fixed hook-version fields must exist before writer/reader tests can create any fixture. Release and every other package are rejected; the protected EasyWork sibling is never opened or queried.

Reader IO preflight reads the sealed original, verifies exact lease, writer PID exit, different PID/process nonce, app and runner APK hashes, bounded 15-minute lifetime and seed integrity. It creates no Session/Activity. First onCreate then selects the leased store, constructs the real owned MobileSession with fixed named ports and follows its normal restore path. No retained Session or earlier default selection is allowed. A framework savedInstanceState Bundle is recorded separately: it may exist after real process death and is not by itself warm adoption. The first MainActivity count and default-branch count prove which constructor path ran.

The Session overlay retains the actual P7 reading/notice port and same ledger/storage, but blocks notification polling only for the active cold binding. The coordinator uses the real scoped NativeChatNotificationPlatform and fixed named metadata reads; it has no fake SystemPort and does not post. Conversation execution methods reject without a transport. The fixed locator checks original target/runtime/captured credential epoch and returns the actual original thread row on page twelve. General Session metadata has both known fixture threads; missing-thread lookup still must not fall back to that cached row.

P8 authority.invalidate remains first in onNewIntent, followed by P7 cover and the existing dispatcher. A passive diagnostic acknowledges only an exact duplicate original after real receive() returns; other P8/attachment actions are not intercepted. Voice preference/durable discard hooks and P8 external/lease configuration stay in place. Discovery is not started for a cold binding. The existing recent-photo configuration/lifecycle uses a fixed NONE/empty source only for this fixture, avoiding any real MediaStore read. No source or method is accepted from the marker.

## Three explicit native roles

Use only the individual selectors and fresh canonical case leases in the plan, not an entire Reader class in one process. Do not activate the default App or use a foreground/Activity rule before these roles. Parent owns all device/process actions; this workline performs no device, permission, Host or model operation.

1. Writer runs without an Activity. It requires the acceptance installation's existing AES KeyStore handle; it neither imports nor overwrites a key and creates no notification device private key. It writes only a fresh UUID store, using actual MobileSession metadata/draft persistence and NativeChatNotificationStore.claim. The seed receipt remains claimed: no OS post is fabricated. It seals the original ticket, target-derived fixture, authority, receipt hash, process identity, implementation APK hashes and case in the separate router.
2. Parent ends/stops that exact acceptance writer process while preserving installation/data. Reader is a new instrumentation process and rejects a living writer, same process, changed APK, stale lease, earlier MainActivity or partial overlay. The test itself launches the first MainActivity with the unchanged original opaque Intent. Positive opens the original page/ticket; expired, wrong-runtime, replaced-credential and missing-thread cases stay unavailable without consuming the original. Every case edits a new current draft, sends the duplicate through actual onNewIntent, and waits for the post-dispatch signal before asserting no new lookup/navigation/draft loss/operation. Positive also returns to the actually read other-thread row and checks its prior draft.
3. After parent stops the reader, a separate observer invocation disarms only a completed router slot. It does not create an Activity or select default storage and is not a cold-route pass. It keeps the original lease store and unique proof files for parent collection/review. Armed/selected unknown results are never replayed or silently overwritten. In particular this harness never accesses the unrelated old unknown 863ec69e.

Use a fresh lease for each of original/expired/wrong-runtime/wrong-credential/missing-thread. Existing system-cycle UUIDs and any existing namespace are refused before seeding. The parent must keep writer→reader→observer together under its device lease, within the 15-minute arm window. A missing AES key, hook, process guarantee or immutable fingerprint is a failed/unexecuted precondition, not a reason to start the default App and relabel it cold.

## Evidence and limits

Unique app-private role proofs include PID/process nonce, unchanged app/runner hashes, immutable plan hash, first Activity/default counters and actual locator cursor sequence. Reader checks real Session restore, actual current full target, original receipt/credential epoch, consumption only on positive, preserved drafts, zero conversation execution, zero notification commands and absent notification identity/recovery/authorization journals. The actual Compose product surface and message input must display the selected page's original draft, the new draft after duplicate dispatch, and the other thread's saved draft after positive return. Existing claim migration guards remain parent-owned and unchanged.

Existing router material requires the already installed AES key before decryption; missing keys, unknown files and partial records fail closed before opening default storage. A failed selected reader emits a separate unresolved observation with current page/draft hash/cursors and leaves the immutable original selected. It neither marks completion nor automatically retries, disarms or replaces the ticket.

The shipping Kotlin auxiliary suite exercises the strict plan, fixed metadata codec, page-twelve actual row, complete absence, foreign runtime/credential/cursor rejection and non-executing command facade. It is not an Android process/Keystore/Activity proof. New helper/native test sources compile locally; the shared overlay still needs the parent's integrated compilation and role execution. The older isolated APK deliberately lacks the parent hook markers, so native tests fail their preflight before launching an unpatched Activity.

No lockscreen/launcher UI, hearing, background vendor delivery, real backend P7 acknowledgement, actual TLS certificate/runtime connection or full DEV success is inferred. Default data and keys are never reset or copied. Original lease data is retained outside the single router slot until parent evidence review; exact owned namespace/children can then be retired after the reader is gone, preserving unknown files and unique receipts. F52/UI11/S15,S16 deltas are supplied separately; iOS A6 remains paused.
