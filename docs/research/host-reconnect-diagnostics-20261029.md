# Host 诊断与恢复候选验收（2026-10-29）

任务：迁移后断连／503 的诊断补齐和只读恢复。来源提供的 Windows 现场概要是线索，未接收未脱敏日志、历史或凭据；本任务不向远端或其他聊天发送消息。A6 保持暂停。

## 根因结论

确认的代码风险：旧错误日志会在请求失败路径同步调用 Windows 权限辅助通道；旧 Windows bridge 的 Duplex 在交给 IPC 前没有 error 消费者；旧连接成功回调未完整隔离显式关闭后的返回。候选分别将日志移出 HTTP isolate、提前消费流错误，并增加连接并发合并和关闭代次守卫。

真实 Node 24 子进程已重现旧 bridge 的普通 stream.destroy() 产生未处理 ABORT_ERR 并退出；候选在 stream destroy、stdin close、stdout close、child kill 四条路径均正常退出。该反例证明代码缺陷，不等于确认了 Windows 11:16 的 ABORT_ERR 或用户那次 503 的唯一根因。现场未取得准确 route／response body，无法唯一判定保存失败、owner 变化、建议读取失败或运行时掉线。启动慢、native 执行慢、worker／child 退出、主线程阻塞的因果比例仍须目标包部署后按新字段关联。TLS／旧 DNS 发现与该 503 分开，不将 TCP 可达写成 HTTPS 通过。
