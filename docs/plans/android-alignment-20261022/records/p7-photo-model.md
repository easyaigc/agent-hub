# P7 图片模型与冷历史恢复档案

## P7-2c 图片实际读取

对照iOS图片选择及本地准备：独立来源APK只创建本次PNG，六位随机标记仅在像素中，文件名/正文不含标记；API37系统页选择唯一已核对媒体记录，经实际Activity回调到加密原草稿。原生设置选择当前默认模型、xhigh、fast和read-only，显式AI分享许可后仍无操作；独立见证器封存原目标、正文、文件声明及设置后，才允许一次准备、一次准确图片上传和一次提交。真实Electron原owner只有一轮、一条用户输入、一张图片和一条最终回答，随机标记完全匹配，没有工具调用。原生加密文件、上传字节和原桌面canonical图片路径的SHA一致；原owner的模型、推理档位、priority、readOnly及默认协作模式另行核对。

原生模型方法通过后，独立控制器把官方无项目目录误按测试目录比较而失败。失败报告保留；另开只读见证，按同一创建操作的准备台账核对官方cwd、准确Host/Thread/operation、原owner和canonical轮，不新发输入，取得通过。输入累计新增1，总计220/P4 205。该输入在下述Host修复前执行；修复后只读核对原轮，不把旧Adapter执行称为新Adapter再次模型执行。新手机/API26回读该模型回答不替代其系统正向选图或图片发送验收。

## Host 冷读图片身份修复

补验同一Host私有状态重开、准确原owner、手机空闲态时，实际发现用户输入重复。历史reader把localImage同时渲染为文件名和“历史附件”，丢掉了私有来源，临时ID行没有注册附件声明；随后真实owner投影同一轮、相同正文和原文件，旧行无法被保守身份规则替换，手机显示两条。原始失败消息索引与GET历史保留，canonical仍只有一条输入，未重放。

reader现在通过仅Adapter内部的类型化回调交出绝对localImage来源，回调不进入HTTP/领域JSON；同一来源走既有授权文件检查、大小/摘要与注册资源路径，不扩大目录权限。已知localImage只保留准确文件名，未知或无可靠来源继续显示未注册提示。完成轮上的用户图片与助手资源共用完整声明身份：准确目标/轮、角色/种类、正文/阶段/详情和全部注册文件版本均一致，且展示名全部由声明覆盖时，临时ID与稳定ID才一对一替换；未完成、变化/缺失/未知文件、其他目标、两个稳定ID及多重同文记录均保留。最新冷读页和owner使用同一边界，较早分页顺序保持；不靠同文、文件名、相同路径或读取历史推断执行/控制连接。

当前Host修复在新手机API33、API26、API37各一次真实GET-only回读通过，共62次GET、零写入；同一Host状态重开、不同Host进程，独立原桌面轮摘要前后不变。手机输入与最终回答各一条、原答复一致、runtime idle、停止控制已退出、空草稿/空附件/空本地操作记录保持。系统宽视口手机、API26与API37截图均已查看；完整主题/字体/AX/横屏矩阵仍按各场景单列。Android生产APK未改；原模型与9项附件归属辅助在新增只读验收类前运行，其389个既有原生/核心/协议输入逐一严格相同，当前只新增独立只读类。1模型+3当前Host回读+9辅助，共13默认存储证明。共享Host同样影响iOS，当前iOS/Windows原生矩阵未由Android结果替代，iOS A6未执行。

边界检查覆盖真实JSONL历史reader的私有绝对路径回调、未知/相对媒体、无来源路径泄漏，以及完成原输入的完整注册声明、目标/字节变化、多重记录、两个稳定ID和未完成保护。当前完整pnpm check通过，620冻结输入前后一致；跳过1/24/22项不构成Windows原生通过。没有复用旧根检查覆盖本次共享Host变化。

## 保留过程与后续

首次控制器误要求原始workspace出现客户端合成的staged能力，零输入即停止；改按实际桌面创建能力核对。另一次系统缩略区域未显示文字，零上传/零模型输入并清理原测试图片；增加画面诊断、显式收起键盘后继续，旧唯一原因未追认。一次见证器误把省略的默认协作字段当错误，在任何产品POST前拒绝；按既有可选字段默认语义和实际原owner设置核对。Host修复后的首次启动被原旧Adapter指纹检查拒绝，未启动原生或提交；改为明确冻结当前修复候选指纹，原模型指纹仍保留。已完成且关闭自身Host的本次控制器因重复observer连接仍存活，核实身份/报告/原轮后仅停止该本任务控制器，留存准确PID回执；未停止原桌面模型任务或其他进程。
