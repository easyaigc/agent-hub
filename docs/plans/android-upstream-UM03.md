## 开发与验收顺序

1. **共同契约和边界。** 增加 fork 选项、请求、操作响应的严格共同 Schema／跨语言向量；纯规则只做身份、准确终态 Turn、能力与阶段判断。SHA、HTTP、加密与文件系统留平台层。保留 Codex 上游 wire 及 Git 实现在 Adapter；不扩大任意方法或 shell 入口。
2. **Android 具名接线与持久化。** AgentCommands／Provider／注册器接现有三个端点；提交前保存不可变源身份、五字段请求及操作 ID。写入失败不发请求；并发双击串行；未知只查询，结束等待保留回执，重开恢复不再次分支。
3. **原生 UI 对齐。** F62、UI03／UI20：从准确助手回复的终态 Turn 打开两种环境菜单；加载／禁用／提交／未知／拒绝／已确认状态按 iOS 文案呈现。确认后校验新 Thread／project，打开分支前再核对当前目标和草稿代次。新分支未加载时只走具名打开，不另起执行实例。
4. **边界与设备回归。** 先跑共同向量和 Android 原生隔离 HTTP／持久化场景，覆盖 wrong host／thread／turn／ID／环境、缺字段、重复与冲突、断开／重启、迟到、查询失败及草稿。随后 API26、API37、小米适用 UI、旋转／重开及现有执行／恢复回归；iOS 受影响基线与原生分支场景独立保存。编译和 fixture 不替代真实分支。
5. **真实 DEV 与交付。** 固定源码、Host／Adapter、双端产物及验收器。实际原 Electron／原生 App 验证同目录和 worktree 继承到指定终态轮次，准确新 owner，原分支／HEAD／暂存／未提交字节不变，无额外占位 Turn；未知和 Host 重启后不产生第二个分支。按环境分别保存证据，必要旧夹具只按精确指纹复用。按用户最新要求，先完成本机与 Mac Mini24G 独立 iOS 的全部适用门槛并回收核实，再更新阶段与功能台账、正常提交推送 main 并独立读回。UM03 全部闭环前不进入 UM04。
