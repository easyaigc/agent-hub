# System-owned channel lockscreen visibility

The parent API26 original `ordinaryClipChannelUsesRegisteredProviderUriWithoutPlayingIt` failed with requested PRIVATE (0) versus stored -1000. Its real silent notification/private publicVersion, preview/badge, cancellation isolation, block-bypass and required-reading methods passed. The supplied source fingerprint is `8d163134b02bf2cfce715b8f578f0245849c9d8cdbcda320acc4c57c15fcfe9b`; the original failure remains a failed result until the corrected case is rerun.

This is a wrong channel-field test assumption. [NotificationChannel.setLockscreenVisibility](<https://developer.android.com/reference/android/app/NotificationChannel#setLockscreenVisibility(int)>) is system/ranker owned. [AOSP android-8.0.0_r1 RankingHelper.createNotificationChannel](https://android.googlesource.com/platform/frameworks/base/+/android-8.0.0_r1/services/core/java/com/android/server/notification/RankingHelper.java) replaces the app-requested channel visibility with the saved per-app visibility for `fromTargetApp`. Its default is VISIBILITY_NO_OVERRIDE. [AOSP API26 Ranking](https://android.googlesource.com/platform/frameworks/base/+/android-8.0.0_r1/core/java/android/service/notification/NotificationListenerService.java) defines that sentinel internally; the [public API31 constant](https://developer.android.com/reference/android/service/notification/NotificationListenerService.Ranking#VISIBILITY_NO_OVERRIDE) documents -1000 as no user/device-policy visibility override. It is not PUBLIC and does not itself show a privacy leak. Actual lockscreen rendering is still unverified.

The correction records the immutable app request immediately before the real NotificationManager channel creation, only on an explicitly scoped acceptance platform. Default production behavior and its requested PRIVATE value stay unchanged. The native assertion requires that captured request to be PRIVATE, creates a separate fresh control channel under the same owned UUID prefix with default NO_OVERRIDE, and compares the returned production channel visibility with the independently returned control. It classifies only known system-owned values; unknown values or a mismatch fail. This is not unconditional acceptance of a returned value, and no user channel/policy is changed.

The ordinary clip keeps its real sound URI, AudioAttributes, badge and exact provider-byte assertions. The real silent-post method additionally checks this split while retaining its original Notification.VISIBILITY_PRIVATE, redacted publicVersion, opaque original PendingIntent and count assertions. A real system/private override may legitimately differ from the app request; the proof records requested, control-requested, observed/control-observed and interpreted policy separately. That never becomes a system lockscreen UI pass.
