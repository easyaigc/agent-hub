# Android 正式签名与 APP 备案准备

本文件记录发布工程准备，不表示已获备案批准、应用市场审核通过或所有设备无风险提示。当前正式包名为 `com.easyai.agenthub.android`；开发、验收包身份保持独立。现有 GitHub 预览版是开发签名，不能作为正式签名或市场审核证明。

已公开的预览版包名为 `com.easyai.agenthub.android.debug`；正式包是独立安装身份，不宣称能覆盖升级预览包或自动承接其数据。保留原预览安装及数据；如需要数据迁移，另行实现并验证明确的迁移流程，不能通过卸载预览版或改签名制造“升级成功”。同一正式包的后续更新须保持签名兼容。

## 签名无需购买或向第三方申请

Android 使用开发者管理的签名密钥。项目提供本机生成、稳定复用、导出公钥和校验发布包的入口；不创建任何商店账号，也不自动上传。RSA 4096、PKCS#12、有效期 10000 天。证书中的产品名称不代表第三方对公司身份的认证。

```sh
pnpm android:signing:init
pnpm android:signing:info
pnpm build:android:release
pnpm android:filing
```

`init` 仅在首次生成；重复执行保持同一证书，部分失败时保留现场并拒绝重建。密钥保存于忽略的 `.local/android-release/signing.p12`，密码和路径仅在忽略的 `.env.android-release.local` 中，目录 0700、文件 0600。初始化当前只支持 POSIX 权限；Windows 须先以原生私有 DACL 准备密钥与配置，不宣称已经完成 Windows 验证。不得提交、聊天发送或向备案平台上传私钥与密码。首次正式分发前，负责人须将密钥及密码放入企业批准的离线加密备份，确认可恢复；同一磁盘的副本不算独立备份。

发布命令显式加载该环境文件，将秘密通过环境传给 Gradle/keytool，不放入命令行字面量。没有完整正式签名时，直接 Gradle release 也拒绝构建。独立 Android 发布输出位于 `.build/native/android-release`，不覆盖默认 debug/acceptance 输出；共享 KMP 工程和已有依赖缓存按正常 Gradle 锁协调。

构建后验证 APK 签名、唯一正式证书、正式包名及不可调试属性，并验证 AAB 签名。实际 APK/AAB、证书和 SHA-256 报告保存在 `.local/android-release`。公钥以 RSA 模数和 PEM 两种格式导出；MD5 是签名证书指纹，**不是 APK 文件 MD5**。备案按原接入商的字段说明填写。Google Play 的上传密钥与用户实际安装包的签名密钥不同；如未来同时上架多个市场且需跨渠道升级，应预先规划 Play App Signing 的同一应用签名密钥，不能把上传证书误填成实际安装包证书。

## 现有备案优先核对，再补 Android

源码中的 iOS 商店资料已登记一个 APP 备案号，属于历史提交资料，不能证明当前权威状态或 Android 平台已登记。不把该号码直接写入 Android 产品界面或宣称备案完成。

1. 在原接入商后台和工信部系统核对主体、APP 名称、备案状态、已登记平台及原接入关系。
2. 同一主体、同名 APP 已有有效备案且缺少 Android 时，向原接入商提交增加运行平台的变更。若已登记 Android，先核对包名、公钥和证书 MD5，避免重复办理。

   若发现同一正式包名已经分发过其他签名的 APK，应先找回并核验原签名密钥与历史安装，不直接把本次新证书当作可覆盖升级的替代品；按实际情况制定签名兼容与数据保留方案。

3. 使用实际服务的域名、IP、云资源、SDK 和分发渠道，不以隐私网页域名代替完整业务网络信息。不为备案预先购买新服务器，不擅自迁移原接入关系。
4. 原平台预审后由属地管局审核；所需短信、人脸、签章或负责人核验由相应本人完成。收到核验通知按其有效期处理。
5. 只有权威状态及 Android 特征核对通过后，才接入正式 APP 的备案编号展示和查询链接，并进行原生验收。

项目会生成忽略且 0600 的 `.env.android-filing.local`。用户仅需在本机补充字段或直接在原备案平台提交证件；不要在聊天中发送密码、身份证、手机号、证件或验证码。`pnpm android:filing` 实际读取此文件并生成 `.local/android-release/filing-private.json`，仅向终端报告缺失字段名称。`filing-technical.txt` 可填包名、公钥和 MD5；不含私钥。

## 用户需要准备的账号、资质和资料

备案操作应先核对原账号、主体、订单与已有平台，继续处理原订单；结果未知时先查原回执，不新建重复申请。真实负责人、证件和订单操作记录仅保存在本机私有目录，不进入源码仓库。

| 项目          | 已有资料与还需确认的部分                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| 原备案账号    | 原接入商/分发平台名称及可登录的企业账号；优先使用已有合法会话，密码不发聊天                                         |
| 现有 APP 备案 | 后台权威记录、主体、APP 名称、现有平台与特征信息，确定变更范围                                                      |
| 主体材料      | 营业执照、统一社会信用代码、主体地址与负责人等，按原平台要求核对，不从公开名称猜造证件信息                          |
| APP 负责人    | 姓名、可接收核验的手机号、邮箱及所需身份证明；授权书/人脸/短信/盖章由实际页面决定                                   |
| 网络资源      | 实际业务域名及实名认证归属、服务器接入商/地域/IP/资源标识；包括实际中继和通知路径，保留自有 Host 可变地址的真实说明 |
| 应用说明      | 同名 Android 包、用途、类目、分发渠道和实际 SDK；项目已可导出包名/签名技术字段                                      |
| 应用市场账号  | 按目标用户机型注册或使用对应企业开发者账号；海外渠道另按适用地区完成 Google 开发者验证                              |
| 商店补充资质  | 软著、商标/授权、前置审批按真实业务与各渠道要求核对；不将其列成所有 APP 通用强制项                                  |
| 密钥备份      | 正式签名密钥及密码的企业离线加密备份与恢复负责人；丢失可能影响既有安装的升级                                        |

## 其他发布门槛：尚未因此关闭

- 项目内现有隐私网页正文明确为 iOS；Android 当前入口指向该 URL，仍需按 Android 实际权限、SDK、通知、语音、第三方服务及删除/撤回路径修订并正式发布，本次线上政策内容未核实。已补[Android 专用政策草案](android-privacy-policy-draft.md)，按源码区分系统识别、本地 Vosk 和电脑端转写，正式发布前补齐文末确认项。不得把项目内草案视为线上完成。
- 审查最终合并 Manifest、依赖/原生库、权限按需请求、同意前数据行为和网络地址。包有相机、录音、媒体、通知与局域网权限，不以仅有权限声明判定已违规或已合规。
- 使用最终签名产物逐品牌执行新装、升级、启动、系统安全扫描、草稿/凭据保留；商店安装与官网 APK 分开记录。开发包/验收包通过不能替代正式包验证。
- 现有 Android 功能对齐、后台通知和暂停范围保持其原台账状态。签名构建通过不等于功能全部验收。
- 历史 iOS 上架资料记录过中国大陆生成式 AI 资质审核反馈，当前 iOS 排除大陆供应。Android 应如实说明 Agent 管理、远程访问和第三方 AI 处理方式，向原接入商/目标市场核实其真实业务类目与适用资质；APP 备案不代替其他适用资质，不以更名或隐藏功能回避审核。
- 真实误报保留设备、系统、提示原文、包摘要和证书指纹，再向对应检测方申诉，处理后复测；不要求用户关闭安全防护。

本次包含构建与发布工具准备及原备案续填，没有新增产品功能 ID 或修改双端 UI/领域规则；iOS 发布身份、上架地区和既有资料保持原约束。源码检查、正式包签名核对、真实设备验收、备案及商店审核各自记证。

## 验证范围

发布工具的单元测试覆盖 APK 的缺失、错误和多签名身份拒绝，以及证书指纹／RSA 公钥字段导出。AAB 当前通过 jarsigner 验证并比对导出的证书；尚未增加未签名成员或多个签名身份的专项拒绝测试，不将其描述为完整发布安全验收。

2026-11-19 留存的 APK/AAB 大小与摘要已核对，但其源码指纹与当前工作区不一致。这些历史产物不能证明当前源码构建、正式安装／升级或商店审核通过。当前提交保留工程能力和验证边界，发布前须针对准确源码重新构建并核对最终签名产物。
