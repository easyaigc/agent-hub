# 空会话准备与原桌面独占执行研究

日期：2026-10-09。当前状态：本机 macOS、MacBook 128 和 Windows 的隔离目录下，零模型调用准备、持久化和跨进程只读核对均通过；本机原桌面接管、项目／无项目首条、原内置工具及回复已通过；正式 Host、远端接管、iPhone 和完整回归尚未验证。此研究不能作为能力启用证明。

## 要解决的问题

现有 `DesktopControllerBridge` 通过普通控制聊天调用内置创建工具。控制聊天归档后 owner 消失，因此全局新建能力也消失；重新打开或重建控制聊天不能满足服务生命周期要求。

候选流程为：手机固定 Host、项目和操作 ID → Host 持久化创建意图 → 官方 App Server 准备空会话并返回实际 ID → 保存标题使空会话持久化 → 准备进程退出 → 官方已有会话深链接 → 原桌面 owner 核对 → 原 owner 接收一次真实首条输入。准备阶段不调用 `turn/start`、不发送初始化正文、不执行模型、不写历史文件。

该流程调整了原“原桌面自己创建和执行”的边界：空会话元数据由 Host 调用官方 API 准备，执行由原桌面独占。用户于 2026-10-09 明确接受“由 Host 准备空会话”的方案，现进入实现及真实接管验收阶段；隔离探针通过仍不能直接启用正式入口。

## 已验证的范围

使用当前安装的官方 CLI 和一个没有登录凭据的可丢弃 `CODEX_HOME`：

1. `thread/start`，`ephemeral:false`、`historyMode:"legacy"`，返回实际会话 ID；此时尚无 rollout。
2. 对同一 ID 调用 `thread/name/set`，空会话得到持久化；`thread/read` 的 `turns` 为空。
3. `thread/unsubscribe` 不等同于进程退出，紧随其后的 `thread/loaded/list` 仍可能包含该 ID。接管前必须等待准备进程实际退出，不能只检查 unsubscribe 回执。
4. 准备进程退出后，重新启动独立只读连接。它能按相同 ID 读取持久化空会话，`turns` 仍为空，`thread/loaded/list` 为空。
5. 通过官方 `project/create` 建立隔离项目，将其准确 ID 传给 `thread/start`。跨进程读取的项目 ID 和目录均与准备目标一致，消息数仍为零。

统一探针为 `scripts/desktop-preparation-probe.mjs`，源码 SHA-256 为 `1c1a351ff96146e39c487574271eb0caa52cc942f8e278af91c12fc4248e8347`。它只继承必要的系统环境，将 `CODEX_HOME` 固定到新建的可丢弃目录；没有接受任意 RPC 的入口。通过 `CODEX_EXECUTABLE=<当前官方 CLI 路径> pnpm probe:desktop:preparation` 执行。三台电脑分别运行了同一源码，各目标报告经鉴权下载并核对身份、范围、字节数和 SHA；退出码均为 0，保存为空会话，模型 Turn 调用数为 0。

Windows 和 MacBook 128 的官方 CLI 均为 `0.162.0-alpha.2`。报告 SHA-256 分别为 `9f4c95594f8b145242b5ccd0080541b4608fb0b1d7b8e074680de6637b2b0fd6` 和 `4747eaa90c5012ea0707841087c2ec07eb9b00cd49beca12e3a897106b1b902e`。目标没有修改生产配置、旧操作记录和原进程。探针创建的会话只存在于各自独立 `CODEX_HOME`，没有接入原桌面。

这些结果只证明元数据持久化，不证明原桌面已经连接。上游 [thread/start 测试](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/thread_start.rs) 也区分新建的 live thread 和首次输入后的持久化。标题保存的当前构建行为以本机实际探针为依据，不直接从上游主分支推断所有桌面版本。

## 实现必须满足的边界

- 只读 `CodexHistoryReader` 保持只读。准备器使用独立窄接口，不能开放任意方法、shell、恢复其他聊天或模型调用。
- 开始准备前持久化原操作 ID 和完整目标指纹。收到真实 ID 后立即持久化；请求已经写出而没有确定回执时禁止再次新建。
- 准备进程必须实际退出。未确认退出时禁止交给原桌面发送消息，避免两个 live writer。
- 原桌面打开固定 ID 后，必须取得新的 owner 发现回执和对应 snapshot。目录、项目、首条输入、附件、模型与权限均独立核对；历史读取和 URL 打开成功不能代替 owner 证明。
- 首条输入沿用现有持久操作回执。崩溃或超时后的查询不得重复执行未知输入；脱离等待也不取消或重放原操作。
- 正式可用性由服务与原桌面连接、当前构建的真实证明决定，不读取任何普通聊天作为运行前提。
- 原桌面仍按官方方式启动。不修改安装包、官方历史、签名校验或私有 App Tools 访问条件。

## 剩余验收

需要实际验证项目与无项目的 UI 归属、零聊天项目、全部原工具恢复、模型和权限设置、混合附件首条输入、回复、停止、审批、断线与 Host 重启恢复。必须归档原配置／控制聊天后仍能新建，并完成 Windows、Mac 和正式 iPhone 验收后才可统一分发和启用。
