No iOS change or A6 execution.

Android now has a separate explicit discard method, and VoiceInputStrip's close/ending-wait action uses it. Re-recording, including switching to system dictation, first completes that same local intent. A saved/provisional original requires a matching durable local terminal acknowledgement before UI clear or new capture. Missing port, write failure, timeout or wrong recording/fingerprint keeps the failed original visible and exposes a local discard retry; it does not quietly query/transcribe the original instead. While the marker is pending the close control is disabled and the local ending status replaces the computer-transcription label. System-only speech has no saved original file to mark and clears only its own capture/partial text.

NativeVoiceDiscardRequest carries the exact original snapshot and a SHA-256 intent fingerprint over ID, normalized machine target, model, certificate, draft key/ID, thread, creation time, original-text SHA and the known manifest. It excludes mutable prepare/upload/receipt flags, so a late receipt cannot change the original local intent. The port must verify request.matches(current); a known manifest cannot change. An originally provisional manifest may advance to a sealed manifest for that same immutable original. Codex account metadata is not a connection/discard gate. NativeVoiceDiscardReceipt must acknowledge the exact ID/fingerprint and a no-longer-offerable local terminal.

Parent integration is `bindVoiceDiscardIfMissing { /* storage-owner port */ }` after/beside voice configuration. The factory is lazy and attached once to the ordinary/question controllers. No specific adapter is referenced, and VoiceRecordingStore/Schema/migration are unchanged here. Until the owner binds a real port, a saved recording fails explicit discard honestly. The owner chooses an existing valid terminal or a versioned marker and excludes it from restore offers after reopen, including activated migrated recordings. Original operation/audio/attachments/receipts are not replayed or deleted by this Controller path. This is not a remote cancellation API. Exact owner responsibilities are in stage7-discard-owner-hook.json.

A local registration deferred retains an exact begin result even if cancellation arrives during the local write. Explicit discard invalidates callbacks, joins old work and stops capture before constructing its marker intent. It cannot clear a still-unknown registration or open a replacement microphone without a matching terminal. Background or navigation during the wait revokes the delayed re-record continuation, even if the same draft becomes current again. Navigation cancel still detaches presentation and preserves restoration; if a marker fails after navigation it may detach only after capture ended, leaving the unmarked original recoverable. This is different from falsely reporting explicit discard success. Suspension preserves pending content. No old result or local acknowledgement can fill another/current-new draft.

The older recovery test now supplies an explicit fake terminal and waits for it before the injected new system capture. These port tests do not prove a production marker/restore adapter, because no terminal Schema was implemented here. They compile but have not executed in this workline.
