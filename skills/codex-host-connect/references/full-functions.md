# 默认完整功能接入与验收清单

首次接入、增加电脑、修复、升级默认使用本清单。完整范围是本产品当前已实现并适用于原桌面模式的功能；用户明确指定子集时记录缩小后的范围。先读取随包实现、运行文档、手机界面和实际 Host 能力，再列出适用项目。已实现功能因配置缺失、身份／协议不匹配或 owner 探测失败而消失，属于待修复，不能改标为“未实现”后省略。

## 安装配置与能力核对

正常安装核对稳定 Host ID、鉴权、回环与实际 HTTPS、当前用户登录自启及全部适用能力。独立桥接默认配置正式 `desktop:creations`、`desktop:creations:projectless`、`desktop:open`；私有权限、本机身份与真实 IPC 就绪决定是否可用；不检查 Codex 应用版本，桥接配置的版本字段可省略且旧值不限制能力，不要求 `verification`、Xcode、iPhone 在场或第二台电脑。正式配置省略 `validationOnly`；用户明确选择的验证专用配置保留。实际操作继续检查原 owner、准备进程退出、目标隔离及持久去重。

默认同时配置自动发现和点选连接，首次接入不以扫码或手动输入密钥为前提。按 [Host 部署](host.md#身份与本机检查) 检查实际私网直连描述与公钥授权，逐项对照当前能力；旧版缺失实现先统一升级。用户明确的关闭发现、验证专用或其他子集选择仍保留。协议就绪可报告已启用；手机未在场、纯跨网无目录来源或其他网络条件缺失时单列未验收，不能据此关闭已实现的正常入口。

每次适用平台的完整安装和升级都完成 [Trace 配置与收尾](desktop-suggestions.md#每次安装与升级的收尾)：说明建议同步的好处与本机保存范围，默认配置持久环境及 Host 观察器，保留用户明确选择，不逐项追加授权。核对未来环境后交付正常重开的具体动作；程序更新、当前 Trace 生效和手机结果分别记录。Windows 使用专用持久工具和原生 DACL，按本机实际部署与运行结果交付。

下列真实验收清单保持完整，按规范仓库最新 `AGENTS.md` 实际执行并单列证据。新包新增已实现的适用功能时，对照运行时契约和手机入口补齐本清单，不将旧能力列表当作默认完整接入的固定上限。安装完成、正式能力启用和全功能实测通过分别表述；报告缺失／过期不关闭独立桥接，不能将能力声明当成场景通过。

## 必验功能

| 身份、鉴权与网络                     | 回环和实际 HTTPS 指向同一稳定 Host ID；错误密钥被拒绝；手机在同一 Tailscale 网络真实连接。网络切换结果分别记录。                                                                                                                                                                                                            |
| 自动发现与点选直接连接               | 默认启用 Bonjour、VPN 目录与私网 HTTPS；公开 `/host` 不含密钥且声明 `automatic`。手机首次点选不扫码、不输入密钥；X25519 公钥 claim 返回加密独立凭据，同公钥重试沿用凭据，真实工作区完整目标与原桌面模式一致。App 重开恢复、地址更新和跨目标隔离另验；仅发现旧版电脑不算连接通过。                                           |
| Host 登录自启                        | 默认安装当前用户 LaunchAgent／交互登录计划任务；核对启用、程序路径、意外退出恢复设置、当前运行与身份。真实注销／重启后自动恢复和原身份保持单独验收，未执行时标明未验收。显式停止关闭自启，重新启动恢复同一私有状态。                                                                                                        |
| 项目、聊天与历史                     | 核对原桌面项目身份、聊天归属、分页、标题和正文；连续切换至少三条聊天，原 owner 状态与手机一致。                                                                                                                                                                                                                             |
| 项目内、零聊天项目、无项目新建       | 由独立桥接执行；测试前完整分页确认空项目；正确 native 项目或明确 projectless；官方零 Turn 元数据准备实际退出、原内置工具、准确 Thread ID、首条正文和模型回复对应，创建与输入各一次。                                                                                                                                        |
| 未加载聊天主动打开                   | 测试前独立只读探测未确认 owner；原导航打开同一 ID 后确认实际 owner，再从手机回复。导航返回成功不能替代执行核对。                                                                                                                                                                                                            |
| 对话分支与独立工作树                 | 当前实现适用时默认开放 `threads:fork`、`threads:fork:worktree`；核对准确已完成 Turn、新 Thread/项目归属、原输入与执行器不变，以及工作树从当前授权现场派生并保留未提交内容。无 Git、未完成 Turn 或不支持的现场明确拒绝；结果未知按原操作 ID 查询，不重复创建或重放模型输入。                                                 |
| 输入、附件与下载预览                 | 首条和后续文字、原生图片、TXT；模型读取正文外随机码及图片内容；实际上传下载字节和摘要、手机预览与原桌面正文/图片/附件显示一致。                                                                                                                                                                                             |
| 独立文件接收                         | 手机侧栏“文件互传”经系统 Files 选择文件上传至该 Host 的固定接收目录；核对真实字节、SHA-256、保存路径、同名不覆盖和 App 重启回执。声明 `files:upload`，不要求聊天或模型运行；不能用聊天附件验收替代。                                                                                                                        |

| 排队与追加                           | 实现且适用于当前模式时验证 queue、steer、FIFO、取消和同轮追加，核对原 owner 实际输入次数；缺少预期能力先修复。                                                                                                                                                                                                              |
| 审批与用户问题                       | 验证当前适配的真实命令/文件审批及问题回答；固定请求、Host、Thread/Turn；核对实际工具结果和另一端请求失效。                                                                                                                                                                                                                  |
| 模型与会话设置                       | 实现且适用于当前模式时验证模型目录、推理、计划与权限设置、速度开关开启／关闭；项目内及无项目新草稿记住选择，重启保留，其他目标隔离。真实 owner 的首条与下一轮参数应匹配；倍数不是可调数值。测试后恢复原设置。                                                                                                               |
| 桌面下一轮建议（macOS／Windows x64） | 原客户端按已配置的 Trace 环境正常重开；来源 Thread／Turn 与预测执行准确绑定，实际 GET 与原响应一致。手机原有连接真实展示、采用只填草稿、撤销、已有原文保护与两个来源切换，原 owner 无新增手机输入。Windows 使用本机原实例与句柄／DACL 校验；正常图标重开、原记录、HTTP 与手机分别实测，不把 Host 升级或能力字符串当作通过。 |
| App 本地输入                         | 手机已提供语音转文字等本地输入时验证其正常生成目标聊天草稿；系统权限缺失列为未验收条件，不能靠 Host 能力声明证明。                                                                                                                                                                                                          |
| 恢复与去重                           | App 回前台/重启、网络断开再恢复、本产品 Host 重启；操作和聊天身份保持，创建/首条输入不重复；未知结果先核对回执。                                                                                                                                                                                                            |
| 多电脑与草稿隔离                     | 有第二台实体电脑时分别真实新建与回复；连接、草稿、事件、审批和回执不跨目标，保留既有连接与用户草稿。只有一台时记录双电脑项待验证。                                                                                                                                                                                          |
| 正式入口与回归                       | 保存本机真实创建/打开证据；正式配置不带测试限制，用户明确的验证专用配置保留；普通启动的正式手机 App 新聊天按钮可用并完成真实模型回复；升级前已验证功能按受影响范围回归。                                                                                                                                                    |

各项结合 [原桌面与手机验收](acceptance.md) 的八个原生场景、普通 App 补充场景和真实 iPhone 验收执行，允许一个真实场景覆盖多项。八项通过不自动证明未覆盖的语音、模型设置、排队或跨网络行为。客户端可由有 Xcode 的主开发 Mac 驱动，目标电脑的原 owner、工具调用、输入与进程身份仍须独立核对。

默认完整接入必须实际开放 `desktop:creations`、`desktop:creations:projectless`、`desktop:open`；缺失时核对私有配置、本机身份、实际版本、真实运行时协议和桥接生命周期，修复后重测，不要求补造报告。测试配置 `validationOnly` 不被普通 App 接受，不能作为默认正式安装；用户明确选择时保留并说明范围。旧兼容 driver 的 `openOnly` 仅用于用户明确只要打开或临时验证。

归档或关闭安装配置聊天及历史控制聊天后，桥接、新建与主动打开应继续工作；这项必须在真实桌面和正式手机验证。当前控制聊天 driver 会随其 owner 消失失去新建能力，属于已确认的设计失败，历史新建通过记录不能覆盖该失败。临时恢复 owner 不等于根治，也不证明旧未知操作已完成。

结果待确认时，本地草稿仍可编辑、清空和删除附件；原操作内容与附件保持不可变。用户明确结束等待后保存独立可查询回执，允许新的操作 ID；结束等待不意味着取消远端或自动重放旧请求。晚到回执不得覆盖新的草稿、操作或当前选择。验收后同时核对 Host 正式声明与手机实时按钮，不能只查看缓存或历史记录。

## 结果和证据复用

逐项保存目标、实现/环境指纹、配置状态、正式能力、测试场景、原生结果、模型回执、原桌面独立核对和时间，区分：

- 本次通过：该项在当前环境真实执行并核对。
- 复用通过：证据目标、桌面构建、实际运行 Adapter、客户端实现与该项条件仍匹配；注明来源与原时间，不伪装为重跑。
- 失败：实际不符合预期，继续定位修复；只撤销受影响能力。
- 未验收：缺真机、网络、系统权限、授权或该项原始证据；记录完成所需动作。
- 未实现/不适用：由当前实现和模式边界确认，并注明依据；不能用来掩盖已经实现但尚未接通的功能。

六项创建门槛及未加载打开通过后才派生对应验收证明；完整清单另外记录，不把辅助编译或 fixture 合成通过写入真实证明。每台电脑派生自己的证明，证明仅记录覆盖，不作为独立桥接的安装／启用门禁。只更新 SKILL/文档且实际 Adapter、客户端与环境未变时，保持原证明和运行配置，复用匹配证据；不要为同步文档重启 Host 或触发模型重跑。

全部适用能力已配置且运行检查成功时可报告安装完成；完整实测通过须全部适用必验项目本次通过或有匹配证据复用通过、正式入口可用且回归无未解决失败。验收未完成时仍交付参数、可用功能及剩余动作，不等待用户再次要求新建/主动打开。APNs、后台传输、公网 Relay、自动冷启动原 Codex 等能力按当前实现和配置单列，不因 Host 安装而自动报告可用或已验证。

通知接入新增 `HOST_NOTIFICATION_RELAY_URL` 与 `HOST_NOTIFICATION_PUBLISHER_TOKEN_FILE`，按电脑独立配置，不随统一代码包复制凭据。没有正式 APNs 绑定时准确显示仅前台提醒，不宣称后台或锁屏已验证。升级保持原通知账本、Host 身份和密钥；包 SHA-256、APNs 接受与 iPhone 实际收到分别记录。通知专项不能替代完整新建／打开／归档控制聊天后恢复的门槛，详见仓库 `docs/notifications.md` 与 `docs/acceptance/task-notifications.md`。
