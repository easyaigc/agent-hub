# 原桌面共享服务的控制适配

2026-11-24 源码候选。部署和手机验收分别记录；当前功能状态只在[唯一功能清单](../plans/android-ios-alignment-20261107/progress.md)维护。

原 `desktop-runtime` 使用私有 follower IPC 取得桌面 owner、状态和控制。当前本机桌面未监听该入口，相关 follower 方法也未在当前桌面产物中发现，而原 Electron 启动的共享 App Server 仍正常运行。因此缺少 IPC 不应使实际可用的同一原桌面服务永久断连；不能仅通过修改版本声明恢复能力。

调用链为手机既有 HTTPS/设备授权 → Host 原有完整目标和不可变回执 → `RuntimeSession` → `DesktopRuntime` → 已验证的原桌面共享服务。外部 `agentId/hostId/workspaceId/runtimeId` 保持原值，仍为 `desktop-runtime`。不切换为托管运行时，不产生第二执行服务，不变更登录、密钥、草稿或操作 ID。

## 选择与归属

先使用原 IPC。仅 `ENOENT` 或 `ECONNREFUSED` 且已有明确共享 URL 时尝试共享适配；权限失败、协议结构不兼容和未知结果不触发替代写入。旧 IPC 和 Windows 原路径保持。

共享入口仅接受明确的回环 WS 根地址。验证私有 v2 环境与 launcher 摘要、owner 文件、当前用户、进程开始时间、原 Electron utility/launcher/官方 executor 父链及唯一端口监听。读前及命令写出前复核同一代身份；变更、歧义或退出撤销该次就绪。只关闭 Host 自己的 WebSocket，不关闭或重建原桌面服务。

进程查询异步执行，不阻塞 Host HTTP。健康连接内的普通只读归属检查与 loaded 目录合并，并仅复用最多一秒的观察；历史中不存在的 owner 不逐条启动系统查询。显式命令仍单独刷新 loaded 目录并重新核验进程归属，然后才进入原持久化写出边界。断线清除读租期、模型/权限观察和旧代合并占位。

## 操作映射

| 领域含义      | 共享服务方法与约束                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 浏览项目/历史 | 原独立只读 reader 保持；不 resume、不发送模型输入。                                                                      |
| 当前会话可控  | `thread/loaded/list` 正面命中准确 ID，再用同服务 `thread/read` 验证目标及当前状态。持久历史不授予控制。                  |
| 最新状态      | 对已观察会话读取有界 turns/items 窗口，结合实际通知刷新；窗口不是完整历史，不替代原历史分页和未知回执核对。              |
| 显式发送/追加 | 只对已加载原会话 attach 同服务连接，省略模型、速度和权限覆盖；然后映射 `turn/start` / `turn/steer`，复用原持久提交边界。 |
| 停止          | 映射 `turn/interrupt`，要求准确且仍活动的原 Turn ID。                                                                    |
| 设置          | 映射 `thread/settings/update`，仅原操作已指定的设置进入请求。                                                            |
| 审批/问题回答 | 仅处理本连接收到且与同一线程/请求匹配的请求；等待准确 `serverRequest/resolved` 后确认。                                  |

读连接不会 attach 未加载对话或创建执行器；显式打开仍沿既有具名打开与原桌面 URI。结果未知不通过另一通道重发。断线/关闭使晚到读取失效，后续重连只建立新的观察，不迁移或重复输入。原 Host 的回执、审批、附加文件和恢复规则继续有效。

旧桌面预设同时携带 profile 提示与具体 sandbox；当前共享接口要求二者互斥。仅三种已知预设与具体 sandbox 类型一致时，保留完整 sandbox（含根目录和网络限制）及审批策略，移除重复提示。未知自定义 profile 或冲突在写出前拒绝，不猜测或扩大权限。

共享服务的 `thread.projectId` 同时转换为既有 owner 快照的 `workspaceKind`：非空项目 ID 对应 `project`，明确的 null 对应 `projectless`，缺失或无法识别的值保持未确认。独立新建仍先核对官方空会话的准确项目、目录及零 Turn，再确认同一原桌面 owner 后提交首条输入。不能因新通道省略旧字段，把已打开的空会话长期误判为接管失败；也不能用缺失字段推断无项目归属。

## 网络配置恢复

系统信任的 Serve HTTPS 地址与固定证书的 LAN/VPN 直连属于不同信任路径。迁移到 Headscale 后旧 `.ts.net` 地址不可凭名称继续宣称在线，也不能把新私有证书套成系统 CA。核对实际控制网络、Serve 路由、直连描述和原证书，再撤下已失效的配置广告。手机在原 Host 记录内学习/更新可达的固定证书入口，保留设备授权、草稿和原操作；不删除重建电脑记录。

## 验证边界

辅助回归覆盖无副作用读取、正面 loaded/归属门禁、同服务显式 attach、速度继承、持久化写出边界、未知结果不重放、审批确认及关闭后的晚到读取。真实部署另核共享服务进程归属、原 Host/证书/设备授权指纹、实际手机项目/历史读取与一次独占测试输入。HTTP、辅助测试及原生手机结果分别留证。
