# 阶段 108：F59 大文件内层封包

Android/KMP 新增独立的 F59 内层流。清单按原 root/UUID、类型、规范名称排序，校验逐项长度与 SHA-256，使用 Long 表达总内容和文件长度。读取验证清单、顺序、尾部、物理 EOF 以及清单/内容/整流摘要。调用方须提供独立可信的预期回执，不能从输入本身取得未认证摘要后当作可信结果。

每项只借给同线程、当前同步回调；迟到或异线程访问在接触 I/O 或错误状态前被拒绝。已发生的第一个 I/O 错误仍为原错误，回调晚抛的其他错误只保留为附加诊断，不重试、不关闭调用方流。完整回执之前只能惰性暂存。Swift 独立小向量验证只用于同字节对照，未接 iOS 产品。

新 SDK purpose `p7-f59-inner-source-v1` 固定 947 个输入、131 个覆盖（130 固定及当前工具自绑定）和原 15 加新 8 的 23 个方法资格。仅增加五个实际编译/测试输入，另绑定主线后的 package.json、pnpm-lock.yaml；旧 SDK purpose、两包构建方法与原验收指纹保留。六份源码及 SDK 工具的准确摘要见产品矩阵。

本切片没有写明文文件、认证加密实现、持久化/SAF/激活、界面或真实 Host 入口；旧 v4/envelope2、原 iOS Payload 和有 F59 时旧整包拒绝保持。未证明真实超 Int 字节传输、完整 24 域、完整 F59 迁移、真机或真实 DEV，原未知操作不重放。任务与项目管理、F75、iOS A6 暂缓。
