# Codex 控制请求等待与本机 Host 同步升级（2026-11-19）

范围：F17/F18/F28/F47、UI04/UI05、S03/S11。Codex 专项，不接管 iOS × EasyWork 唯一计划、Android 独立进度或 A6。

## 两个独立问题

已合并的 Host 同步修复解决原 owner 消息尚在投影时提前发布 `unavailable`。此前受控真实 Electron／原生模拟器对照中，旧正式模块 13 次目标轮询中有 2 次不可用，修复模块 9 次中为 0；两轮均未发送模型输入。该证据不证明发送等待问题已经解决。

本轮进一步确认 iOS 控制请求的两处缺口：连接总截止时间在首次打开返回之后才建立，循环外及循环内的单次 `await` 没有绝对上限；URLSession 请求空闲超时会被持续收到的数据续期。旧路径恢复还遗漏打开状态与消息回执 GET，旧查询可能继续占着发送或恢复观察。辅助测试能够在受控 HTTP 小段响应下保持旧请求悬挂，同时另一个新连接已能查到原操作结果；这不是原手机自然故障的抓包证明。

## 实现候选

Codex JSON 控制请求以 `ContinuousClock` 同时约束完整请求和上层连接预算；连接的 180 秒预算在首次打开前建立，单请求沿用其显式时限，普通请求为 35 秒。即使持续收到响应片段，也不能无限续期；迟到结果不作为本次等待成功。

路径恢复取消具名安全 GET，包括历史、事件、目录、打开状态和消息回执／投递状态，以便同 ID 继续核对。POST 不因恢复自动重放，等待超时也不表示远端已取消。原消息／打开操作 ID、草稿和附件保留；二进制上传、下载与开发预览沿用各自传输预算。Android 不使用该 URLSession 实现，本轮没有 Android 原生通过结论。
