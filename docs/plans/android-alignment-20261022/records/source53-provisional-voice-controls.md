## 准备与上下文修正

首次准备失败没有改变产品预期：完整录音的共享 helper 继续要求可检查 manifest；未封口专用准备经相同 destination admission、队列同步和真实 `beginVoice(recoverSavedFile=true)`，核对恢复的是同一条原件，不直接设置 FAILED 或 pending，不封口、修头、发送或替换原 row。

后续崩溃没有可归因的原堆栈。独立静态检查确认，锁定的 AndroidX 组件存在将 framework application Context 强转为 Application 的路径，全局返回私有 ContextWrapper 有契约风险。r5 保持 framework Application 原样，Main 内的项目接入通过默认值等同原值的 `runtimeContext()` 窄 hook 使用私有安装；正常、retained、P9 和 restore 顺序保持。这是更正当的候选边界，不能宣称已经确认原崩溃根因。

未来新场景的 test-only uncaught reporter 只输出有界 Base64 诊断并委托原 handler，不伪造方法终态；诊断送达与同步耗时没有保证。旧 unknown 不因增加诊断而重跑。

## 继续与待验

原 API26 现场隔离；另建无 App 的 API26 环境，并在原启动进程退出后以任务专属临时服务恢复，非登录自启、无自动重启。新 boot 独立重新冻结期待，首次安装前核三包完整缺席；安装后显式准备缺失框架目录，不改既有目录模式、不创建默认 store/key/cipher。完整基线无默认目录/文件，未授权麦克风；这不是 Android 默认0771模式证明。当前三个 owner 方法在新 API26 通过：完整原 raw/row 导出与惰性激活、活跃 writer 拒绝且不停写、冻结拒绝真实 capture 和原件修改。六个基础方法在当前双 SDK 复验通过，独立核795份实际调用；47份首次安装调用另列。上述原生中未发生新 unknown。API37 owner、未封口流式与不同进程链、父侧完整 owned 原件/缓存采集、语音交互/模型控制和 UI7 当前 AX/像素继续分别验收。刻意保留的符号链接和共享缓存不伪称普通私有文件树。
