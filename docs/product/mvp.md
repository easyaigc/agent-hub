## 用户与核心流程

第一阶段服务于拥有多台开发电脑的个人用户。电脑端先支持 macOS，客户端先支持 iPhone / iOS 17 及以上。

典型流程：打开手机 → 添加或切换客户端 → 选择或添加项目 → 新建或继续对话 → 发送文字、图片或文件 → 查看结果或处理审批。

官方手机 Remote 已覆盖相近场景。产品应重点验证统一多电脑总览、自托管连接、待处理事项聚合和用户自己的管理流程是否具有独立价值，不能仅依赖界面重新包装。

## 首版界面

| 页面     | 内容                                       | 验收重点                               |
| -------- | ------------------------------------------ | -------------------------------------- |
| 左侧栏   | 当前客户端的项目、历史与关联对话           | 同名项目不混淆，不跨电脑错误归类       |
| 客户端   | 添加、配对、切换、在线状态、最后在线时间   | 所选设备清晰，电脑确认与离线行为准确   |
| 添加项目 | 选择所选电脑上的已有目录、设置显示名称     | 目录所属电脑清楚，不重复登记           |
| 新建对话 | 选择或继承项目、输入首条消息与附件         | 首次发送目标明确，不重复创建线程       |
| 对话详情 | 历史分页、增量回复、输入框、附件、停止任务 | 发送目标明确，历史与实时状态来源可区分 |
| 待处理   | 需要回答的问题、审批、失败与完成提醒       | 请求不重复处理，不操作已失效任务       |

采用 ChatGPT APP 风格的主聊天区和左侧项目、对话抽屉，右上角增加 Codex 客户端切换。新对话由顶部或侧栏进入，设置由侧栏底部个人入口进入，待办放入次级入口；不使用三个底部页签。详细流程、视觉规范、异常状态与可点击原型覆盖见 [iOS 初版 UI / UX](../design/ui-ux-v1.md)。

当前原生 iOS 已实现真实持久对话、混合附件上传/下载、流式消息、工具/计划/Diff、Turn 控制、审批和断线恢复。直接 Host 使用 HTTPS 与 Keychain 密钥；保留明确标注的本地示例和 history-only 路径。当前本机官方桌面没有开放共享 socket，托管线程不替代桌面已有线程接入。验收见 本机验收（本地文件 `docs/acceptance/ios-local.md`）。

## MVP 必需能力

- 一次性配对、电脑确认、设备撤销。
- 切换至少两台电脑，按电脑查看项目与对话。
- 添加电脑上的已有目录为项目，明确所属客户端并避免重复登记。
- 全局新建选择项目，项目内新建继承项目；首次发送时创建对话并防止重复创建。
- 原桌面模式的新建须由原桌面执行，覆盖已有项目、空项目首条对话及无项目对话；验证来源和同一执行实例，不能只验证新线程出现在存储列表。
- 读取历史、展示工具活动与实时输出。
- 继续已有会话；运行中消息提供清晰的排队或调整行为。
- 文字、截图与文件回复，展示附件传输和提交进度。
- 处理审批与用户问题，并同步已处理状态。
- 前台断线恢复与后台通知，明确离线和未发送状态。
- 版本兼容范围、能力降级和本机安装启动方式。

## 暂不纳入首版

完整远程终端、代码编辑器、跨电脑迁移任务、团队协作与权限体系、远程唤醒电脑，以及任意文件格式均可直接理解的承诺。Android 已作为完整后续版本单独规划，不属于本段的排除项。

新建会话、登记授权根内已有目录、渲染上游文件 Diff 已实现。创建新目录/Git 仓库、完整代码审查编辑器留到后续。官方桌面共享运行时仍是独立门槛，真实托管链路可先验证功能，不能据此宣称桌面接管成功。

## 里程碑

| 阶段           | 交付                                               | 进入下一阶段的条件                 |
| -------------- | -------------------------------------------------- | ---------------------------------- |
| M0：仓库初始化 | Monorepo、Xcode 工程、服务健康检查、工程规范与文档 | TypeScript 与原生工程可构建        |
| D1：交互设计   | 客户端、项目、新建对话、回复与待办的交互原型和规格 | 核心流程与目标上下文经过评审       |
| M1：共享运行时 | 官方桌面已有项目和会话的读取、实时状态与回复       | 原会话收到回复，不出现重复执行实例 |
| M2：跨电脑     | Relay、iPhone、两台电脑的文字闭环                  | 路由准确，重连不丢历史或重复执行   |
| M3：附件与审批 | 图片、文件与审批同步                               | 内容确实被读取，请求只处理一次     |
| M4：MVP        | 配对、加密、撤销、推送、原生交互、安装与分发       | 关键 PoC 和恢复场景全部通过        |

如果 M1 只能做到 Host Agent 自己托管的会话，需要显式调整产品范围后才能继续，不能直接按“接管官方桌面会话”验收。

工程初估：PoC 5–7 个工作日；核心门槛通过后，2 名工程师约 6–8 周完成可用的 TestFlight MVP。估算不代表当前已有完整实现，也不包含不可控的外部审核等待时间。
