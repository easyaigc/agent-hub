# iOS 外部附件与文件粘贴（2026-10-26）

对应 F71／UI07。iOS 新增文件打开注册和“添加到 Agent Hub”系统操作扩展；附件面板的显式系统粘贴支持文件 URL、文件字节和图片。Android 对应接收／粘贴入口仍待 A6，暂停状态保持。

外部文件先复制到 App Group 的本地收件箱，扩展显示保存确认。返回 App 后可选择准确聊天，确认加入草稿或稍后添加。系统“用其他应用打开”直接进入 App；操作扩展遵循系统生命周期，保存后提示返回 App，不使用私有接口强行启动主 App。

文件只在用户发送时上传。收件箱按批次原子发布，名称／大小／SHA-256 校验，临时 URL 在供应器回调内复制；草稿代次和固定文件 ID 防止迟到回调及重复添加。收件箱只在准确附件落盘后消费；部分导入的原目标绑定保留，不能改投其他草稿。普通复制文本和网页链接不转为附件。

单附件仍为 20 MiB 上限；用户截图的 28.3 MB ZIP 会明确提示超限。该项不扩大 Host 或协议限制。

真机来源为当前电脑已配对的 iPhone 15 Pro Max（iOS 27.0.1），通过 CoreDevice 与 XCTest 无线执行。独立主 App 的 bundle 为 `com.easyai.agenthub.externalattachments.acceptance`，名称为 Agent Hub External DEV；受控来源为另一个独立进程 `com.easyai.agenthub.externalfilesource.acceptance`。按准确 bundle 和前台状态执行，不能凭相同图标／名称选中其他 DEV。来源只提供本任务创建的文件，不读取微信数据。

真实模型试验使用独立本机 Host、原 Electron owner 和显式手机发送。发送前 548 次观察没有发现附件上传、会话创建或输入提交；发送后原桌面独立确认一个用户输入、一个完成轮次和实际 xhigh。两个校验码来自图片／TXT 文件，不在请求正文。另从手机独立导出原始 TXT，与 Host 收到的文件逐字节摘要核对。最终 UI 包与模型包名称／DEBUG 夹具不同；附件读取、收件箱、草稿准备及发送生产源文件摘要逐项相同，分别保留包指纹，不宣称整包相同。

本次修复及失败记录：

- 首次模型试验发现 `NSItemProvider(contentsOf:)` 的文件 URL 可表现为 NSURL 二进制归档。旧读取将归档错误上传，模型仍可能根据归档中的路径读到原文件，因此“回复含校验码”不足以验收。该次独立字节核对失败保留；修复为原生 URL 对象读取，兼容官方 NSURL 表示解码，失败不降级为归档附件，再由本次物理手机原始文件摘要通过。
- 首次分享出现空收件箱列表，修复为展示不可变批次快照；扩展采用独立直接加载执行文件，避免调试 dylib 导致入口无法打开。
- 早期与其他真机 XCTest 竞争、入口同名及系统紧凑菜单的远端无障碍可见区域错误均保留为失败，不能算作通过；只停止本任务自己的冲突运行。标准分享／粘贴已在无竞争窗口按独立身份重跑通过。
- 直接打开的独立跟进已通过。系统“更多”列表的单元格不带名称，准确名称在子文字中，且位于初始可见区域之外；修正原生测试为读取准确文字并滚动该列表，不选择其他同名 App。此前失败保留。首张 App 局部截图为空白，原图保留。补拍重跑在点选目标前遇到系统菜单 AX 查询超时；Device Hub 按准确物理设备和 bundle 再激活后仍返回 DeviceKitError 3000（远端通知观察服务断连）。CoreDevice 激活及进程存在分别确认；该项仅记录预览／渲染待确认，不归因手机锁定、人类切换或产品白屏，也不把补拍失败算成通过。系统分享、收件箱及文件粘贴已有可见截图；最后的直达草稿全屏图仍未验收。
- 最后一轮完整检查曾在无关的审批 fixture 读取 `approval-response` 时出现一次 ENOENT；单独重跑该边界和完整 `pnpm check` 重跑均退出 0，原失败未改写或隐去。最后的原生截图测试微调另有签名编译及最终源指纹／一致性检查，不扩大 UI 通过范围。
- 模拟器早期两项交互通过仅属于当时包；后续修复以物理手机结果为准。全功能 F71、权限／字体／旋转组合矩阵及真实微信仍不升级为通过。
