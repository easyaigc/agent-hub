# 手机额度与余额 UI 设计

日期：2026-10-28，修订 6。状态：**修订 6 已获用户确认并实现到双端；真实 Host 到原生 iOS 模拟器通过，物理 iPhone 自动化环境失败单列**。对应 F73、UI02／UI03／UI12；[执行计划](../plans/agent-usage-20261028.md)、[类型约束](agent-usage-contract.md)、[交互源稿](../../design/mobile/agent-usage-preview.html)。源稿内所有客户端与数值均为虚构设计示例，不是当前账号实况。

## 已明确的两个展示位置

用户最新要求为两个位置同时显示，不再提供二选一的入口方案：第一处是客户端选择弹层中各个客户端的额度；第二处是切换后侧栏底部现有“个人空间”的设置入口区域，显示当前客户端额度。第二处不是另造一个设置首页或将额度藏进设置的次级菜单。

原生对照依据为当前 `apps/ios/Sources/Sheets.swift` 的 `ClientPickerView`／`SettingsView`、`apps/ios/Sources/RootView.swift` 的侧栏与 `open-settings`，以及 `design/mobile/tokens.json`。已查看原生合成基线的[客户端弹层](../../design/mobile/ios-baseline/clients--testClientEditCancelAndNicknamePreserveSelectionAndDraft--client-list-edit-entry--1.png)和[完整侧栏](../../design/mobile/ios-baseline/sidebar--testSidebarSearchAndProjectSelection--compact-sidebar--1.png)。截图用于核对原生结构；当前源码已有的“项目与任务”“文件互传”也保留在示意中。重绘是可点击设计稿，不是已实现功能的手机截图。

## 位置一：原生客户端选择弹层

保留真实手机界面的聊天背景、半透明遮罩、原生底部 sheet、拖动条、居中“客户端”标题和右侧“完成”。列表每行仍是电脑图标、名称、来源、在线／进行中／未读，尾部为选中标记和独立“编辑”。在该行原有状态下方加入余额与限制文本，不增加第三个独立“额度”按钮，不把客户端选择改成卡片仪表盘。

- Codex 仅周窗口与 credits：余额行 `12,480.13 credits`，下一行 `7 天剩余 68%`。
- Codex 多窗口：余额行 `840.25 credits`，下一行 `5 小时剩余 24% · 7 天剩余 59%`，实际返回的两个窗口都可见。
- EasyWork 算力：余额行 `8,640.13 算力点`，下一行 `今日请求剩余 760 次`；多余额可换行，不能混算。
- 未读取：`额度待同步`；不支持：`暂未提供额度`；旧缓存：`上次读取 · 15:24`。额度状态不替代既有在线／离线状态。

点击客户端主行仍只选择并切换客户端，随后两个位置使用该目标的数据；编辑仍只编辑连接，不选择客户端。余额是主文字，限制为次级文字；多个窗口按来源稳定顺序显示并允许换行。数据很多时最多显示两个余额和两个限制，附“另有 N 项”，详情保留全部；不比较异种限制、不自行求和。新增行使 sheet 优先展开到 large detent，字号不因条目增多而缩小，长列表由原生 List 滚动。列表只读取可见项且并发最多 2，离页停止，不唤醒全部已保存电脑。

## 位置二：侧栏底部用量圆环与两行小字（原设置入口位置）

保留真实侧栏与原底部分隔线、右侧收起按钮。按用户最新指示，“我”圆形头像改成用量百分比圆环，右侧最多两行小字；继续去掉“个人空间”文案。此前单行余额方案由本修订替代。

圆环图形 38pt，触控热区至少 44pt，中心用 11pt 字体显示“已用百分比”，例如 `32%`；弧长与中心值都表示已用，不与详情中的“剩余”条形图混淆。只代表来源明确主指标；未声明主指标时，在同一适用范围中采用稳定的首个有效窗口，并在右侧说明／辅助功能中标明来源，不把不同窗口或单位加总、取平均。Pro 示例对应 7 天已用 32%；双窗口示例对应 5 小时已用 76%，第二个窗口在小字及详情中保留。数量型限额仅在有真实 used／limit 且分母大于零时换算。

用户最新指定底部左右分区：左侧固定“齿轮＋设置”，右侧显示用量圆环与余额，数据组位于收起侧栏按钮的左边。排列为 `设置 → 弹性留白 → 用量圆环＋余额 → 收起侧栏`，不再把设置放在圆环右边或叠在余额上方。

- 左侧设置保留独立 60pt 宽、至少 44pt 高热区，13pt 文字与 16pt 齿轮始终可见，不随数据多少移动。
- 右侧用量和余额整体靠右，与最后一个收起按钮保持间距；圆环仍显示已用百分比，不混算窗口。
- 有余额时，圆环右边用 12／11pt 两行小字显示“数值”及“单位”，两行右对齐，例如 `12,480.13`／`credits`，避免窄屏挤压单位。多余额可在单位后显示 +N，详情列全，不相加。
- 没有余额时省略余额文字块，保留圆环；设置仍固定在左边，不在右侧重复设置文字。缺失不伪造 0，未知用量用中性横线。
- 离线时在单位行显示缓存标记，不冒充实时；额外余额数量可留在详情，优先保留单位和缓存说明。

左侧设置按钮打开原设置；右侧圆环与余额构成同一个额度详情按钮；最右侧按钮收起侧栏。三个独立热区不得嵌套或重叠。客户端名称继续在侧栏顶部，各按钮的辅助功能标签包含当前目标身份及用量范围。

设计预览提供“来源返回余额”开关，便于确认有余额／无余额两种形态；这只是设计数据开关，不是产品里的设置。

客户端 A→B 后底部立即显示 B 的身份；尚无 B 的数据时显示同步中，不能短暂挂着 A 的额度。两个位置读取同一目标缓存并复用新鲜数据，不能各维护一份余额状态。设计稿可从侧栏顶部进入客户端选择，选择任一台电脑后自动回到侧栏并更新底部，再点击额度查看详情。

## 详情的信息层级

1. 顶部导航：返回、`额度与余额`、刷新。下面始终显示准确客户端名称与 Agent；来源提供时展示 `Pro` 等套餐标签和“个人额度／组织共享”。套餐不参与计算或显隐。
2. `余额`：数值最醒目，单位紧邻且永远可见。每种余额单独一项；算力点、credits、货币不合计。只有余额、没有上限时不画环形图／进度条；有到期时间显示“有效至…”。来源明确无限时显示“无限制”，同时有数值则数值保留、另标“使用不限额”。
3. `使用限制`：按桶／适用范围分组，逐个显示实际窗口或容量限制。默认主文案“剩余 68%”，次文案“已用 32%”；条形图表达剩余，读屏同时读明方向。数量型显示“剩余 760 次／上限 1,000 次”，未知分母不画假比例。
4. 时间：窗口下显示来源的重置时刻，临近 24 小时内可同时显示相对时长；没有时刻时写“重置时间暂不可用”。到达时间后标“正在更新”，不自行恢复成 100%。余额到期和窗口重置为两种独立文案。
5. 页尾：`由 Codex 返回 · 15:24 读取`／`由 EasyWork 返回 · 15:24 读取`。有多个桶时全部保留；来源关系不明时用“各项额度由服务独立判断”，不承诺余额可解除窗口限制。

当前 Pro 账号应按实际返回仅出现 credits 和周窗口；不显示灰色的“5 小时暂无”，不宣称所有 Pro 都没有该窗口。其他账号若返回 5 小时，则自然出现对应卡片。

## 状态与文案

| 状态               | 呈现与交互                                                                              |
| ------------------ | --------------------------------------------------------------------------------------- |
| 首次加载           | 当前客户端身份先显示；数值区域静态骨架，“正在读取额度”；不出现临时 0 或虚构百分比       |
| 正常               | 精确余额的适当格式 + 实际限制；刷新只触发具名只读请求                                   |
| 仅余额             | 只显示余额分组；没有空的“使用限制”卡片                                                  |
| 仅窗口             | 只显示实际限制；不占位“余额 0”                                                          |
| 空数据             | `来源暂未返回额度数据`；保留客户端身份和刷新，不解释成免费或无限                        |
| 部分缺失           | 有效项继续显示；受影响项 `暂不可用`；页内“部分额度暂不可用”，刷新有界                   |
| 额度耗尽／超额     | 数值零或欠额／超额 + 文字提示；不阻止发送，不推断其他余额能抵扣                         |
| 旧版本不支持       | `此客户端暂未提供额度查询`；可说明更新连接程序，不以失败弹窗阻塞聊天                    |
| 未登录／禁止读取   | `电脑端暂时无法读取额度` 与来源可核实的具体原因；不引导手机输入账号、API Key 或模型令牌 |
| 断线有缓存         | `离线 · 显示上次读取` 和完整时刻；不显示实时成功状态；缓存按目标与额度来源隔离          |
| 断线无缓存         | `暂时无法读取额度`、重试按钮；不显示旧目标数值                                          |
| 切换与来源变化     | 立即更换身份／显示加载；旧请求不覆盖新页；Codex 账号元数据变化只影响额度数据            |
| 来源过期／更新失败 | 保留同来源旧数据并标时间和失败；无来源连续性就撤下数值。禁止循环弹窗                    |
| 未知扩展           | 已知指标正常显示；有界纯文本扩展显示在“其他额度”，不支持的未知类型提示部分不可展示      |

设计控件中的“部分缺失／离线缓存”等仅切换示例，不属于产品里的设置。可点击预览呈现同一设计的两个展示位置、三个虚构客户端、切换联动、原设置操作、详情、刷新和返回；不展示充值、消耗重置券、购买套餐或计费写入按钮。

## 数量、视觉与可访问性

- 延续 iOS 系统背景／次级分组背景／secondaryLabel、现有浮动表面与列表圆角；浅深色跟随系统。Android 映射同一语义 token，不因壁纸改变额度含义。
- 默认正文 16–17 pt，说明 12–13 pt，余额 30–32 pt、等宽数字；大字体自动换行且保留单位。行内金额可简洁四舍五入，但详情可展开“精确数值”并复制原始十进制字符串；协议原值始终不变。过大数值换行，不用科学计数法隐藏精度。
- 使用已有主色绘制剩余条，不为不同客户端各配彩色图表。耗尽／超额使用语义警示并加文字；低余额阈值只采用来源明确阈值，首版不猜“还能用多久”。
- iOS 触控至少 44pt，Android 至少 48dp；“选择客户端”“编辑连接”“查看额度”分别有独立热区和读屏标签。余额详情按钮不触发选中行，不出现嵌套 Button。
- 进度条无装饰性描边。读屏示例：“7 天用量，剩余百分之六十八，已用百分之三十二，下次重置十一月四日十五点”。未知比例无 progressbar 角色。
- 刷新过程中保留已有布局；同一来源数值更新可静态替换，不循环动画。减少动态效果时只显示静态加载说明。时间按手机时区／语言展示，详情提供明确年月日和时区。
- 额度属于所选电脑的 Agent 来源，不是 Agent Hub 手机登录余额；不复制原账号邮箱、计费凭据或公开真实余额到示例。

## 双端与确认点

| 项目       | iOS                                | Android                  | 共同断言                                      |
| ---------- | ---------------------------------- | ------------------------ | --------------------------------------------- |
| 入口       | 原生客户端 sheet／侧栏底部用量圆环 | 对应原生选择器／侧栏底部 | 两处同时显示，切换联动；设置与额度操作独立    |
| 数据与状态 | 原生页面 + KMP 规则                | 原生页面 + 同一 KMP 规则 | 余额、窗口、缺失、部分失败和缓存语义相同      |
| 操作       | 原生刷新、返回、精确值展开复制     | 同等原生操作             | 全部只读；不触及任务、草稿、充值或重置        |
| 系统差异   | SF Symbols／VoiceOver／44pt        | 原生图标／TalkBack／48dp | 记录系统差异，不降低文字或命中区标准          |
| 当前状态   | 待 UI 确认与实现                   | 待 UI 确认与排期         | 本次没有两端实现或真机通过，A6 原暂停范围不变 |

两个展示位置已由用户明确；本轮按用户指定改为原入口位置的用量圆环和两行较小文字，排版待视觉确认，后续不再要求二选一。仍处于设计阶段，不以本次重绘或交互检查宣称手机功能已实现。

## 修订 6 的生产实现

2026-10-28 用户要求按本方案实现。双端生产入口已采用左侧固定设置、右侧用量环与两行余额、最右侧收起按钮。KMP 负责精度、窗口选择、未知类型和过期投影，原生端负责布局及独立点击；首个有真实比例、适用于全部的有效窗口作为环来源，其次为总量限额，不合并独立 bucket。无余额只保留环，无真实比例显示破折号。多余额显示首项及 +N，详情逐项保留精确原值。

真实与辅助结果见 [F73 验收记录](../acceptance/agent-usage-20261028.md)，HTML 原型仅保留为已确认设计参考。
