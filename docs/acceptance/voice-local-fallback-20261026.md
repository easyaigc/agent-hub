# 语音失败后选择本地转写（2026-10-26）

F64，S04／S11／S17／S18，UI06／UI21。按本次用户明确要求，iOS 在原录音电脑端转写首次失败时直接弹出“重试转写”和“使用本地转写”。前者沿用原操作查询／补齐，后者通过手机系统识别同一保存录音，不重新采集、不改变默认提供者、不自动发送。主输入与问题回复共用，失败输入条保留本地转写和重新录音入口。

本地识别只在用户选择后请求 Speech 权限；支持语言使用 DictationTranscriber／SpeechAnalyzer 文件输入，旧系统／语言沿用 SFSpeechURLRecognitionRequest，支持时优先设备识别。与既有本地听写一样，不保证全部设备／语言离线。结果仍核对原目标和原草稿，取消或切目标后的结果不回填。原电脑操作及 WAV 保留至既有过期清理，本地已使用标记阻止再次恢复该录音。

本次真实文件识别场景通过（18.093 秒）：首次弹窗核对两个选项；点击重试后保留原草稿，再次快速失败通过录音条的“使用本地转写”接续；手机实际识别为“这是语音转写回退测试”，精确追加到该轮独立原草稿，保持未发送。原 WAV、清单指纹及本地已使用标记均从独立 App 容器复制核对，截图逐项查看。UI 合成场景在同一产品源码快照的早一轮单项通过，覆盖首次弹窗、重试及本地结果回填；本轮整组为一通过、一失败，后者再次受到另一独立验收 App 前台切换影响，原日志明确记录该 bundle，不能把两个单项证据写成最新整组通过。

验收时其他工作继续修改共享文件：当前 RootView 与快照在外部附件模态入口存在差异，语音错误弹窗、问题回复及录音条三个片段逐字核对相同；本地识别器与保存录音逻辑保留准确源码指纹。当前六个文件的产品登记包含已保留的并行修改，真实结果仍绑定冻结候选，不能据此宣称所有并行功能已验收。

保留的早期失败：首次私有快照构建因 Gradle 脚本在快照根目录查找依赖失败，修正私有构建路径后通过；首轮按钮数量断言把 iOS 无障碍树中的重复按钮节点计为四项，实际截图只有两个动作，改为核对名称集合与实际点击。随后固定测试草稿恢复了前轮保留录音，测试点击底层控件时系统默认中断处理器直接选择了本地转写，整轮按失败保留；识别结果和原文件另行核对，不改写为完整通过。验收草稿改为独立随机标识后，与本机其他真机验收重叠的键盘焦点与弹窗交互失败保留；一次自有重叠运行主动结束，仅停止本项进程。另一轮把再次快速失败必须重弹相同文案作为断言，未覆盖仍存在的输入条本地入口，原失败保留，修正为检查实际可用恢复入口后真实场景通过。最后通过只读进程核对等待手机空闲再开测，但其他入口仍在中途切换另一验收 App，因此保留单项通过与整组失败的区别。

Android 保存录音的本地系统识别适配尚待实现，F64 新增共同断言记为进行中；已有电脑端转写保留。本次不扩展其他 A6 暂停项，不新增 Windows、Android、真实麦克风采音或真实电脑转写服务通过，不向模型发送聊天输入。未创建临时工作树或分支。
