# 桌面标题格式一致性与后台持久化

2026-11-23，初次只优化候选编码和历史复用的 r7，两段120秒采样为37.91%与39.10%（100%=一个核心），未取得目标降占用验收。继续修复标题格式后，保留原任务的对照为39.51%→31.71%，下降约19.7%；两个内部测点均值为67.34/65.83°C→58.99/57.53°C，GPU均值29.24%→29.20%。采样没有锁定全部应用、请求频率及室温，内部测点不是机壳温度，不能将全部温度变化归因于Host或将实测比例写成持续保证。

继续只读取样发现，部分间隔内持久化业务内容没有变化，只有标题交替变化。目录 `thread/list` 的 `name` 含成对的 Markdown 加粗标记和换行，而已连接原 owner 的标题是单行纯文本。例如 `**来自：示例电脑**\n  同一任务` 与 `来自：示例电脑 同一任务` 会被两个读取入口交替写回 Host 缓存。它们对用户呈现相同内容，却使整份约37MB元数据反复序列化、编码、校验和发布；已有内容复用因输入确实不同而无法命中。

`desktopTitle` 在目录映射和原 owner 摘要入口使用同一规则：移除同一行中成对的 `**` 标记，将连续空白合为一个空格并去除两端空白。目录空白标题沿用未命名回退。普通文字、Unicode、未配对星号、单星号和下划线保留；没有添加通用 Markdown 渲染器、改写官方历史或调用重命名接口。

本轮只统一 Host 的标题展示值，不缓存 owner 控制权、权限、附件访问或真实文件检查，不修改模型输入、原 turn、队列、回执、历史正文或落盘屏障。真正不同的标题仍从原读取来源更新并持久化。现有持久化及 r7 的单次候选复用保持。

回归使用实际目录映射、owner 摘要和持久化实现，交替读取两种等价标题并核对发布及屏障计数不再增长；同时验证真实 owner 重命名、目录重命名、普通符号和原输入未修改。先在 r7 编译模块证明失败，再验证候选。源码检查、统一包实际 ESM 校验、原 Host 正常切换、输入完整性以及暖态 CPU/内部温度复测各自验收，不将辅助夹具写成真实 Windows 或手机操作通过。

macOS实机部署核对3478条原输入、138条创建输入摘要以及原桌面、模型和其他受保护进程身份保持。短时采样48次保存有42次命中精确复用，8个观察间隔没有标题格式来回变化；有界诊断Worker随后明确关闭。回归中的三轮等价标题刷新从额外6次状态发布、12次落盘屏障变为无额外发布，真实改名仍保存。完整检查通过，Windows和手机原生结果不由macOS证据升级。

精确源码、统一包和私有部署证明分别保留，源码回归开发主仓库后由既有Gitea main同步链交付；提交、远程CI、公开同步和各机部署分别核对，未重新部署的机器不承接本机通过。程序回退使用当前兼容状态，不覆盖旧runtime.json或重放未知输入。
