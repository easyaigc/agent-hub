# 阶段114 冻结锁原关闭回执

基准为主线 `a4a9e41a`。P7 的 F59 家族源在退出回调后完成源 FD 关闭，认证容器还需核对原 Frozen 的实际释放。此前 `releaseFrozen` 先移除登记再关闭，异常后同 token 再关闭会返回，新 writer 也可进入。

本阶段在原关闭开始前登记尝试。原锁和 channel 均执行关闭，首个异常保留，独立后续异常加入 suppressed。只有关闭成功才移除原 State。失败保留原 State、Handle、token 和同一异常，后续关闭返回原失败，继续使用及新 voice writer、F59 writer 和 freeze 均拒绝。成功后的旧 token 与伪造 token 沿用原行为。

已有三个原生用例覆盖 writer 全部关闭才可冻结、真实核锁和无效文件、并发 worker。新增三个用例覆盖锁和 channel 双失败、锁已释放但关闭回执失败，以及并发重复关闭。新故障通过窄端口注入，实际 channel 均关闭，属于关闭结果不确定的受控验证。

源码独审和锁定 Gradle App/测试包构建通过。首轮独立 API33 的六项均有 start/done，最终 `OK (6 tests)`、0失败/跳过；覆盖的1919项非文档输入在构建前后及测试后一致。App SHA-256 为 `8fdc9c703351d8d55d7b119ac4a0bf94d974bb58f4b3cd04f3684cf4a4dea9d0`，测试包为 `b7b8a9700c277b122c0d593e6ebd97383f8249f74f60fbbadf65eb67ce69edac`。首轮缺安装后独立字节核对和系统 build fingerprint；原身份采集部分命令错误保留。构建增量缺前置基线，无法证明原2GiB门槛；虚拟设备最大一次实测约899MiB，峰值未连续采集。原实例已正常关闭并删除。新环境独立补验的结果见下段。进程内门禁、跨进程/冷重启、自然系统 I/O 故障、认证外层、完整24域/激活、Main/手机/Host及完整交互界面分别验收。未知业务操作只核对原回执，任务和项目管理继续暂缓。

独立补验使用另一全新 API33 环境，运行前两个包均不存在。安装后和测试后分别读取两个 `base.apk` 的实际 SHA-256，均与上述两包一致，签名证书一致；记录完整系统 build fingerprint、boot ID 和 user 0。六项再次均有 start/done，0失败/跳过，原始 instrumentation 退出0、终态 `OK (6 tests)` / `-1`。Root 独立核对50条原命令与1919项输入、包字节和原始日志。主证据 SHA-256 为 `02098c1ffdac5c19a273ffa6910e618d6965db45e7a69806ed376219ec19e5a1`。

该环境采样最大分配增长 `1,014,153,216` 字节，最低可用空间 `102,756,884,480` 字节，满足本轮4GiB/12GiB门槛。原 launcher/QEMU 的实际 wait0、日志EOF/关闭、进程和端口退出、官方 AVD/登记删除均核对。中间指纹采集尝试只安装两包，尚未执行 instrumentation 即关闭，其原回执与缺项保持；最终通过只对应上述新环境。
