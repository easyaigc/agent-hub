# Migration entry copy and actual IO completion

The correction routes every migration label, progress/result message, count and notification setup hint through the existing NativeL10n/productText catalog and format grammar. Existing shared iOS keys supply title/password/export/import text. Twenty-five Android-only keys are appended by exact key; the current parent catalog retains all existing entries and generates 1879 entries per language. Source IDs and percent tokens remain literal format arguments, and the password stays in memory. No shared iOS catalog is edited and no new resolver is introduced.

The actual production factory passes the Session scope to the coordinator. That relationship alone was insufficient evidence: worker/query/action handles may be cleared on disposal, and HTTP bridges use separate Java executors whose cancelled Future can be done while its runnable or disconnect is still running. The proposed coordinator owns an explicit child Job and IO completion tracker. Session/voice scopes carry trackers as well. Four existing producer submission/cancellation sites feed this tracker; both Future cancellation and disconnect run off the cancellation caller. Stop-and-join waits for the owned coroutine tree and actual executor exit. The existing quiescence budget is retained.

A cancelled or failed quiescence keeps the old Session/draft and a Session-owned list of retiring coordinators. Actual completion removes an owner from that list. Another migration stays gated while old IO remains, including after its coroutine Job has completed; the draft remains editable. The real serial writer still reports unresolved failures. Unknown intents, IDs, payloads and receipts are retained without replay.

Migration restore opens the exact namespace/alias and prepares named child handles on IO. Pointer/generation authorization also runs on IO. Main publishes memory using a one-use generation/epoch permit under a short monitor containing no disk/crypto transaction; retirement uses no disk lock. A generation publication invalidates prepared permits and children before changing files. Fresh restore initially keeps foreground IO off, reconciles its existing reading ledger, then configures notifications after the native children and resumes the actual Activity. Rollback rebinds only the coordinator and resumes the same model, avoiding child construction behind held old IO.

The eight shared overlays are rebased on the actual parent P8 and P9 cold versions. They retain action leases, unique credential references, Main intent invalidation, cold selection before default storage, cold polling/coordinator and empty photo ports, and afterNewIntent. The fixed cold acceptance lease cannot be mutated by migration. Four additional producer patches contain only the tracking submission/cancellation substitutions and are supplied separately with exact base/proposed hashes. Parent files were not edited.

Validation: the current combined App/runner compiled; the existing catalog generator/check and four catalog boundary tests pass for both own and merged parent catalogs. Four actual-helper JVM checks pass: running Future cancellation waits for runnable exit, queued cancellation never runs, held Future cancellation and disconnect are off the event thread and included in completion, and closed owners reject new work. These are JVM auxiliary results. Native copy/AX (2), held storage lock/publication permit (3), and actual coordinator IO plus real Cancel control (1) are prepared alongside the prior seven methods, for 13 compiled native methods. No device, Host or model operation was executed here.

Parent native/DEV runs remain required with the exact new source/App/runner fingerprint. Prior parent passes remain bound to their original inputs; they do not become passes for this correction. A6 and business tasks/projects remain paused. The 8MiB text frame work is isolated outside this correction; EasyWork fence/orphan candidate archives, format interoperability and full P7 remain open.
