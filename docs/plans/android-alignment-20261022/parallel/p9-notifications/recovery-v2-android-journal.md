# Android v2 local journal and migration handoff

Implemented production decoder: `NativeChatNotificationRecoveryStore.validateEncoded(raw)`. This validates an archived string without reading or writing active storage. It does not authorize migration activation, device identity reuse, subscriptions, queries with imported credentials, or replay. The journal record is `native-chat-notification-recovery-v2` with integer version 2; private installation identity remains `native-chat-notification-identity-v1`. Both are installation-local. Existing `native-chat-notification-foreground-v1` remains unchanged.

The encrypted root is a closed object with `version`, `deviceId`, public-key hash `identity`, and `targets`. Every target row is closed over `target`, `operations`, `epoch`, `after`, `through`, `resetId`, `lastResetId`, `resetAfter`, `resetSequence`, `batch`, `outcomes`, and `gaps`. A null live epoch requires cursor zero/no high water. Pending batches bind an applied original operation, generation, epoch and exact original page. Reset sequence stores original IDs in order, resolves to the retained full originals, and is hashed as the canonical event array before baseline publication.

Operations contain closed `original`, `authorization`, `state`, and `receipt`. The complete v2 original uses the frozen Host contract; authorization is the captured fingerprint, never a bearer credential. States are unknown with no receipt, or reserved/applied/rejected with their exact matching original receipt. Unknowns are not normalized or discarded. A higher confirmed revoke can fence an older operation without changing its state. Local generations allocate above all recorded attempts, including rejects. Historical reset IDs and original receipts remain after snapshot completion/expiry.

A batch contains UUID `id`, applied source `operationId`, immutable original `page`, mutable exact-ID `decisions`, and mutable complete `activeIds`. An outcome contains canonical full raw event `original`, raw `fingerprint`, `state`, and safe timestamp `at`. Pending/waiting-host/processing are nonterminal. Processing is persisted before a P7/platform call; a restored processing record becomes unknown-interrupted-no-replay. Terminal results include suppressed, system-unavailable, submitted-to-system, unknown-no-replay, unknown-interrupted-no-replay, stale-target-or-generation, expired-or-future, duplicate-expired-or-read, host-inactive and host-expired. No unread counters are stored here.

Limits are 4 MiB canonical UTF-8, 64 targets, 256 total original operations, 2048 total outcomes, 64 accepted gaps per target, and the exact negotiated Host page bounds. Unknown/interrupted originals are never silently evicted. Current reset sequence originals remain retained. Ordinary terminal outcome retention uses the existing 24-hour notification horizon. Reaching a limit blocks the next write and preserves the original file; it never removes unknowns or silently advances a cursor. Existing identity `journalBound` accepts the old or new journal; a bound identity missing both journals, or a journal missing identity, blocks regeneration.

P7 integration must classify both records and the existing private identity explicitly. Until archive-only handling is implemented, a nonempty/unknown-version record must stop export/activation with preserved bytes, rather than be omitted. If archived, retain the exact original string and validate it with the production decoder. Do not activate the imported device/key, live lease, generation, cursor, batch, accepted reset or ticket into production. Reconnect/re-enroll is a separate human-authorized installation action; imported unknown originals remain read-only evidence. Any archive-only status/original-ID query needs a separately reviewed original-target/original-authorization port and cannot become POST permission.

This slice supplies the validator and contract only. It does not edit NativeMigrationInventory/Export/Activation or any central schema/classification table, does not relax the parent's existing v1 nonempty migration block, and does not alter the P7 MigrationTombstones claim hook. Unknown schema failure and archive-only no-activation are exercised by JVM auxiliary vectors and compiled native scenarios; full migration UI/native acceptance remains unverified.
