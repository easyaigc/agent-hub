# 办公室路由子网发现

2026-11-21，F06/F08，UI01/UI02，S01/S11。本文件定义范围和契约，不另建进度事实源；当前状态见 [唯一台账](../plans/ios-easywork-alignment-20261112/README.md) 的 `F06-office-subnet-discovery`。

## 根因和现有能力

Bonjour 仅提供当前本地网络的服务提示。VPNPeerDirectory 从 Tailscale 在线节点生成 `/discovery/peers`；`VPNPeerSnapshot` v1 仅接受 VPN 地址。路由器发布子网解决可达性，不会自动枚举子网中的 Host，也不会跨路由转发 Bonjour。

已配对 Codex 的候选与 EasyWork 的设备绑定可保存 LAN 地址；原 LAN 地址经子网路由仍可达、目标和证书/公钥匹配时，现有已保存电脑探测可恢复。不要求每台电脑继续运行 Tailscale。DHCP 换址后没有新提示时，旧候选无法自动推导新地址。每台电脑仍需实际运行 Host；路由器管理页不是 Host 目录。

## 有限实现

手机在 Codex 或 EasyWork 的发现页配置一次“办公室网段”，两种客户端共用配置。当前入口接受完整位于一个 RFC1918 地址块内的对齐 IPv4 CIDR，惰性迭代全部可用地址；普通子网排除网络/广播地址，`/31` 点对点与 `/32` 单主机保留其可用地址。分别探测固定 HTTPS 8796（Codex）及 4319（EasyWork）。不采用旧 VPN 的 32 条限制，不截断列表，不从 Host 广告递归扩展扫描范围。

不设置额外前缀上限或主机数裁剪，不限制旧 Bonjour、二维码、手工地址、VPN 目录及已保存候选。`/8` 也仅保存起始地址和计数，按四并发逐项调度；大范围需要很长时间，界面提示并可取消。IPv6、自定义端口和集中目录不在当前新入口范围，仍可用原手工/二维码流程。后续如引入高效目录，须是独立、受信任且有界分页的契约，不向 v1 VPN peers 塞 LAN 地址。该扩展不要求同步升级旧 Host。

扫描由打开已配置的发现页、保存配置或再次点击“保存并查找”触发。全局发现预算最多四并发，每次读取两秒资源期限，收到就发布；全 `/24` 仅无响应请求的预算就约四至五分钟，与其他发现共享并发时实际更长。界面提示大范围耗时、显示完成数/总数，可停止、移除配置。停止仅取消后续调度及迟到结果，保留当前已发现条目和进度，仍可点击连接；未扫完显示“已停止”，不冒充完整结束。明确新一轮、换范围和移除配置才清空该轮结果。关闭页、进入后台会取消本代扫描；不做后台定时扫网。配置恢复重新校验 CIDR，仅存网段，不存发现凭据。

## 调用链与安全边界

`OfficeDiscoverySection` → `OfficeDiscoveryScope` → `OfficeHostDiscovery` → 固定 `/host` GET → 各客户端现有描述适配器 → 公共发现列表 → 原连接授权流程。

| 边界       | 行为                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 发现请求   | 不携带 Authorization、Host Key、设备凭据；不创建绑定、不发送命令、不重放原操作                                                       |
| 传输       | 仅显式私网和固定端口；沿用拒绝重定向、真实 TLS 证书摘要与描述声明相符的发现策略；响应流最多 64 KiB                                   |
| 初次发现   | 自声明名称/身份是候选信息，不证明已获授权；点击时固定本次观察的证书与完整目标，EasyWork 另固定公钥                                   |
| 已保存电脑 | 同 Host ID/设备 ID 只保留一行；先匹配原完整目标和固定证书，EasyWork 另匹配原绑定公钥；冲突不更新旧记录                               |
| 地址学习   | 实际读到的 TLS 核验端点独立保存在可选 `observedEndpoint`，不改写原描述的最多 32 条广告；恢复仍核原 pin；健康当前连接不被背景扫描切换 |
| 连接       | Codex 仍走 Host Key/既有设备授权；EasyWork 仍走自己的设备绑定/自动授权能力；发现不授予连接能力                                       |
| 错误       | 无响应/非 Host/错证书跳过；扫描结束明确显示完成和排查方向；旧绑定、草稿、附件和未知写入保持                                          |
| 恢复       | 已保存目标由现有 pinned read 及原回执查询恢复；扫描停止不声称取消远端业务                                                            |

既有首次发现采用私网内证书观察，而非公有 CA 对身份的背书；本实现没有放宽这一策略。已配对身份不被扫描结果替换。目标绑定、公钥、设备授权与原操作 ID 的权威性不来自网段配置。

Codex v1 描述原本最多 32 条 `endpoints`；已保存候选的既有合并路径也取前 32 条。本扩展不收紧或盲目扩大它们：额外的实际 TLS 路由单独记录，不能为了塞入实际地址裁掉第 32 条广告。新字段为 App 私有持久化中的可选值，旧存储缺少该字段仍可读；恢复、选择路由和 HTTPS 会话注册共同校验它，且不把它当作系统 CA 地址。后续发现保留旧凭据；显式重新授权仍走原授权流程，并保留已核验观测路由。广告与旧候选超过原合并容量时仍受既有 32 条规则约束，与本次网段主机扫描总数无关。

## 双端与验收边界

iOS 新增共用原生入口和有限扫描，Codex/EasyWork 共用控制语义。Android 需同等显式范围、全范围扫描、取消、去重与授权边界；本轮未实现其入口，不借用 iOS 检查证明 Android 通过。Host v1、Relay、路由器、ACL、WAN 公告与正式安装无变化。F75/A6 暂停保持。

辅助验证必须覆盖 `/24` 最后可用地址、非法/公有/跨私网边界拒绝、`/8` 惰性计数与取消、完整计数、并发、取消/迟到、同身份多地址、旧 pin 冲突及仅 GET。原生模拟器另验输入、保存、冷恢复、停止和移除。二者均不能证明蜂窝或设备 VPN。

真实退出门槛：目标电脑退出 Tailscale 且 Host 运行；手机在办公室外的蜂窝/其他 Wi-Fi 通过已批准的 Tailscale 子网路由；App 中出现正确电脑名，原凭据连接成功，完整目标/证书/公钥/设备权限保持，地址变化仍是同一记录。无法建立该拓扑时保留未验，不用开发机 LAN 或固定 fixture 代替，不重复配置已批准路由或改 ACL。
