# 阶段95：旧回复记录的保守恢复与界面门槛

阶段94 F59源码已提交推送60fdb284，1992键生成、范围一致性及全仓格式检查通过，当前编译/Native/真实DEV仍待验。本阶段继续公共原操作安全，不等待环境项，也不重放任何未知原输入。

## 原因与改动

Android普通操作日志的旧not-written/READY只是保存的状态；由于普通写入的持久确认尚未补强，不能追溯证明它未跨发送边界。现在原ID用户重试、恢复原文和日志消费统一要求现有strong-not-accepted：完整原目标、证书信任、不可变指纹、未消费、未脱离、非迁入只读、无已有结果且证明仍在60秒有效期。原Flow发送前仍再次读当前日志和原状态、消费原额度；不新增ID、不自动继续。

初次prepare→markSubmitting→send路径及KMP/iOS共享算法不改。本切片是保守保护，**不是完整持久性修复**：普通消费软写、同ID首次路径复用、source/outbox严格原件链、v2新准备lineage和原文读取后generic detach竞争仍待后续。旧记录不会被补标为新算法证明的未发送。

## 交互与界面对照

旧failed且attempted=false不再被标成已确认“未提交”或提示重新发送，始终保留原ID查询入口。未脱离、failed且无结果的reply纳入原目标Composer等待门槛；用户须查询，或显式结束本地等待后再处理新草稿。结束等待只置本地detached并保留原件/回执查询，不取消电脑任务、不重发原输入。creation既有返回草稿、结束等待确认与其他控制保持。

“未提交/可重试原消息”说明及按钮使用当前mayRetryReply资格，不只读原phase。Compose在有效资格期间按秒刷新到期状态，动作入口仍用实际当前时间再验证；预期最多一秒隐藏延迟与前后台/导航/新证明替换需真实UI验收。旧内存卡片不单独授予发送权，Flow仍读取当前日志。

新增4项隔离Native测试源码覆盖：冷v1旧READY阻断原重试/恢复且零读/零发送；共享规则与初次日志转换保持、failed Composer谓词；新鲜强证明一次消费；过期/证书/目标/已消费/脱离/只读/已结果/缺证明拒绝。每项使用独立UUID namespace与Keystore alias，退役所建storage后仅清理自有目录/密钥，不借默认密钥测试。合成旧快照不冒充真实磁盘故障，日志第二实例不冒充进程死亡。
