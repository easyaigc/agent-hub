# P7 reading / P9 consumption contract (candidate v1)

Task: `android-parallel-p7-reading-voice-20261028`; base `1e908bea1ac75341e17e56a518d7bebd46620c4d`.

Implemented candidate sources: `ThreadReading.kt`, `NativeReadingLedger.kt` in the Android package. This is an integration proposal until the main coordinator registers it in MobileSession/MainActivity. Native execution and real DEV have not run in this workline.

- `ThreadReadPosition(revision, messageId, contentVersion)` uses protocol read-state v1 safe integer bounds, SHA-256 lowercase, and iOS/KMP UTF-8 framing. `ThreadReadState.decode` is the strict reader-specific wire decoder. A desktop/other reader acknowledgement cannot clear phone state.
- `NativeReadingLedger(storage)` owns the one `mobile-reading-ledger-v1` encrypted record, using the existing NativeSessionStorage lock/read/write boundary. P9 must consume this instance/API rather than keep a separate unread boolean. Storage errors propagate and original bytes are preserved; UI should retain its last successful immutable snapshot and show the actual failure.
- `reconcile(allSavedRealTargets, snapshots)` includes offline computers; duplicates of the same full target count once. Source unread is an initial seed only; later server reads cannot undo phone reads. Route, endpoint, project display grouping and Codex account metadata are outside reading identity; non-Codex account identity remains.
- `receive(NativeReadingEvent(id,target,threadId,kind,position))` is a transaction. P9 authenticates the event and registration generation first, maps `readTarget ?? target` after validating they describe the same runtime, and passes protocol kinds except `connection` (no thread unread). A versioned completed event cannot revive already read or older content; equal-revision conflicts do not overwrite known bytes. An unversioned notice keeps a durable seen tombstone by ID, across process/ledger instances. P9 separately owns registration-generation/event-ID delivery receipts; this ledger owns unread semantics only.
- `snapshot()` returns `NativeUnreadSnapshot(revision,unreadKeys,countsByTarget)`, `count(target)`, `isUnread(target,threadId)`, and `badge(enabled)`. Privacy/disabled badges only affect projection/delivery, never delete this ledger. At most one unread count per full target/thread, even with both reply and multiple notices. Scopes can be removed from counting without erasing tombstones.
- `NativeReadingLifecycle` issues view-owned leases after actual latest content is visible and matches the exact displayed position, including optional source/display projection. `present` takes only the notice IDs actually exposed with the content. Cover/uncover, background/foreground, target navigation and changed display version invalidate old callbacks. `visibleNotices` supports explicit notice visibility without a reply. `readVisible` checks the lease inside the storage transaction; a newer reply can arrive in between and must remain unread. No API approves, sends, navigates or retries model input.
- `pendingReads()` exposes read positions for the existing named Host acknowledgement path. Retry of this metadata is safe; use the same readerId derived from deviceId plus canonical target/thread. `reconcile` clears pending only for an exact acknowledgement with matching local reader identity and position. Never copy a desktop readerId.
- Bounds are explicit (16,384 rows, 256 notice IDs per row, 8 MiB encoded ledger); capacity failure preserves rows/tombstones and must be surfaced, not silently pruned. Migration line needs to include/validate this narrow record schema before its export/import can claim reading coverage.

Integration ownership remains with the main coordinator. No central manifest, progress, global localization/generated file, storage migration implementation or shared UI registration is edited here.

`NativeReadingEvent` additionally carries `runId`, `requestId`, `operationId`. `notices(target,threadId)` exposes unseen immutable `NativeReadingNotice` rows with these fields and kind, so visibility can match the actual approval/question/plan/receipt/run exactly as iOS. The same ID with different original metadata is rejected. `NativeReadingLedger.validateEncoded(text)` validates the closed record with the actual production decoder for the migration owner; no second parser is required. Every row stores target/thread, optional latest/read/pendingReader, replyUnread and a map of full notice metadata plus seen tombstones; root stores version=1/revision/scopes/rows. No unknown root/row/notice fields are accepted.

For direct read acknowledgements, `acknowledge(capturedPending, responseJson)` validates the closed response (`hostId`, `threadId`, `target`, `readerId`, `read`) from the existing Host `POST /v1/threads/read`. It only clears the exact pending flag, leaving newer unread content intact. Native Android commands have **not** registered this endpoint yet; the main coordinator must add its narrow request/response schema and provider method, not send an arbitrary path. Workspace/history reader IDs and acknowledged reader IDs must be identical; existing Android `nativeReaderId(client.readerId)` must be reconciled with the canonical identity before wiring.

Run all storage operations on the existing background I/O writer and publish only immutable snapshots to Compose. `readVisible` holds the lifecycle lock only during in-memory validation/mutation; encryption and file I/O do not hold the view lock. A failed write leaves the last published UI snapshot and original storage intact.

P9 requested event-level presentation query is implemented as `mayPresent(event: NativeReadingEvent): Boolean`. It loads and checks the same encrypted authority under the existing storage transaction lock and does not modify any ledger bytes. After `receive`, it returns true only for the exact current unread reply position (latest identity/revision/content SHA all equal and not settled by the phone watermark) or the exact unseen notice metadata (ID/kind/run/request/operation). An old read/older version/equal-revision conflicting reply, a seen notice, another target/thread, removed scope or reused ID with different metadata is false even when the conversation remains unread because of newer content. P9 should map **all** runId/requestId/operationId fields, use this query for the first `shouldAlert` and requery immediately before claiming/dispatching. `snapshot().isUnread` remains a count/row projection only. Receiving, querying and opening are not reading.

`NativeReadingPresentationTest` executes the actual pure production predicate on host JVM (old/new versions, equal revision conflict, read watermark, seen tombstone while newer unread remains, original intent). `NativeReadingLedgerTest.presentationQueriesUseExactEventAndPreserveSeenTombstonesWhileThreadIsUnread` prepares the real encrypted transaction/query and no-write assertions for the coordinator's native run. The ledger query is synchronous and includes storage I/O; the parent should keep this operation off the UI thread when wiring P9's final query port, retaining an explicit suspension and lease recheck instead of a stale chat-wide boolean.
