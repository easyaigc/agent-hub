# Binary inventory regression correction

The modern-name resolver read a single byte although the production binary writer stores a four-byte big-endian version. A sealed recording therefore begins with zero and was rejected before either typed or current streamed export could authenticate its header. This also affects other supported local binary originals; it is a product reader defect rather than a typed-fixture or directory exception.

The resolver now distinguishes one-byte text versions 1/3 from four-byte binary versions 2/4. Legacy binary version 2 still needs its exact indexed alias. Modern version 4 still authenticates the encrypted logical name and every chunk. Unknown/truncated framing, changed originals, unsupported graph entries and pending AtomicFile files continue to reject the whole export. No reader recovery, rewrite, unknown-file skip or voice input replay is added.

`NativeMigrationLocalRecordFormatTest` covers the actual `DataOutputStream.writeInt` framing and nine malformed/truncated prefixes. `NativeMigrationBinaryInventoryTest` prepares the actual sealed-voice typed/current-streamed round trip and unsupported/pending binary rejection. Compilation and JVM framing are auxiliary evidence; Android Keystore, existing eight voice regressions and the four new methods await coordinator execution with fresh fixtures. Preserve the original stage26 failures.

Apply `binary-inventory-code.patch` once to the recorded source bodies. The original voice test drivers stay unchanged. This correction is independent of the EasyWork live-owner proposal.
