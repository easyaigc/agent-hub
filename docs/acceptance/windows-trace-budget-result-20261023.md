## 问题与最小修复

原实际 Host 的 prepare 在 4 秒到期。单次原生数字证据显示，48 批中最后一批有完成记录，但晚于 reader 截止；CreateFile 组的重复完整父路径打开占主要原生累计墙钟，stdout 写入很小，所有完整 B8 已达到八并发。已排除“只调整 Task 内存优先级即可解决”的假设。未将底层责任唯一归给磁盘、杀毒软件、GC 或操作系统调度。

产品提交 `e151f73` 仅改变 Windows `packages/codex-adapter/windows/trace-state.cs`：同一个 B 命令内，私有 Trace 根上方的 namespace 祖先鲜开一次并持有；每项仍完整执行读前、读后身份及 ACL 检查，祖先读前还须等于批初始值。私有根及所有后代继续逐项鲜开，批内全部并发完成后释放共享句柄，不跨 B 或请求复用。S 单项路径保持。`4bb2fec` 只修正测试夹具的 DACL 节范围，产品 C# 不变。

没有改变批大小、并发、来源选择、最新版本、权限拒绝、prepare/commit 各 4 秒、共享 7 秒、单原生 750ms、HTTP 8 秒或最终租期 6 秒。macOS 生产路径逐字节保持，手机交互没有修改。
