# P9-3 foreground notification contract audit

Baseline `f9e935b37f3f49e5a689f34397163a63ab13dc82`. Read-only comparisons: current iOS TaskNotifications.synchronize/NotificationHostMonitor/AgentClient, Host runtime-server notification routes, packages/protocol/src/notifications.ts and packages/notification-runtime/src/index.ts. No live Host/model/device requests are authorized in this workline.

The five operations exist: POST register `{hostId,registration}`; POST preferences `{hostId,deviceId,target,preferences}`; POST unregister `{hostId,deviceId}`; GET status `hostId,target,deviceId`; GET events adds `after`. The transport must also supply the complete target query (global runtime-server precheck). Foreground registration supplies a real stable local deviceId/X25519 public key and preferences, omitting deviceToken/environment entirely. No fake APNs/FCM token, vendor readiness or background delivery is implied. Wire parsing is closed and independently typed; generated Codex command schemas do not currently contain these notification definitions, so they must not be pretended to validate them.

Host feed is `{events,cursor,activeIds,status}`. Original SHA-256 event IDs/kinds/occurredAt/readTarget/readPosition are retained; no events are synthesized from UI/runtime status. Host includes otherwise-muted thread events when badgeEnabled, uses actual active/current filtering, and suppresses foreground event payloads when an APNs binding exists. Missing APNs-token reason together with `delivery=foreground-only` is a usable foreground subscription, not vendor readiness.

## Required gaps, not guessed receipts

- **FG01 / unknown mutation recovery:** status currently echoes target/delivery/state/revision and optional relay data. It does not echo deviceId, incoming public-key fingerprint, preferences generation/full fingerprint or subscription generation. Therefore status revision equality alone is not a complete receipt for a lost registration/preferences response. After an attempted mutation without its validated direct response, query the same deviceId status only and retain unknown/no-replay; do not send another registration or mint a different deviceId. A receipt/status extension must bind these fields and the original immutable operation before automatic recovery may confirm/retry it. The implementation can run the successful direct-response path and recover its locally confirmed subscription via the original status; it must visibly stop ambiguous mutation recovery.
- **FG02 / unknown unregister before registration:** Host unregister of an absent device returns disabled without creating a tombstone. A previously unknown enabled register may arrive later. The client cannot claim that a single absent-device unregister guarantees no resurrection. An authoritative registration-generation tombstone or an explicitly reviewed disabled-registration fencing flow is required. Keep local delivery fenced off and retain pending revocation until the parent resolves/proves this branch; no blind unregister/re-register loop.
- **FG03 / feed bounds:** current feed has no epoch/paging/reset marker. An unknown `after` cursor restarts from retained entries; original-event dedupe and immutable durable results are mandatory. Active actionable entries can exceed the retained last-512 floor, so Android must bound bytes/entries and report capacity failure without advancing the cursor. A bounded paginated contract is needed before claiming arbitrary backlogs covered.
- **FG04 / public-key lifecycle:** no device private key, OS permission, old subscription or delivery ticket may become active through profile migration. A missing/corrupt local identity is an error when prior foreground state exists, not permission to generate another device ID/key and replay registrations. The local installation identity is independently encrypted and must be excluded/reset by the P7 migration owner.

The foreground monitor receives immutable saved/retained client+credential snapshots and shared P7 reading/draft-preserving route ports. The parent must invalidate its presentation fence **before** navigation/credential/preference/read-visibility/migration changes, and must retain an original credential snapshot for an unconfirmed revocation. Store/ledger/large JSON operations run on IO; OS/UI work runs on Main. Cancellation and every async return recheck the captured fence; no late callback may advance a newer stream or post for an old target.

Integration/implementation details and final source hashes are supplied with the phase handoff; this audit does not mark central routing, actual subscription, Android execution or vendor delivery passed.
