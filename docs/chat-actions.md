## 实现边界

管理操作经 AgentClient 的具名 Provider 方法进入 Host，再由 `packages/codex-adapter` 的专用元数据连接调用官方接口。此连接只允许初始化、准确 Thread 的元数据读取及这五项操作，不允许执行、resume、任意方法、shell 或 IPC 透传；原历史 reader 继续只读。Codex 账号只作为历史元数据，目标按 Agent／Host／workspace／runtime 校验。

已独立验证未加载、零 Turn 官方元数据的归档、恢复、删除，不启动模型；该辅助证据不能替代真实已加载 Electron 聊天的验证，也不能由原生菜单或编译通过替代。不得发送虚假的 `thread-archived` 通知来强制释放 owner，不使用控制聊天、修改官方历史／状态、接管执行或绕过受保护工具管道。补齐加载场景需要上游提供具名生命周期入口。

当前 Codex 映射为 `thread/section/move`、`thread/archive`、`thread/unarchive` 和 `thread/delete`。置顶使用当前桌面 profile 中内置的 server-owned section；手机不能传入 section ID。置顶排序读自官方服务的 section 顺序，旧全局状态文件仅继续用于已有的只读项目归属映射。管理不会写官方状态或历史文件。接口和本机 schema 已复核，不能据此保证所有上游版本均支持。

Host 和手机均在提交前保存稳定操作 ID、完整目标、原 Thread 与动作。相同 ID 的不同意图被拒绝；重复请求只返回原回执。超时、连接断开或 Host 重启后的未知记录不自动重放，菜单提供原操作查询。用户可明确结束本机等待并保留原回执；这不会取消电脑端操作或重新提交；原结果未确定时仍阻止同一聊天的新管理操作。从 2026-10-20 起，手机单项操作和批量归档不再以运行、等待审批、待回答问题、原 owner 或输入回执状态作为前置拒绝条件；Host 也不再根据这些摘要拦截，直接让官方元数据接口决定是否接受。只有离线、运行目标不匹配、正在提交同一聊天的管理操作、原管理操作结果未知等传输及身份条件继续限制。官方明确拒绝显示拒绝原因并释放管理等待，不能误报为结果未知。归档历史为只读，恢复后才重新开放输入。手机不能仅靠删除本地列表伪装电脑端操作完成。

## 状态展示（2026-10-20）

对话菜单、删除确认、批量归档行和归档列表同时显示“已归档／未归档”及任务状态。当前聊天优先使用该目标的运行时摘要；其他行使用目录摘要。执行中、等待审批、执行失败、已停止、已完成、空闲和状态未确认分别展示，离线时标注上次状态。仅有 idle 不能推断任务完成或停止；原 owner 最新轮次的明确终态（可选 `lastTurnStatus`）可细化 idle，不能拿某个工具已结束代替整轮任务已完成，未知运行状态不靠旧正文推断。归档状态由官方目录维护，归档本身不能被呈现为已停止；界面不为归档自动调用停止或清空输入队列。

删除保留一次不可恢复确认，并明确桌面删除还包括子对话；取消不发出请求。归档沿用直接操作，操作前可在同一菜单查看状态。已归档聊天不再出现在批量归档候选中。

产品目标是与桌面一致，允许任何执行状态下管理聊天。本次修改落实手机与 Host 的操作策略及状态展示，不代表已经打通原桌面 writer 的生命周期入口。`threads:archive:unloaded` 继续保留其实际能力范围；不新增“已加载归档可用”能力、不伪造归档通知、不修改官方历史，不以按钮可点或 fixture 成功替代真实桌面执行结果。

### 原桌面入口复核（2026-10-20）

后续真实 DEV 使用原生 iOS 新建的专用模型任务，独立核对准确原 owner、同一运行中轮次、一次输入和实际 xhigh。执行中的归档、删除请求均收到明确拒绝，操作后同一轮次仍为 `inProgress`。另外分别尝试官方 `codex archive <UUID>` 和 `codex delete <UUID> --force`；均退出 1，原 owner 与运行中轮次保留。CLI 只返回一般失败文案，不能据此声称其错误详情也包含写入锁原因。这些结果是阻塞复现，不是生命周期功能验收通过。

官方 [App Server 文档](https://learn.chatgpt.com/docs/app-server) 定义了归档、删除以及 stdio／WebSocket／Unix socket 传输，[CLI 命令文档](https://learn.chatgpt.com/docs/developer-commands) 也允许向指定远程 App Server 提交归档、删除。但本机正常启动的原执行器只有 stdio，没有具名 App Server socket 或 TCP listener；默认 daemon 控制 socket 的只读连接实际失败。安装代码中，桌面界面将归档、删除交给自己的原连接；当前协调协议没有相应 follower 请求，公开深链接也未提供生命周期动作。不能把另外启动的元数据服务当成原执行器。

在当前已核对的接口中，仍缺原桌面对独立 Host 开放的、绑定准确目标并返回真实结果的生命周期入口。可行的上游契约应提供具名归档／恢复／删除请求，或在正常启动下开放原执行器的受控连接；必须由原桌面处理执行中任务、子对话和缓存失效，并能查询未知结果。不能通过更改官方启动链路、接管私有 stdio、绕过工具来源校验或伪造归档广播补齐。运行中与已加载成功场景全部通过前，不更新正式手机和日常 Host。

## 搜索与定位

搜索读取当前聊天的全部可读历史，逐页直到游标结束，并拒绝重复游标。搜索正文、工具输入／完整可读输出、Diff 及附件名称，按消息显示匹配片段。点击结果后扩大本地显示窗口、定位原消息 ID 并突出匹配；折叠工具组中的目标消息单独展开定位。长消息先显示匹配上下文，可展开完整内容。

Codex 的搜索历史有独立只读端点，不接管 owner，不改变聊天正在浏览的分页游标，也不调用模型。已加载聊天优先通过准确原 owner 的完整历史／revision 边界补齐工具项；当前 CLI 的旧格式 `thread/read` 可能只投影文字，不能用它覆盖仍可从 owner 读取的工具历史。未加载聊天继续读取官方可用的持久历史，上游未提供的内容不推断补造。普通历史展示保留已有输出长度边界，搜索读取完整可读输出。搜索读取失败或离线时明确提示只搜索缓存，保留重试入口；不能将缓存无结果解释为完整历史无结果。切换电脑、聊天或配置后，取消及晚到结果不会导航或覆盖新目标。

## 协议

| 方法与路径                       | 输入与结果                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `POST /v1/threads/actions`       | 严格请求：`hostId`、`target`、`threadId`、`clientOperationId`、`action`；返回原请求及 `phase`、`error` |
| `GET /v1/threads/actions`        | `hostId`、`threadId`、`id` 查询原回执，不重新执行                                                      |
| `GET /v1/threads/search-history` | `hostId`、`threadId`、可选 `cursor`；返回准确目标、原消息 ID 和下一页游标                              |

`action` 仅允许 `pin`、`unpin`、`archive`、`unarchive`、`delete`。回执阶段为 `submitted`、`confirmed`、`rejected`、`outcome-unknown`。能力 `threads:manage` 由实现了此边界的 desktop-runtime Host 声明；其他 Agent 的管理由其 Provider 独立实现，不能自动映射到 Codex。搜索沿用 Provider 的只读历史能力。
