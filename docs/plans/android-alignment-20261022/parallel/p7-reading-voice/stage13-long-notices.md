The iOS reference `SessionStore.recordVisibleContent` matches runtime approvals/plans after RootView's active-scene, settled-sidebar, uncovered and latest-message gate. It has no per-block cumulative visibility proof to reuse. Android's existing `ReadContentProjection` binds source and displayed content versions; this stage applies that principle to a renderer-owned semantic document, rather than interpreting a chat-bottom marker as proof that a long panel was read. No iOS, KMP wire schema, Host or command change is made.

`NativeNoticeReadDocument` enumerates every required original field before coverage can complete. Approval/question fields are title (except the existing async-deck projection), detail, prompts, option labels/descriptions and actual translated approval decision labels. Async titles follow the existing Android/iOS projection, which displays original prompts/detail instead of the generic approval title. User answer text, selections, dictation and feedback fields never enter the document. Plans require the exact immutable original plan text and a current `ParsedMarkdown(source, document)` pair. A stale async parse cannot publish its earlier projection. The existing renderer supplies each supported Markdown leaf, list marker, table cell, code-language label and actual code payload; container nodes are not flattened twice. Triple-backtick code uses the existing raw-payload function, preserving CRLF/copy behavior.

Coverage is ephemeral and belongs to one mounted content surface, exact original, Session render epoch and native window. A document stores part IDs, hashes and UTF-16 lengths; bounded bitsets store only the glyph offsets actually witnessed. There is no second persistent reading system, raw text/answer archive, event consumer or ledger. The original Session store/writer, P9 ledger/publication, body-versus-notice isolation and atomic Session/view guard remain unchanged. Five shared-file base/proposed hashes are supplied; all five proposed files equal their captured parent bases, so no shared patch is needed.

The actual `TextLayoutResult` must match the declared part hash/length and attached coordinates. Each observed glyph must fit the ancestor-clipped text bounds and visible native-window bounds. Only the renderer's ordinary translation geometry is supported. Horizontal code/table clipping, ellipsized/max-line-hidden offsets and unseen middle ranges cannot borrow coverage from adjacent text or a bottom visit. The observer waits two stable native frames before sampling. Work is limited to visible lines and at most 8,192 glyph queries per frame; subsequent batches still require the same live layout/window generation. This is a paint/geometry witness, not a dwell-time threshold or a claim about human comprehension.

Every declared part must have one current layout in the same native view before sampling can begin. Scrolling retains witnessed offsets for that same layout, with no interpolation between samples. Original/projection replacement, text-layout or coordinate-owner replacement, content-size change, whole-panel offscreen, native-window metric/focus/lifecycle loss, cover or Session-frame replacement clears prior coverage. Old view guards retract synchronously before a different owned projection/layout is published. A current visible declared semantic text fragment and complete coverage are both required for a positive report. The existing ledger checks the resulting view proof together with the Session guards inside its original short in-memory mutation after storage loading; encryption and disk I/O remain outside those guards.

Native window continuity also belongs to that source, so replacing an unseen-notice snapshot does not itself clear the same original's witnessed ranges. A late event still needs its exact tuple and two current native frames; changed scenes never inherit coverage. The content slot, remembered context, approval draft, focus owner, selected answers and plan disclosure remain stable when metadata arrives or becomes seen. Ordinary Markdown outside a notice surface installs no extra geometry callback. The optional null binding installs no native window/lifecycle observer, report or I/O. Scalar read-only native-test diagnostics expose part/layout/coverage counts and mismatch categories, without text, answers, target IDs or credentials; prepared failure captures use those bounded diagnostics.

The explicit conservative gaps are retained:

- A projection is capped at 1,024 nonempty semantic parts and 131,072 UTF-16 units. Projection traversal also stops beyond 64 nested levels or 8,192 node visits. Unsupported or oversized input remains unread.
- Hidden link/image destinations, unknown Markdown nodes and a plan with no supported semantic text lack sufficient original evidence and remain unread. This stage does not alter their rendering or invent source coverage for them.
- An ellipsized code-language header or otherwise unavailable original field cannot complete until the renderer can actually expose it. Coverage is not combined across separate windows, unmounted views or disclosures.
- Arbitrary same-window alpha/paint occlusion still needs accurate owner cover truth. No platform claim is inferred from an unexecuted native scene.

Auxiliary verification and native preparation are distinct. The original nine UI methods and bilingual toggle method are retained.
