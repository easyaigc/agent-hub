## 原记录的状态解释

- **未开发/部分实现**：有明确缺实现依据，并写到具体子能力，不能把整个“开放”列表叫未开发。
- **代码已存在、完整性待核对**：有源码，但尚不能证明覆盖当前全部对齐目标；先审再决定补开发或补验收。
- **已实现、未验收/历史部分通过**：代码状态与真实验收分开；有源码或编译通过不等于功能通过。
- **历史限定通过、待匹配复用**：保留原范围，确认当前源/包/设备/断言依赖后才能复用。
- **历史限定通过、本次匹配未成立**：审查已经完成，当前证据不足或实现已变化；明确等待补证/重验，不再标成审查仍未开展。
- **待集成/部署未核实**：提交合入与实际运行包是两个事实，不把本机候选算成已部署主线。
- **待执行/阻塞/暂停**：不再使用旧in-progress推定正在开发；实际Fast阻塞与F75/A6暂停分别记录。

原“44个开放父项”只是首次盘点的范围统计，包含不同开发与验收状态，不是44个未开发功能。原任务当时由status.json生成数量；该机制现仅作为历史来源，不再用于维护当前数量。

## 原任务的执行说明（历史）

开发与审计同时遵守 [统一 Host 协议与客户端适配规范](../../design/unified-host-protocol.md)：以已实现 Host 契约和公共 App 流程为基准，先做有限调用链映射与缺口归属，再实施必要变化。原专项的纠偏、兼容例外及修复曾由协调会话写入 `status.json`；该文件现仅保留原始记录，当前双端状态只维护在上述唯一完整功能清单。

原任务当时先按 [核心使用验收](core-acceptance.md) 核用户实际操作，再按范围补扩展功能和工程边界。读取台账与维护规则 → 核对应 F、EW、AC 和准确基线 → 复用适用证据，补实际缺口并验收 → 更新四维状态 → 生成并检查视图 → 清理结束阶段的自有资源。

原记录时点的执行约定为：**该轮 iOS 场景使用原生模拟器验收**。扫码输入、网络切换、录音、通知与密钥行为的模拟器替代断言登记在台账，原实体断言保留为历史。需要桌面执行的场景连接独立 EasyWork Electron，实际模型结果和原资源按场景核对。该轮开发取舍由主会话处理，本机测试与资料核验按全局规则分派 Terra medium，配置的请求值与可核实际值分别登记。
