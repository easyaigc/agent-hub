# P7 图片选择与本地准备档案

## P7-2a 图片入口与原草稿准备

逐项对照iOS PhotosPicker及LocalAttachmentPreparation，Android加号先增加“选择图片”，由锁定Activity1.13原生合约只请求图片，最多5项/有序结果，系统决定现代选择器或回退，不在用户点击前读取相册。Android仍为过渡菜单，iOS完整附件面板、相机、最近30图及新增提醒/权限是后续范围，不省略。

菜单关闭后才启动系统页：原菜单释放通知核同一展示目标，再等主窗口焦点和一帧；旧菜单不能释放新请求。一个原请求持于Session，窗口回调捕获该请求对象与准确原草稿代次；空结果保留原稿，旧对象不能消费/失败新请求，URI立即复制并有序去重；上限/读取失败按原错误代次保护。返回原目标后才展示对应本地文件，导航到另一聊天不污染其草稿。Activity旋转及进程死亡后的真实系统结果仍待验，不把对象持有推论写成通过。

图片走真实ContentResolver有界读取，再核原图维度/解码，100MP上限，按EXIF方向变换；PNG保留PNG，其余转JPEG92并修正扩展名/MIME，输出有界20MiB，bitmap及时回收。原PNG像素及方向2/6/8用独立固定色块向量核对；普通文件读取仍保留原字节，其与iOS文件/粘贴图统一归一化的差异单列。不可读取或非content来源使用图片专属固定错误并保留原cause。添加仅本地加密保存，不上传/发送。Android新增一个回退选择数文案，1603共享+76平台共1679双语键。

101匹配辅助：三平台各29项（图片7、附件归属9、文件粘贴5、收件箱7、catalog1），API26双倍字号/API37深色各7。系统图片选择器实际打开、确认准确系统owner、窗口内容/空闲后截图，再SDK返回取消，三环境原稿/文件/操作不变；没有选择任何系统照片，不能提升为正向选图。3实际原Electron目标/工具资源整例通过：同App验收器PNG经生产照片控制器、本机像素/原名/MIME/加密字节及元数据确认到准确草稿，仅清理本次新增引用，原附件列表/正文保留。它不是系统选择器的正向结果；新图未由模型读取。实际代理只GET，累计219/P4 205不变。104默认存储证明。当前物理图片准备截图为2250×946宽视口，非物理竖屏通过；各系统选择器截图尺寸单独登记，参数请求portrait不等于强制物理窗口方向。API26/API37系统页及手机/API26图片准备4图已查看，完整物理系统视觉矩阵仍未关闭。

保留失败：最初EXIF标签必须1的oracle错误，PNG可剥离标签，改独立最终像素与0/1标签；运行后挂控制器的plain字段未被根界面观察，改Session可观察状态；第二轮请求pending无异常却未见窗口，验收器未推进Compose帧时钟，补原生启动前帧等待。首批101/3功能通过但系统截图捕获过渡，原图保留，补Compose关闭/原生空闲及owner/children检查后重跑当前候选，不把旧包计为当前。过大/未读/坏图片及正向来源/完整格式仍按独立矩阵推进。

一次手机实际整例在图片准备已过后、粘贴前即时canCompose断言失败，原记录保留。验收器增加同一原目标/选择代次最长10秒就绪等待和前态诊断，保留权限断言，不重放输入；旧唯一原因未追认，不把等待策略称为权限修复。实际验收隔离Session提前交由Activity，使前后台/网络监测持有同一Session；粘贴用原生语义OnClick及有界菜单发现，实际触摸/剪贴板覆盖层仍待验。另按iOS关闭面板后再打开系统页，新增原菜单释放+主窗口焦点+一帧/原请求守卫；菜单修复后的产品候选执行101辅助；随后只调整实际ResourceLiveTest的Activity归属/就绪/语义动作，产品APK及所有辅助/核心/协议输入逐一严格匹配，101辅助复用，当前runner另跑3实际整例，不把旧失败/首帧提升为通过。

## P7-2b 独立来源与系统正向回调

新增仅验收APK的来源Activity，在独立UID/PID内创建唯一PNG及原子私有台账，随机码只在图片像素中，文件名不含随机码；报告通过只读DocumentsProvider授权，照片本身不向接收App直接授权。来源按准确URI、名称、目录、所有者与原字节核对后才清理，不遍历删除相册。旧权限仅对API26来源APK临时授予并恢复；生产App权限没有变化。

API37原生正向通过：验收器先确认准确自有模拟器，再要求系统媒体库只有本次唯一原媒体ID；通过真实系统选择器的SDK可访问性动作选择该唯一缩略图、确认，由实际Activity回调原请求。最终640×320像素摘要、PNG类型、系统返回名及加密原草稿均核对，正文与原目标保留，没有上传或发送。系统选择器将原名转换为媒体ID加扩展名，本次按原媒体ID准确核对该隐私别名，没有从URI推断任意文件路径。已有原请求/旧对象/错误代次、EXIF、文件归属回归在API26/API37/真机共49方法及49默认存储证明通过。Host为GET-only辅助，不能替代真实Electron和模型图片读取；累计模型219/P4 205不变。对照iOS PhotosPicker回调及LocalAttachmentPreparation，完整面板、相机、最近图片、格式/权限和冷结果继续开放，iOS源码不变且A6未执行。

过程与未验：两台自有模拟器控制台显示stopped，分别恢复，不操作其他实例。首轮真机控件名是“影集”，补实际文案后仍只见固定分类，无自定义nonce相册；不选择未知照片，正向真机单列。API26修正验收器高版本权限API后，来源真实字节与URI已确认，但系统页没有Images根/受控图片，根因未确认，正向单列。API37原“无相册”不能当产品失败；改用全局唯一原媒体记录的严格前置，原失败保留。此前一份本任务App生成的媒体库截图已在树外读回核SHA后只删除其准确媒体记录，保留文件证据，防止混入选图。一次回归误写测试类名导致初始化失败，准确类名当前重验通过，不把该次计为产品失败或通过。首次截图捕获系统页过渡，保留原图；最终先观察唯一缩略区域内已生成的黑色文字像素再保存，系统页与原稿截图已查看。系统使用SDK动作，未声称物理指针/完整视觉矩阵通过。
