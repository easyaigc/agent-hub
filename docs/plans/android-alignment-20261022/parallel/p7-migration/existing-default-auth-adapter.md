## Constructor and complete protected call chain

The previous proposal (through commit `6ae07663`) was rejected at source review before adoption or native execution: its ExistingReader constructed an ordinary Storage whose `writableGeneration` could call `activeGeneration -> decodeAtomic -> AtomicFile.readFully`; postwrite default/evidence reads also used ordinary Storage. Inventory prechecks alone do not close a later cross-process recovery window. Prior SDK/JVM receipts remain auxiliary results for that rejected source.

Strict construction now selects an in-memory successful generation result, bypassing ordinary pointer initialization entirely. It checks only an existing private namespace, absent pointer/base/backup/new files and an existing SecretKey. `activeGeneration` and ordinary access guards reject this mode; no constructor/reopen path can call AtomicFile, create a directory or generate a key. Pending files may still race in, but strict reads only reject or observe immutable bytes and never repair/rename/remove them. Namespace/sidecar/path identity checks bracket raw no-follow file reads. Missing optional text is returned only after ENOENT and repeated pure absence checks; malformed/unreadable text or missing key throws.

Actual synthetic writer/Session continuation remain writable as required by their separate roles; this mode does not claim those roles are source-read-only.

## What is authenticated

The adapter requires API26 and the exact DEBUG acceptance package, no MainActivity, an exact current App/runner/UID/signer identity and a newly observed current BOOT_COUNT. It does not impose the old one-alias restriction: only the explicitly required existing aliases are used, with no key import or generation. The native proof explicitly says the kernel boot ID is parent-checked, not native-checked. Root must compare the actual current kernel boot ID before/after each role against the separately hashed current observation; an old boot value is not supplied as current evidence.

For the existing default bootstrap:

- Plan v2 binds a complete bounded current scan to a sorted subset of the exact eleven known `mobile-v1*` roots, one original `mobile-v1` ciphertext, no nested/extra members and private empty sibling roots. Current counts/digest and the independent immutable single-root bootstrap digest are separate. Unknown families, pending files, links and extra records reject.
- The actual default ciphertext is read without following links and compared in full before/after. A shared read lock on the pre-existing empty bootstrap lock file prevents inspection while its original writer owns the fence; no lock bytes, intent or completion are written or repaired.
- Original bootstrap intent/completion bytes must have the pinned hashes, closed supported fields, original ID, one-write semantics, matching intent link, original installed identity and original completed family digest. Original App/runner bytes are compared to original receipts; current App/runner bytes are checked independently. Old receipts/boot data are never rewritten to match an upgrade.
- The shared existing-key text decoder authenticates the actual payload under the installation alias and exact record name. Its complete JSON must be exactly version/purpose/bootstrapId with the declared bootstrap semantics. The proof exports payload/cipher/family hashes and counts, not content or a key. This is bootstrap content, not nonempty draft metadata.

For each of the two explicitly declared Source45 diagnostic originals:

- Paths and aliases are derived only from the pinned old lease UUID. No arbitrary namespace/path/alias is accepted. The declaration, original baseline, original intent, submission and input WAV are read from the existing private root and checked against independent pinned hashes.
- The old declaration remains immutable evidence, even if expired. No `NativeRealFileAsrLease`, `VoiceRecordingStore`, Session, engine, initializer, seal, prepare, transcribe, receipt query or installer is constructed/invoked by authentication.
- The declared namespace must contain exactly the expected index, original-row and binary-audio files, with the parent-observed full ciphertext map, sizes and supported formats. The reader authenticates the exact index and persisted row. Canonical original JSON uses the exact ASR harness encoder (`JSONObject.quote` for keys and strings), separate from EasyWork wire canonical. Original canonical/hash bytes, ID/fingerprint, manifest, attempt flags and all baseline bytes are checked; historical fields in the exact raw row are not ignored.
- Every stored WAV byte is authenticated through the original binary decoder and compared to the full pinned input WAV and manifest. Original baseline/intent/submission/declaration and namespace bytes are reread unchanged. No result is reapplied and no original operation runs.

Source namespaces and their records are read-only. The native authenticator writes only its separate one-use intent/completion evidence. It never borrows an old lease's execution authority or relabels a ciphertext hash as plaintext authentication.
