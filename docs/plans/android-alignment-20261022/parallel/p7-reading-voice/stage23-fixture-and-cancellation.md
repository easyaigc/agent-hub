## Actual product SAF cancellation preparation

The existing three SystemPicker methods remain the selectors. `actualSystemCreateAndOpenCancellationConsumeOnlyTheirOriginalIds` will launch one original product CREATE and one original product OPEN request via the actual Main registry. It never invokes `receivePicker`, `completePicker`, `pickerFailed` or controller `cancel()` to manufacture a result. The new observation policy is an auxiliary pure rule, not a native SAF result.

The test no longer requires or executes a guessed `cancelBackCount`. An optional historical value in a supplied observed profile is validated as metadata only. On the original request it reads the exact system owner and the product's original picker ID/kind/launched state plus its issued queue. It permits one native BACK at a time only while those boundaries still match, with a one-second observation interval and at most three attempts in a 15-second observation window. Returning to this App permanently disables further BACK input for that request; the test then waits for the real null-URI cancellation, original-ID retirement and non-busy `CANCELLED` state. A missing window receives no input. A third owner or unknown/changed caller stops immediately. Rejected input, timeout and unknown results retain the original request and never launch a second picker.

Each original request writes a small `system-picker-cancellation-ID.json` with original ID/kind, monotonic timestamps, actual accepted BACK count, owner/caller state and the actually observed callback. No hierarchy, password or file content is captured. Cleanup sends no additional BACK and calls no controller cancellation. An unresolved caller/window retains its private synthetic storage and records `system-picker-caller-retained.json`; it does not restore another session over that caller. The parent must inspect and reconcile that same original outcome before continuing the native batch.
