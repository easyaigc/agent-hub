# 每项功能同时对齐双端与双 Provider

更新：2026-11-07。用户补充后，EasyWork成为每项功能的固定来源和验收维度。原来把EasyWork集中在N5拉取的做法不再适用；N5仅保留适配器/连接模块的代码归属。

## 两个方面和四个验收格

| 方面               | 必须落实的内容                                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 双端功能一致       | 逐功能比较iOS/Android的功能、交互、页面/字段/状态、文案、系统能力、错误/恢复及无障碍；按准确实现指纹复用旧证据                                 |
| 桌面契约与结果一致 | 同时拉取Codex Host/Adapter与EasyWork最新已提交来源，核对实际声明、生产dispatcher、输入/事件/历史/资源/回执及真实桌面结果，不能只对照另一手机端 |

每项登记 **iOS×Codex、Android×Codex、iOS×EasyWork、Android×EasyWork**。完整范围见[75项四格矩阵](provider-matrix.md)。同一行为在不同Provider上可以使用不同协议；专属或未开放能力记录准确版本、能力、入口禁用/拒绝与理由，不伪造支持，也不把缺证据当不适用。

本地显示、系统授权、迁移等共通项可按同一OS、输入和源码/包指纹复用公共证据，另核两Provider来源数据与权限；不把一次操作虚报为四次实际测试。Codex账号仍按机器目标策略处理，EasyWork维持自身account/grant/绑定协议，不能为了统一界面改变身份约束。

## 会话和资源收尾

按[五条工作线](workstreams.md)拆分。当前调用入口只有最多4个活跃Agent（含总控），采用3路执行轮转；本轮没有正式独立侧栏聊天创建/归档工具，因此使用可核验的本机子Agent，不宣称创建或归档了侧栏聊天，也不通过本机Host或修改官方历史绕过。

每个执行子任务完成且交付验收/合并核实后结束执行，记录实际状态；临时脚本、索引、构建/测试副本、专用进程与端口按准确归属回收，先保存最小证据。共享设备/模拟器/Host、现有绑定/凭据和独有数据不作为普通临时资源删除。确需保留的源码/包列依赖、释放条件和24小时内复核点，工作树完成生命周期检查后再交付。
