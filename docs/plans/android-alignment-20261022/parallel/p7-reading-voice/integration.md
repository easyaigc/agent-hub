Shared integration hooks:

1. Initialize one `NativeReadingLedger(storage)` alongside session storage and one view-owned `NativeReadingLifecycle` per active reading surface. Read/store on `Dispatchers.IO`, publish a cached `NativeUnreadSnapshot`. Reconcile every saved real target; never restrict scopes to the visible online client. Use `workspace.wire` thread summaries / history `wire.thread.readState` to decode `ThreadReadState`; missing legacy state must use the actual latest complete assistant reply with `localPosition`, never an earlier page.
2. On actual displayed target/version change call `present`; foreground/background call `foreground`; drawer, sheet, image viewer and system cover call `uncovered`; navigation away calls `leave`. After latest message text/status/source projection is actually visible, request a lease and enqueue `readVisible`. `latestContentVisible=false` cannot acknowledge. Notice IDs must be matched to the current actual run/request/operation, as in iOS SessionStore.recordVisibleContent; reading an approval must not invoke any decision method.
3. Consume `pendingReads` through a registered typed provider method for `/v1/threads/read`, carrying original full target, threadId, readerId and position. Validate with `acknowledge`; a 409 fetches fresh metadata and does not clear newer content. Metadata retries never replay inputs. Old unknown operation remains sealed/read-only.
4. Parent-owned AndroidManifest `<queries>` needs one intent with action `android.speech.RecognitionService` for modern package visibility. No new permission is needed beyond existing RECORD_AUDIO. `VoiceInputController.start(...,provider=Provider.SYSTEM)` uses the independent system adapter; it never invokes Host commands or writes desktop voice manifests. Pass original target/draft-version guard and apply callback exactly as desktop. For SYSTEM route, use the phone speech disclosure and avoid requiring desktop `codex-dictation` consent; preserve actual Agent permission rules. Default remains DESKTOP until global preference/preflight is implemented. Do not silently select SYSTEM after desktop capture/upload has begun.
5. Integrate `localization-delta.json` into the indicated shared iOS/native Android catalog and regenerate the union catalogs once. Shared N067 only adds its exact key; avoid whole-file overwrite. Without this integration, the new stop hint and a few owned error keys are not fully bilingual. Existing product-owned status localization and arbitrary Host/OS error literals remain separate.

The native SpeechRecognizer adapter prefers an available on-device service (API31+) and otherwise uses the selected system speech service with `EXTRA_PREFER_OFFLINE`; this extra is a preference, so the system service may use network. It is one bounded recognition session, not an automatic restart loop. Android's saved-audio EXTRA_AUDIO_SOURCE is API33+ and may be ignored by unsupported recognizers, which then open the microphone. Consequently, same-recording local fallback is **not implemented or claimed** by this live adapter. It needs a capability-verified file-input provider; API26 remains a platform gap. API37 file source support, no mic reopening and source SHA must be separately proven. See [Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer) and [RecognizerIntent.EXTRA_AUDIO_SOURCE](https://developer.android.com/reference/android/speech/RecognizerIntent#EXTRA_AUDIO_SOURCE).

`NativeReadingLedger.mayPresent(event)` now supplies the exact per-event query requested by P9, including full original run/request/operation metadata; see interfaces.md. Its pure production predicate has 5 host-JVM cases; the transaction/no-write/target tests remain prepared for native execution.
