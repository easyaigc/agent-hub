# Shared bounded workspace thread directory

`NativeWorkspaceThreadDirectory` centralizes named workspace scanning for complete target validation, cursor validation, 1024 pages, 16384 unique thread IDs and 16384 cursor characters. It checks actual coroutine cancellation and the captured owner before and after each fetch, every 32 rows and before returning an actual result. Pages and cursors remain bounded; a repeated cursor, foreign row/project/envelope or a safety limit raises an explicit incomplete-directory failure. At most 1024 reads are issued. Exhausting a safety budget is never returned as proof that the original thread does not exist.

The notification locator uses this scanner with its captured immutable connection and existing `HostReads.workspace` method. It returns only the actual thread and workspace containing the original ID, including a thread after page eight or on page 1024. A complete directory ending without that ID returns no route. An incomplete directory propagates to the coordinator's existing unavailable/retry state, without consuming the opaque ticket. A stale navigation lease yields no route; actual coroutine cancellation still propagates. There is no synthesized thread, alternative owner, conversation action or additional protocol endpoint.
