# P9-3 ordinary Codex foreground notifications

This is an implemented, compilable foreground workline after `8b3af30d`. Shared app navigation/session/Manifest, P7 production adapters and central parity/localization integration remain with the coordinator. It does not close F51–F54 or Android real DEV acceptance. EasyWork/Task Hub and supplier push are unchanged.

## Required integration

`NativeChatNotificationCommands` exposes exactly register, preferences, unregister, status and events. `NativeChatNotificationHttp` implements their actual Host v1 HTTP routes. A separate closed codec validates notifications because the generated Codex command schema does not contain these definitions. No general route/method/IPC forwarding was added to `NativeCodexCommands` or `CodexCommands`.

Capture a `NativeChatNotificationSnapshot` from the actual verified saved/retained `MobileClient`, its credential string and its credential-reference epoch. Resolve the credential on IO before capture. The snapshot freezes the complete accountless Codex host/workspace/runtime, copied paired routes/certificate, endpoint, credential and epoch. Its authorization fingerprint binds machine target, paired certificate, epoch and credential hash, independent of route or legacy account metadata. It never reads a live token callback and redacts diagnostics. A changed credential with a still-active subscription requires the original retained snapshot for revocation; a new credential cannot replace an unknown operation's authority.

Construct one `NativeChatNotificationForegroundMonitor` per exact saved target, using the same root `NativeSessionStorage`/`NativeChatNotificationStore`/sound library as the settings and P7 ledger. Construct `NativeChatNotificationForegroundDelivery` with the **required** shared P7 `NativeChatNotificationReading` and an active-set reconciliation callback. The callback must check the supplied `current` fence before changing P7 state, scope the Host's actual active IDs to ordinary actionable notices on that exact target, and preserve other targets/read watermarks. There is no default/noop unread adapter, no second unread ledger and no invented badge event. P7 receives the original event, including original read target/version, before muted kind/banner/system decisions.

The parent owns a `NativeChatNotificationPresentationFence`. Invalidate it **before** changing read visibility/read-watermark advancement, navigation, credentials, saved target or migration state; stop the old monitor before starting a new immutable snapshot with a newly captured lease. Stop it on background/lifecycle exit. `start` polls sequentially only while its captured fence is current; it has no background service or vendor wakeup. The status flow is typed machine state, not localized user copy. The localization delta supplies suggested mapping for the coordinator's status UI.

Use `NativeChatNotificationForegroundDelivery.open` for tap handling and supply the existing exact-target, draft-preserving route. It reads and consumes the opaque original ticket on IO, refreshes the exact target, rechecks local and parent leases, and opens on Main. It exposes no approval, resume, input or replay function. Do not mount both this reader and the legacy P9-1 `Runtime.receive/open` path; the legacy compatibility methods still have synchronous storage calls and are not the new production foreground path. Preserve mainline's existing Runtime `mayPresent` hook when integrating this branch.

The new Store claim includes the same mainline P7 `mayPresent` check inside the shared root operation lock. Preference changes immediately invalidate memory-only configuration/presentation leases, including before an async settings save starts. Target bind/revoke invalidates only that target's presentation lease. The final Main post uses these atomic leases without decrypting JSON or holding a disk lock across a dispatcher hop. Parent invalidation is still required for P7 read visibility and migration changes.

## Durable identity, operations and batches

`NativeChatNotificationIdentity` generates and encrypted-persistently stores a real X25519 private/public key pair with a stable local device ID. It is separate from EasyWork. Registration omits `deviceToken` and `environment`. The Host's missing-APNs-token status with `delivery=foreground-only` is usable foreground status after a confirmed registration; it does not imply background capability. Missing/corrupt identity or a missing previously bound journal fails closed without a new ID/key. A journal-bound marker is written before first journal publication; a crash between these files blocks safely.

The foreground journal stores each immutable mutation before any HTTP attempt. It retains the operation ID, kind, exact preferences, authorization fingerprint, composite device/public-key identity and scoped target. Only a validated direct response to that still-original call can confirm it. A missing/failed/invalid response remains unknown. Repeated synchronization queries status for the same local device ID and original captured authorization; it never reissues the mutation, invents another device ID or treats revision equality as a complete receipt. Confirmed operations are retained for at least 24 hours; bounded capacity fails without clearing an unknown operation. A known preferences generation cannot move backwards, and enabling after a confirmed revocation requires a higher generation.

Every feed is strictly bounded to 2 MiB UTF-8 and 2048 original events/active IDs. Its complete target, original IDs, kinds, timestamps, read target/position and cursor relation are validated. The journal prepares the whole bounded batch before P7 or OS calls. Before each event call it durably records `processing`; afterwards it stores a final queryable outcome. A process interruption leaves started work `unknown-interrupted-no-replay`; it is not called again. Unstarted pending events can proceed under their original still-current batch. Duplicate originals from a restarted Host cursor reuse their immutable result; a reused ID with changed payload is rejected.

The cursor advances only once all original batch IDs have durable final outcomes and the required P7 active-set reconciliation returns under the captured fence. Exceptions preserve the old cursor. Late old streams cannot overwrite a different pending batch or newer subscription: original batch/authorization/revision and current cursor are checked under the storage transaction. A preference/authorization mismatch abandons the old batch without advancing its cursor, retaining terminal results and marking unattempted work stale. `outcome(identity,target,eventId)` and `view(identity,target)` query local results; `view.mutations` preserves original operation receipts. The report retains a count/state for unknown event outcomes even after the cursor is safely committed. These results describe processing and system submission, not display/sound/device arrival.

All new ledger/notification journal, hashing of large preferences, encrypted preference/catalog/claim/ticket work runs on IO. Channel/notification/navigation/permission and page projection work runs on Main. Default and category sound settings now load/reload/select/delete on IO with captured generation and revision checks. Errors preserve original bytes, show unavailable/retry, and never show writable fake defaults. An activity-result URI is queued until resume; import keeps its original preference revision, cancels on page pause/disposal, and does not automatically replay or select after a late result. This supersedes the synchronous child-page limitation recorded in the earlier settings recovery checkpoint.

## Contract gaps and acceptance

The [Host contract audit](foreground-contract.md) defines FG01–FG04. Host v1 status lacks device/public-key/preferences/subscription intent fingerprints, so ambiguous register/preferences/unregister recovery stays visibly blocked even if status revision matches. Unknown registration cannot be followed by unregister as proof that an absent-device tombstone exists. Feed pagination/epoch/reset is absent; capacity failure does not advance. These need backend/parent review before automatic recovery can be promised. No backend receipt or remote tombstone support was invented here.

The app and runner compile with the new code. The shipping wire/journal decoder and actual single-attempt HTTP implementation pass 45 JVM vectors against an owned loopback fixture. This is auxiliary evidence. Twenty-six foreground tests compile with real private Android storage plus synthetic command/reading ports; six settings recovery and four sound UI scenarios compile in the owned MainActivity fixture with an outer timeout and default-data preservation. None were executed on Android in this workline.

The coordinator must mount the new path/P7 callbacks, apply localization/parity/migration deltas, and execute native API26/API37/physical acceptance under its lease. Then verify a fresh foreground registration, actual ordinary Electron/model events, P7 badge/read suppression, late target/preference/read results, unknown recovery without reissue, exact draft-preserving cold click, and independent desktop no-duplicate-input evidence. Existing F53 system-process URI/playback gates remain open. No physical device, real Host, model, OS notice/player, provider or vendor action was performed here; no current native or real DEV pass is claimed.
