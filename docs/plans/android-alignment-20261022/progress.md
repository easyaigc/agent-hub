## 接下来按什么顺序做

1. **P7当前优先**：F59 portable第一切片和6项共同规则已接入；current-generation与旧代family十五项Native已通过；Long 内层封包已接入，原冻结锁释放失败保持原失败并阻止新 owner 已通过受控原生用例；最后一个 voice/F59/inbox writer 的原关闭门禁及十项原生也已通过，继续认证加密容器与目的端惰性发布。当前原生 24 项已按候选通过；硬链接 reader 拒绝、真实故障、交互和 UI 另验；旧UNKNOWN不重放。原回复strict source/outbox/消费/编辑退场仍开放，随后语音/未读/生命周期。
2. **完整迁移**：继续真实Main导入/导出、24组库存、失败补偿、自然故障与冷恢复。F59 Android生产和portable描述/校验已接入，认证容器、激活与 iOS 域未实现，有原件时整包迁移保守拒绝；iOS现有F59原件/journal也未进入迁移Payload，双端缺口单列，不能按完整迁移通过。
3. **语音、未读、生命周期**：原件与失败恢复、阅读权威/原通知回执、Main/系统冷入口、真实停止/死亡/重开逐项验。
4. **P9独立项**：新三包诊断先完成精确源码/SDK/API36准入，再采集SystemUI拒绝节点；本轮未找到原通知行，系统前置状态待准确准备；诊断不算通知点击通过。继续真实Host、偏好/声音/隐私与完整UI。
5. **新增iOS差异及P1–P6剩余矩阵**：F73共享额度非法数值/字符串/非有限值拒绝及合法超100%双端UI仍需按新指纹补验；下一轮模型/强度/速度预览与owner分离、文件大小兼容、HTML预览/速度图标/最近导航，以及原owner、复制、建议、资源、视觉/AX按优先级补齐。
6. **P10**：适用依赖关闭后执行最终双端、版本、主题、语言、方向、字号、性能、稳定性和发布门槛。

后续各阶段从 Gitea 最新 `main` 开始，按独立验收范围使用短期 PR 分支。验收通过后更新本表与阶段档案，直接提 PR 合入 `main`。核对远端主线包含已交付提交后清理对应分支，再从最新主线推进下一阶段。环境待验项保留在单独清单中。
