# Saved-file destination: post-write process termination

This is an opt-in native execution contract for two fresh synthetic actual Sessions. It uses existing `NativeEncryptedVoiceDraftDestinationPort` and controller boundaries. No production patch is proposed. The three previously passed Session fixture files remain unchanged. This child supplies source/auxiliary compilation; the parent owns the actual process termination, native results, app/runner/source fingerprints and device lease.

## Exact boundaries

`savedVoicePostWriteBoundary` is a closed integer argument, default `1`:

| Value | Held point                                                                         | Actual state before termination                                                                                                                        |
| ----- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1     | `NativeSessionStorage.writeVoiceDestinationMetadata` checkpoint 1                  | The real encrypted metadata write finished; the product's readback/acknowledgement and memory publication have not run.                                |
| 2     | The same method's checkpoint 2                                                     | The product read back the exact metadata; it has not returned its acknowledgement or published memory.                                                 |
| 3     | Controller's result port, immediately before the concrete encrypted `applied` call | The actual destination returned its validated receipt and the actual Session published memory. The fixture holds the port before the catalog terminal. |

Values 1 and 2 reuse the existing executor-checkpoint parameter while retaining the actual Session owner. Value 3 forwards `pending` and `stage` to the actual encrypted port, observes the actual destination receipt, and pauses before invoking its terminal. The product authors every stored draft and receipt. The fixture authors no applied terminal. Its observation receipt is kept in evidence and is supplied to no product write port during recovery.

All values reach the requested post-write/pre-applied state. Start with value 1. Each additional value requires a new run and another separately recorded termination; one run must never be reused for a different boundary.

## Unknown outcomes and evidence

Only one bounded heartbeat file is replaceable. `intent`, `inputs`, two observations, `ready`, claims and completions are immutable. Existing run directories, namespaces or claims reject a new writer/reader attempt. On any unknown result, inspect the same intent, heartbeat, process state, source catalog and completion before scheduling further work; do not blindly repeat a writer, reader, recognition or original operation.

If a writer reaches its timeout or normal cleanup, it creates `writer-ended.json`. That run cannot qualify as the requested process-termination proof. Preserve it as failed/inconclusive. Do not delete or retry its namespaces to manufacture a clean attempt. Normal abort releases and joins its synthetic owners without publishing a passing window result.
