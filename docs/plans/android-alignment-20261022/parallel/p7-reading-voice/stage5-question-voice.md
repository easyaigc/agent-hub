# Stage 5: voice input for existing question drafts

Base `6a4c788f6612087ab2a8e2175f4f01d76a83eee7`. Actual iOS reference: RootView.QuestionAnswerField, its voiceTarget/provider, recordingQuestionId fences, secret-field exclusion, lifecycle and shared VoiceInputControls. Android's existing question fields had text entry but no voice entry. This stage adds only voice-related field/Session fragments; question submission, decisions, transport and P9 notice authority are unchanged.

A separate Session-owned question controller uses the same default setting, explicit desktop grant/system-service boundary, permission gate, native listening/finishing component and failure actions as ordinary input. Only one question controller exists, and ordinary/question capture cannot start while the other is active. A default change applies to the next capture. The global App hosts one permission launcher for each mutually exclusive controller; no MainActivity or Manifest change. New non-secret custom question fields expose “dictate reply”; secret fields and non-question approvals have no entry and the Session rejects them before reading text for voice.

The voice owner key combines the complete existing target/thread cache key with a canonical JSON tuple of thread, turn, approval and question IDs. It does not infer identity from titles. Callback validity also requires current exact approval/destination, connection revision/endpoint/certificate/reader/provider, foreground, original answer text and the original desktop grant when used. A result only appends to that question's still-current custom draft, leaving the main composer and choices alone. The active answer field and question submit/skip buttons are disabled during question voice; successful recognition never invokes answer/approval or a model operation. Submission remains an independent explicit action under its existing content-sharing rules.

NativeQuestionVoice uses the real existing custom-answer map, remembers current text/callbacks instead of a stale Compose value, and cancels only its own owner on disposal. Background/navigation/restore suspend the corresponding controller and reject old callbacks. Replacement approvals dispose the original owner, even if IDs are reused with changed content. Partial recognition can only be filled explicitly into the same original answer. Cancelling a provisional unsealed capture follows existing cleanup; already sealed/attempted original recordings stay in the existing encrypted store with their immutable identity and receipt behavior. There is no original-file phone transcription, replay, new store/Schema or migration path.

Prepared NativeQuestionVoiceUiTest uses the actual question UI/Session/Keystore with synthetic workspace/runtime and injected recognizer callbacks. It checks secret exclusion both at the UI and Session guard without even reading the secret for voice; an otherwise enabled submit button becomes disabled while recording; the selected route fills only the question draft and keeps the main composer unchanged; defaults cannot retarget the active route; and background/approval replacement/navigation reject late callbacks without answering. It mounts the production question panel without the permission launcher and resolves only a fake callback gate, so neither OS permission nor microphone is changed. Three native methods are compiled, not executed here. All scene/real-device/real Host/DEV, asynchronous question-sheet layout, English catalog union and acoustic verification remain coordinator gates.

Stage 3's parent-reported physical directory rules/session pass and the prior reading/hint passes remain separate fingerprinted evidence. Stage 4's persistence/Manifest owner handoffs still apply: current default is explicitly session-only until the approved store port is bound; system capability queries and the original-file limitation must not be promoted to microphone/offline or file-transcription acceptance. The sealed original operation and A6 remain untouched/paused. Exact source, APK, log, recovery-chain and publication evidence stays outside the worktree.
